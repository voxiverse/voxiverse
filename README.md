# Voxiverse

Voxiverse is a voxel sandbox of many worlds. Each one is different, and none of them is the last.

Voxiverse is written from scratch in [Odin](https://odin-lang.org/) on raw Vulkan, with no
engine and no third-party art. Every texture and sound is generated by code, and the game is
a single small executable.

## Status

Voxiverse is pre-alpha and under active development. It runs on **Windows and Linux**. macOS
(Apple Silicon) builds and packages in CI but is not tested on hardware by the project.

- [docs/platforms.md](docs/platforms.md) describes what runs where and what each platform requires.
- [docs/plan.md](docs/plan.md) contains the design and the milestones.

## Download

Builds for 64-bit Windows and Linux are published on the
[Releases](https://github.com/voxiverse/voxiverse/releases) page once a release exists. Unpack
the archive and run the game; there is nothing to install.

Every push to `main` also produces these builds, which are kept with the corresponding
[CI run](https://github.com/voxiverse/voxiverse/actions). Downloading them requires a GitHub
login.

To determine which download applies to your system, and what your graphics driver and
operating system must provide, see [docs/platforms.md](docs/platforms.md). To build the game
yourself, follow the instructions below.

## Building from source

### Requirements

- A GPU driver with Vulkan 1.3. Any recent NVIDIA, AMD or Intel driver qualifies; on Linux,
  Mesa's Vulkan drivers qualify.
- On Linux, an X11 or Wayland desktop.

### Installing the toolchain

Install the Odin toolchain with [odinup](https://github.com/voxiverse/odinup). This is done
once per machine. odinup installs whatever is missing, including a C toolchain; Visual Studio
is not required on Windows.

On Linux:

```sh
curl -sSfL https://raw.githubusercontent.com/voxiverse/odinup/main/install.sh | sh
```

On Windows (PowerShell):

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/voxiverse/odinup/main/install.ps1 | iex"
```

Open a new terminal afterwards so that `odin` is on your `PATH`.

### Building and running

Clone the repository, install the exact compiler and tools it pins, and run the game:

```sh
git clone https://github.com/voxiverse/voxiverse
cd voxiverse
odinup install
./build.sh run        # Windows: .\build run
```

The first build also fetches the pinned shader compiler (checksum-verified, into `build/`)
and, on Linux, compiles Odin's sound library (miniaudio) once. Subsequent builds take seconds.

Once the game is running, choose **Singleplayer**, create a world, and play.

### Development tools

For work on the code, `odinup install --dev` also builds the development tools:

- the [ols](https://github.com/DanielGavin/ols) language server, for your editor;
- `odinfmt`, which `build check` and `build fmt` use.

### Vulkan validation layer

The Vulkan validation layer is optional but recommended for development. Debug builds enable
it automatically, and it reports GPU API misuse in the log.

| Platform | Package |
|---|---|
| Linux | `vulkan-validation-layers` (Fedora, Arch) / `vulkan-validationlayers` (Debian, Ubuntu) |
| Windows, macOS | The [Vulkan SDK](https://vulkan.lunarg.com/sdk/home) |

## Build commands

Run `./build.sh <command>` on Linux and macOS, and `build <command>` on Windows
(`.\build <command>` in PowerShell).

| Command | Description |
|---|---|
| `check` | Type-checks every package (`-vet -strict-style`; warnings are errors) and verifies formatting. |
| `test` | Runs the unit tests. |
| `fmt` | Formats all sources in place. |
| `shaders` | Compiles `assets/shaders` to SPIR-V (only what changed). |
| `build` | Builds the game into `build/`. The default is a development build (lightly optimized, with debug info and the development aids). Variants: `--debug` (unoptimized, for stepping), `--release` (fully optimized; slow to compile), `--release --symbols` (for profilers), `--sanitize`, `--profile`. |
| `run` | Builds and runs the game. Arguments after `--` are passed to the game, e.g. `run -- --frames 120`. |
| `serve` | Builds and runs the dedicated server. Arguments after `--` are passed to it. |
| `debug` | Builds the game and starts it in gdb/lldb (RAD Debugger on Windows) with the Odin pretty-printers. |
| `netdump`, `replay` | Prints a network trace, or replays its client messages against a fresh server (see [docs/debugging.md](docs/debugging.md)). |
| `sfx` | Writes every sound effect to `build/sounds/*.wav`. |
| `worldmap` | Draws a world from above to `build/worldmap.png` (`-seed:42 -size:4096`; `-bench:64` times chunk generation). |
| `bench <scenario>` | Benchmarks under fixed conditions. Scenarios: `chunks` (generation, light and meshing on one thread; `-check` as in CI), `telemetry` (an event's emit and write cost; `-check` as in CI), `budgets` (the server's save, audit, counters, journal and flood costs; `-check` as in CI), and the game scenarios `viewmodel`, `load`, `views`, `flight`. Results are written to `build/benchmarks/`. |
| `trace` | Summarizes a profile trace (`build/voxiverse.spall`). |
| `perf` | Records the game, `server` or `bench` under Linux perf and prints where the time went (`perf -- --exec "..."`). |
| `package` | Builds a release package for this platform in `build/dist/`: one executable each for the game and the server, `README.txt`, and the licences. |
| `icon` | Draws the game's icon to `build/voxiverse.ico`. |
| `help` | Lists the commands and their flags. |

For debugging and profiling (validation, leak tracking, stack traces, the sanitizer, debuggers
with Odin pretty-printers, RenderDoc captures, CPU and GPU profiling), see
[docs/debugging.md](docs/debugging.md).

### Versioning and releases

Versions take the form `0.<milestone>.<patch>` and are derived from git. A commit tagged
`v0.21.0` builds as 0.21.0; the commits after it build as `0.21.0+N`.

To make a release, tag the commit with the release's name as the tag message, then push the
tag:

```sh
git tag -a v0.21.0 -m "Pre-Alpha 1"
```

CI builds the packages and creates a **draft** release, which is reviewed and published by hand.

## Playing

`build run` opens the title screen.

### Saves

**Singleplayer** lists your saves, most recently played first. From this screen you can:

- play a save (or double-click it);
- create a save. Its seed is under More options: any text is accepted, and an empty seed
  selects a random one;
- rename a save or open its folder (Edit);
- delete a save.

The game saves every minute and when you leave the world. Saves are stored in
`voxiverse/saves` in your user data directory: `~/.local/share` on Linux, `%LOCALAPPDATA%` on
Windows, and `~/Library/Application Support` on macOS.

### Controls

| Key | Action |
|---|---|
| Mouse | Look. |
| <kbd>W</kbd> <kbd>A</kbd> <kbd>S</kbd> <kbd>D</kbd> | Walk. |
| <kbd>Space</kbd> | Jump. Double-tap to start or stop flying. While flying: up. |
| <kbd>Shift</kbd> | Sneak: crouch, and keep to the edge of a ledge. While flying: down. |
| <kbd>Ctrl</kbd> | Sprint. |
| Left / right click | Break / place a block (hold to repeat). |
| <kbd>1</kbd>–<kbd>5</kbd>, mouse wheel | Choose what to hold from the five-slot hotbar. A new player starts with stone, dirt, grass, sand, logs, leaves, water and lamps, and the rocket launcher where they are permitted to fire it. Placing a block uses one up; breaking a block drops it, to be picked up by walking over it. |
| <kbd>E</kbd> | Inventory. Drag stacks between slots, right-click to split a stack, shift-click to move between the hotbar and the rest, or press a number key to swap with that hotbar slot. In your own world every item is available to take. |
| <kbd>Q</kbd> | Drop one of the held item (<kbd>Ctrl</kbd>+<kbd>Q</kbd>: all of it). |
| <kbd>T</kbd>, <kbd>/</kbd> | Chat / a server command (`/spawn`, `/mute bob 1h`; Tab completes). `&c` colours and `&l` bolds text where your role allows it. Up and Down step through what you have sent. |
| <kbd>Esc</kbd> | Close whatever is open (chat, console, a menu); otherwise open the game menu (Back to Game, Options, Open to LAN, Save and Quit to Title). When you are alone in your own world, pausing stops the world. |
| <kbd>F11</kbd> | Fullscreen. |
| <kbd>F2</kbd> | Screenshot. |
| <kbd>F3</kbd> | Debug overlay: position, chunks, memory, server tick. |
| <kbd>F4</kbd> | Tuning panel: every setting and debug switch, live. |
| <kbd>`</kbd> | Console. |

These are the default bindings. Every binding can be changed in Options > Controls. Keys are
bound by their physical position on the keyboard, so WASD stays together on any layout, and
are named as your layout prints them.

### Options

Options are organized in tabs:

| Tab | Settings |
|---|---|
| Video | Display, VSync, a frame rate limit, field of view, render distance, GUI scale, brightness, clouds, the FPS counter. |
| Sound | Volume. |
| Controls | Mouse; hold or toggle for sneak and sprint. |
| Accessibility | Reduce motion, chat text size. |
| Profile | Your name. |

### Commands

Commands are entered in the chat, starting with `/`; Tab completes the commands you are
permitted to use. In your own world you may do anything. On a server, you may do what its
roles allow (see [Permissions](docs/debugging.md#permissions)).

Builders edit in bulk. `/pos1` and `/pos2` mark the corners of a box at the block you are
looking at; then `/fill stone`, `/replace dirt sand`, or `/sphere 5 stone` (at the first
corner) applies the edit.

### Worlds

New worlds are Earth-like: continents and oceans, rivers, mountains with cliffs and
overhangs, caves and ores, forests, taiga, tundra, deserts and beaches. Worlds saved earlier
keep the land they were created with.

- `/locate desert` flies you to the nearest desert. A double tap of jump starts or stops flying.
- `set worldgen.mountain_height 180` in the console (or F4) changes how land is generated from
  then on, and `/regen` regenerates the land around you accordingly. Your edits are kept.

### Water

Water flows as in Minecraft. Open the side of a lake and the water pours out, downwards first,
then spreading and thinning. A new source forms between two sources.

In water you swim: jump to rise (and, against a ledge, to climb out), and sneak to dive. Under
the surface the world turns blue and the view closes in. Sunlight fades with depth, and trees
cast shade.

### Structures

Towers, ruins and wells stand in the world, and dungeons lie beneath it, reached by a spiral
stair in a stone shaft (`/locate tower`, `/locate dungeon`).

You can also save your own structures:

1. Select a box with `/pos1` and `/pos2`.
2. `/structure save hut` keeps it with the world. Its air leaves whatever is already present
   when pasted; `/structure save hut clear` makes the air clear it instead.
3. `/structure paste hut 1` places it at the first corner, turned a quarter.
4. `/structure list` lists the saved structures.

Cobblestone, stone bricks, planks and glass are intended for building.

### Developer console

The console (`` ` ``) is intended for developers. It shows the log and accepts developer
commands; `help` lists them, and `server <command>` sends a server command.

`run -- --exec "cmd; cmd"` types console commands at startup to reproduce a state, for example:

```sh
./build.sh run -- --exec "set render_distance 8; singleplayer; /tp 0 80 0 45 -20"
```

## Multiplayer

### Opening your own world

Pause, then choose **Open to LAN**. Others on your network see the world listed under
**Multiplayer**, or can join `your-address:27315` by **Direct Connection**.

### Running a dedicated server

```sh
./build.sh serve -- --universe universes/home --password secret
```

Run `build/voxiverse-server --help` for every flag (port, name, seats, view distance,
permissions). Ctrl+C saves the universe and stops the server.

### Playing over the internet

Forward UDP port 27315 on the host's router to the host, then join the host's public address.
There is currently no relay or NAT hole punching.

### Player names

Multiplayer asks for your name the first time; afterwards it is in Options > Profile. Worlds
keep each player's position by name.

## Where things go

[docs/layout.md](docs/layout.md) lists every folder, what belongs in it and the file-name
patterns it allows. `./build.sh check` fails on a tracked file that matches no pattern of its
folder, on a folder the manifest does not list, and on an untracked file anywhere outside
`build/` (every temporary file goes under `build/`, which git ignores). Adding a folder means
adding its row to the manifest in the same commit.

## Source layout

See [docs/plan.md](docs/plan.md#layout). Packages depend only downward: `common/base/` depends on
nothing, `common/game/` never imports platform or GPU code, and `client/ui/` never imports the renderer.

Imports go through the collections `client`, `server` and `common`
(`import "common:game"`, `import "client:gpu"`), never a relative path. `./build.sh` passes
them to every `odin` it runs. To run `odin` yourself (`odin check client`, or an editor's
language server) pass the same flags, which `ols.json` lists:

```
odin check client -no-entry-point -collection:client=client -collection:server=server -collection:common=common
```
