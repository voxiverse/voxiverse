# Voxiverse

A voxel world you can build and break, alone and later with friends. Written from scratch
in [Odin](https://odin-lang.org/) on raw Vulkan, with no engine and no third-party art:
every texture is generated by code.

**Status:** early and moving fast. You can create worlds, walk, fly, break and place blocks
(lamps light up caves) under a sky that runs through day and night, meet the critters that
wander the grass, play together over the LAN or the internet, and everything is saved. Runs
on **Windows and Linux**; macOS is planned.
[PLAN.md](PLAN.md) has the design and the milestones.

## Quick start

You need a GPU driver with Vulkan 1.3 (any recent NVIDIA, AMD or Intel driver; on Linux,
Mesa's Vulkan drivers) and, on Linux, an X11 or Wayland desktop.

1. Install the Odin toolchain with [odinup](https://github.com/voxiverse/odinup), once per
   machine (it installs what's missing, including a C toolchain; no Visual Studio needed on
   Windows). Open a new terminal afterwards so `odin` is on your PATH.

   ```sh
   # Linux
   curl -sSfL https://raw.githubusercontent.com/voxiverse/odinup/main/install.sh | sh
   ```

   ```powershell
   # Windows (PowerShell)
   powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/voxiverse/odinup/main/install.ps1 | iex"
   ```

2. Get the code, install the exact compiler and tools it pins, and run it:

   ```sh
   git clone https://github.com/voxiverse/voxiverse
   cd voxiverse
   odinup install
   ./build.sh run        # Windows: .\build run
   ```

The first build also fetches the pinned shader compiler (checksum-verified, into `build/`)
and, on Linux, compiles Odin's sound library (miniaudio) once; after that a build takes
seconds. Choose **Singleplayer**, create a world, and play.

Working on the code? `odinup install --dev` also builds the development tools: the
[ols](https://github.com/DanielGavin/ols) language server for your editor, and `odinfmt`,
which `build check` and `build fmt` use.

Optional, recommended for development: the Vulkan validation layer, which debug builds turn
on automatically and which reports GPU API misuse in the log.

- Linux: `vulkan-validation-layers` (Fedora, Arch) / `vulkan-validationlayers` (Debian, Ubuntu)
- Windows / macOS: the [Vulkan SDK](https://vulkan.lunarg.com/sdk/home)

## Build

`./build.sh <command>` on Linux/macOS, `build <command>` on Windows (`.\build <command>` in PowerShell):

| Command | What it does |
|---|---|
| `check` | Type-check every package (`-vet -strict-style`, warnings are errors) and verify formatting |
| `test` | Run the unit tests |
| `fmt` | Format all sources in place |
| `shaders` | Compile `assets/shaders` to SPIR-V (only what changed) |
| `build` | Build the game into `build/` (debug; `--release`, `--sanitize`, `--profile`) |
| `run` | Build and run; arguments after `--` go to the game, e.g. `run -- --frames 120` |
| `serve` | Build and run the dedicated server; arguments after `--` go to it |
| `debug` | Build and start in gdb/lldb (RAD Debugger on Windows) with Odin pretty-printers |
| `netdump`, `replay` | Print a network trace / replay its client messages against a fresh server (DEBUGGING.md) |
| `sfx` | Write every sound effect to `build/sounds/*.wav` |
| `worldmap` | Draw a world from above to `build/worldmap.png` (`-seed:42 -size:4096`; `-bench:64` times chunk generation) |
| `help` | List the commands and their flags |

Debugging and profiling (validation, leak tracking, stack traces, sanitizer, debuggers with
Odin pretty-printers, RenderDoc captures, CPU/GPU profiling): see [DEBUGGING.md](DEBUGGING.md).

## Running

`build run` opens the title screen. Singleplayer lists your worlds: create one (any text works
as a seed, or leave it empty for a random one), play, or delete. Worlds save every minute and
when you leave; they live in `voxiverse/saves` in your user data directory
(`~/.local/share` on Linux, `%APPDATA%` on Windows, `~/Library/Application Support` on macOS).

| Key | |
|---|---|
| Mouse | Look |
| <kbd>W</kbd> <kbd>A</kbd> <kbd>S</kbd> <kbd>D</kbd> | Walk |
| <kbd>Space</kbd> | Jump; double-tap to fly or stop flying (flying: up) |
| <kbd>Shift</kbd> | Sneak (flying: down) |
| <kbd>Ctrl</kbd> | Sprint |
| Left / right click | Break / place a block (hold to repeat) |
| <kbd>1</kbd>–<kbd>9</kbd>, mouse wheel | Choose the block to place (stone, dirt, grass, sand, log, leaves, water, lamp), or the rocket launcher (9, where you may fire it); `place <block>` places any other |
| <kbd>T</kbd>, <kbd>/</kbd> | Chat / a server command (`/spawn`, `/mute bob 1h`; Tab completes). `&c` colours and `&l` bolds where your role allows; Up/Down walk what you sent |
| <kbd>Esc</kbd> | Close what is open (chat, console, a menu), else the pause menu (Resume, Options, Open to LAN, Leave World). Alone in your own world, pausing stops it |
| <kbd>F11</kbd> | Fullscreen |
| <kbd>F2</kbd> | Screenshot |
| <kbd>F3</kbd> | Debug overlay: position, chunks, memory, server tick |
| <kbd>F4</kbd> | Tuning panel: every setting and debug switch, live |
| <kbd>`</kbd> | Console |

Options has the FPS counter (**Show FPS**), **VSync** (off: as many frames as the machine
can draw), fullscreen, field of view, view distance and volume.

In your own world you may do anything; on a server, what its roles let you (see
[DEBUGGING.md](DEBUGGING.md#permissions)). Then the console also edits in bulk: `pos1` and `pos2` mark the corners of a box at the block you aim at, then
`fill stone`, `replace dirt sand` or `clear`; `sphere 5 stone` and `explode 8` act on the
aimed block. Hotbar slot 9 is a rocket launcher.

New worlds are Earth-like: continents and oceans, rivers, mountains with cliffs and
overhangs, caves and ores, forests, taiga, tundra, deserts, beaches (worlds saved before
keep the land they were made with). `locate desert` flies you to the nearest desert, `fly`
starts or stops flying. `set worldgen.mountain_height 180` (or F4) changes how the land is
made from then on, and `regen` remakes the land around you that way (your edits stay).

Water flows as in Minecraft: open a lake's side and it pours out, down first, then spreading
and thinning; between two sources a new one forms. In water you swim: jump to rise (and,
against a ledge, to climb out), sneak to dive; under the surface the world turns blue and
close. Sunlight fades with depth, and trees cast shade.

Out in the world stand towers, ruins and wells; dungeons lie under it, a spiral stair in a
stone shaft leading down (`locate tower`, `locate dungeon`).
Build your own: select a box (`pos1`, `pos2`) and `structure save hut` keeps it with the world
(its air leaves what is there when pasted; `structure save hut clear` clears it);
`structure paste hut 1` puts it at the block you aim at, a quarter turned. `structure list`
shows them. Cobblestone, stone bricks, planks and glass are for building (`place glass`).

The console shows the log and takes commands (`help` lists them); `run -- --exec "cmd; cmd"`
runs commands at startup, e.g. `--exec "set view_radius 8; set view_height 4; singleplayer; tp 0 80 0 45 -20"`.

## Playing together

- **From your own world:** pause, then **Open to LAN**. Others on your network see it under
  **Multiplayer** (or join `your-address:27315`).
- **A dedicated server:** `./build.sh serve -- --world worlds/home --password secret` (or run
  `build/voxiverse-server --help` for every flag: port, name, seats, view distance, permissions).
  Ctrl+C saves and stops it.
- **Over the internet:** forward UDP port 27315 on the host's router to the host, then join its
  public address. There is no relay or hole punching (yet).

Your name is set in **Multiplayer** or Options. Worlds keep each player's place by name.

## Layout

See [PLAN.md](PLAN.md#layout). Packages only depend downward: `base/` depends on nothing,
`game/` never imports platform or GPU code, and `ui/` never imports the renderer.
