# Voxiverse

A voxel world you can build and break, alone and later with friends. Written from scratch
in [Odin](https://odin-lang.org/) on raw Vulkan, with no engine and no third-party art:
every texture is generated by code.

**Status:** early and moving fast. You can create worlds, walk, fly, break and place blocks
(lamps light up caves) under a sky that runs through day and night, meet the critters that
wander the grass, play together over the LAN or the internet, and everything is saved. Runs
on **Windows and Linux**; macOS is planned.
[PLAN.md](PLAN.md) has the design and the milestones.

## Download

Builds for Windows and Linux (64-bit) are on the
[Releases](https://github.com/voxiverse/voxiverse/releases) page once one is out: unpack
and run, nothing to install. Every push to main also builds them, kept with its
[CI run](https://github.com/voxiverse/voxiverse/actions) (downloading those needs a
GitHub login). To build it yourself, read on.

## Quick start

You need a GPU driver with Vulkan 1.3 (any recent NVIDIA, AMD or Intel driver; on Linux,
Mesa's Vulkan drivers) and, on Linux, an X11 or Wayland desktop.

1. Install the Odin toolchain with [odinup](https://github.com/voxiverse/odinup), once per
   machine (it installs what's missing, including a C toolchain; no Visual Studio needed on
   Windows). Open a new terminal afterwards so `odin` is on your PATH.

   ```sh
   # Linux
   curl -sSfL https://raw.githubusercontent.com/voxiverse/odinup/main/install.sh | sh
   ```

   ```powershell
   # Windows (PowerShell)
   powershell -NoProfile -ExecutionPolicy Bypass -Command "irm https://raw.githubusercontent.com/voxiverse/odinup/main/install.ps1 | iex"
   ```

2. Get the code, install the exact compiler and tools it pins, and run it:

   ```sh
   git clone https://github.com/voxiverse/voxiverse
   cd voxiverse
   odinup install
   ./build.sh run        # Windows: .\build run
   ```

The first build also fetches the pinned shader compiler (checksum-verified, into `build/`)
and, on Linux, compiles Odin's sound library (miniaudio) once; after that a build takes
seconds. Choose **Singleplayer**, create a world, and play.

Working on the code? `odinup install --dev` also builds the development tools: the
[ols](https://github.com/DanielGavin/ols) language server for your editor, and `odinfmt`,
which `build check` and `build fmt` use.

Optional, recommended for development: the Vulkan validation layer, which debug builds turn
on automatically and which reports GPU API misuse in the log.

- Linux: `vulkan-validation-layers` (Fedora, Arch) / `vulkan-validationlayers` (Debian, Ubuntu)
- Windows / macOS: the [Vulkan SDK](https://vulkan.lunarg.com/sdk/home)

## Build

`./build.sh <command>` on Linux/macOS, `build <command>` on Windows (`.\build <command>` in PowerShell):

| Command | What it does |
|---|---|
| `check` | Type-check every package (`-vet -strict-style`, warnings are errors) and verify formatting |
| `test` | Run the unit tests |
| `fmt` | Format all sources in place |
| `shaders` | Compile `assets/shaders` to SPIR-V (only what changed) |
| `build` | Build the game into `build/`: a development build (lightly optimized, debug info, the dev aids), or `--debug` (unoptimized, for stepping), `--release` (fully optimized; slow to compile), `--release --symbols` (for profilers), `--sanitize`, `--profile` |
| `run` | Build and run; arguments after `--` go to the game, e.g. `run -- --frames 120` |
| `serve` | Build and run the dedicated server; arguments after `--` go to it |
| `debug` | Build and start in gdb/lldb (RAD Debugger on Windows) with Odin pretty-printers |
| `netdump`, `replay` | Print a network trace / replay its client messages against a fresh server (DEBUGGING.md) |
| `sfx` | Write every sound effect to `build/sounds/*.wav` |
| `worldmap` | Draw a world from above to `build/worldmap.png` (`-seed:42 -size:4096`; `-bench:64` times chunk generation) |
| `bench <scenario>` | Benchmark under fixed conditions: `chunks` (generation, light and meshing on one thread; `-check` as CI), `load`, `views`, `flight` (the game); results in `build/benchmarks/` |
| `trace` | Summarize a profile trace (`build/voxiverse.spall`) |
| `perf` | Record the game, `server` or `bench` under Linux perf and print where the time went (`perf -- --exec "..."`) |
| `package` | A release package for this platform in `build/dist/` (one executable each for the game and the server, README.txt, licences) |
| `icon` | Draw the game's icon to `build/voxiverse.ico` |
| `help` | List the commands and their flags |

Versions are `0.<milestone>.<patch>`, from git: a commit tagged `v0.21.0` builds as
0.21.0, the commits after it as `0.21.0-dev.N`. To release, tag with the release's name as
the message, `git tag -a v0.21.0 -m "Pre-Alpha 1"`, and push the tag: CI builds the
packages and makes a **draft** release, to be looked at and published by hand.

Debugging and profiling (validation, leak tracking, stack traces, sanitizer, debuggers with
Odin pretty-printers, RenderDoc captures, CPU/GPU profiling): see [DEBUGGING.md](DEBUGGING.md).

## Running

`build run` opens the title screen. Singleplayer lists your saves, the last played first:
play one (or double-click it), create one (its seed under More options: any text works, or
leave it empty for a random one), rename it or open its folder (Edit), or delete it. Saves
save every minute and
when you leave; they live in `voxiverse/saves` in your user data directory
(`~/.local/share` on Linux, `%APPDATA%` on Windows, `~/Library/Application Support` on macOS).

| Key | |
|---|---|
| Mouse | Look |
| <kbd>W</kbd> <kbd>A</kbd> <kbd>S</kbd> <kbd>D</kbd> | Walk |
| <kbd>Space</kbd> | Jump; double-tap to fly or stop flying (flying: up) |
| <kbd>Shift</kbd> | Sneak: crouch, and keep to the edge of a ledge (flying: down) |
| <kbd>Ctrl</kbd> | Sprint |
| Left / right click | Break / place a block (hold to repeat) |
| <kbd>1</kbd>–<kbd>5</kbd>, mouse wheel | Choose what to hold from the five-slot hotbar (a new player starts with stone, dirt, grass, sand, logs, leaves, water and lamps, and the rocket launcher where they may fire it). Placing a block uses one up; breaking one drops it to pick up by walking over it |
| <kbd>E</kbd> | Inventory: drag stacks between slots, right-click to split, shift-click to move between the hotbar and the rest, a number key to swap with that hotbar slot; in your own world every item is there to take |
| <kbd>Q</kbd> | Drop one of what you hold (<kbd>Ctrl</kbd>+<kbd>Q</kbd>: all of it) |
| <kbd>T</kbd>, <kbd>/</kbd> | Chat / a server command (`/spawn`, `/mute bob 1h`; Tab completes). `&c` colours and `&l` bolds where your role allows; Up/Down walk what you sent |
| <kbd>Esc</kbd> | Close what is open (chat, console, a menu), else the game menu (Back to Game, Options, Open to LAN, Save and Quit to Title). Alone in your own world, pausing stops it |
| <kbd>F11</kbd> | Fullscreen |
| <kbd>F2</kbd> | Screenshot |
| <kbd>F3</kbd> | Debug overlay: position, chunks, memory, server tick |
| <kbd>F4</kbd> | Tuning panel: every setting and debug switch, live |
| <kbd>`</kbd> | Console |

These are the default keys: every one can be changed in Options > Controls, where keys are
bound by their place on the keyboard (WASD stays together on any layout) and named as yours
prints them. Options also has, in tabs: display, VSync, a frame rate limit, field of view,
render distance, GUI scale, brightness, clouds, the FPS counter (Video); volume (Sound);
mouse, hold or toggle for sneak and sprint (Controls); reduce motion, chat text size
(Accessibility); your name (Profile).

Commands go in the chat, starting with `/` (Tab completes the ones you may use). In your own
world you may do anything; on a server, what its roles let you (see
[DEBUGGING.md](DEBUGGING.md#permissions)). Builders edit in bulk: `/pos1` and `/pos2` mark the
corners of a box at the block you look at, then `/fill stone`, `/replace dirt sand`, or
`/sphere 5 stone` at the first corner. Hotbar slot 9 is a rocket launcher.

New worlds are Earth-like: continents and oceans, rivers, mountains with cliffs and
overhangs, caves and ores, forests, taiga, tundra, deserts, beaches (worlds saved before
keep the land they were made with). `/locate desert` flies you to the nearest desert; a
double tap of jump starts or stops flying. `set worldgen.mountain_height 180` in the console
(or F4) changes how the land is made from then on, and `/regen` remakes the land around you
that way (your edits stay).

Water flows as in Minecraft: open a lake's side and it pours out, down first, then spreading
and thinning; between two sources a new one forms. In water you swim: jump to rise (and,
against a ledge, to climb out), sneak to dive; under the surface the world turns blue and
close. Sunlight fades with depth, and trees cast shade.

Out in the world stand towers, ruins and wells; dungeons lie under it, a spiral stair in a
stone shaft leading down (`/locate tower`, `/locate dungeon`).
Build your own: select a box (`/pos1`, `/pos2`) and `/structure save hut` keeps it with the
world (its air leaves what is there when pasted; `/structure save hut clear` clears it);
`/structure paste hut 1` puts it at the first corner, a quarter turned. `/structure list`
shows them. Cobblestone, stone bricks, planks and glass are for building.

The console (`` ` ``) is for developers: it shows the log and takes developer commands
(`help` lists them; `server <command>` sends a server command). `run -- --exec "cmd; cmd"`
types console commands at startup to reproduce a state, e.g. `--exec "set render_distance 8;
singleplayer; tp 0 80 0 45 -20"`.

## Playing together

- **From your own world:** pause, then **Open to LAN**. Others on your network see it listed
  under **Multiplayer** (or join `your-address:27315` by **Direct Connection**).
- **A dedicated server:** `./build.sh serve -- --universe universes/home --password secret` (or run
  `build/voxiverse-server --help` for every flag: port, name, seats, view distance, permissions).
  Ctrl+C saves and stops it.
- **Over the internet:** forward UDP port 27315 on the host's router to the host, then join its
  public address. There is no relay or hole punching (yet).

Multiplayer asks for your name the first time; it is in Options > Profile after. Worlds keep
each player's place by name.

## Layout

See [PLAN.md](PLAN.md#layout). Packages only depend downward: `base/` depends on nothing,
`game/` never imports platform or GPU code, and `ui/` never imports the renderer.
