# L2-L3 (L1 is in history.md): the file layout, feature packages, the layout manifest and its lint (issue #96, the owner's priority #1)

The owner's decisions (2026-10-31) are in issue #96; the goal is a layout so plain that an
agent always knows where a new file goes and `check` refuses anything else. The manifest is
[../layout.md](../layout.md); this is the plan for reaching the layout it describes.

These rows are **first among the open rows**. Behaviour does not change; every test, check,
lint, scene, baseline and CI step still runs; commits are small and each passes `check`,
`test`, `smoke` and `determinism`.

## Decisions (made here; the issue left them open)

- **Three rows, not one.** L1 builds the manifest and what can be enforced at once; L2 splits
  the packages; L3 turns the cap on. A lint that the tree fails today cannot be switched on
  first, and a per-folder allowance would be an exemption (#62; T6 did the same with the
  sleep lints), so the **cap lint lands in L3**, when nothing violates it.
- **The manifest is a table in `docs/layout.md`**, one row per folder with file-name globs;
  a row covers the files directly in the folder. The pure parser and the two lints are in
  `tools/build/layout.odin` with tests on text (`layout_test.odin`). An unsplit package's row
  holds `*.odin` until its split narrows it.
- **The scratch lint** (`scratch_lint`) fails on any untracked, non-ignored file. A session
  commits (with the manifest row, if a folder is new) before it runs `check`.
- **The `tools` collection is gone.** Its only user was `tools/build/limited`, now
  `common/limited`; the three collections are `client`, `server`, `common`.
- **The cap's number** is chosen in L3 from the layout it counts and recorded in the manifest
  with the reasoning.

## L2: the packages (first slice done, in history.md); L2b: the rest (open)

L2 moved the files that depend on nothing left in their package: `client/starfield`,
`client/planet`, `client/formatted`, `client/dev`, `client/music` (the piece table) and
`server/packs`. Measured then (a name-level dependency graph of each root package): 61 of
the 68 non-test `server` files and 75 of the 81 `client` files form one cycle (the `Server`
state and the client's `App`, which nearly every file reads and writes), so the rest cannot
be moved by renaming. **The decision for L2b:** the state types and what ticks them stay
together in one lower package (`server/core`, `client/app`); a feature (commands, save,
journal, HUD, overlays, screens) becomes a package above it that imports it, and where the
lower package must call up (the tick calling a command or a save), it does so through a
table of procedures the top package (`server/dedicated`, `client`'s `main`) fills at start,
not through an import. A mechanical move script (qualify each moved name, add the import)
did L2's slice and does the rest; do the leaves of the remaining graph first, one package a
commit. The tests beside the code move with their package; helpers shared by several packages
go to `tests/`.

### L2b (open), the exit

Exit: `client/` and `server/` hold no `.odin` file at their root (`client/app`, `hud`,
`screens`, `overlays`, ...; `server/core`, `commands`, `save`, `packs`, ... as the code's
imports allow, cycles broken by moving code where that is clean); the prefix of every moved
file is dropped (`hud_hotbar.odin` becomes `hud/hotbar.odin`); tests sit beside the code as
`<file>_test.odin`, test-only helpers (`*_check.odin`, `*_test_support.odin`,
`audio_baseline`, `audio_check`) are in `tests/` or a test-kit package; each library-plus-tool
pair keeps the library in `common/` or `client/` with only the command line in `tools/`
(`common/ogg` and `tools/ogg`, `client/sfx` and `tools/sfx`, the client's `music*` files and
`tools/music`); fuzz code is `fuzz*.odin` in the owning package; `ols.json`, the plan's paths,
the specs' file paths and the docs follow; the manifest rows narrow to the names each folder
allows; `check`, `test`, `smoke`, `determinism` pass after every commit. The final reply lists
the tree, the rename list and the caps. The audit's checklist is in the issue: `menus` next to
`menu_*`; `title`, `creation`, `universes` next to `screen_*`; `overlay_*`, `hud_*`, `dev_*`;
`music`, `music_app`, `music_data`, `music_files`; `viewmodel*`; `entity`, `entities`,
`entity_arena`; `players` and `player_data`; the `save*` and `journal*` groups; `pack_*` and
`packs`; `commands_*`; fuzz code in `client/fuzz`, `server/fuzz*`, `common/game/fuzz*` and
`tools/fuzz`.
