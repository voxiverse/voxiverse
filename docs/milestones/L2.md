# L2 and L2b: `client/` and `server/` split into packages (issue #96, the owner's priority #1)

L2's first slice is done (history.md, "L2, first slice"): `client/starfield`, `client/planet`,
`client/formatted`, `client/dev` (`fps.odin`), `client/music` (`data.odin`) and `server/packs`
(`dir.odin`). This file is the spec of **L2b**, the rest. L2b is a remainder: it is finished, not
split. Read [L1.md](L1.md) (the manifest, its lints, the decisions that stand) and
[../layout.md](../layout.md) first.

**Why.** The owner's layout (#96): no package at a collection's root, a new feature gets a new
folder, the folder is the noun, tests beside the code, and `check` refuses a file that has no
place. `client/` and `server/` still hold 113 and 127 `.odin` files at their roots, one package
each, so an agent cannot tell where a file goes and L3's cap has nothing real to count.
Behaviour does not change: every test, check, lint, scene, baseline and CI step still runs.

## What was measured (2026-10-31, on the tree at 86e773a)

A name-level dependency graph of each root package (a top-level name declared in one file and
used in another, locals and comments ignored):

- **`server`:** 66 non-test files; 63 form one cycle around `Server`, `Client` and `World`.
  Only `chunks.odin` depends on nothing in the package, and only `budgets`, `replay` and
  `script_api` are used by nothing in it (and all three are used by the package's own tests).
  43 of the 60 test files run the stepped harness (`harness_start`, in `harness.odin`), and 27
  of them drive the server through commands (`game.Command{...}`, `command(m, ...)`, `admin`).
  Taking the commands out (`admin.odin`, `commands_*.odin`) would need one hook (the tick
  calls `admin`) plus 12 helpers moved down; but the harness lives in the same package as the
  tests that use it, and a hook the harness cannot fill (it cannot import a package above it)
  means the 27 tests that send commands would have to leave the code they test. The journal
  (24 names used by the rest: `Act`, `Journal`, `action_begin`, `world_act`...), the save
  (`Store` is a field of `Server`; `store_write` is called by four files) and the pack files
  (`server.odin`'s tick calls 12 of their names) are the state's own machinery.
- **`client`:** 76 non-test files; 72 form one cycle around `App` and `Session`. The cycle is
  made by two things only: `App` holds every feature's state by value (`Console`, `Toasts`,
  `Overlays`, `Inventory_View`, `Creation_Screen`, `Fps`, `Music_App`...), and `app.odin`'s
  frame calls every feature. With `app_init`, `app_destroy`, `app_frame` and `dispatch.odin` at
  the top, and the feature state types and the procedures that only change that state moved
  down, what is left layers cleanly: the features need from the lower package and from each
  other only in the order below (the measured up-references are listed in step 5).

## Decisions (made here, from the measurements; L1.md's "decision for L2b" is refined, not reopened)

- **The server is one package: `server/core`.** Every file at `server/`'s root moves to
  `server/core/` under its own name (no file there carries a `core_` prefix; `harness.odin`,
  `journal*.odin`, `save*.odin`, `pack_*.odin`, `commands_*.odin` keep theirs). Its state is
  one cycle, and breaking it means giving each feature its own state type in a package below
  `core` that `Server` composes: a design change, not a move (see *Left out*). L1's table of
  procedures is therefore not needed on the server. `server/packs` stays the leaf it is
  (reading pack folders); the `pack_*` files stay in `core`, because the tick calls them.
- **The client's lower package is `client/engine`, not `client/app`.** 304 procedures take a
  parameter named `app: ^App`; inside them `app.x` is the parameter, so a package named `app`
  could not be called by name. `engine` is used as a name nowhere in the code.
- **The client's executable package is `client/main` (package `main`).** It holds `main.odin`,
  `dispatch.odin` and `frame.odin` (`app_init`, `app_destroy`, `app_frame`, moved out of
  `app.odin`); `GAME_PACKAGE` becomes `"client/main"`. Checked: Odin builds, checks and tests a
  package named `main` (`-define:ODIN_TEST_NAMES=main.test_x`).
- **The client's packages and their order** (each imports only those before it; `client/music`
  and `client/testkit` are below `engine`):

  | Package | Holds |
  |---|---|
  | `client/testkit` | The helpers several packages' tests share (the base registry, a mode by name); imports only `common:` |
  | `client/music` | The piece table (L2's `data.odin`) and now the director (`director.odin`) |
  | `client/engine` | `App`, `Session`, the world copy, settings, input and actions, prediction, sounds, the session's messages, and the state of every feature `App` holds |
  | `client/prompt` | Button prompts: an action's glyph and the prompt bar (screens and the HUD both draw them) |
  | `client/menu` | The game menu, the player menu, the inventory and statistics sections |
  | `client/screen` | The title, options, credits, universes, creation, ignite, multiplayer and loading screens |
  | `client/dev` | Developer overlays and panels (the audio recorder and inspector, the F3 panels) |
  | `client/console` | The developer console: its view, its command line, its world primitives, startup scripts |
  | `client/overlay` | The overlay stack's drawing and the dialogs: chat, death, dial, LAN, quit, toasts |
  | `client/hud` | The in-game HUD: crosshair and hearts, hotbar, player list, item popup |
  | `client/autopilot` | The modes that drive the game with nobody at the keys: exit checks (`--check`), benchmarks (`--benchmark`), visual scenes (`--scene`) |
  | `client/main` | The entry point, the frame and the dispatch to screens and overlays |

  `autopilot`, not `check`: `main.odin`'s `run` has a local named `check`. The `*_check.odin`
  files are run modes of the shipped game (CI runs `--check fly`), not test-only helpers.
- **What moves down into `engine`.** A declaration `engine` (or a package below the feature)
  uses moves down when it is a type `App` or `Session` holds, a constant, or a procedure that
  only reads or changes that state (`overlay_open`, `overlay_close`, `overlay_is_open`,
  `overlay_top`, `overlay_toggle`, `world_paused`, `game_controls`, `toast`, `chat_add`,
  `chat_delete`, `console_print`, `loading_begin`, `stats_data_take`, `stats_data_clear`,
  `lan_dialog_open`, `close_lan`...). It goes into an `engine` file named for its feature:
  `engine/overlay.odin` (the stack: `Overlay`, `Overlays` and their procedures),
  `engine/toast.odin`, `engine/chat.odin`, `engine/console.odin` (`Console`, `Command`,
  `console_print`), `engine/loading.odin` (`Loading`, `Failed`, `loading_begin`,
  `world_settled`), `engine/stats.odin`, `engine/lan.odin`, and so on for each feature whose
  state moves. `client/dev/fps.odin` (`Fps`, a field of `App`) moves to `engine/fps.odin`.
  `main.odin`'s `Options` (read by `text.odin` and the overlays) moves to `engine/options.odin`.
- **Hooks only where a move down would drag drawing code into `engine`.** If, after the moves
  above, an `engine` procedure must still call a feature's procedure, the call goes through
  `Hooks :: struct` (a field of `App`, in `engine/app.odin`), which `main`'s `app_init` fills
  before the first frame; the call site asserts the field is set. Measured: none is expected.
  No globals (ground rule 4).
- **The music director moves into `client/music`.** It reads `Screen` only through
  `Music_Input.screen`, which nothing reads (only `music_app.odin` writes it): the field is
  deleted, and `music.odin` becomes `client/music/director.odin` with its test
  (`director_test.odin`); `music_app.odin` becomes `engine/music.odin`.
- **The client's test helpers become `client/testkit`.** `registry_test_support_test.odin`
  becomes `testkit/registry.odin` (`test_reg`, `test_blocks`, unchanged);
  `mode_test_support_test.odin` becomes `testkit/mode.odin`, whose
  `mode :: proc(reg: ^game.Registry, name: string) -> game.Mode` returns the mode (its callers
  write `s.mode = testkit.mode(s.reg, "...")`), so `testkit` needs nothing from `engine` and
  every package's tests can import it. Only tests import it, so it is not linked into the game.
  The server's `test_reg` stays in `core/harness_client.odin` (its fuzz targets use it).
- **Tests.** A test file follows the file whose stem it carries, renamed the same way
  (`overlay_dial_test.odin` becomes `overlay/dial_test.odin`; one named after the feature alone
  becomes `<folder>/<folder>_test.odin`: `hud_test`, `overlay_test`, `menus_test` become
  `hud/hud_test.odin`, `overlay/overlay_test.odin`, `menu/menu_test.odin`). A test without such
  a file goes to the lowest package that has every name it uses: expected `menu` for
  `inventory_tweaks_test` and `stats_test`; `screen` for `title_test`, `creation_test`,
  `universes_test`; `overlay` for `toast_test`; `main` for `frame_rig_test`, `still_test`,
  `input_modes_test`; `engine` for `light_cache_test`, `pack_assets_test`,
  `effects_spectrum_test`; the compiler decides. `audio_baseline_test.odin` goes where its
  names are, and the driver's audio baselines run that package (a constant
  `AUDIO_BASELINE_PACKAGE` beside `GAME_PACKAGE`; the test names in
  `-define:ODIN_TEST_NAMES` take the new package prefix).
- **Identifiers keep their names.** Only files are renamed; `hud_draw` stays `hud_draw`
  (called `hud.hud_draw`). Renaming identifiers is not this row's work.
- **Every check keeps covering what it covered.** The UI-literal lint (`lints.odin`:
  `is_layer_file` on files directly in `client/` with the prefixes `screen_`, `menu_`,
  `overlay_`, `hud_`) would silently stop seeing the moved files; it becomes folder-based: a
  layer file is a non-test file in `client/screen`, `client/menu`, `client/overlay`,
  `client/console`, `client/hud` or `client/prompt` (the old prefixes count only while a file
  with one still sits in `client/` or `client/engine`; that clause is deleted in the last
  step). The block-write pipeline lint's `PIPELINE_FILES` become `server/core/chunks.odin`,
  `server/core/changes.odin`, `server/core/edits.odin`. The determinism session is
  `core.test_determinism_session` run with `odin test server/core`.
- **A new lint, `package_lists`, in `check`.** With a dozen new packages, a folder left out of
  the driver's lists would silently not be type-checked or tested (ground rule 7), and every
  new feature folder from now on (layout rule 4) has the same risk. It fails when a folder
  holding a tracked `.odin` file is not in `PACKAGES`, when a folder outside `tests/` holding
  an `@(test)` procedure is not in `TEST_PACKAGES` (`tests/` and its fixtures are
  `build smoke`'s, by location, as the test lints already treat `tests/`), when a
  `TEST_PACKAGES` entry is not in `PACKAGES`, and when a folder is under none of
  `SOURCE_DIRS`. It is a pure procedure on lists of paths with a test on text, in
  `tools/build/layout.odin` beside `layout_lint`. Today it would fail on four folders not in
  `PACKAGES` (`tools/fuzz`, `tests/crash_fixture`, `tests/panic_fixture`,
  `tests/window_fixture`): they are added, and whatever `odin check` then finds in them is
  fixed.
- **The open specs' paths are not rewritten here.** 383 file paths in `docs/milestones/*.md`
  name today's files; other sessions edit those specs at the same time, and each spec's own
  session already corrects its spec against the code (plan, "Specs written ahead"). The
  rename table below is their map; it is copied into history.md with this row.
  `docs/*.md` (debugging, determinism, journal, saves, script API notes, layout, the plan) and
  code comments follow in this row; history.md keeps the paths it recorded.

## The move script (scratch, `build/tmp/`, not committed)

L2's slice used a Python script that moved files and qualified the moved names in the files
left behind. L2b needs both directions; write it again in `build/tmp/` if it is not there:

1. `git mv` each file to its new path; set its `package` line.
2. In every `.odin` file under `client/`, `server/`, `tools/` and `tests/` outside the
   destination: each bare use of a top-level name the moved files declare (not after a `.`,
   not in a string or comment, not where that file declares the same name as a local,
   parameter or loop variable) becomes `<dest>.<name>`; each `<source>.<name>` of a moved
   name becomes `<dest>.<name>`; the import is added where a file now uses it, removed where
   it no longer does.
3. In the moved files: each bare use of a name still declared in the source package becomes
   `<source>.<name>`, with its import.
4. `odin check` on every touched package; what the regex misjudged is fixed by hand.

## Steps (one commit each; `./build.sh check` and the touched packages' tests pass before each)

1. **`package_lists`** with its test on text; the four folders added to `PACKAGES`.
2. **`server/core`.** Every root `server` file moves (names kept); importers say
   `import "server:core"` and `core.` (`client/`, `server/dedicated`, `tests/`, `tools/replay`,
   `tools/bench`, `tools/fuzz`); `PACKAGES`, `TEST_PACKAGES`, `SOURCE_DIRS`,
   `DETERMINISM_DIRS`, `PIPELINE_FILES`, the determinism session's package and name; the
   manifest's `server` row replaced by `server/core`'s; the docs' `server/<file>` paths.
   `./build.sh determinism` passes.
3. **`client/engine` and `client/main`.** Every root `client` file moves to `client/engine`
   under its own name, except `main.odin` (to `client/main`, with `Options` going to
   `engine/options.odin`); `GAME_PACKAGE`; `#load` paths; `tools/audiodump` and `tools/fuzz`
   import `client:engine`; the test names the driver and `ci.yml` run; `is_layer_file` sees the
   prefixed files in `client/engine`; the manifest's `client` row replaced by
   `client/engine`'s and `client/main`'s. `./build.sh build` and `--check fly` run.
4. **`client/testkit`**, and the tests use it.
5. **Down into `engine`:** `fps.odin` from `client/dev`; the music director to
   `client/music/director.odin` (the `screen` field deleted); `music_app` → `engine/music.odin`;
   `app_clock` → `engine/clock.odin`.
6. **`client/main` takes the frame:** `dispatch.odin`, and `app_init`, `app_destroy`,
   `app_frame` into `main/frame.odin`.
7. **The features, top first** (each moves only after the packages above it, so a moving
   package only ever needs `engine`, the packages below `engine` and the features still to
   move, which are in `engine`): `autopilot`, `hud`, `overlay`, `console`, `dev`, `screen`,
   `menu`, `prompt`. For each: the declarations `engine` uses move down first (measured: from
   `overlay`, `Chat_Entry`, `Overlay`, `chat_add`, `chat_delete`, `game_controls`,
   `open_screenshots`, `overlay_open`, `overlay_close`, `overlay_is_open`, `toast`,
   `world_paused`; from `menu`, `PREVIEW_IMAGE`, `Player_Menu`, `SLOT_SIZE`, `Stats_Data`,
   `stats_data_clear`, `stats_data_take`; from `screen`, `Failed`, `Loading`, `loading_begin`,
   `world_settled`; from `console`, `Command`; and the types `App` holds:
   `Console`, `Toasts`, `Overlays`, `Item_Popup`, `Prompt_Icons`, `Inventory_View`,
   `Stats_View`, `Creation_Screen`, `Credits_View`, `Ignite`, `Multiplayer_Screen`,
   `Options_View`, `Universes_Screen`, `Dial_View`, `Lan_Dialog`, `Audio_Debug`, `Bench`,
   `Exit_Check`, `Fly_Test`, `Blast_Test`, `Tour_Test`, `Audio_Check`, `Scene_Run`), then the
   files move with their tests, the manifest row is added, the driver lists follow. Between
   features the measured cross-references (from `overlay`: `close_lan` and `lan_dialog_open`
   used by the game menu; from `menu`: `CURSOR_CATALOG_BASE`, used by the prompts; from
   `screen`: `var_widgets`, used by the dev panels) move down the same way.
8. **Close:** no `.odin` at `client/` or `server/`'s root; `is_layer_file`'s prefix clause
   deleted; the manifest's "The move" section says L2 is done and L3 is next; `docs/*.md`'s
   paths and the plan's *Layout* and *Nomenclature* (`core.Server`, `core.Client`,
   `core.Config`, `engine.Session`, `engine.Settings`) follow; the rename table and what
   differed go to history.md; the plan row says what was done.

## Left out

- **Splitting `server/core` and `client/engine` further.** Each feature's state would get a
  package below them (permissions, journal, save store, chat, the console's state...) holding
  its type and the procedures on it alone, which `Server` and `App` compose; procedures that
  take `^Server` would take the part they use. That changes signatures across the code: a
  design milestone of its own if the owner wants it, sized from `core`'s and `engine`'s files
  after this row. L3 chooses its cap knowing those two counts.
- Renaming identifiers to drop prefixes inside packages (`hud_draw`, `overlay_open`).
- The open milestone specs' file paths (see the decision above).
- Any behaviour, any new feature, any change to what a test checks.

## Tests

- `package_lists`' test on text: a folder with `.odin` missing from `PACKAGES` fails; one
  with `@(test)` outside `tests/` missing from `TEST_PACKAGES` fails; a `TEST_PACKAGES` entry
  not in `PACKAGES` fails; a folder under no `SOURCE_DIRS` entry fails; `tests/x` with
  `@(test)` passes; the complete lists pass.
- `is_layer_file`'s test on text: `client/hud/hotbar.odin` and `client/console/line.odin` are
  layer files, `client/engine/session.odin` and `client/hud/hud_test.odin` are not.
- The pipeline lint's tests use the `server/core/` paths.
- **No test is lost:** the number of `@(test)` procedures under `client/` and `server/` after
  the last step equals the number before the first (counted with
  `git grep -c '^@(test)' -- 'client/*.odin' 'server/*.odin'` at the start, written in the
  report; tests other sessions add meanwhile are counted at their new place).
- Every existing test, lint, scene, baseline and CI step, unchanged in what it checks.

## Exit check

`client/` and `server/` hold no `.odin` file at their root; the packages are the ones in the
table above and `server/core`; every new folder has its manifest row and the `client` and
`server` rows are gone; `package_lists` and the folder-based UI-literal lint run in `check`;
the test count matches; `./build.sh check`, `test`, `smoke` and `determinism` pass after every
commit; CI green.
