# M1: window and GPU (closed as built)

## Why

M1 is the plan's second row: Win32 and X11 backends, the Vulkan device, swapchain and frames in
flight, a clear and a triangle, resize and minimize. Its exit check is "Runs on Windows and Linux
with zero validation messages". The code was written on 2026-10-22 (2c2a527 "M1: native window
+ Vulkan 1.3 bring-up, triangle"; the validation plumbing followed in 8daff25 "Debugging
foundations"), before specs were written down. Every later milestone draws through it. What M1
never got was a spec, a "done" in its row and a line in the cost table. Some of the row's words
also no longer match the tree, and half of its exit check (Windows) is not something CI can see.
This milestone closes M1 against the tree as it is now, the way M0 was closed. It writes no code.

## Decided

- **M1 is closed as built, not rebuilt.** Each of the row's parts is in the tree, and every
  milestone since has drawn through it. The places where the words differ are later choices or
  facts of CI, so the words change, not the code.
- **The triangle stays gone.** It proved the device, swapchain and pipeline could draw; the title
  screen now proves the same on every run, and a demo kept beside it would be dead code (T7's
  prune). The row's slice drops "a clear + triangle".
- **Windows under validation is a hand check, not a CI job.** A software Vulkan driver on the
  Windows runner (Mesa's lavapipe or SwiftShader, downloaded and pinned) would be new
  infrastructure, which the plan rules out unless something breaks or the owner asks ("How a
  milestone is sized": *No more infrastructure*). The Win32 code is kept together and checked on a
  Windows machine once ("Windows-only code is kept together"). So the Windows half of M1's exit
  check joins the plan's list *Deferred until a Windows machine is at hand* as its own item, and
  M1's row says so. Recorded in the plan's Decisions table (*Windows under validation*).
- **No resize test is added.** No CI run resizes or minimizes the window: the platform interface
  has no call that sets a window's size, and adding one to three backends for a test is a feature
  the row never asked for. Resize and minimize under validation become a hand check (below), on
  Linux and on the Windows list.
- **The cost line has no measures:** `| M1 | n/a | n/a | 0 | ... |`. The 2026-10-22 session was
  not measured, and the closing session writes only docs.

## Left out

- A Vulkan driver on the Windows CI runner, or any other CI change (decided above).
- A window-size call in the platform interface, and a resize check (decided above).
- Bringing back the triangle, or any other code.
- New tests. The row's Linux claims are covered by CI runs that already exist; its Windows claim
  needs a machine.
- The items already on the Windows list (`WM_DPICHANGED`, the modal move loop, `SC_KEYMENU` and
  so on): they are that list's business, not M1's.
- M1b. Its row already says M47d and M47e replaced it; closing that row is its own business.
- Native Wayland (the Decisions table: later).

## Exit check

`./build.sh check` and `./build.sh test` pass. Locally on Linux with the validation layer
installed, `./build.sh build` then `./build/voxiverse --frames 120` exits 0 and its log has no
`validation finding` line (with no display, `xvfb-run -a` and `VK_DRIVER_FILES` set to lavapipe's
ICD, as CI does). The M1 row reads done as in step 2. The cost table has M1's line. `docs/plan.md`
has the *Windows under validation* Decisions row and the Windows list item. `docs/history.md`
ends with `## M1: window and GPU`, and `docs/milestones/M1.md` is gone. CI is green on the commit:
the loop watches that, not the session.

## Check by hand

- **Windows, under validation.** On a Windows 10 or 11 PC with a GPU driver and the Vulkan SDK
  installed (it carries `VK_LAYER_KHRONOS_validation`): `build.bat build`, then
  `build\voxiverse.exe --frames 600`. Expect exit code 0 (`echo %ERRORLEVEL%`) and no `vulkan [`
  error or warning line and no `validation finding` line in the log. Then `build.bat run`, drag
  the window's border to resize it several times, minimize it from the taskbar for ten seconds,
  restore it, enter a world and quit from the menu: expect the same clean log, the picture
  filling the window after each resize, and the process using almost no CPU while minimized.
- **Linux, resize and minimize under validation.** On an X11 or XWayland desktop with
  `vulkan-validation-layers` installed: `./build.sh run`, resize the window by dragging a corner
  several times, minimize and restore it, enter a world, quit. Expect no `vulkan [` error or
  warning line, no `validation finding` line, and exit code 0.
