# M47: registries and the base data pack

**Why.** Everything a pack, a script or an agent adds is content: blocks, items, textures,
sounds, recipes. Today each is an Odin table or a `switch` that will not compile until a
new block says what it is (`game.BLOCK_INFO`, `game.TOOL_INFO`/`MATERIAL_INFO`/`ARMOR_INFO`,
`mesh.block_shape`, `mesh.block_faces`, `sfx.material_of`, `game.block_drop`,
`game.block_is_plant`/`plant_supported`/`can_till`), and saves and the wire carry the
enum's numbers (`common/game/codec.odin`'s `write_chunk_blocks` puts raw `u16` ids in every
region file). The survey for this section found:

- `Block :: enum u16` (57 members) is named by about 270 lines outside `common/game/block.odin`:
  worldgen (`.Stone`, `.Stone_Bricks` in `common/worldgen/earth_terrain.odin`, `classic.odin`,
  `structures.odin`, `gates.odin`), liquids, plants, farming, gates, chests, tests. Those
  names are mechanics on particular blocks, not properties, and they stay code until their
  systems move (M49 liquids and random ticks, M53 gameplay).
- Properties are read through seven helpers (`block_collides`, `block_opaque`,
  `block_targetable`, `block_shades`, `block_light`, `block_by_name`, `block_valid`) and
  `BLOCK_INFO[b]` directly in 8 files; `[Block]` arrays and `len(Block)` sized palettes in
  `common/game/codec.odin`, `common/game/structure.odin` and `common/game/chunk.odin`.
- Items are `distinct u16` with a numbering scheme (block id + 1; `TOOL_ITEMS` 0x8000,
  `MATERIAL_ITEMS` 0xA000, `ARMOR_ITEMS` 0xC000) and are already saved by name
  (`item_name`/`item_by_name` in `server/save.odin`, `containers.odin`,
  `player_data.odin`). Structures (`.vxs`) already keep a palette of block names.
- `common/game/state_kinds.odin`'s `check` procs call `item_valid` and the codec calls
  `block_valid` with no context: validation reads the constant tables.
- Assets are compiled in (`common/worldgen/shipped.odin`: `#load_directory("../assets/structures")`):
  nothing beside the executable, which the base pack must keep.

**Design.**

*The id.* Every registered thing has an id `namespace:name`. `namespace` is
`[a-z0-9_]{1,32}`, `name` is `[a-z0-9_]{1,48}`; one colon. The base pack's namespace is
`voxiverse` (reserved: only the base pack may use it as its own). Wherever an id is read
from text written by people or by older saves (commands, `.cfg` files, `.vxs` palettes,
completion), a name without a colon means `voxiverse:` (`game.id_parse(text) -> (Id,
bool)`), so `/give stone`, today's saves and the shipped structures keep working with no
migration of their text. Everything written from now on writes the full id. Kinds with
ids: blocks, items, textures, sounds, block tags, item tags, recipes, structures (files in
packs); entities and biomes (ids from the engine's own tables, `voxiverse:sheep`,
`voxiverse:plains`, so M50 and the data-worldgen tier can move them to files without
renaming anything; packs cannot add these yet); loot tables (the id kind exists; the file
format is M53's).

*The text format: pack JSON.* Pack files are JSON (RFC 8259) plus `//` and `/* */`
comments and trailing commas, nothing else. Chosen over a line format of our own because
packs hold nested data (shapes with cases in M48, quests and dialogue in M53), models
write JSON most reliably, and M54's machine-readable schemas are JSON schemas. Read by
`common/game/pack_json.odin`, our own tree builder on `core:encoding/json`'s tokenizer
(`json.make_tokenizer(text, .JSON5)`, so comments and trailing commas tokenize), which
keeps every value's line and column and refuses what JSON5 allows beyond the above:

- unquoted keys (`Ident` tokens): `keys are quoted: write "light"`;
- single-quoted strings: `strings use double quotes`;
- `Infinity`, `NaN`, hexadecimal, leading `+` or `.`, trailing `.` (checked with
  `json.is_valid_number(text, .JSON)`): `numbers are plain decimals`;
- a key twice in one object: `"light" is given twice (first on line 4)`;
- integers outside `i64`, depth over 32, a string over 4096 bytes, an array or object
  over 4096 entries, a file over 1 MiB.

Values are `Json_Value {kind: enum {Null, Bool, Int, Float, String, Array, Object}, line,
column: i32, ...}`; objects keep their keys in source order (a slice of `{key, key_line,
key_column, value}`), never a map, so nothing depends on map order.

*A pack on disk.* A directory whose name is its namespace:

```
<namespace>/
  pack.json         {"format": 1, "namespace": "farmfix", "version": "1.0.0",
                     "title": "Farm fixes", "description": "...", "requires": ["voxiverse"]}
  blocks/*.json     block definitions
  items/*.json      item definitions
  textures/*.json   block textures (by generator here; images in M47b)
  sounds/*.json     block sound sets (by generator here; Ogg files in M47b)
  block_tags/*.json
  item_tags/*.json
  recipes/*.json
  structures/*.vxs  templates (today's binary format, unchanged)
```

Each `.json` file in a category directory is one object whose keys are names in the
pack's namespace (`"stone"`) or, to override, full ids of another pack (`"voxiverse:stone"`),
and whose values are definitions. A file may hold one definition or many. Any other file
or directory is an error (`farmfix/blocks/notes.txt: not a pack file: blocks/ holds .json
files`; `loot_tables/` says `loot tables are read from M53 on; remove the directory`), so
nothing is silently ignored. Files are read in byte order of their paths, keys in source
order: id assignment is a function of the files alone.

*The base pack* is `assets/packs/voxiverse/`, compiled in by `common/game/base_pack.odin` with one
`#load_directory` per category (the directive is not recursive) and `#load` for
`pack.json`. Its files:

- `blocks/air.json` (air), `terrain.json` (stone, dirt, grass, sand, gravel, bedrock,
  snow, ice, clay, sandstone, the three ores), `trees.json` (log, leaves, spruce_log,
  spruce_leaves), `plants.json` (tall_grass, poppy, dandelion, cactus), `water.json`
  (water, water_1..water_7, falling_water), `built.json` (cobblestone, stone_bricks,
  planks, glass, lamp, wool, black_wool, chest), `gates.json` (gate_ring, gate_chevron,
  gate_chevron_lit, gate_horizon), `farming.json` (farmland, farmland_moist,
  wheat_0..wheat_7).
- `items/tools.json` (rocket_launcher, hoe), `materials.json` (seeds, wheat,
  feather_charm), `armor.json` (cap, tunic, trousers, boots). Block items are not listed:
  every placeable block has one (below).
- `textures/blocks.json`: one entry per today's `mesh.Texture` member, in its order
  (`"grass_top": {"generator": "grass_top"}`).
- `sounds/blocks.json`: one sound set per `sfx.Material` (`"stone": {"generator":
  "stone"}`).
- `block_tags/soil.json`: `wild_plant_soil` (grass, dirt, sand), `tillable` (grass, dirt),
  `farmland` (farmland, farmland_moist).
- `structures/ruin.vxs`, `well.vxs` (moved from `assets/structures/` byte for byte).
- No recipes: the game has no crafting, and making it is a gameplay decision (content
  waves). The recipe kind is built and tested with a test pack.

*What moves from Odin to data* (each table or switch is deleted once its data is read):

| Today | Becomes |
|---|---|
| `game.BLOCK_INFO` (name, collides, opaque, targetable, breakable, placeable, replaceable, shades, light) | block fields of the same names |
| `mesh.block_shape` | block `render` (`"cube"`, `"cross"`, `"none"`) and `layer` (`"opaque"`, `"cutout"`, `"translucent"`) |
| `mesh.block_faces` | block `textures` (`all`, or `side`/`top`/`bottom`), naming texture ids |
| `mesh.Texture` (the enum) | texture ids; the enum is renamed `mesh.Texture_Generator`, `generate_texture` keeps its code and takes a generator |
| `cube_faces`'s glass-on-glass and water-beside-water culling | block `cull_same: true` (glass), `liquid: true` (the water blocks: surface and culling) |
| `sfx.material_of` | block `sound` (a sound set id; absent: silent); `sfx.Material` stays as the generators |
| `game.block_drop` | block `drop` (an item id, or `"none"`; default its own item when placeable, else none). Chance drops (tall grass seeds, wheat by stage) stay server code, their blocks say `"none"` |
| `block_is_plant`, `plant_supported` | block `support: {"below": "<block tag>"}` (tall grass, flowers: `voxiverse:wild_plant_soil`; wheat: `voxiverse:farmland`); a plant is a block with `support` |
| `can_till`'s grass-or-dirt | the `voxiverse:tillable` tag (the hoe's rule stays code: a tillable block with air above becomes farmland) |
| `TOOL_INFO`, `MATERIAL_INFO`, `ARMOR_INFO` | item files |
| `common/worldgen/shipped.odin`'s embedded `.vxs` | structures from the registry |

What stays code: `Block`'s members as the **builtin blocks** (below), wheat stages and
water levels as ranges of builtins, farmland's lowered top in the mesher (M48 replaces it
with a shape), the `Tool`, `Material` and `Armor` enums as engine behaviours, entity kinds
(`ENTITY_INFO`), biomes, event sounds (player, sheep, blasts: M58).

*Block fields* (every one optional; the default is an ordinary solid cube):

| Field | Type | Default | Rule |
|---|---|---|---|
| `collides`, `opaque`, `targetable`, `breakable`, `placeable` | bool | true | `opaque` needs `render: "cube"` and `layer: "opaque"` |
| `replaceable`, `shades`, `cull_same`, `liquid` | bool | false | |
| `light` | int | 0 | 0..15 |
| `render` | string | `"cube"` | `cube`, `cross`, `none` |
| `layer` | string | `"opaque"` | `opaque`, `cutout`, `translucent` |
| `textures` | object | `{"all": "<this id>"}` | keys `all` or any of `side`, `top`, `bottom` (missing ones take `side`); values texture ids |
| `sound` | string | none | a sound set id |
| `drop` | string | own item, or `"none"` | an item id or `"none"` |
| `support` | object | none | `{"below": "<block tag id>"}` |
| `override` | bool | false | required on a definition whose id is another pack's |

*Item fields:* `stack` (1..999, default 64), `places` (a block id: seeds place
`voxiverse:wheat_0`), `tool` (`"launcher"`, `"hoe"`: the engine's behaviour; a pack's
new hoe works like the hoe), `armor` (`"cap"`, `"tunic"`, `"trousers"`, `"boots"`: the
avatar's model), `equip` (`"head"`, `"chest"`, `"legs"`, `"feet"`, `"offhand"`),
`modifiers` (at most 2 of `{"stat": "<Modifier stat name>", "amount": <float>}`, the names
of `common/game/mods.odin`'s stats), `override`. Every block with `placeable: true` gets an item
of the same id (stack 64, places it); an item file may override it like any other.

*Other kinds:*

- Texture: `{"generator": "<Texture_Generator name>"}`. Sound set: `{"generator":
  "<sfx.Material name>"}`.
- Tag (`block_tags/`, `item_tags/`): `{"values": ["voxiverse:grass", "#voxiverse:other_tag"],
  "replace": false}`. Tags from several packs merge (values appended, duplicates dropped)
  unless a later one says `"replace": true`. A tag naming itself, through any chain, is an
  error.
- Recipe: `{"type": "shapeless", "inputs": [{"item": "<id or #tag>", "count": 1}, ...],
  "output": {"item": "<id>", "count": 4}}` or `{"type": "shaped", "pattern": ["##", "##"],
  "key": {"#": "<id or #tag>"}, "output": {...}}`: patterns up to 3x3, one-character keys,
  space for empty, at most 9 inputs. `game.recipe_match(reg, grid: [9]Stack, width, height)
  -> (Recipe_Id, bool)` finds the first recipe (in registry order) the grid satisfies,
  shaped ones placed anywhere in the grid and not mirrored. Nothing calls it in the game
  yet.
- Structure: the `.vxs` bytes, decoded at load (an undecodable file or an unknown block
  name is a pack error with the file).

*Builtins: how worldgen and the rest keep their ids.* `Block` stays `enum u16`; its members
are the builtin blocks, the ones engine code names. `common/game/block.odin` keeps one table,
`@(rodata) BUILTIN_BLOCK_IDS := [Block]string {.Air = "voxiverse:air", ...}` (today's names:
`black_wool`, `falling_water` as they are), and loses everything else. The registry gives
builtin blocks the numbers of their enum members (air 0, stone 1, ... chest 56), then every
other block in load order (pack order, then file path, then key order). A registry in which
a builtin is undefined is an error naming it (`voxiverse:lamp is not defined by any pack;
the engine needs it (common/game/block.odin)`). A pack may override a builtin's properties, not
remove it. So with the base pack alone every block has today's number and today's
properties (a test compares them field by field against a frozen copy of today's
`BLOCK_INFO`), worldgen writes the same numbers, and its golden hashes, M38's roots and
M39's bandwidth baseline stay exactly as they are. Values past the enum's members are
pack blocks; Odin allows them in an `enum u16`, and they never reach a non-partial
`switch` or a `[Block]` array (both go). `MAX_BLOCK_STATES :: 4096` (M48 makes each value
a state) caps the registry; the codec's palette arrays are sized by it, not `len(Block)`.

Items keep their numbers the same way: builtin items bind by id to `Tool`, `Material` and
`Armor` members (`BUILTIN_TOOL_IDS` etc.) and keep `TOOL_ITEMS + n` and so on; block items
are `Item(block + 1)` as today; pack items that are not blocks get `PACK_ITEMS ::
Item(0x6000)` + n in load order (at most 0x2000).

*The registry* (`common/game/registry.odin`). Built once, then immutable; owned by its holder in
its own `virtual.Arena`, never global.

```
Registry :: struct {
	arena:    virtual.Arena,
	blocks:   Block_Table,          // the hot part, below
	items:    Item_Table,           // by range, as item_info decodes today
	textures: []Texture_Def,        // layer = index
	sounds:   []Sound_Def,
	block_tags, item_tags: []Tag_Def,
	recipes:  []Recipe_Def,
	structures: []Structure_Def,    // id + Template
	packs:    []Pack_Info,          // namespace, version, title, file count, in load order
	ids:      Id_Index,             // sorted (id string, kind, index) for lookups by id
	hash:     u64,                  // registry_hash
}

Block_Table :: struct {
	count:   int,
	flags:   []Block_Flags,         // bit_set: collides, opaque, targetable, breakable,
	                                // placeable, replaceable, shades, cull_same, liquid
	light:   []u8,
	defs:    []Block_Def,           // id, render, layer, texture layers per face, sound,
	                                // drop, support tag, tag membership
}
```

- `registry_build(sources: []Pack_Source, allocator) -> (^Registry, []Pack_Error)`: a
  `Pack_Source` is a namespace and its files in memory (`[]Pack_File {path, data}`), so
  tests build registries from string literals and nothing in `game/` touches the disk.
  `registry_base(allocator)` builds from the embedded base pack (tests and tools call
  it). `pack_read_dir(dir, allocator) -> (Pack_Source, []Pack_Error)` (server) reads a
  directory, refusing symlinks, paths outside it and the size limits below.
- The lookups take the table: `block_collides(t: ^Block_Table, b)`, `block_opaque`,
  `block_targetable`, `block_shades`, `block_light`, `block_valid(t, id: u16)`,
  `block_by_id(reg, text)`, `block_id(reg, b) -> string`, `item_info(reg, i)`,
  `item_by_id`, `item_id`, `every_item(reg, allocator)` (blocks, tools, materials,
  armor, then pack items: today's order first), `block_drop(reg, b)`, `block_supported(t,
  plant, below)`, `block_in_tag(t, b, tag)`. Arrays indexed by the id: as cheap as today's
  `rodata` table.
- **Plumbing.** `Block_Query` gains `blocks: ^Block_Table` (and every literal becomes a call
  to a helper: `world_query(w)` in `server/`, `session_query(s)` in `client/`);
  `Light_Input` gains `blocks`; the mesh job carries it; worldgen's `Generator` gets the
  registry at `generator_make` (for `block_collides`, `block_shades` and the
  templates); `server.Server` owns the universe's registry (`s.registry`), built in
  `server_init` before any world loads; `client.App` owns the base registry (menus, icons,
  the catalog) and a `Session` the one its server uses (singleplayer builds it from the
  same sources as its server; a remote session uses the App's). Tools that decode chunks
  (`netdump`, `replay`, `worldmap`, `bench`, `collector`) use `registry_base`.
- **The codec and checks get the table.** `read_chunk_blocks(r, dst, t)` and
  `decode_client`/`decode_server` validate block ids with `block_valid(t, id)` (counts
  cap palettes at `MAX_BLOCK_STATES`). `State_Kind_Info.check` becomes `proc(value:
  rawptr, reg: ^Registry) -> bool`; `Receiver` gains `reg`. `Block_Record.block` gets
  the tag `` `net:"open"` ``: a new schema rule for an enum whose values the kind's
  `check` validates instead of its declared members (the schema text says `open`, so the
  hash changes once). `PROTOCOL_VERSION` 25.
- **The client's textures follow the registry.** `world_pass_init` builds the texture
  array from the App's registry (`len(reg.textures)` layers, in registry order: the base
  pack's are today's order, so layers keep their numbers); a session whose registry hash
  differs from the App's rebuilds it (`render.world_set_textures`, after
  `gpu.wait_idle`), and goes back on leaving. `Session.texels` and `icons.odin` index by
  texture layer, not by the enum. The sound bank keys block sounds by sound set index.

*Load order, overrides, conflicts.*

- Order: the base pack, then the universe's packs in the order `universe.cfg` lists them
  (`packs = farmfix moretrees`; absent: none). Packs live in `<universe>/packs/<namespace>/`.
  A listed pack not there, a pack there but not listed (warned, not loaded), a namespace
  that differs from its directory, `requires` naming a pack not loaded before it, or more
  than 32 packs: errors.
- A pack defines new ids only in its own namespace. Defining another namespace's id needs
  `"override": true`, and the id must exist (an override of a missing id is an error with
  a suggestion). Without `override`, defining an existing id is an error naming the first
  definition's file and line.
- An override merges field by field: the fields it gives replace the earlier
  definition's, the rest stay. Arrays and objects (`textures`, `modifiers`, `inputs`) are
  replaced whole. An override may not change a definition's kind of thing (a block's
  `render` from `cube` to `cross` is fine; a recipe's `type` is replaced with its fields).
- **A conflict is an error**: two packs, neither the base, overriding the same field of
  the same id, unless the later one lists the earlier in `requires` (it then knowingly
  builds on it). The message names both places: `moretrees/blocks/x.json:3:5:
  voxiverse:stone.light is also set by farmfix (blocks/y.json:9:5); add "farmfix" to
  moretrees' requires to override it knowingly`.
- References (a texture, a sound, a drop, a tag, a recipe's items) are resolved after
  every pack is merged, so a pack may refer to what a later file or pack defines.

*Errors* are values: `Pack_Error {pack, file: string, line, column: i32, message:
string}`, all of them collected (capped at 100, then `... and 37 more`), sorted by load
order, file, line and column, written one per line as
`<pack>/<file>:<line>:<column>: <what is wrong>; <the fix>`:

- `farmfix/blocks/stone.json:12:5: "ligth" is not a block field; did you mean "light"?`
  (suggestions within edit distance 2 among the valid names; otherwise the list of valid
  names);
- `farmfix/blocks/lamp.json:4:14: light is 0..15, got 20`;
- `farmfix/items/a.json:7:15: "voxiverse:stoen" is not a block; did you mean
  "voxiverse:stone"?`;
- `farmfix/blocks/a.json:3:3: "stone" is defined twice (first at blocks/b.json:8:3);
  rename one`;
- `farmfix/pack.json:1:1: namespace "farmfix" does not match the directory "farm_fix";
  rename one`.

A failed registry is not used: the server refuses to start the universe and logs every
line (the client shows the first ten on the screen that opened it). `./build.sh packs
[dir ...]` (`tools/packcheck`: the base pack plus the given pack directories in order)
prints the errors and exits non-zero: the validator an agent or a pack author runs.

*Limits* (constants in `common/game/registry.odin`, each an error with the number): 32 packs; a
pack 16 MiB, 1024 files; a `.json` file 1 MiB; a path 128 bytes of `[a-z0-9_./-]`;
`MAX_BLOCK_STATES` 4096 blocks; 0x2000 pack items; 1024 textures; 256 sound sets; 512 tags
of 1024 values; 4096 recipes; 256 structures.

*The registry hash.* `registry_text(reg, b)` writes every resolved definition in id order
(`block voxiverse:stone 1 flags=collides,opaque,... light=0 render=cube layer=opaque
textures=0,0,0 sound=2 drop=2`, and so on for every kind, the structures as a hash of
their cells); `registry_hash` is `game.Hasher` over it, as `schema_hash` is.
`Welcome` gains `content: u64` (the server's registry hash) and `packs: string` (`farmfix
1.0.0, moretrees 0.3.0`, at most 1024 bytes). A client whose registry hash differs
disconnects with `this server uses content packs this game does not have: farmfix 1.0.0,
moretrees 0.3.0` before it reads a chunk. (Sending the packs is M47b.)

*Saves store names* (a migration in M46's registry). Region format 2 adds a name table
after the region's position: `varint n`, then `n` block ids (strings, at most 112 bytes
each); every chunk's palette indexes that table instead of holding block numbers.
`write_chunk_blocks(w, c, remap: []u16 = nil)` writes `remap[b]` for each palette entry
(the network encoding passes nil and is unchanged); `read_chunk_blocks` takes the
reverse. The region writer builds the table from the chunks it writes, in order of first
use. On load, each name is looked up; a name the registry lacks refuses the world with
`world <address> has blocks no loaded pack defines: farmfix:peat (in 3 regions); enable
the pack in universe.cfg, or set unknown_blocks = air there to replace them`, and
`unknown_blocks = air` (universe.cfg, default `refuse`) loads them as air and logs each
name once. The migration (registered as M46 registers its steps, from the save version
M46 leaves to the next): every format 1 region file of every world is read through a
frozen copy of today's 57 names (`LEGACY_BLOCK_NAMES_V1`, in the migration's file, never
edited) and rewritten as format 2, with M46's atomic writes; the format 1 reader then
exists only inside the migration. M45's on-disk journal, which stores block values, gets
the same name table per file in the same migration (if M45 already stores names, nothing
changes there). `.cfg` files already store item names; from now on they write full ids,
and read both.

*Not in this milestone* (M47b): sending packs to clients, images and Ogg files in packs,
hot reload, the export carrying packs.

**The order of the steps** (each leaves the suite passing):

1. `common/game/pack_json.odin` and its tests.
2. `common/game/registry.odin`: ids, `Pack_Source`, the kinds, merging, references, errors,
   limits, the hash; the base pack's files written to equal today's tables;
   `registry_base`; `tools/packcheck` and `./build.sh packs`. The equivalence tests
   (below) pass before anything uses the registry.
3. The plumbing: `Block_Table` through `Block_Query`, light, the mesh job, worldgen,
   `server.Server`, `client.App` and `Session`, the codec and the checks, the tools. Then
   delete `BLOCK_INFO`, the item tables, `block_shape`, `block_faces`, `material_of`, the
   `Texture` enum's use as layers, and `assets/structures/`. Worldgen's golden, M38's
   determinism test and M39's bandwidth test must pass unchanged at the end of this step.
4. Universe packs: `universe.cfg`'s `packs`, `pack_read_dir`, `/packs` (lists packs,
   versions and the registry hash; any player), `Welcome.content` and the refusal.
5. Name palettes in region files, `unknown_blocks`, the M46 migration, the journal's name
   table.
6. The test pack and the broken-pack suite.

If the session must split, the remainder is **M47a: steps 5 and 6**, with
`test_region_names_migrate` and `test_pack_adds_block_item_recipe` as its exit check
(the broken-pack suite goes with it).

**Left out:** removing a definition (a pack can make a block unplaceable, not delete it);
pack-defined entities, biomes and worldgen; loot table files (M53); localization and
display names (UI v2); crafting in the game; per-world content (content is per universe: a
character's items travel between its worlds, so blocks and items must mean the same in
all of them; a pack's behaviour, its scripts and gameplay data, is enabled per world in
`worlds/<id>/world.cfg`'s `packs` by M52-M54); signatures (M54).

**Tests:**

- `common/game/pack_json_test.odin`: every value kind with its line and column; comments and
  trailing commas; each refused form with its exact message and position; the limits;
  key order kept.
- `common/game/registry_test.odin`:
  - `test_base_matches_legacy`: the base registry against frozen copies of today's
    `BLOCK_INFO`, `TOOL_INFO`, `MATERIAL_INFO`, `ARMOR_INFO`, `block_drop`, `can_place`,
    the plant support rules and `every_item`'s order, block by block and field by field,
    with the numbers of every builtin block and item;
  - **`test_pack_adds_block_item_recipe`** (the exit check): a pack in memory adds
    `testpack:marble` (a block using `voxiverse:stone`'s texture, light 7), `testpack:chisel`
    (an item, stack 1) and a shaped recipe from two marble to a chisel; the registry
