# M47c: Tier 2 in CI (Linux arm64, macOS x86_64)

> **Deferred (owner, #35, 2026-10-27).** Not in the build order: this is "Tier 2 CI" in the plan's next-tier list, to be
> planned again when it is taken up. The spec below is kept as written.


**Why.** `docs/platforms.md` promises Tier 2 targets a CI build and the unit tests. Today
neither exists: nothing in CI builds for Linux arm64 or for an Intel Mac, so code that breaks
there is found by a user. This is a small CI item, placed first because it needs no new game
code and the macOS Intel job is also the first proof that the code builds for macOS twice.

**Design.** Two jobs in `.github/workflows/ci.yml`, beside "Test · macOS arm64" and
"Test · Windows x64", each named `Test · <target>` and doing only `check` and `test`:

- **Test · Linux arm64** on `ubuntu-24.04-arm` (a hosted arm64 runner; free for public
  repositories). The pinned shader compiler has no arm64 download (README: set `GLSLANG`), so
  the job installs the distribution's `glslang-tools` through `.github/actions/apt` and sets
  `GLSLANG=$(command -v glslangValidator)` for its steps. Odin: `.github/actions/setup` first
  tries `laytan/setup-odin` for the pinned release; if that release has no linux-arm64 build,
  the job runs `odinup install` (Odin from source, cached by `actions/cache` on the pins). The
  step order and the cache keys use the same `image` word as the other jobs.
- **Test · macOS x86_64** on an Intel runner (`macos-15-intel`; GitHub's last Intel image,
  announced to end in 2027: when it goes the job is deleted and the target moves to Tier 3,
  a one-line change in `docs/platforms.md` and `TIER1_TARGETS`'s neighbour test).

Neither job runs the game, the determinism run, benchmarks or packages. Both need `check`
(format and compile for the host) and `test`. A failure there blocks the push's result like
any other job; a flaky one is a bug.

**The order of the steps:** (1) Linux arm64: the runner, Odin, `GLSLANG`, `check`, `test`;
fix what the first run shows (assumptions of x86_64: SIMD, `ODIN_ARCH` branches, the
`base/machine_*.odin` facts). (2) macOS x86_64: the same, `check` and `test`. (3)
`docs/platforms.md`: the "What CI does today" rows of both targets say what they now are;
the "Will it run" rows' status becomes "builds; unit tests pass" (still no package).

**Left out:** running the game on either (no GPU on the runners; Tier 2 is a build promise);
packages for either (on request: `build package` on the host); Windows arm64 (Tier 3).

**Tests:** the jobs are the tests. Locally: `./build.sh check` and `./build.sh test` stay as
they are on this machine. `test_platforms_doc_matches` (tools/build) still passes: Tier 1 is
unchanged.

**Exit check:** both jobs exist and are green on the commit's push (CI is the check: the
session cannot run an arm64 or an Intel Mac); the suite and `build check` pass locally.

**Check by hand:** none.
