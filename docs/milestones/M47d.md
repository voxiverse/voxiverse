# M47d: macOS: the Cocoa window, keyboard and mouse

**Read first:** `client/platform/platform.odin` (the interface, the `Event` union, the
procedures each OS implements), `platform_darwin.odin` (today: keep-awake only; `native_open`
fails with a message), `platform_linux.odin` and `platform_windows.odin` for what each
procedure must do, and docs/platforms.md.

**Why.** macOS arm64 is a Tier 1 target and has no window: the game cannot start. The window
and its input are made first and on their own, because they can be tested in CI without a GPU
(the runners have a window server and a logged-in session), while the Vulkan side (M47e)
cannot be. The owner has no Mac: everything here is built to be checked by tests that post
synthetic events, with a short by-hand list for what only real hardware shows.

**Design.** `client/platform/platform_darwin.odin` implements the whole interface with AppKit,
through `core:sys/darwin/Foundation` (where it lacks a class or method, the Objective-C
runtime through `intrinsics.objc_*`, as `pad_darwin.odin` does). No Objective-C file, no
Swift, nothing linked that macOS does not ship.

- **Application.** `NSApplication` with activation policy `.regular` (a Dock icon and a menu
  bar), an `NSApplicationDelegate` class made at run time (`applicationShouldTerminate`: closing
  asks like the close button on the other OSes; `applicationDidResignActive` and
  `DidBecomeActive`: `Focus_Event`), a minimal menu bar (Voxiverse: About, Hide, Quit with
  Cmd+Q; Window: Minimize, Enter Full Screen), and `finishLaunching` once. The event pump is
  `native_poll`: `nextEventMatchingMask` with a distant-past date, `sendEvent`, until empty;
  `native_wait` blocks on it with a timeout (the loop's idle wait).
- **Window.** An `NSWindow` (titled, closable, miniaturizable, resizable) holding an
  `NSView` subclass made at run time, which is layer-backed with a `CAMetalLayer` (M47e
  attaches the Vulkan surface to it) and accepts first responder. Content size in points is
  the window's size; the framebuffer size is points times `backingScaleFactor`, reported by
  `Resize_Event` in pixels like the other backends, and a move between displays of
  different scale re-reports it (`viewDidChangeBackingProperties`). The window opens centred
  on the main display at the size in `settings.cfg` (floored to 640x360 and capped to the
  screen's visible frame).
- **Keyboard.** `key` is the physical key from the hardware key code (`NSEvent.keyCode`; the
  table `MAC_KEYCODES` lists every `Key` the other backends map, from the Carbon
  `kVK_*` constants written as numbers with their names in comments); `symbol` is the key
  the layout makes it, from `charactersIgnoringModifiers` (Cmd+Z is the key marked Z on any
  layout). Auto-repeat comes from `isARepeat`. Modifier keys arrive as `flagsChanged`, diffed
  against the last flags into presses and releases. Cmd sets the `.Ctrl` modifier the UI's text shortcuts read (they say "Ctrl+"; on a Mac
  the shortcut key is Cmd), as the physical Control key does; both report the same
  modifier, and the keys `Left_Control`/`Right_Control` stay the physical Control key.
- **Text.** `NSTextInputClient` on the view (`insertText:replacementRange:`,
  `hasMarkedText`, `setMarkedText`/`unmarkText` accepted and ignored, `doCommandBySelector:`
  swallowed) delivers typed text as `Text_Event` runes, dead keys and Option combinations
  included; marked (IME) text is not drawn yet.
- **Mouse.** Moves in view coordinates flipped to top-left pixels; buttons 0 to 4;
  `scrollingDeltaY` for the wheel, with `hasPreciseScrollingDeltas` (a trackpad) scaled to
  the same steps as a wheel's lines. **Capture** (`native_set_mouse_captured`): hides the
  cursor, `CGAssociateMouseAndMouseCursorPosition(false)` so it does not move, and reports
  `Mouse_Delta_Event` from `deltaX/deltaY`; releasing it warps the cursor back to where it
  was. Losing focus releases capture and tells the game as the other backends do.
- **Fullscreen** (`native_set_fullscreen`): `toggleFullScreen` (the system's own Space) and
  the state follows the window's notifications, so the green button and Ctrl+Cmd+F agree
  with the game's setting.
- **Title and icon.** `setTitle`; the icon is M47g's.

**The order of the steps:** the application, the delegate, the menu and the pump; the window
and view with resize and scale; keys (table, symbols, modifiers) and text; mouse, scroll and
capture; fullscreen and focus; the tests.

**Left out:** the Vulkan surface (M47e: `native_vulkan_*` stay as they are), IME composition
display, drag and drop, a clipboard (there is none on any OS yet), multiple windows.

**Tests:** `client/platform/platform_darwin_test.odin` (`#+build darwin`), run by the macOS
jobs of `build test`. A test opens a real window on the runner and drives the pump with
**synthetic events** made by `NSEvent` class methods (`keyEventWithType`,
`mouseEventWithType`, `otherEventWithType`) and posted with `postEvent:atStart:`: no
accessibility permission and no real input device are needed.

- `test_mac_keycodes`: every `Key` has a hardware code, no code maps twice, and a set of
  known codes (A, Return, Space, arrows, F1, keypad 5) map to their keys.
- `test_mac_keys_and_text`: a posted key-down of `W` gives a `Key_Event` with key `.W`,
  symbol `.W`, pressed, and a `Text_Event` of `w`; the key-up gives the release; with the
  Cmd flag the symbol is the characters-ignoring-modifiers one; a key whose characters
  differ from its position (a synthetic event on a layout table where code 0 means `q`: the
  event carries the characters, the test sets them) gives key `.A`, symbol `.Q`; a held
  repeat sets `repeat`; a flags change gives modifier presses and releases in order.
- `test_mac_mouse`: moves, the five buttons and scroll (a line wheel and a precise trackpad
  delta give the same step count) arrive in order and in top-left pixels; capture on and a
  posted delta gives a `Mouse_Delta_Event` and the cursor's reported position does not
  change; capture off restores it.
- `test_mac_window`: `setContentSize` gives a `Resize_Event` in pixels; the scale factor is
  applied (read back from the screen, whatever it is on the runner); minimising and
  restoring give focus events; asking to close gives the close request once;
  `toggleFullScreen` is requested and the state is reported (the runner may refuse: the
  test accepts a refusal that is logged, and fails only on a state that disagrees with the
  last notification).
- `test_mac_no_window_server`: when `NSApplication` cannot reach a window server (an SSH
  session), `native_open` returns false with `no window server: run the game from the
  desktop` and does not crash.

**Exit check:** the tests above pass in the "Test · macOS arm64" job (CI is the check); the
Linux and Windows jobs and the cross-OS check still build the darwin file (`build check`
cross-compiles it from this machine); the suite is green locally.

**Check by hand** (a tester with a Mac, a few minutes, `voxiverse` from a CI build once
M47e lets it draw; before that only the window is seen): the window opens centred with the
title; dragging it between a Retina and a non-Retina display keeps the picture sharp
(resize event reports the new pixel size in the log: `grep resize voxiverse.log`); WASD and
the mouse look work, and Cmd+Q and the red button ask to quit; typing an accented letter
with Option+E then E gives `é` in a text field; a two-finger scroll moves a list about one
step per notch of a wheel; the green button enters full screen and back.
