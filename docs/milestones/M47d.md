# M47d: macOS part 1: the Cocoa window, input, MoltenVK and the renderer

**One pass (owner, #35).** The macOS port is two milestones, this and M47e, each written once,
built and linked in CI, and left. Nobody here has a Mac: no session, CI round or test is
spent on how it *behaves* on one. A tester tries everything later in one go and what they
find becomes an issue then. So: no new offscreen game checks, no macOS-specific test suites,
no screenshots or benchmarks. This replaces the former M47d, M47e (checked window and
renderer) and the probe work.

**Read first:** `client/platform/platform.odin` (the interface, the `Event` union),
`platform_darwin.odin` (today: keep-awake only; `native_open` fails with a message),
`platform_linux.odin` and `platform_windows.odin` for what each procedure must do,
`client/gpu/gpu.odin` and `swapchain.odin`, `tools/build/glslang.odin` (the pattern for a
pinned download with a checksum), docs/platforms.md.

**Why.** macOS arm64 is a Tier 1 *target* and has no window: the game cannot start.

**Design.** `platform_darwin.odin` implements the whole interface with AppKit through
`core:sys/darwin/Foundation` (the Objective-C runtime through `intrinsics.objc_*` where it
lacks a class or method, as `pad_darwin.odin` does). No Objective-C file, no Swift, nothing
linked that macOS does not ship.

- **Application.** `NSApplication`, activation policy `.regular`, a delegate class made at
  run time (`applicationShouldTerminate`: closing asks like the close button elsewhere;
  resign/become active give `Focus_Event`), a minimal menu (Voxiverse: About, Hide, Quit with
  Cmd+Q; Window: Minimize, Enter Full Screen), `finishLaunching` once. `native_poll` pumps
  `nextEventMatchingMask` with a distant-past date until empty; `native_wait` blocks on it
  with a timeout.
- **Window.** An `NSWindow` (titled, closable, miniaturizable, resizable) holding an `NSView`
  subclass made at run time: layer-backed with a `CAMetalLayer`, first responder. The
  framebuffer size is the content size times `backingScaleFactor`, reported by `Resize_Event`
  in pixels, and re-reported on `viewDidChangeBackingProperties`. It opens centred at the
  size in `settings.cfg` (floored to 640x360, capped to the visible frame). Without a window
  server (an SSH session) `native_open` returns false with `no window server: run the game
  from the desktop`.
- **Keyboard and text.** `key` is the physical key from `NSEvent.keyCode` through a table
  `MAC_KEYCODES` (every `Key` the other backends map; Carbon `kVK_*` numbers with their names
  in comments); `symbol` comes from `charactersIgnoringModifiers`; repeat from `isARepeat`;
  modifiers from `flagsChanged` diffed against the last flags. Cmd sets the `.Ctrl` modifier
  the UI's shortcuts read, as the physical Control key does. `NSTextInputClient` on the view
  delivers `Text_Event` runes (dead keys and Option combinations included; marked/IME text is
  accepted and ignored).
- **Mouse.** Top-left pixel coordinates, buttons 0 to 4, `scrollingDeltaY` for the wheel
  (precise trackpad deltas scaled to a wheel's steps). Capture hides the cursor,
  `CGAssociateMouseAndMouseCursorPosition(false)`, reports `Mouse_Delta_Event`; release warps
  back; losing focus releases it. Fullscreen is `toggleFullScreen`, the state following the
  window's notifications.
- **MoltenVK is a pinned download.** `tools/build/moltenvk.odin`, like `glslang.odin`: the
  release URL and its SHA-256 committed, unpacked into `build/tools/moltenvk/` with the `curl`
  and `tar` macOS ships; `build` and `package` call it on macOS only; CI caches it by hash.
  The newest release is the pin. One universal `libMoltenVK.dylib`.
- **No Vulkan loader.** `VULKAN_LOADER` is the path of `libMoltenVK.dylib` found in order at
  `<exe dir>/../Frameworks/` (inside the `.app`, M47e), `<exe dir>/`, `build/tools/moltenvk/`;
  the runtime opens it with `dynlib` and takes `vkGetInstanceProcAddr` from it. A missing
  library is `the Vulkan driver (MoltenVK) was not found next to the game; reinstall`.
- **Surface and portability.** Instance extensions `VK_KHR_surface`, `VK_EXT_metal_surface`,
  `VK_KHR_get_physical_device_properties2` (and `VK_KHR_portability_enumeration` with the
  portability flag on instance creation); `native_vulkan_create_surface` calls
  `vkCreateMetalSurfaceEXT` with the view's layer; the layer's drawable size follows
  `Resize_Event`, `displaySyncEnabled` follows vsync. The device extension
  `VK_KHR_portability_subset` is enabled when listed.
- **The renderer.** Written to what it already uses (dynamic rendering, synchronization2,
  bindless descriptors, buffer addresses). Where MoltenVK is known to need care (Metal's 0..1
  depth with the reverse-Z projection, the push-constant size limit, descriptor-indexing
  settings such as `MVK_CONFIG_USE_METAL_ARGUMENT_BUFFERS` set by the platform layer before
  the first Vulkan call) the code follows the documented behaviour; a feature the device
  lacks is named in the log at start (the existing device check lists what it needs), not a
  crash. Whether MoltenVK covers everything is what the first tester finds out; a gap becomes
  an issue then, not a session now.

**The order of the steps:** the application, delegate, menu and pump; the window and view;
keys, text, mouse, fullscreen; the MoltenVK pin and loader path; the surface and the
portability bits; `build check` and the macOS CI build.

**Left out:** IME display, drag and drop, a clipboard, multiple windows, a GPU feature probe
or `--check triangle` (macOS verification is deferred: see "macOS verification in CI" in the
plan's next tier), native Metal (never; MoltenVK is the decision).

**Tests:** none new for macOS. A `tools/build` test that the MoltenVK pin's checksum is a
64-hex string and its URL names the version is the one cheap exception (any OS, no device).

**Exit check:** `./build.sh check` passes, including the cross-OS pass that compiles the
darwin backend from here; the game and server build and link on the macOS CI runner (the
existing "Test · macOS arm64" job) and its existing unit tests pass there; the suite is green
locally.

## Check by hand

For the owner's occasional Mac testers, a few minutes, with a CI build of the game:

- `./voxiverse`: a window opens, centred, titled; the title screen draws (crunchy block
  textures, not blurred).
- A singleplayer world draws sky, terrain and clouds; resizing and the green full-screen
  button keep the picture; Cmd+Q and the red button ask to quit.
- WASD and the mouse look work; typing `é` (Option+E, E) in a text field gives `é`.
- `grep -i vulkan voxiverse.log` shows no error lines; if the game says a feature is
  missing, send that line.
