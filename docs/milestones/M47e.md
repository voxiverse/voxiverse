# M47e: macOS part 2: gamepads, audio, keep-awake, the icon and the `.app` package

**One pass (owner, #35):** as M47d. Written once, built and packaged in CI, then left; no
macOS-specific test suites, no extra rounds. This merges the former M47f (gamepads, audio,
keep-awake, icon) and M47g (the `.app`).

**Read first:** `client/platform/pad_darwin.odin` and `pad.odin` (the GameController backend
written through the Objective-C runtime, never run), `client/audio/device.odin`,
`platform_darwin.odin`'s keep-awake, `tools/build/package.odin` (`package_game`, the README
text), `tools/build/icon.odin`, `.github/workflows/ci.yml`'s "Package" and "Draft release"
jobs, M47d (where `libMoltenVK.dylib` is found) and docs/platforms.md.

**Design.**

- **Gamepads.** With M47d's run loop, `pad_darwin.odin` subscribes to
  `GCControllerDidConnectNotification` and `...DidDisconnectNotification` on the default
  `NSNotificationCenter` (a delegate class made at run time) in place of the polling
  workaround, and enumerates `GCController.controllers()` at start. The extended gamepad
  profile maps to the layout `pad.odin` uses (face buttons by position; analog shoulders and
  triggers; sticks and clicks; d-pad; Menu and Options; Home if exposed). The family (Xbox,
  PlayStation, Switch Pro, other) comes from `vendorName` and `productCategory`, for M42's
  glyphs. Handlers run on the main queue and push into the same event list as the other
  backends.
- **Audio.** miniaudio's CoreAudio backend, compiled by `ensure_miniaudio` on macOS, linked
  with `-framework CoreAudio -framework AudioToolbox -framework CoreFoundation` (added to the
  link list if missing). Opened as on the other OSes; a changed default output restarts the
  stream. With no output device the game starts on the null device and logs `no audio device
  found; sound is off` once, never a crash.
- **Keep-awake.** The existing IOKit assertion (M40) stays as it is.
- **The icon.** `NSApplication.setApplicationIconImage` from the generated icon (`#load` of
  the PNG the build makes), so a run from the terminal shows it in the Dock.
- **The `.app`.** `package_game` on macOS makes `build/dist/voxiverse-<version>-macos-arm64/`:

  ```
  Voxiverse.app/Contents/Info.plist
                        /MacOS/voxiverse              the game (release build)
                        /Frameworks/libMoltenVK.dylib the pinned MoltenVK (M47d)
                        /Resources/Voxiverse.icns     the icon
  voxiverse-server                                    the dedicated server
  README.txt, licenses/, LICENSE
  ```

  archived by `ditto -c -k --keepParent` as `voxiverse-<version>-macos-arm64.zip`.
  - `Info.plist` is written from a template with the version: identifier
    `net.voxiverse.game`, name `Voxiverse`, executable `voxiverse`, short version without the
    commit, build number the commit count, package type `APPL`, icon `Voxiverse`,
    `LSMinimumSystemVersion` from `MACOS_MINIMUM`, `NSHighResolutionCapable`, the games
    category, `NSSupportsAutomaticGraphicsSwitching`; no permission strings.
  - `MACOS_MINIMUM :: "13.0"` is one constant in `tools/build`, passed as
    `-minimum-os-version` and written to the plist; a tester's report on an older macOS is
    what moves it. The macOS row of docs/platforms.md says so.
  - `Voxiverse.icns` is made by the build tool from the generated icon (`ic07` 128, `ic08`
    256, `ic09` 512, `ic10` 1024, `ic11` 32, `ic12` 64, each a PNG from `base.png_encode`),
    no `iconutil`.
  - The executable's rpath is `@executable_path/../Frameworks`; after building, the tool
    runs `otool -L` and fails the package on anything outside `/usr/lib`, `/System` and that
    rpath.
  - The bundle and the server are signed ad hoc (`codesign --force --deep --sign -`,
    hardened runtime off). Not a Developer ID signature, not notarized (an Apple account is
    the owner's decision). `README.txt` says how to open it the first time (right-click,
    Open; or `xattr -dr com.apple.quarantine Voxiverse.app`), where settings and saves are
    (`~/Library/Application Support/voxiverse/`) and that the log and screenshots go beside
    the app.
  - **CI.** The "Package" matrix gains `{ os: macos-latest, name: macOS arm64 }`; after
    `build package` it unpacks with `ditto -x -k`, `plutil -lint`, `codesign --verify --deep
    --strict`, runs `voxiverse-server --version` and `Voxiverse.app/Contents/MacOS/voxiverse
    --version`; the artifact is the `.zip`. The "Draft release" job expects three packages
    and its macOS download line reads "macOS (Apple Silicon): the .zip. macOS asks you to
    confirm opening an app that is not from the App Store: see README.txt."
- **Docs.** docs/platforms.md and README.md say macOS arm64 "builds and packages in CI; not
  tested on hardware by the project" (the Tier 1 *target* stays; `TIER1_TARGETS` is
  unchanged).

**The order of the steps:** notifications and the family mapping; the audio device and
fallback; the icon; `MACOS_MINIMUM`, the plist and icns writers; the assembly, library check
and signing; the README text; the CI job and the release job; docs.

**Left out:** rumble, light bar, gyro, remapping beyond M41, audio device selection,
notarization, a `.dmg`, universal binaries (Intel is Tier 2, "Tier 2 CI" in the next tier),
auto-update, the App Store, running the packaged game in CI.

**Tests:** none new for macOS. The writers are pure functions of the build tool; a plain
unit test each for the plist (every key, `&` and `<` in a version escaped) and the icns
(header, entry lengths, total length) is cheap, runs on any OS and is allowed; nothing more.

**Exit check:** `./build.sh check` passes, including the cross-OS pass; the game and server
build and link on the macOS CI runner and the existing unit tests pass there; "Package ·
macOS arm64" produces `voxiverse-<version>-macos-arm64.zip` as a CI artifact; the suite is
green locally.

## Check by hand

For the owner's occasional Mac testers, once, with the CI `.zip`:

- Unzip, move `Voxiverse.app` to Applications, open it (macOS asks once): the Dock shows the
  Voxiverse icon and a singleplayer world works (M47d's list).
- Sound plays on the speakers and follows unplugged headphones; with no output device the
  game still starts.
- Pair a controller before or after starting: the sticks move the camera, the menus show its
  glyphs, a disconnect shows the prompt.
- Leave the game in a world past the display's sleep time: the screen stays on.
- `./voxiverse-server --universe test --seconds 5` from Terminal in the unzipped folder runs.
