# M47f: macOS: gamepads, audio, keep-awake and the icon

**Read first:** `client/platform/pad_darwin.odin` and `pad.odin` (the GameController backend
written through the Objective-C runtime and never run: the plan's M41 note says its "run loop
and connection notifications need M1b", the macOS window), `client/audio/device.odin`
(miniaudio opens the output device only), the audio smoke check in CI's Linux "Game" job,
`platform_darwin.odin`'s keep-awake, `tools/build/icon.odin`.

**Why.** Four things the window (M47d) does not cover and that the first launch exposes: the
controller backend has never had a run loop to deliver connections to; the audio device is
CoreAudio through miniaudio and has never been opened on a Mac; keep-awake exists (M40) but
has never been seen working; the Dock shows a generic icon. Each is checked in CI as far as a
machine with no controller, no speaker and no one looking allows.

**Design.**

- **Gamepads.** With M47d's run loop, `pad_darwin.odin` subscribes to
  `GCControllerDidConnectNotification` and `...DidDisconnectNotification` on the default
  `NSNotificationCenter` (blocks created with the Objective-C runtime's block support, or
  selectors on a delegate class made at run time) in place of the polling `controllers`
  workaround, and still enumerates `GCController.controllers()` at start. `startWirelessController
  Discovery` is not called (the system's Bluetooth settings pair controllers). The extended
  gamepad profile maps to the layout `pad.odin` already uses (face buttons by position: the
  bottom button is `A` on an Xbox pad and Cross on a PlayStation one, as GameController
  reports it; the two shoulders and triggers analog; both sticks and their clicks; the d-pad;
  Menu and Options; the Home/Guide button if exposed). Controller families (Xbox, PlayStation,
  Switch Pro, other) come from `vendorName` and `productCategory`, so the prompts show the
  right glyphs (M42's prompts). Handlers run on the main queue and push into the same
  event list as the other backends, so threading stays as `pad.odin` has it.
- **Audio.** miniaudio's CoreAudio backend (compiled in by `ensure_miniaudio` on macOS from
  the C source Odin ships; the link adds `-framework CoreAudio -framework AudioToolbox
  -framework CoreFoundation`, which `tools/build` already passes for the game's other
  frameworks if present, and is added to the list if not). The device is opened as on the
  other OSes (the mixer's rate and a period of about 10 ms); the default output changing
  (headphones unplugged) is reported by miniaudio's notification and the stream restarts, as
  on Windows. When no output device exists, the game starts with the null device and says so
  once in the log and in the Audio options tab (`no audio device found; sound is off`), never
  a crash.
- **Keep-awake.** The existing IOKit assertion (M40) is kept as it is: held while a world is
  open, released otherwise, decided by the call sites as on the other OSes. This milestone
  proves it exists (the test below).
- **The icon.** `NSApplication.setApplicationIconImage` from the game's own generated icon
  (`write_icon`'s image, built into the executable's bytes by `#load` of the PNG the build
  makes), so a run from the terminal shows it in the Dock; the `.icns` file M47g puts in the
  bundle is the same picture. The window has no title-bar icon on macOS (none is set).

**The order of the steps:** notifications and the family mapping; the audio device
open/fallback; the keep-awake test; the icon; the tests.

**Left out:** rumble and haptics (not in the engine on any OS), the controller's light bar and
gyro, controller remapping beyond M41's, the Siri Remote, Touch Bar, audio device selection
(the default output only, as on the other OSes), spatial audio / AirPods head tracking.

**Tests** (`#+build darwin`, in the macOS jobs; none needs a controller or speakers):

- `client/platform`: `test_mac_pad_framework`: GameController loads, `controllers()` returns
  an empty list on the runner (or the connected ones, whatever they are), the connect and
  disconnect observers are registered and removed without leaking (the count of observers
  before and after), and posting the system's own connect notification with no controller
  changes nothing and does not crash. `test_mac_pad_mapping`: the extended-gamepad value
  table (each element id -> our `Pad_Button`/axis, with the face-button position rule)
  checked as data for the Xbox, PlayStation and Switch Pro names, one test row per family;
  the dead-zone and response code is M41's and unchanged.
- `client/audio`: `test_mac_audio_device_or_null`: open the default device; either it opens
  and `device_info` reports a rate and a channel count and a short silence plays, or it
  fails with no device and the fallback to the null device is taken with the message; either
  way the mixer runs for 100 ms and stops cleanly. `build audio` (the offline baselines, no
  device and no window) passes on macOS with the `Darwin` checksum lines (M32f); the
  game's `--check audio` is M47h's.
- `client/platform`: `test_mac_keep_awake`: `native_set_keep_awake(on)`, then `pmset -g
  assertions` run as a child and its output contains `Voxiverse: playing` and
  `PreventUserIdleDisplaySleep`; after `off` it does not. (If `pmset` cannot be run, the
  test is skipped with a log line and counted in the job summary.)
- `client/platform`: `test_mac_icon`: after `set_window_icon`, the application's icon image
  has the generated icon's pixel size and its pixels equal the PNG's.

**Exit check:** the tests above pass in the macOS jobs; `build check` cross-compiles; the
suite is green locally.

**Check by hand** (a tester with a Mac and a controller, ten minutes): plug in or pair an Xbox or
PlayStation controller before and after starting: the game shows its glyphs in the menus and
prompts, the sticks move the camera, a disconnect shows the prompt in M41's way; the Dock
shows the Voxiverse icon; sound plays on the speakers and follows an unplugged pair of
headphones; leave the game open in a world for the display's sleep time (about two minutes
more than your Energy setting) and the screen does not sleep.
