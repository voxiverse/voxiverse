# M47g: macOS: the `.app` package

**Read first:** `tools/build/package.odin` (`package_game`: what a package is, how the Linux and
Windows ones are made, the README text), `tools/build/icon.odin`, `.github/workflows/ci.yml`'s
"Package" and "Draft release" jobs, M47e (where `libMoltenVK.dylib` is found) and
docs/platforms.md.

**Why.** Tier 1 promises a release package. `build package` refuses on macOS today
("no macOS package until the macOS backend"). A Mac player expects a `Voxiverse.app` they can
drag to Applications; Apple Silicon also refuses to run unsigned code at all, so the bundle
must at least be ad-hoc signed.

**Design.** `package_game` on macOS makes, in `build/dist/`, a folder
`voxiverse-<version>-macos-arm64/` (the architecture of the host: `arm64` on the CI runner)
holding:

```
Voxiverse.app/Contents/Info.plist
                      /MacOS/voxiverse              the game (release build)
                      /Frameworks/libMoltenVK.dylib the pinned MoltenVK (M47e)
                      /Resources/Voxiverse.icns     the icon
voxiverse-server                                    the dedicated server (a command-line program)
README.txt, licenses/, LICENSE
```

archived as `voxiverse-<version>-macos-arm64.zip`, made by `ditto -c -k --keepParent`
(macOS's own: it keeps the executable bit, symlinks and extended attributes, and
Finder unpacks it as is; `zip` from other tools can lose them).

- **`Info.plist`**, written by the build tool from a template (a fixed string with the
  version): `CFBundleIdentifier` `net.voxiverse.game`, `CFBundleName` and
  `CFBundleDisplayName` `Voxiverse`, `CFBundleExecutable` `voxiverse`,
  `CFBundleShortVersionString` the version without the commit, `CFBundleVersion` the commit
  count, `CFBundlePackageType` `APPL`, `CFBundleIconFile` `Voxiverse`,
  `LSMinimumSystemVersion` `MACOS_MINIMUM` (below), `NSHighResolutionCapable` true,
  `LSApplicationCategoryType` `public.app-category.games`, `NSSupportsAutomaticGraphicsSwitching`
  true, `GCSupportsControllerUserInteraction` is not set (that is for iOS). No permission
  strings: the game asks for no camera, microphone or files.
- **The minimum macOS version** is one constant, `MACOS_MINIMUM :: "13.0"` in
  `tools/build`, passed to the compiler as `-minimum-os-version` and written to the
  plist. It is 13 as a safe first value: no Apple Silicon Mac runs less than 11, the pinned MoltenVK
  (M47e) may need more than that for Metal features, and nobody can test an older system
  here. Lowering it is a decision that needs a Mac of that age to check by hand; it is not
  made here, and the first tester report on an older macOS is what moves it.
  `docs/platforms.md`'s macOS row is updated to say it.
- **The icon.** `Voxiverse.icns` is made by the build tool from the generated icon, in the
  `icns` container (`ic07` 128, `ic08` 256, `ic09` 512, `ic10` 1024, `ic11` 32, `ic12` 64,
  each a PNG of the icon at that size, written with `base.png_encode`), no `iconutil`.
- **Libraries.** `otool -L` of the game lists only system libraries and
  `@rpath/libMoltenVK.dylib`; the executable's rpath is `@executable_path/../Frameworks`
  (`-extra-linker-flags`). The build tool checks this after building and fails the package
  otherwise (nothing outside `/usr/lib`, `/System` or the rpath).
- **Signing.** After assembly the bundle is signed ad hoc, `codesign --force --deep --sign -`,
  with the hardened runtime off (it would require library validation of the bundled
  MoltenVK against a Team ID this bundle does not have); the server is signed the same way.
  That runs on Apple Silicon and shows no "damaged" message, but is not a
  Developer ID signature and is not notarized: the owner has no Apple developer account and
  getting one is a decision for the owner (it costs money and a secret in CI), so it is left
  out. On first launch of a downloaded copy macOS asks the player to confirm; `README.txt`
  says how (right-click the app, Open, Open; or `xattr -dr com.apple.quarantine
  Voxiverse.app`), in words as for Windows's "unknown publisher".
- **README.txt** (`package_readme.txt`) gets the macOS lines: run `Voxiverse.app`; Vulkan is
  inside it (MoltenVK); the first-launch confirmation; where settings and saves are
  (`~/Library/Application Support/voxiverse/` for `settings.cfg` and `saves/`, which is what
  the platform's paths already return; check `base/disk_darwin.odin`) and that the log and
  screenshots are written beside the app (in the folder the zip unpacked, or the Downloads
  folder: a read-only `/Applications` makes the game fall back to the settings folder, said in the
  log). The "Where your things are" text for the log's place is corrected for all three OSes
  if the macOS answer shows it was wrong.
- **CI.** The "Package" job's matrix gains `{ os: macos-latest, name: macOS arm64 }`. After
  `build package`: unzip with `ditto -x -k`; `plutil -lint` the plist; `codesign --verify
  --deep --strict`; `otool -L` as above; `voxiverse-server --version` and the 5 s server
  run as on Linux; `Voxiverse.app/Contents/MacOS/voxiverse --version`; and, when M47e's probe
  says the runner has a GPU, the package's game plays a world and screenshots (as the Linux
  step). The artifact is the `.zip`; the "Draft release" job expects three packages (`windows-x64.zip`,
  `linux-x64.tar.gz`, `macos-arm64.zip`) and its Downloads text line for macOS becomes "macOS
  (Apple Silicon): the .zip. macOS asks you to confirm opening an app that is not from
  the App Store: see README.txt."; its `needs` already waits on the package job.

**The order of the steps:** `MACOS_MINIMUM` and the compile flag; the plist and the icns
writers with their tests; the assembly, library check and signing; the README text; the CI
job and the release job's count and text; `docs/platforms.md` and `README.md` (the macOS
download row and the "in progress" text become what is true).

**Left out:** notarization and a Developer ID certificate (owner's account), a `.dmg`
(a zip is enough for testers), universal (arm64 + x86_64) binaries (Intel is Tier 2: its
package is on request and made by the same code on an Intel host), auto-update, the Mac App
Store, the server as a bundle.

**Tests:**

- `tools/build` (any OS): `test_plist` (the template with a version gives a document with
  every key above, escaped, and a version with `&` or `<` cannot break it);
  `test_icns` (the container's header, each entry's type and length, its PNG decodes to the
  size it claims with `base.png_decode`, the total length field is right);
  `test_macos_minimum_is_used` (the constant appears in the plist text and in the compiler
  flags the build tool makes for darwin).
- The package job's steps above, on macOS, are the integration test.

**Exit check:** the three tools/build tests pass locally; the "Package · macOS arm64" job is
green on the commit's push and its artifact is the `.zip`; a tag's "Draft release" job would
find three packages (its count check is the same code path); the suite and `build check` pass
locally.

**Check by hand** (a tester with a Mac, once): download the `.zip` from the CI run, double-click
it, move `Voxiverse.app` to Applications, open it: macOS asks once; the Dock shows the icon;
Singleplayer works (M47e's check); `README.txt` in the folder reads right for a Mac; quit
and run `./voxiverse-server --universe test --seconds 5` from Terminal; delete the app and the
settings folder leaves nothing else behind.
