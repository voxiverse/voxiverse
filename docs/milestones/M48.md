# M48: block states and shapes

**Why.** Stairs, slabs and ladders are the first blocks that are not a cube or a plant,
and the first whose one kind has several forms (a stair facing four ways, upside down or
not). Everything that reads a block reads it as a full cell today: `common/game/physics.odin`'s
`solid_at` (and `sweep`, `box_blocked`, `against_wall`), `common/game/raycast.odin` (a cell is hit
at its entry face), `common/game/light.odin` (opaque or not), `client/mesh/mesh.odin` (a cube's six
faces at whole-block positions packed in 5 bits each, a cross, and farmland's
`TILLED`/`LOWERED` hack for its sixteenth-low top), the outline in `client/camera.odin`
and `common/game/edit.odin`'s `can_place_at` (the whole cell against the player's box).

**Design.**

*States in the stored value.* A block value (`Block`, `u16`) becomes a **state id**: the
flattened form (as Minecraft has since 1.13). A **block type** (`Block_Type :: distinct
u16`, one per definition) owns a run of consecutive state ids, one per combination of its
properties' values:

- A property is a name and 2 to 16 values (identifiers), declared in order. A type has at
  most 6 properties and 256 states. State index within the type is mixed-radix with the
  last property fastest: `index = Σ value_i * stride_i`, `stride_last = 1`. The state id is
  the type's `first_state + index`.
- Ids are assigned type by type in M47's order, each type taking its state count. Every
  builtin (`Block`'s members) has exactly one state (a pack giving one `states` is an
  error: `voxiverse:stone is named by the engine and keeps one state`), so builtins keep
  their numbers and the builtin enum is both type and state. Water levels and wheat
  stages stay separate builtin types (M49 runs water's flow and wheat's growth over these
  ids as they are; a fluid channel waits for a gameplay need, M49's "Left out").
- `Block_Table` gains per state: `type_of: []Block_Type`, the shape ids (below) and the
  flags (copied from the type: every flag is per type in this milestone); per type:
  `first_state`, `state_count`, `props: []Prop_Def {name, values: []string}`, `default`
  (a state), `place` (the placement rule), `climbable`.
- `state_value(t, b, prop: int) -> int`, `state_with(t, b, prop, value) -> Block`,
  `prop_index(t, type, name) -> (int, bool)`, `state_text(reg, b, buf)` and
  `state_parse(reg, text) -> (Block, bool)` for `voxiverse:planks_stairs[facing=east,half=top]`
  (every property, in declared order; a type with no properties is its id alone). A parse
  missing a property takes the default's value; an unknown property or value fails.
- Items: one per type. `item_of_block(b)` is `Item(type_of(b) + 1)`; placing an item
  places its type by the type's placement rule. Builtin numbers are unchanged.
- **Saves.** M47's region name table holds `state_text` strings, so no format change:
  a name without `[...]` (every save so far) is the type's default state, and missing
  properties take defaults, so a pack adding a property to its block keeps its worlds.
  An unknown property or value is treated as an unknown name (M47's `unknown_blocks`).
- **Wire.** Chunks and records carry state ids, which both sides agree on through M47's
  registry hash.
- **Commands** (`/setblock`, `/fill`, `/give` and completion) take `state_text`; `/give`
  takes a type.

*Shapes.* A box is `Box :: struct {lo, hi: [3]u8}` in sixteenths of a block, `0 <= lo <
hi <= 16` on each axis (collision boxes may reach `y = 24`: a fence's height, for M48b).
A shape is a list of at most 16 boxes; shapes are interned in `Block_Table.shapes` (each
`{first, count}` into one `boxes` array), with `SHAPE_EMPTY :: 0` and `SHAPE_CUBE :: 1`
(the box 0,0,0 to 16,16,16). Every state has three shape ids: `collision`, `selection`,
`render`. A render shape also has its **cover**: per face, 16 rows of 16 bits saying which
sixteenths of that cell face its boxes cover (`cover: [][Face][16]u16`, by shape id),
computed at load.

*The pack format for states and shapes* (new category `shapes/`, and block fields):

```
// shapes/stairs.json
{
  "stairs": {
    "boxes": [[0, 0, 0, 16, 8, 16], [0, 8, 0, 16, 16, 8]],   // written for facing=north
    "rotate": "facing",
    "flip": {"half": "top"}
  },
  "slab": {
    "cases": [
      {"when": {"type": "bottom"}, "boxes": [[0, 0, 0, 16, 8, 16]]},
      {"when": {"type": "top"},    "boxes": [[0, 8, 0, 16, 16, 16]]},
      {"when": {"type": "double"}, "boxes": [[0, 0, 0, 16, 16, 16]]}
    ]
  },
  "ladder": {"boxes": [[0, 0, 13, 16, 16, 16]], "rotate": "facing"},
  "farmland": {"boxes": [[0, 0, 0, 16, 15, 16]]}
}

// blocks/stairs.json
{
  "planks_stairs": {
    "states": {"facing": ["north", "east", "south", "west"], "half": ["bottom", "top"]},
    "default": {"facing": "north", "half": "bottom"},
    "shape": "voxiverse:stairs",
    "place": "stairs",
    "opaque": false, "shades": true,
    "textures": {"all": "voxiverse:planks"}, "sound": "voxiverse:wood"
  }
}
```

- A shape definition has `boxes` (always present), `cases` (each `{"when": {prop: value
  or [values]}, "boxes": [...]}`; every case that matches adds its boxes), `rotate` (a
  property whose values are `north`, `east`, `south`, `west`: boxes are written for north
  and turned a quarter clockwise, seen from above, per step: one step maps `(x, z)` to
  `(16 - z, x)`, then each box's corners are re-sorted; east is one step, south two, west
  three), `flip` (`{prop: value}`: when it matches, `y` becomes `16 - y`, before
  rotation). Shapes refer to properties by name; a block using a shape must have every
  property the shape names, with every value the shape names (checked at load, with the
  file and line of both).
- Block fields: `states` (property name to a list of values, or `"bool"` for `["false",
  "true"]`), `default` (property to value; absent: each property's first value), `shape`
  (one shape for all three), or `collision`, `selection`, `render_shape` separately (each a
  shape id, `"cube"` or `"empty"`; they override `shape`), `place` (a rule name, below),
  `climbable` (bool). `render: "cube"` (M47's default) now means "draw the render shape";
  `"cross"` and `"none"` as before. A block whose render shape is not the cube cannot be
  `opaque` (an error). Defaults: collision, selection and render shapes are the cube for
  `render: "cube"` blocks; for `cross` blocks collision is empty and selection the cube (as
  today: a plant is targeted by its whole cell); `none` blocks have all three empty.
- The base pack gains `shapes/stairs.json` (stairs, slab, ladder, farmland),
  `blocks/stairs.json` and `blocks/slabs.json` for stone, cobblestone, stone_bricks and
  planks (`stone_stairs`, `stone_slab`, `cobblestone_stairs`, ... eight types; slabs have
  `"states": {"type": ["bottom", "top", "double"]}`, `"shape": "voxiverse:slab"`,
  `"place": "slab"`), `ladder` (states facing; `"render": "cube"`, `"layer": "cutout"`,
  `"collision": "voxiverse:ladder"`, `"climbable": true`, `"place": "attached"`,
  `"support": {"back": "full_face"}`, `"collides": true`, `"opaque": false`, a new
  generated texture `ladder`: two rails and four rungs, transparent between), and
  farmland and farmland_moist get `"render_shape": "voxiverse:farmland"` (their collision
  and selection stay the full cube: what the player stands on and aims at does not move,
  so M38's scripted farm field keeps its hashes). `support` gains `back` (the cell behind
  a `facing` block: `pos - facing`) and the requirement `"full_face"` (that cell's
  render cover of the face toward this block is full) beside a tag.

*Meshing* (`client/mesh/mesh.odin`):

- **Vertex.** Still 8 bytes. `packed`: `x | y << 9 | z << 18 | face << 27 | ao << 30`,
  positions in sixteenths (0..256); `layer`: `texture layer (12 bits) | sky << 12 | block
  << 16 | surface << 20 | drop << 21`. `TILLED` and `LOWERED` go (farmland's top is its
  shape now). `assets/shaders/world.vert` unpacks the new layout (`local = vec3(...) /
  16.0`); uv still follows the position, so a slab's side shows the lower half of the
  texture and a top slab the upper half, as the world grid says. `WORLD_VERTEX_SIZE` is
  unchanged; `vertex_position` returns sixteenths (tests compare against positions × 16).
- **Boxes.** A `render: "cube"` block draws its render shape: `SHAPE_CUBE` takes today's
  path unchanged in every respect but the packing (the fast path); any other shape emits
  each box's faces:
  - A face on the cell's boundary (`hi.x == 16` for +x, ...) is skipped when the neighbour
    is opaque, or when the neighbour's render cover of the opposite face covers the face's
    rectangle (row masks: every row of the rectangle's mask set in the neighbour's), or,
    for `cull_same` and `liquid` blocks, as today. Its AO and light are today's four corner
    values of the whole cell face, interpolated bilinearly to the rectangle's corners and
    rounded to the nearest level (a full face gets exactly today's values).
  - A face inside the cell (a bottom slab's top, a stair's step) is always drawn, with AO
    3 (open) and its own cell's light, raised to the block's own `light` (as
    `cross_quads` lights plants).
  - The cover test replaces today's cube faces' `opaque` test for every face: a full
    cube's cover is full, so a block's face against a bottom slab's bottom is hidden and
    the face against its top is drawn; two slabs side by side hide their halves; the
    farmland-against-farmland special case is now the general rule.
- AO from neighbours still counts opaque cells only: a stair beside a wall does not
  darken it (Minecraft's rule too).
- Greedy meshing merges full-cell faces only (all four corners at multiples of 16);
  partial quads are kept as they are. The grid of `merge_faces` is in blocks as before.
- The client's chunk-skip test (`client/world.odin`'s enclosed chunk) and `tools/bench`
  read `opaque` from the table, unchanged in meaning.

*Lighting.* No change to `common/game/light.odin`'s algorithm: light passes through every
non-opaque state, and shaped blocks are never opaque; whether a block is a column's top
for sky light is its `shades` flag (stairs and slabs shade, like leaves and water: under
a slab roof sky light seeps in one less per block instead of falling straight through;
ladders do not shade). Light does not depend on direction or on which half of a cell is
solid (Minecraft's per-face light occlusion is left out).

*Collision* (`common/game/physics.odin`):

- `cell_boxes(q, p) -> []Box`: the collision shape of the block at `p` (unloaded and below
  the world: the cube; above the world: empty).
- `box_blocked` overlaps the box with every collision box of the cells it covers, from
  `floor(lo.y) - 1` (a box reaching above its cell) to `floor(hi.y)`. A box in world
  units is `f64(cell) + f64(v) / 16` per bound: sixteenths are exact in binary, so a
  cube's box is exactly `cell` to `cell + 1`.
- `sweep` takes, among the collision boxes of the cells the moving box can reach
  (the swept range on the axis, the covered range on the other two, one more cell down for
  tall boxes), those that overlap on the other two axes (with today's `EPS`) and lie
  ahead (`box.lo[axis] >= face - EPS` moving up the axis), and moves to the nearest:
  `moved = min(delta, box.lo[axis] - face)` (or `box.hi[axis] - face` moving down). For a
  world of cubes this gives today's numbers bit for bit (`f64(layer) + 0` is
  `f64(layer)`; the nearest box is today's first solid layer), which a test checks against
  a frozen copy of today's `sweep` over 10 000 random cases.
- `against_wall` and `solid_at` become point and box tests over `cell_boxes`.
  `common/game/landing.odin`'s `fits` uses `box_blocked`.
- **Stepping up.** `STEP_HEIGHT :: 0.5625` (a constant until someone tunes it): when a
  player on the ground, not flying and not swimming, is stopped on x or z, `player_step`
  tries the same horizontal move from `STEP_HEIGHT` higher (a sweep up, the two
  horizontal sweeps, a sweep down by what it rose) and keeps it only if it went strictly
  farther horizontally; otherwise state is exactly as without the attempt. On a world of
  full blocks an attempt can never go farther (a wall one block high still stops the
  raised box), so the scripted session's roots do not move. Entities do not step.
- **Ladders.** A player whose box overlaps a cell holding a `climbable` block, not flying:
  falling speed is at most `LADDER_FALL_SPEED :: 3.0` blocks/s; moving horizontally into
  something (stopped on x or z this tick) or holding jump climbs at `LADDER_CLIMB_SPEED
  :: 3.0`; sneaking holds still vertically (velocity.y at least 0). Landing on a ladder
  resets the fall (M28's fall damage reads the clamped speed).

*Raycast and selection* (`common/game/raycast.odin`): the walk through cells is unchanged. A
targetable cell whose selection shape is the cube is a hit exactly as today (its entry
distance and face). Any other selection shape is tested box by box (slab method, in
`f64`) from the cell's entry distance: the nearest box hit within `max_distance` is the
hit, its normal the box face entered; no hit goes on to the next cell (aim passes over a
bottom slab's empty half to the block behind). `Ray_Hit` gains `point: [3]f64` (the hit
position: `origin + d * distance`). The outline in `client/camera.odin` draws every box of
the aimed state's selection shape, just outside it.

*Placement rules* (`common/game/placement.odin`, shared; the client predicts what the server
decides):

```
Place_Rule :: enum u8 {Default, Stairs, Slab, Attached}

Place_Context :: struct {
	target: Block_Pos,   // the cell aimed at (Ray_Hit.block)
	face:   Face,        // the face aimed at (from Ray_Hit.normal)
	hit:    [3]u8,       // where on it, in sixteenths of target (0..16)
	yaw:    f32,         // the player's, at the input the edit follows
}

placement :: proc(reg: ^Registry, type: Block_Type, ctx: Place_Context, q: Block_Query) -> (pos: Block_Pos, b: Block, ok: bool)
```

- `hit` is the client's `point - target` times 16, floored and clamped to 0..16, and
  both sides compute from `f64(hit) / 16`: the client quantizes first and uses the
  quantized value itself, so server and client run the rule on the same numbers.
- **Default**: `pos = target + normal`, the type's default state.
- **Stairs**: facing is the direction the player looks, from the yaw (yaw 0 looks north,
  -z; it grows towards west): `k = int(floor(mod(yaw, 2π) / (π/2) + 0.5)) & 3`, k 0..3 is
  north, west, south, east (in `f64`; `floor` and `mod` are allowed functions). Half: a
  bottom face aimed at gives `top`, a top face `bottom`, a side face `top` when `hit.y >=
  8`. `pos = target + normal`.
- **Slab**: aiming at a slab of the same type on its inner face (a bottom slab's top, a
  top slab's bottom) makes it `double` at `pos = target`. Otherwise `pos = target + normal`
  and the half as for stairs; if that cell already holds a single slab of the same type
  with the other half, it becomes `double` there. Breaking a double slab drops two.
- **Attached** (ladders): only a side face (`normal.y == 0`); facing is the normal's
  direction; the cell behind (the target) must give a full face (the support rule). `pos =
  target + normal`.
- `can_place_at(t, current, b, pos, player)` tests the placed state's collision boxes
  against the player's box (a bottom slab can go under a player's head), and lets a slab
  merge into its own type.
- **The edit.** `Edit` gains `target: Block_Pos`, `face: u8` (0..5; 6 when breaking) and
  `hit: [3]u8`. The client runs `placement` from its aim and the yaw of the input the edit
  follows, predicts the result and sends it with the context. The server, in
  `apply_edit`, runs `placement` with the context, its own blocks and the yaw of that
  input (`c.look` as that input left it), and accepts only if it gives the same `pos` and
  state. Breaking is as today. `PROTOCOL_VERSION` 27 (M47b's 26 plus one).
- **Support.** `set_block` (M45's pipeline) checks the support of the six neighbours of
  a changed cell, not only the one above (a ladder whose wall goes breaks and drops, as a
  plant does); bulk edits check their box grown by one on every side. The rule is shared
  (`block_supported(t, b, pos, q)`), and the client's prediction of an edit applies it to
  the neighbours as the server will.

*Order of the steps* (each leaves the suite passing):

1. States in the registry: properties, flattening, `state_text`/`state_parse`, commands,
   saves of state names; tests.
2. Shapes: the format, rotate and flip, interning, cover; the base pack's shapes; tests.
3. Collision (`cell_boxes`, `box_blocked`, `sweep`, stepping up, ladders) with the
   frozen-sweep equivalence test; raycast with boxes and its equivalence test; the
   outline.
4. Meshing: the vertex layout and shader, boxes, cover culling, interpolated corners,
   merging; farmland's shape replaces `TILLED`; mesh tests.
5. Placement rules, the edit's new fields, server validation, support from all sides.
6. The base pack's stairs, slabs and ladder with the ladder texture; the agreement tests.

If the session must split, the remainder is **M48a: steps 5 and 6** (placement and the
shaped blocks of the base pack), with `test_placement_rules` and `test_shapes_agree` as
its exit check; M48 then ends with the collision, raycast and mesh tests on test packs'
shapes.

**Left out:** doors, fences and other blocks that change with their neighbours, and
block entities (M48b); stair corners (inner and outer stairs are one more property and a
neighbour rule: with fences in M48b's update mechanism if wanted); waterlogged blocks
(a fluid channel: not planned, see M49); directional light occlusion; AO cast by partial blocks; icons
shaped like their block (a stair's icon is a cube of its texture); per-state flags
(collides or light by state); entities stepping up; rotation of structures turning
facing states (a pasted stair keeps its facing).

**Tests:**

- `common/game/registry_test.odin`: mixed-radix ids and `state_value`/`state_with` over every
  state of a 3-property type; `state_text`/`state_parse` round-trip every base state;
  defaults for missing properties; rotate and flip give the expected boxes for all eight
  stair states (a table of boxes); interning (eight stairs share eight shapes); cover
  masks of a slab and a stair; broken states and shapes with exact messages (a shape
  naming a property the block lacks, a value it lacks, a box outside 0..16, a collision
  box above 24, more than 16 boxes, an opaque shaped block, states on a builtin, more
  than 256 states, a `default` value not in the list).
- `common/game/physics_test.odin`: `test_sweep_cubes_unchanged` (10 000 random boxes and moves
  in a random world of cubes: the new `sweep` and `box_blocked` equal frozen copies of
  today's bit for bit); standing on a bottom slab at `y + 0.5`; walking up a stair and a
  slab staircase without jumping; not stepping onto a full block; bumping a top slab's
  underside; ladder: climbing at 3 b/s, falling no faster than 3 b/s, sneaking holds.
- `common/game/raycast_test.odin`: `test_raycast_cubes_unchanged` (10 000 random rays in a
  world of cubes: hits, normals and distances equal today's); a bottom slab's top hit at
  `y + 0.5` with normal +y and the right point; a ray over a bottom slab hits the wall
  behind; a stair's step and riser.
- `common/game/placement_test.odin`, `test_placement_rules`: stairs facing for yaws around
  each boundary (exactly at 45 degrees goes to the next direction up); half from each
  face and from `hit.y` 7 and 8; slab merging both ways and refusal into another type;
  ladder only on sides and only against a full face; `can_place_at` with a slab above a
  crouching player.
- `client/mesh/mesh_test.odin`: a world of builtin cubes meshes to the same quads as
  before (positions × 16, the same AO and light); a lone bottom slab: five boundary faces

  side by side hide each other's sides; a stair's faces; farmland's top at 15/16 and its

  sky light 14.
- `server/shapes_test.odin`, **`test_shapes_agree`**: a stepped server (M38) and its
