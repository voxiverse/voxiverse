# M48d: Menus, part one (the player menu, the HUD, toasts, the title screen, the layer layout)

**Why.** The owner's design interview (2026-10-28, #45) decided the menus: [design.md](../design.md)
is the source, cited below as *(section)*. This milestone is the first of two (the Menus
milestone, first among the open rows, before M49); **M48e** does the universes screen, universe
creation and the camera and keys. Documents were written first (design.md, its glossary, the
plan's locked decisions); this one builds, and renames the code to the glossary.

**Hard stop.** Nothing under design.md's *The owner decides* is built, inferred or prototyped.
The Character and Journal sections stay hidden (no attributes, levels, skills; equipment
modifiers are not character attributes). Health stays hearts. The death screen stays as it is.
No Map, no Atlas (next tier): their keys (M, L) are declared in the section table as hidden.

**Design (decided).**

*Layout by layer (Code layout).* Files in `client/` are named by the layer they belong to, and
a layer's files only call down: `screen_*` (title, universes, creation, options, multiplayer,
credits, failed), `menu_*` (the player menu and its sections, the game menu), `overlay_*` (chat,
console, quit dialog, dial, toasts, consent), `hud_*` (hotbar, crosshair, health, prompt bar,
item-name popup), `dev_*` (tuning F4, audio inspector F8, the F3 debug screen, benchmark's
panels). Renames are `git mv` of tracked files, e.g. `screens.odin` split into `screen_title.odin`
and `menu_game.odin`, `worlds.odin` -> `screen_universes.odin` (its contents change in M48e),
`options.odin` -> `screen_options.odin`, `multiplayer.odin` -> `screen_multiplayer.odin`,
`stats_ui.odin` -> `menu_statistics.odin`, `inventory_ui.odin` -> `menu_inventory.odin`,
`chat.odin`, `console.odin`, `dial.odin` -> `overlay_*`, `audio_inspector.odin` -> `dev_*`. The
code's names follow the glossary: `Overlay.Inventory` and `.Stats` become one `.Player_Menu`
with a `Section`; "Worlds" becomes "Universes" in identifiers and UI text; "Settings" stays the
stored values' type, "Options" is the screen. Input goes to the top layer first: overlays, then
menus, then screens, then the world (one dispatcher, a test for the order).

*String keys (Language).* Every UI string goes through a key: `Text :: enum` with an English
table `TEXT_EN` (an enum-indexed constant array, `client/text.odin`) and `tr(key, args...)`.
Formatting arguments are positional (`{0}`). A test fails if a key has no string, and a scan
test fails if a `ui.button`, `ui.label`, `ui.title` or `toast` call in `screen_*`, `menu_*`,
`overlay_*` or `hud_*` takes a string literal (dev panels are exempt: not translated). Item and
block names come from the registry (packs give them), not from the table.

*The player menu (The player menu).* One overlay, `Player_Menu`, with the open section stored in
the app (`last_section`, not saved between runs). A constant
table `SECTIONS :: [Section_Id]Section{...}` declares, per section: id, label key, key action,
`visible` (a constant `bool`: Character and Journal false; Map and Atlas not yet in the table's
enum values that draw, listed with `visible = false` and `draw = nil`), and the `draw` proc. Later
sections are added by one table row and a draw proc. Order: Map (M), Journal (J), Inventory (E),
Character (C), Atlas (L), Statistics (K). Rules: a section's key opens it, and pressing it while
it is open closes the menu; Tab opens the last section (Inventory the first time) and closes if
open; Esc closes (it does not open the game menu in the same press); opening another section's
key while the menu is open switches section; the controller's View opens it (Tab's action) and
LB and RB step sections (visible ones only, wrapping); there is no Q/E stepping in the player
menu (Q/E stays for Options' tabs: those actions are bound only in the Options context). It
does not pause; the world behind is dimmed (the existing dim). The menu's look: the retro-futurist
panel theme (thin lines, cool accent colours, glyph set) as a `Theme` scope used by `menu_*`.
The tab strip shows visible sections with their key.

*The Inventory section.* Pockets stay 5x5. Left: the character preview (the render-to-texture
preview, rotatable by dragging, showing armour). Right of it: the item details panel (the hovered
or selected item's name, description, modifiers as "Speed +10%", tags). A Sort button and a
search box filter and sort your own pockets (the search dims non-matching slots; Sort is the
existing sort, kept). The container view (a chest's slots) docks above the pockets while a
container is open, and the character preview is hidden meanwhile. Creative's catalog docks in
the same section (where it is today, restyled). Tooltips (a tooltip layer widget): name, a short
description from the item's data (the pack's `description` string; items without one show none),
and the modifiers listed. If the registry's item definition has no `description` field yet, add
it as an optional string (a registry schema change: packs and the base pack's items get short
descriptions for the base items).

*Statistics.* Kept as it is (grouped counters with search), moved to a section, restyled.

*The HUD (HUD).* `hud_*` holds the hotbar (5 slots), crosshair (a plus), health (hearts), the
prompt bar and the item-name popup. F1 (`Toggle_HUD`, rebindable) hides all of it, and the
viewmodel later; it is a per-session toggle, not saved. The popup shows the held item's name
above the hotbar when the selected slot changes (including the first frame in a world), holds
1.5 s and fades over 0.5 s; nothing for an empty slot; Reduce motion: no fade, appears and
disappears. No coordinates or compass on the HUD, ever; no clock.

*Toasts (Loading, notices, screenshots).* `overlay_toasts.odin`: `toast(app, key, args..., on_click = nil)`.
Top right, newest on top, at most 4 shown (older ones leave early), 4 s each, slide in over
0.2 s and fade over 0.4 s (Reduce motion: no slide, no fade, shown and removed). They take
pointer input only on themselves (the world still gets the rest); a click runs the toast's
action. Used first for F2: "Screenshot saved", a click opens the screenshots folder (the
platform's open-folder call; if it has none on an OS, the toast has no click). Joins ("X joined")
use the same system. The game menu stays the only thing that pauses.

*The title screen (Title screen).* Buttons: Singleplayer, Multiplayer, Options, Quit Game; the
splash text; the version lower left; the warp starfield behind (kept; Reduce motion as today).
`splashes.txt` is in `assets/` and read through the asset path the build already embeds (one
entry per line; blank lines and `#` lines ignored); one entry: "The Universe, Voxelized." Which
splash shows: chosen from the clock's second at start-up (a client-visual, free-tier use of
time), kept for the screen's lifetime; drawn tilted a few degrees, a gentle pulse (off with
Reduce motion). Singleplayer leads to the universes screen as today. The menu music rule is
M48e's.

*The start kit (Inventory section).* A new character starts with only the rocket launcher, in
hotbar slot 1: `kit_default` in `server/player_data.odin` has that one entry. The rocket launcher
stays out when `world.fire` is false, as now. Tests that relied on the old kit's blocks give the
world the kit they need (`world.cfg`'s `kit`) or use creative's catalog: no test is weakened.
Creative's catalog is how blocks are reached; survival's way of gathering is the owner's
(hard stop), so survival has the launcher only and that is the decided state.

*Gamepad and keys.* New actions (rebindable, in Controls): `Player_Menu` (Tab; pad View),
`Map` (M), `Journal` (J), `Character` (C), `Atlas` (L), `Toggle_HUD` (F1); `Inventory` (E) and
`Stats` (K) stay. M, J, C and L are bound and do nothing while their section is hidden. The
pad's Menu button still opens the game menu. Section stepping is its own pair of actions bound
to LB and RB only.

**Left out.** The Map and Atlas sections, the viewmodel, the ghost preview, the sound of the UI
(next tier: plan.md), anything in M48e (universes, camera, F5, F/P keys, the F3 option),
localization beyond the string keys, a "Continue" button.

**Tests.**

- `client/menus_test.odin` (extended): the section table (order, keys, hidden flags; only
  Inventory and Statistics visible); a section's key opens, a second press closes; Tab opens the
  last section and closes; Esc closes without opening the game menu; LB/RB step visible sections
  and wrap; no Q/E stepping in the player menu and still in Options; Character and Journal keys
  do nothing; the menu does not pause (the tick count advances).
- `inventory_ui_test.odin` (extended): with a container open, the preview is hidden and the
  container's slots lie above the pockets; without one the preview shows; Sort and search; a
  tooltip lists name, description and modifiers; the catalog is docked in creative.
- `hud_test.odin`: F1 hides every HUD element and shows them again; the popup appears on a slot
  change, holds, fades and is gone; no popup for an empty slot; with Reduce motion it does not fade.
- `toast_test.odin`: stacking order, the cap of 4, lifetimes, the click action runs once,
  Reduce motion.
- `text_test.odin`: every key has a string; the literal-scan over `screen_*`, `menu_*`,
  `overlay_*`, `hud_*`.
- `title_test.odin`: `splashes.txt` parses (comments and blanks skipped, at least one entry);
  the four buttons exist in order.
- `server/kit_test.odin` (or the existing kit test): a new character has the rocket launcher in
  slot 1 and nothing else; none without `world.fire`.
- A still of the title screen, the Inventory section (with and without a chest) and the
  Statistics section is added to the screen-test set that exists (`still_test.odin`).
- Layer order test: input given to an overlay is not seen by the menu or the world beneath.

**Exit check (M48d):**

- The tests above pass; `build check` (cross-OS included), the suite and the CI run of the
  commit are green.
- No identifier or UI text says "pause menu" or "Worlds screen" (a grep in the commit message's
  report: none).
- `client/` file names follow the layers; nothing outside `git ls-files` was edited.

**Check by hand (M48d):** run the game. (1) The title screen shows the splash tilted beside
the logo and four buttons in order; the version is lower left. (2) Enter a world; press E: the
Inventory opens with the character preview, details panel, Sort and search; press K while it is
open: Statistics; press Tab: it closes, Tab again reopens Statistics (the last section); Esc
closes. M, J, C, L do nothing. (3) Open a chest: it sits above the pockets and the preview is
gone. (4) F1 hides the hotbar, crosshair and hearts; change slots with the wheel: the item's name
fades in above the hotbar. (5) Press F2: a "Screenshot saved" toast top right; click it: the
folder opens. (6) A new character holds only the rocket launcher in slot 1 (survival) and has
the catalog in creative. (7) On a pad: View opens the player menu, LB/RB switch sections.
