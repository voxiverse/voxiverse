# M48g: party 1, part two: the damage pipeline, death, respawn, kits, regeneration, pvp and death messages

The remainder of party milestone 1 (M48f is the first part; this is a remainder and is
finished, not split again). Rules and decisions: design.md's *Survival for the LAN party*.

- *One damage pipeline.* `server/damage.odin`: `damage(s, target: ^Client, amount: f32,
  source: Damage_Source) -> Damage_Result` replaces `damage_player`. `Damage_Source ::
  struct {kind: Source_Kind, attacker: Maybe(Client_Id), weapon: string, pos: [3]f32}`;
  `Source_Kind :: enum {Fall, Explosion, Weapon, Command, Void}` (a new source is an enum
  value, a message key and a call). It checks, in this order: the target is playing and
  alive; `invulnerable` (`Ability.Invulnerable`) -> `.Blocked`; the world's `pvp` rule
  when the source has an attacker who is a player (including the target themselves? no:
  self-damage is not pvp) -> `.Blocked`; `health` ability absent -> `.Blocked`. Then
  subtracts, resets the regeneration clock, records the `Damage` telemetry, raises the
  `damaged` script event, tells the victim the **direction** (a `Damage_Hit` event
  record: the angle from the source's position, for M48h's HUD), and at 0 calls `die`.
  Falls, explosions and `/damage` all go through it; nothing else changes health.
- *Regeneration:* `regenerate` ability and `natural_regeneration` rule: after
  `regen_delay` (5 s, in ticks) without damage, `regen_rate` points a second (1 a second:
  0.05 a tick at 20 Hz; the server tick rate is read, not assumed). `Client.last_damage`
  is a tick. It is in `health_tick`.
- *Death:* `die(s, c, source)`: records `Death` and the stats `deaths`; the killer's
  stat `kills` (a player attacker who is not the victim) through `stat_add` (the
  statistics counters the player list reads); `Player_Died` event and the `died` script
  event; drops the inventory only if `drop_on_death` (ability) and not `keep_inventory`
  (rule): the owner's rule is that survival keeps it; sets `Client.dead` and opens the
  death screen. Death messages: `death_message(reg, source, victim, attacker) -> string`
  builds the line from string keys `death.fall` ("{victim} fell"), `death.explosion`
  ("{victim} blew up"), `death.weapon` ("{victim} was shot by {attacker} ({weapon})"),
  `death.command` ("{victim} died"), `death.void`; sent to every player in chat as a
  system line. No source-specific branches: the key is the source kind's name.
- *The death screen* (M53b's placeholder made real now; M53b's own spec is superseded
  where it said "no death message"): the `Health.dead` field and `Client.dead` as M53b
  specifies (the simulated empty input, edits refused, prediction exact); the screen is
  a simple overlay (`overlay_death.odin`, not the dialogue runtime, which does not exist
  yet): the string key `death.title`, the **cause line** (the same message as in chat,
  with "You" for the viewer's own death: `death.you.fall` "You fell", etc.) and a
  **Respawn** button (Enter, a pad's confirm, a click). `Respawn` is a client message
  (`Client_Kind.Respawn`, `PROTOCOL_VERSION` +1), accepted only while dead. M53b, when it
  comes, makes this screen a dialogue and keeps its words.
- *Respawn:* `respawn(s, c)`: `set` full health, `dead` off, `land_at_spawn(remember =
  false)` (the **world spawn**), the kit given (below), `respawned` script event, the
  state records sent. Leaving while dead respawns before the save.
- *Kits are data:* `Mode_Def.kit` (M48f loaded it): given at respawn after clearing
  nothing (the inventory is kept: only missing kit items are added, magazines refilled by
  M48h's `refill_weapons`), and at join for a character with no saved inventory. A world's
  rules may name another kit: `rules.respawn_kit` (a string `Var`, a kit id from a pack's
  `data/kits/*.json`, falling back to the mode's). The base `survival.json` lists the four
  weapons from M48h (resolved lazily: this milestone ships the kit mechanism with the base
  survival kit holding `base:pickaxe_iron`'s sibling starters that exist today, and M48h
  adds the weapons to the file); a test pack's kit proves the mechanism.
- *The `pvp` rule* is read only in `damage`; friendly fire off when off, no teams.
- *Journal:* damage and death are `record`ed (telemetry) as before; the death's cause is
  the source kind. Rollback and replay are unaffected (nothing here edits blocks).
- *Statistics:* `kills` and `deaths` counters (`stat_add`), shown in the Statistics tab
  and read by M48i's player list; `kills` counts player kills only.

## Tests

- Damage while `invulnerable` does nothing (creative player falls 20 blocks: health
  unchanged, no `Damage`, no message).
- `pvp` off blocks player-sourced damage but not falls or explosions; `pvp` on allows it.
- The death message for each source kind, through the string table: "Sam fell",
  "Alex blew up", "Alex was shot by Sam (sniper)", and the viewer's own ("You fell").
- Regeneration: nothing for 4.9 s after damage, 1 point a second from 5 s, stops at max,
  resets on damage, off with the rule off or without the ability.
- Death keeps the inventory (survival default) and drops it with `keep_inventory` off
  and `drop_on_death`; respawn at the world spawn (not where the player slept), with
  full health; the kit given once and not duplicated; the stats counters move.
- The death screen: shows the cause and one Respawn button (a UI test); Respawn is
  refused while alive; a desync check over a death and respawn (`latency_test.odin`).
- Over UDP, two clients: one kills the other with `/damage` and a fall; both chats show the
  message once.
- The suite, `build check`, `build determinism`.

**Exit check (M48g):** the tests pass, the whole suite and `build check`, CI green; the old
`health_test.odin` assertions hold on the new pipeline (updated only where "instant
respawn" became the Respawn button).

**Check by hand (M48g):** in survival jump off a tall tower: health drops, regenerates
after five seconds idle, you die, the screen says how and Respawn puts you at the spawn
with your things; the chat names you.

## As built (decisions where the spec was open)

- The server ticks at `TICK_RATE` (30 Hz), not 20: regeneration is `regen_rate / TICK_RATE`
  a tick after `regen_delay * TICK_RATE` ticks; the tests read the constant.
- The death lines live in `common/game/damage.odin` (`DEATH_LINES`, one row per
  `Source_Kind`, `death_text`), because the server writes the chat line and the client the
  screen's "You ..." line from the same table; the screen's own words (`death.title`,
  Respawn) are client string keys (`Death_Title`, `Death_Respawn`). A new source is an enum
  value and a row.
- Kits are `Mode_Def.kit` only (`kit_give` adds what is missing, so a kept inventory is not
  doubled). The world-level `rules.respawn_kit` and `data/kits` are not built: a world that
  wants another kit uses a mode that has it (`default_game_mode`). The base survival kit is
  empty until M48h adds the weapons.
- `Health.dead` and `Player_Died{cause, attacker, weapon}` are replicated; `Damage_Hit
  {yaw, amount, known}` is a new event the client stores (`Session.hurt`) for M48h's
  damage direction. `Respawn` is a client message (`PROTOCOL_VERSION` 33). `/damage
  <player> <amount>` (node `voxiverse.command.damage`, admin) goes through `damage`.
- While dead the server steps the player with an empty input and refuses edits and other
  actions; the client does the same under the death overlay. The `damaged`/`died`/
  `respawned` script events are the telemetry `Damage`, `Death` and `Respawned` kinds until
  the VM exists.

## Check by hand (M48g, as built)

`/gamemode survival`, then `/damage <your name> 100`: the screen says "You died" and the
chat says "<name> died"; Escape does nothing; Respawn (click, Enter) puts you at the spawn
at full health. Fall from a tall tower: health drops; five seconds idle, it climbs a point a
second.
