# M49b: neighbour rules as data (random ticks, spreading, growth, fire)

**Why.** M49's scheduler runs engine behaviours with numbers from data. What blocks do on
their own beyond flowing is still code (`server/random_ticks.odin`'s `switch`). This
milestone gives packs a small, bounded statement language for rules, moves grass,
farmland and wheat onto it with identical RNG draws, and proves it with a creeping
substance and fire in the test pack (fire is not added to the base game: no gameplay
before the foundation is done).

**Design (M49b).**

*Rules.* A rule (registry `rule`, M47's format) is:

```
rule <id> {
  block <match> [, <match>]...        the cells it runs on (a block, a block[state=v], #tag)
  trigger random | scheduled
  [delay <ticks 1..1200>]             scheduled: ticks after a wake (default 1)
  [wake placed | neighbour | load ...] scheduled: when it is woken (default placed)
  <statement>...                      in order
}
```

Statements:

| Statement | Meaning |
|---|---|
| `require <cond>` | if false: the rule ends (inside `repeat`: this round ends) |
| `chance <n>` (2..65536) | draws `rng_int_max(n)`; anything but 0 ends the rule (the round) |
| `if <cond> { ... } [else if <cond> { ... }] [else { ... }]` | |
| `repeat <n> { ... }` (1..16) | |
| `pick <name> <x lo..hi> <y lo..hi> <z lo..hi>` | binds a cell at self plus offsets drawn x, then y, then z, each `rng_int_max(hi - lo + 1) + lo`, no draw for a range of one value |
| `set <cell> <block>` | through `set_block` (M48's default state, or `<block>[prop=v,...]`) |
| `set <cell>[<prop>] <expr>` | one state property of the cell's block, clamped to its range |
| `set <cell>.<channel> <expr>` | through `set_channel`, clamped to 0..max |
| `schedule <cell> <ticks>` | `schedule(w, cell, ticks)` (1..1200) |
| `stop` | the rule ends (even inside `repeat`) |

Cells: `self`, `above`, `below`, `north` (-z), `south`, `east` (+x), `west`, a picked name,
or `<cell> + (dx, dy, dz)`. Every cell a rule reads or writes must be within 8 blocks of
`self` on each axis (checked at load from the offsets and pick ranges).

Conditions: `<cell> is <match>`; `<cell> not <match>`; `loaded <cell>`; `<expr> <op>
<expr>` (`== != < <= > >=`); `any box(<x lo..hi>, <y lo..hi>, <z lo..hi>) is <match>`;
`count box(...) is <match> <op> <n>`; `<cond> and <cond>`, `<cond> or <cond>`, `(<cond>)`.
Expressions: integer literals, `<cell>.<channel>` (including `.light`), `<cell>[<prop>]`
(an integer or boolean state property), `+` and `-`.

Semantics (the parts that decide results):

- **Unloaded cells:** every condition about a cell that is not loaded is false (`is`,
  `not`, comparisons using it, `loaded`); `any`/`count` count it as not matching; a `set`
  or `schedule` of it does nothing.
- **Draws** come from `w.tick_rng` (one stream for all simulation, so the RNG section of
  the hash keeps its shape), in statement order, only when a statement is reached.
- **Writes** are immediate: later statements see them. A `set` to the same value is no
  change (no wake, no record).
- **Order:** random rules of a block run in rule order; after one changes `self`'s block
  the rest are skipped (as for scheduled rules).
- **Cost bound:** each rule gets a static cost at load (each statement 1, each cell read
  1, each box its volume, `repeat` multiplies its body); more than `RULE_MAX_COST ::
  4096` is refused. Also refused: more than 64 statements, nesting deeper than 4, more than
  4 picks, a box over 9 x 9 x 9, a block match naming a block or tag that does not exist,
  a state or channel the block or world lacks, a `set` of a computed channel, a
  scheduled rule without a way to wake. Each refusal names file, line and the fix
  (`sim/fire.sim:12: rule sim_test:fire costs up to 5 120 cell reads a run, over 4 096:
  shrink the box or the repeat`).
- Compiled once (`common/game/sim_rules.odin`: lexer and parser on M47's text reader, the checks,
  then a flat `[]Stmt` with child and else indices, `[]Cond`, `[]Expr`; no allocation
  while running). Interpreted by `server/sim.odin` `rule_run(w, p, rule)` with a frame of
  at most 5 bound cells. No recursion, no loops but `repeat`.

*Random ticks on rules.* `random_ticks` keeps its loop (pool slot order, uniform chunks
skipped, `rules.random_tick_speed` draws of `rng_u32 & 4095`); `has_random_tick(b)`
becomes "the block has a random rule", and `random_tick` becomes running them. The base
pack's `base/sim/growth.sim`, written to draw exactly as the code it replaces (the names
are M47's and M48's for these blocks and the wheat stage property):

```
rule base:grass {
  block base:grass
  trigger random
  require loaded above
  if above is #base:opaque { set self base:dirt  stop }
  repeat 4 {
    pick t -1..1 -3..1 -1..1
    require t is base:dirt
    require (t + (0, 1, 0)) not #base:opaque
    require (t + (0, 1, 0)).light >= 9
    set t base:grass
  }
}

rule base:farmland {
  block base:farmland, base:farmland_moist
  trigger random
  require loaded above
  if any box(-4..4, 0..1, -4..4) is #base:water {
    if self is base:farmland { set self base:farmland_moist }
  } else if self is base:farmland_moist {
    set self base:farmland
  } else if above not #base:wheat {
    set self base:dirt
  }
}

rule base:wheat {
  block #base:wheat
  trigger random
  require loaded above
  require self[age] < 7
  if below is base:farmland_moist { chance 3 } else { chance 6 }
  set self[age] self[age] + 1
}
```

`#base:opaque` and `#base:water` are tags the base pack gets here if M47 did not make
them (every opaque block; every water state). The grass and farmland code, `wheat_block`'s
use there, and `farmland_wet` leave `random_ticks.odin`; `light_above` moved to
`sim.odin` in M49. Note that `require (t + (0,1,0)) not #base:opaque` is false when that
cell is unloaded, which is exactly today's `!over_loaded || opaque` (one of the reasons
"not" is false on unloaded cells).

*The test pack's substances* (`sim_test`, added to M49's):

```
channel sim_test:potency { bits 4  default 0  saved true  replicated true }
block sim_test:creep { ... }        (opaque, breakable)
block sim_test:fire  { ... }        (not colliding, light 15)

rule sim_test:creep {
  block sim_test:creep
  trigger scheduled
  delay 10
  require self.potency > 0
  repeat 2 {
    pick t -1..1 -1..1 -1..1
    require t is base:stone
    set t sim_test:creep
    set t.potency self.potency - 1
    schedule t 10
  }
}

rule sim_test:fire {
  block sim_test:fire
  trigger scheduled
  delay 15
  wake placed neighbour
  if count box(-1..1, -1..1, -1..1) is #sim_test:flammable == 0 { set self base:air  stop }
  schedule self 15
  repeat 3 {
    pick t -1..1 -1..1 -1..1
    require t is #sim_test:flammable
    chance 3
    set t sim_test:fire
  }
  chance 6
  set self base:air
}
```

`#sim_test:flammable` is planks, log, leaves and wool. (Creep set into stone by `set t
sim_test:creep` resets `potency` to 0 first, then the next statement sets it: a channel
without `keep`.)

**The order of the steps (M49b):**

1. The parser, checks and compiled form, with the refusal tests (no running yet).
2. The interpreter, scheduled rules through M49's dispatch, the test pack's creep and
   fire and their tests.
3. Random ticks on rules: `base/sim/growth.sim`, the code removed. Then
   `farming_test.odin`, `determinism_test.odin` and the bandwidth tests must pass
   untouched.
4. The budget test.

**Left out (M49b):** rules written in scripts (M51-M52 add a `behaviour script`); rules on
the client; a rule triggered by an entity or an item (M53's triggers); fire, spreading or
any new mechanic in the base game; plant support (`server/plants.odin` stays code: it
drops items through the ledger, which rules cannot do yet); per-rule budgets.

**Tests (M49b):**

- `common/game/sim_rules_test.odin`: every statement and condition parses to the expected
  compiled form; costs computed as specified (the grass rule costs 4 x 6 + 3, ...);
  `test_rule_refusals`: a table of 14 broken files (each limit above, an unknown block,
  tag, state, channel, a `set` of `light`, an offset of 9, a pick of five cells, a missing
  `trigger`, a `require` with no condition, an unclosed brace), each refused with its
  exact message, file and line; `test_rules_parse_fuzz` (random bytes and mutated valid
  files never crash the parser and always end in a value or a refusal), run in the suite
  for a fixed budget.
- `server/rules_test.odin` (stepped server, the test pack):
  - `test_creep_spreads`: one creep at potency 15 in a 31 x 31 x 31 box of stone. After
    600 ticks: every creep cell has potency less than its distance (Chebyshev) from the
    start allows, at least one cell has potency 0, nothing outside the stone changed;
    the mirror holds every potency the server does; two runs end with the same world
    hash.
  - `test_creep_survives_save`: saved and reloaded at tick 100 (as M49's test); the world
    hash at tick 600 equals the uninterrupted run's.
  - `test_fire_burns_out`: a fire set on a 5 x 3 x 5 planks house standing on stone:
    within 3 000 ticks no fire is left, the stone and the air around are untouched, and
    at least half the planks are gone.
  - `test_rule_reads_unloaded`: a creep at a chunk's edge next to an unloaded chunk
    spreads only inward; once the neighbour loads, it goes on.
- `server/sim_budget_test.odin`: `test_ten_thousand_rule_cells`: 10 000 creep cells
  scheduled at once (a 100 x 100 layer at potency 15 over stone); the slowest
  `sim_run_scheduled` over 300 ticks is under 8 ms optimized (80 ms unoptimized, as the
  flood test's two budgets), and at least 10 000 cells were waiting at its peak.
- Unchanged and passing: `server/farming_test.odin`, `server/liquids_test.odin`,
  `server/determinism_test.odin`, the bandwidth tests (roots and bytes), the suite.

**Exit check (M49b):**

- `farming_test.odin` and `liquids_test.odin` pass unchanged; the bandwidth roots are the
  baseline's: random ticks draw and decide exactly as before, now from data.
- `test_creep_spreads`: a pack defines a spreading substance, with a custom channel, with
  no engine code; `test_fire_burns_out` likewise for fire.
- `test_ten_thousand_rule_cells` within its budget, optimized, in CI.
- Every refusal names file, line and the fix; the parser fuzz runs clean.
- `random_ticks.odin` has no block names left in it.
- `build determinism`, `build check`, the suite and CI green.

**Check by hand (M49b):** a field of wheat grows and grass creeps into lit dirt as before.
