# M49b: neighbour rules as data (the rule language, scheduled rules, a spreading substance and fire)

**Why.** M49's scheduler runs engine behaviours (`flow`) with numbers from data. What a block
does on its own beyond flowing is still code (`server/random_ticks.odin`'s `switch`), and a
pack cannot say "this spreads", "this burns" or "this grows". This milestone gives packs a
small, bounded statement language for neighbour rules, runs it on M49's scheduler, and proves
it with a creeping substance and fire in the test pack (fire is not added to the base game:
no gameplay before the foundation is done). Random ticks move onto it in **M49e** (split
off 2026-10-30, #85: below).

**Checked against the code (2026-10-30, #85).** Corrected here: packs are JSON
(`common/game/pack_json.odin`); there is no "M47 text reader", so the rule files' format is
decided below. The base pack's namespace is `voxiverse` (`BASE_NAMESPACE`), not `base`.
Wheat is eight separate blocks (`voxiverse:wheat_0`..`_7`, `assets/packs/voxiverse/data/blocks/farming.json`),
not one type with an `age` state, and there are no `opaque` or `water` tags: "opaque" is a
block flag (`Block_Flag.Opaque`, `game.block_opaque`), and water is M49's flow rule's blocks.
The language below covers all three (flags, lists) without a second copy of any fact.
`server/rules_test.odin` already exists (the game rules' variables), so the tests here are
`server/sim_rules_test.odin`. Timing moved out of tests into `build bench budgets` (T5).
Tags hold their members ascending (`Tag_Def.members`), so a tag cannot say an order: ordered
block lists are their own entries (below).

**The split (decided 2026-10-30, #85).** The old M49b was the language, its interpreter, the
substances and moving random ticks with identical RNG draws: two systems' worth of work. This
row is the language and scheduled rules, proved by the test pack. **M49e** moves grass,
farmland and wheat onto random rules with a differential test against today's code, and
removes the code. Each has its own exit check. (This is planning before any work: the
"never split a remainder" rule is about a session splitting work it started.)

**What this builds on (M49, as its spec states; the session checks what M49 actually built
and corrects this spec in the same commit):** `common/game/sim.odin` (`Sim_Rules`, `Rule`,
the per-block `scheduled`/`random` index lists, `wakes`, `delay`), the registry kind
`sim_rule` (files in `data/sim/*.json`), `server/sim.odin` (`sim_update`, `sim_wake`,
`sim_wake_box`, `sim_run_scheduled`, `schedule`, `Sim_Stats`, `Rule_Stats`), `server/flow.odin`
(`Fluid`, `fluid_level`), channels (`common/game/layers.odin`, `chunks_channel`,
`set_channel`, the computed channel `voxiverse:light`), saved updates, and M49's test pack
`sim_test` (`data/channels/test.json`, `oil`). Also: `Pack_Error {pack, file, line, column,
message}` (`common/game/registry_load.odin`), `json_parse` and `Json_Value`'s line and column
(`pack_json.odin`), `Block_Flag` (`registry.odin`), `registry_block_tag`, `state_parse` (M48),
`set_block` and `world_act` (`server/journal.odin`), Q1's fuzz harness (`base/fuzz`,
`tools/fuzz/targets.odin`), `server/budgets.odin` and `tools/bench/budgets.odin`.

## Design (M49b)

### The format (decided 2026-10-30, #85)

Rules are **pack JSON**, in M49's registry kind `sim_rule` (`data/sim/*.json`), beside the
flow rules: the envelope (which blocks, when, the statement tree) is JSON, and each
statement, condition and expression is a short string in a statement language. So rules
reuse everything packs already have (the registry's ids, load order, overrides and errors,
the pack hash, hot reload, packs over the wire, Q1's `pack.json` and `pack.registry`
fuzzing) and need only a small lexer for the strings, not a file format of their own. Why not
a `.sim` text file: it would need its own file kind in packs, the pack hash, archives and
hot reload, for no gain in what a rule can say. Why not statements as JSON objects all the
way down: `{"op": "require", "cond": {"is": ...}}` is unreadable for people and models
alike. Written in the plan's foundation-arc *Decisions*.

A `sim_rule` entry is exactly one of: a flow rule (`"behaviour": "flow"`, M49), a **list**
(`"list": [...]`) or a **statement rule** (`"trigger"`). The example (the test pack's creep, its file `data/sim/creep.json`; M49
keeps `sim_test`'s files in memory beside M47's test pack, `common/game/pack_testdata.odin`):

```json
{
  "creep": {
    "blocks": ["sim_test:creep"],
    "trigger": "scheduled",
    "delay": 10,
    "do": [
      "require self.potency > 0",
      {"repeat": 2, "do": [
        "pick t -1..1 -1..1 -1..1",
        "require t is voxiverse:stone",
        "set t sim_test:creep",
        "set t.potency self.potency - 1",
        "schedule t 10"
      ]}
    ]
  }
}
```

Envelope fields:

| Field | Value | Default |
|---|---|---|
| `blocks` | array of 1..16 matchers (below): the cells the rule runs on | required |
| `trigger` | `"scheduled"` (M49's queue) or `"random"` (random ticks: M49e runs them; M49b parses, checks and compiles them, and its tests run them by calling `rule_run` directly) | required |
| `delay` | scheduled: ticks from a wake to the run, 1..1200 | 1 |
| `wake` | scheduled: an array of `"placed"`, `"neighbour"`, `"load"` (M49's `Wake`) | `["placed"]` |
| `do` | the statements: an array of 1..64 items | required |

A `do` item is a string (one statement) or an object:

- `{"if": "<cond>", "then": [...], "else": [...]}`: `else` is optional; an `else` holding
  exactly one `if` object is an "else if" (no extra nesting is counted for it).
- `{"repeat": <n 1..16>, "do": [...]}`.

A list: `{"wheat": {"list": ["voxiverse:wheat_0", ..., "voxiverse:wheat_7"]}}`, 1..64
block matchers that each name one block value (an id or a state), in order. A **flow rule is
also a list**: its `levels` then its `falling` (so `$voxiverse:water` is water's eight blocks,
from M49's one definition).

### The statement language

Statements (in a string):

| Statement | Meaning |
|---|---|
| `require <cond>` | if false: the rule ends (inside `repeat`: this round ends) |
| `chance <n>` (2..65536) | draws `rng_int_max(n)`; anything but 0 ends the rule (inside `repeat`: the round) |
| `pick <name> <x lo..hi> <y lo..hi> <z lo..hi>` | binds a cell at self plus offsets drawn x, then y, then z, each `rng_int_max(hi - lo + 1) + lo`, no draw for a range of one value |
| `set <cell> <block>` | through `set_block` (an id: its default state, M48; or `<id>[prop=v,...]`) |
| `set <cell> $<list>[<expr>]` | the list's block at the index, clamped to 0..len-1 |
| `set <cell>[<prop>] <expr>` | one state property of the cell's block (M48's `state_with`), clamped to its range |
| `set <cell>.<channel> <expr>` | through `set_channel`, clamped to 0..max |
| `schedule <cell> <ticks>` | M49's `schedule(w, cell, ticks)`; ticks a literal 1..1200 |
| `stop` | the rule ends (even inside `repeat`) |

Cells: `self`, `above`, `below`, `north` (-z), `south` (+z), `east` (+x), `west` (-x), a
picked name, or `<cell> + (dx, dy, dz)` (literals). Every cell a rule reads or writes must
be within 8 blocks of `self` on each axis: checked at load from the offsets and the pick
ranges (`RULE_REACH :: 8`).

Matchers (in `blocks`, in conditions, in lists): `ns:name` (every state of a block type; M48),
`ns:name[prop=v,...]` (the states with those values), `#ns:tag` (a block tag), `@flag` (a
`Block_Flag`, lower case: `@collides`, `@opaque`, `@targetable`, `@breakable`, `@placeable`,
`@replaceable`, and every flag the enum has when the session runs), `$ns:list` (a list or a
flow rule). Each matcher compiles to a bit set over block values (one bit per value, M48's
state ids), so matching is one load and a test.

Conditions: `<cell> is <matcher>`; `<cell> not <matcher>`; `loaded <cell>`; `<expr> <op>
<expr>` (`== != < <= > >=`); `any box(<x lo..hi>, <y lo..hi>, <z lo..hi>) is <matcher>`;
`count box(...) is <matcher> <op> <n>`; `<cond> and <cond>`, `<cond> or <cond>`, `(<cond>)`
(`and` binds tighter; both short-circuit, left to right).

Expressions (integers, `i32`): literals, `<cell>.<channel>`, `<cell>[<prop>]` (an integer or
boolean state property: false 0, true 1), `index($<list>, <cell>)` (the cell's block's place
in the list, -1 if absent), `+` and `-`. A channel is named by its id (`sim_test:potency`)
or by a bare name, looked up in the rule's own namespace first, then `voxiverse` (so
`.light` is `voxiverse:light`); a bare name found in neither is refused, and so is one that
the rule's namespace and `voxiverse` both have unless written in full.

The lexer (`common/game/sim_lexer.odin`): identifiers with an optional namespace
(`[a-z_][a-z0-9_]*(:[a-z0-9_/]+)?`), decimal integers with an optional `-`, `..`, the
punctuation `( ) [ ] , . + - = # @ $ == != < <= > >=`, spaces. A rule string may not contain a
JSON escape or a control character (refused: "a rule statement may not contain escapes or
control characters: write it plainly"), so a token's column is the string value's column
(`Json_Value.column`, at its opening quote) plus 1 plus its byte offset, exactly. Tokens
carry `line` and `column`; nothing is allocated per token (a fixed array of 64 tokens per
string; a longer string is refused: "statement too long (over 64 tokens): split it").

### Semantics (the parts that decide results)

- **Unloaded cells:** every condition about a cell that is not loaded is false (`is`, `not`,
  comparisons using it, `loaded`); `index` gives -1; a channel or property read of it is 0
  but makes its comparison false; `any`/`count` count it as not matching; a `set` or
  `schedule` of it does nothing. (So `require (t + (0, 1, 0)) not @opaque` is false when that
  cell is unloaded: today's `!over_loaded || opaque` in the grass code, M49e.)
- **Draws** come from `w.tick_rng` (one stream for all simulation, so the RNG section of the
  hash keeps its shape), in statement order, only when a statement is reached.
- **Writes** are immediate: later statements see them. A `set` to the cell's current value is
  no change (no wake, no record, not counted in `changes`).
- **Order:** the scheduled rules of a block run in rule order (M49's `sim_update`); after one
  changes `self`'s block, the rest are skipped. Random rules likewise (M49e).
- **Cause:** a scheduled rule's writes carry M49's cause (`system sim <rule id>`); a random
  rule's carry `Edit_System.Random_Tick`, as random ticks do today.
- **Cost bound (`RULE_MAX_COST :: 4096`).** Each rule's static cost, computed at load: each
  statement 1; each cell read in a condition or expression 1 (`is`, `not`, `loaded`, a
  stored channel, a property, `index`); a computed channel read its declared cost
  (`voxiverse:light`: 377, the cells within Manhattan distance 6 that `light_above` reads);
  each box its volume; an `if` the sum of its conditions and all its branches (an upper
  bound, kept simple); `repeat n` n times its body. Example: the grass rule of M49e costs
  1 543 (`require loaded above` 2; the `if` with its read, `set` and `stop` 4; the `repeat`
  1 plus 4 rounds of 384: `pick` 1, `require t is` 2, `require ... not @opaque` 2, `require
  ... .light >= 9` 378, `set` 1).
- **Limits** (each refused at load): cost over 4 096; more than 64 statements in a rule
  (nested ones counted); nesting deeper than 4; more than 4 picks (a frame of at most 5
  bound cells with `self`); a pick name bound twice or read before it is bound; a box over
  9 x 9 x 9; a reach over 8; more than 16 `blocks` matchers; a list over 64 or naming a
  matcher that is not one block value; a matcher naming a block, state, tag, flag or list
  that does not exist; a property or channel the block or world lacks; a `set` of a computed
  channel; a literal out of its range; a `$list[...]` set whose list is not a list; a
  statement rule that also has `behaviour`, or a list with `do`; a block with both a flow
  rule and a scheduled statement rule (M49's "one flow rule per block" extended).
- **Error format.** Every refusal is one `Pack_Error {pack, file, line, column, message}` at
  the token at fault, message `<what is wrong>: <the fix>`, e.g. `sim_test:data/sim/fire.json:14:21:
  rule sim_test:fire costs up to 5 120 cell reads a run, over 4 096: shrink the box or the
  repeat`. Parsing goes on to the next statement after an error; at most 20 errors a file.

### The compiled form and the interpreter

- `common/game/sim_rules.odin`: the parser (recursive descent over the tokens of one
  string, the JSON tree giving the structure), the checks, and the compiled form, flat and
  index-linked: `Rule_Program {stmts: []Stmt (child, next and else indices), conds: []Cond,
  exprs: []Expr, cells: []Cell_Ref, matchers: []Matcher (bit sets), cost: i32}` per rule,
  all in the registry's arena (freed with it, swapped with it at a tick boundary, M47 and
  M49). `rule_compile(reg, entry: Json_Value, pack, file) -> (Rule_Program, []Pack_Error)`.
  Nothing in the compiled form points into the JSON text.
- `server/sim_interp.odin`: `rule_run(w, p, rule: ^Rule) -> Rule_Result {changed_self:
  bool, reads, writes, draws: i32}`. A frame of at most 5 bound cells on the stack; an
  explicit stack of at most 4 `repeat` counters; no recursion, no loops but `repeat`, and
  **no allocation while running** (a test checks it). In debug builds (`ODIN_DEBUG`) it
  asserts `reads <= rule.cost` after each run (a static-cost bug is a crash, not a slow tick).
- Scheduled rules on M49's dispatch: `sim_update` runs a block's statement rules beside its
  flow rule (the order: flow first, then statement rules in rule order). `Rule_Stats` per
  rule: `runs`, `changes`, `reads` (summed), so the minute's tick summary can name a rule
  that reads most.

### The test pack's substances (`sim_test`, added to M49's)

- `data/channels/test.json` gains `"potency": {"bits": 4, "default": 0, "saved": true,
  "replicated": true}` (M49's `wetness` and `secret` stay: three channels).
- `data/blocks/substances.json`: `creep` (collides, opaque, breakable) and `fire` (no
  collision, not opaque, light 15), each the minimal block definition M47 accepts (the base
  pack's textures by id; the tests never draw them).
- `data/block_tags/flammable.json`: `flammable` = `voxiverse:planks`, `voxiverse:log`,
  `voxiverse:leaves`, `voxiverse:wool`.
- `data/sim/creep.json`: as above. (Creep set into stone by `set t sim_test:creep` resets
  `potency` to 0 first, then the next statement sets it: a channel without `keep`.)
- `data/sim/fire.json`:

```json
{
  "fire": {
    "blocks": ["sim_test:fire"],
    "trigger": "scheduled",
    "delay": 15,
    "wake": ["placed", "neighbour"],
    "do": [
      {"if": "count box(-1..1, -1..1, -1..1) is #sim_test:flammable == 0",
       "then": ["set self voxiverse:air", "stop"]},
      "schedule self 15",
      {"repeat": 3, "do": [
        "pick t -1..1 -1..1 -1..1",
        "require t is #sim_test:flammable",
        "chance 3",
        "set t sim_test:fire"
      ]},
      "chance 6",
      "set self voxiverse:air"
    ]
  }
}
```

- `data/sim/broken/` is not in the pack: the refusal tests build their broken files in
  memory (Q1's `pack_files_memory`).

## The order of the steps (M49b)

1. `common/game/sim_lexer.odin` and its tests; `common/game/sim_rules.odin`: the parser,
   the checks, the compiled form, the costs; lists; the refusal table; the fuzz target.
2. `server/sim_interp.odin`: `rule_run` and its unit tests (each statement's semantics, the
   draws, unloaded cells, no allocation, reads within cost).
3. Scheduled statement rules through M49's dispatch; the test pack's creep and fire; their
   tests; the determinism pins.
4. The budget scene and its limits; the threat model row.

## Left out (M49b)

Random ticks on rules and the base pack's growth rules (M49e); rules written in scripts (M52
adds a `behaviour script`); rules on the client (the "Prediction" decision wants them later:
the language is deterministic and shared in `common/game` so that is possible, but no client
runs them here); a rule triggered by an entity or an item (M53's triggers); fire, spreading or
any new mechanic in the base game; plant support (`server/plants.odin` stays code: it drops
items through the ledger, which rules cannot do yet); per-rule budgets (M52); variables
beyond picks; multiplication, division and randomness in expressions.

## Tests (M49b)

- `common/game/sim_lexer_test.odin`: every token kind; namespaced ids; `-1..1` as three
  tokens; positions: a statement on line 7 at column 9 of a JSON file gives its third
  token's exact line and column; escapes, control characters and 65 tokens refused with
  their messages.
- `common/game/sim_rules_test.odin`:
  - `test_rules_compile`: every statement, condition, expression, matcher kind and envelope
    field compiles to the expected flat form (stmts, child/next/else indices, conds, exprs,
    cells, matcher bits checked against `block_in_tag`, the flag and the list members).
  - `test_rule_costs`: the creep rule costs 17 (`require self.potency > 0` 2; the `repeat`
    1 plus 2 rounds of 7: `pick` 1, `require t is` 2, `set` 1, `set t.potency` with its
    read 2, `schedule` 1), the fire rule (its arithmetic written out in the test's comment
    and asserted), and a rule with nested `repeat`s, `if`/`else if`/`else`, boxes and
    `.light` (377).
  - `test_rule_refusals`: a table of at least 24 broken rules, one per limit and refusal
    listed above (cost over, 65 statements, nesting 5, five picks, a pick bound twice, a
    pick read before binding, box 10 wide, reach 9, 17 matchers, a list of 65, a list member
    naming a type with several states, unknown block, state value, tag, flag, list, channel,
    property; a `set` of `.light`; `chance 1`; `repeat 17`; `delay 0`; `schedule t 1201`;
    a missing `trigger`; a `require` with no condition; an unclosed parenthesis; an unknown
    statement word; a rule with both `behaviour` and `trigger`), each refused with its exact
    message, file, line and column.
  - `test_rule_errors_cap`: a file with 50 broken statements gives exactly 20 errors.
  - `test_rule_compile_frees`: compiling and freeing the test pack 100 times leaves the
    tracking allocator empty (the suite's `ODIN_TEST_FAIL_ON_BAD_MEMORY` checks the rest).
- Fuzz (Q1's harness): target `pack.sim_rules` (`fuzz_sim_rules` in
  `common/game/fuzz.odin`, listed in `tools/fuzz/targets.odin`): the input is a `data/sim`
  JSON file compiled against the base registry and `sim_test`'s channels. Its generator
  writes valid rules from the grammar (random statements, conditions, boxes, picks, nesting
  near the limits), which the harness mutates; dictionary: the statement words, `..`, `self`,
  `$`, `#`, `@`, `box(`, `.light`. Contract (Q1's, plus): the result is a compiled
  program or `Pack_Error`s, each with a line and column inside the input; a compiled
  program's cost is at most 4 096. Signature: the first error's refusal code (an enum, one
  per row of the refusal table), the stage reached, the bucket of tokens read.
  `test_fuzz_pack_sim_rules_smoke` (200 cases, seed 84) and its regression files run in the
  suite on the three OSes; CI's "Fuzz (smoke)" step runs it at 2 000 cases.
- `server/sim_interp_test.odin` (a stepped harness world, rules compiled from strings in the
  test):
  - `test_rule_statements`: one case per statement and condition: `require` ends the rule
    and, in a `repeat`, the round; `chance` draws exactly `rng_int_max(n)` (the RNG state
    after equals a hand-drawn copy's); a pick of ranges `0..0` draws nothing; `stop` inside
    `repeat` ends the rule; writes are seen by the next statement; a `set` to the same value
    makes no record and no wake; clamping of a channel (to 15 for 4 bits) and a property;
    `set ... $list[9]` on a list of 8 clamps to its last; `and`/`or` short-circuit (the read
    count shows it).
  - `test_rule_unloaded`: each condition kind on an unloaded cell is false, `index` is -1,
    `any`/`count` skip it, `set` and `schedule` of it do nothing.
  - `test_rule_run_allocates_nothing`: 10 000 runs of the creep and fire rules with
    `context.allocator` and `context.temp_allocator` set to a counting allocator: zero
    allocations.
  - `test_rule_reads_within_cost`: 2 000 rules from the fuzz generator (seed 85), each run
    on 20 random 17 x 17 x 17 neighbourhoods (random blocks, channels and unloaded chunks):
    `reads` never exceeds the rule's static cost, and two runs from the same RNG state give
    the same writes and draws.
- `server/sim_rules_test.odin` (stepped server, the test pack):
  - `test_creep_spreads`: one creep at potency 15 in a 31 x 31 x 31 box of stone. After 600
    ticks: every creep cell's potency is at most 15 less its Chebyshev distance from the
    start, at least one cell has potency 0, nothing outside the stone changed; the mirror
    holds every potency the server does; two runs end with the same world hash, and that
    hash equals a constant written into the test when it first passes (so the three OSes'
    CI runs check it is bit-identical everywhere).
  - `test_creep_survives_save`: saved, unloaded and reloaded at tick 100 (as M49's
    `test_updates_survive_save`); the world hash at tick 600 equals the uninterrupted run's.
  - `test_fire_burns_out`: a fire set in a 5 x 3 x 5 planks house standing on stone: within
    3 000 ticks no fire is left, the stone and the air around are untouched, at least half
    the planks are gone, and the world hash at the end equals a pinned constant.
  - `test_rule_reads_unloaded`: a creep at a chunk's edge next to an unloaded chunk spreads
    only inward; once the neighbour loads, it goes on.
  - `test_rules_hot_reload`: the creep rule's `delay` changed and the pack reloaded (M47i)

    next runs use the new delay.
  - `test_ten_thousand_rule_cells`: calls `budget_rules` (below) for what it does: at least
    10 000 cells waiting at its peak, every run's `reads` within the creep's cost, and the
    ledger audit clean.

## Benchmarks (M49b)

`budget_rules` in `server/budgets.odin`, judged by `build bench budgets -check` (limits in
`tools/bench/budgets.odin`'s `BUDGET_LIMITS`, new `base.Metric`s, `BUDGETS_VERSION` bumped):
10 000 creep cells scheduled at once (a 100 x 100 layer at potency 15 over a stone slab, on
`budget_world`), 300 ticks of `budget_world_tick`.

| Metric | What | Limit |
|---|---|---|
| `Rules_Tick` | the slowest world tick, CPU us | 16 000 (half the tick: the old test's 8 ms, doubled for slow runners as the flood's is) |
| `Rule_Run` | CPU ns per rule run (the ticks' total over the runs) | 3 000 |
| `Rules_Compile` | compiling the test pack and 500 generator rules near the limits, CPU us | 50 000 |

The scene fails (not a limit: a broken scene) if fewer than 10 000 cells were waiting at its
peak.

## Threat model (Q5)

A pack's rule is untrusted input that runs every tick. The cost bound, the limits, the
no-allocation interpreter and the parser fuzz are its defences: the session adds (or marks
built, if Q5 wrote it) the row "a hostile pack's rule exhausts the tick" in
`docs/threat_model.md` with those covers, in the same commit.

## Exit check (M49b)

- `test_creep_spreads` and `test_fire_burns_out`: a pack defines a spreading substance, with
  a custom channel, and fire, with no engine code; their pinned hashes hold on the three OSes
  in CI.
- Every refusal names file, line, column and the fix (`test_rule_refusals`); the fuzz smoke
  target runs clean; `test_rule_run_allocates_nothing` and `test_rule_reads_within_cost`
  pass.
- `build bench budgets -check` within the three limits above (CI's "Benchmark check").
- `farming_test.odin`, `liquids_test.odin` and the bandwidth tests pass unchanged.
- `build determinism`, `build check`, the suite and CI green.
