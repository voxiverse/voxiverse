# M49e: random ticks on rules (grass, farmland and wheat as data, drawing exactly as before)

**Why.** Split from M49b (2026-10-30, #85). M49b built the rule language and scheduled rules.
Random ticks are still a `switch` on block names in `server/random_ticks.odin`. This row moves
grass, farmland and wheat onto random rules in the base pack, drawing from the RNG and
deciding exactly as the code does, proves it with a differential test against the code, and
removes the code.

**What this builds on:** M49b (`common/game/sim_rules.odin`: the language, lists, `@flag`
matchers, `$` lists including flow rules as lists, `trigger "random"`; `server/sim_interp.odin`:
`rule_run`), M49 (`Sim_Rules.random` per block value, the computed channel `voxiverse:light`,
`light_above` moved to `server/sim.odin`), and today's `server/random_ticks.odin`
(`random_ticks`, `has_random_tick`, `random_tick`, `farmland_wet`; checked 2026-10-30, #85).
The session first checks M49 and M49b as built and corrects this spec in the same commit.

## Design (M49e)

*Random ticks on rules.* `random_ticks` keeps its loop exactly (pool slot order, uniform
chunks skipped, `rules.random_tick_speed` draws of `rng_u32 & 4095` per chunk);
`has_random_tick(b)` becomes `len(w.sim.random[b]) > 0`, and `random_tick` becomes running
the block's random rules in rule order (after one changes `self`'s block, the rest are
skipped). Their writes keep the cause `Edit_System.Random_Tick`.

*The base pack's rules*, `assets/packs/voxiverse/data/sim/growth.json`, written to draw and
decide exactly as the code they replace (the comments say which line of the old code each
statement is):

```json
{
  "wheat": {"list": ["voxiverse:wheat_0", "voxiverse:wheat_1", "voxiverse:wheat_2",
                     "voxiverse:wheat_3", "voxiverse:wheat_4", "voxiverse:wheat_5",
                     "voxiverse:wheat_6", "voxiverse:wheat_7"]},
  "grass": {
    "blocks": ["voxiverse:grass"],
    "trigger": "random",
    "do": [
      "require loaded above",
      {"if": "above is @opaque", "then": ["set self voxiverse:dirt", "stop"]},
      {"repeat": 4, "do": [
        "pick t -1..1 -3..1 -1..1",
        "require t is voxiverse:dirt",
        "require (t + (0, 1, 0)) not @opaque",
        "require (t + (0, 1, 0)).light >= 9",
        "set t voxiverse:grass"
      ]}
    ]
  },
  "farmland": {
    "blocks": ["voxiverse:farmland", "voxiverse:farmland_moist"],
    "trigger": "random",
    "do": [
      "require loaded above",
      {"if": "any box(-4..4, 0..1, -4..4) is $voxiverse:water",
       "then": [{"if": "self is voxiverse:farmland", "then": ["set self voxiverse:farmland_moist"]}],
       "else": [{"if": "self is voxiverse:farmland_moist", "then": ["set self voxiverse:farmland"],
                 "else": [{"if": "above not $voxiverse:wheat", "then": ["set self voxiverse:dirt"]}]}]}
    ]
  },
  "wheat_growth": {
    "blocks": ["$voxiverse:wheat"],
    "trigger": "random",
    "do": [
      "require loaded above",
      "require index($voxiverse:wheat, self) < 7",
      {"if": "below is voxiverse:farmland_moist", "then": ["chance 3"], "else": ["chance 6"]},
      "set self $voxiverse:wheat[index($voxiverse:wheat, self) + 1]"
    ]
  }
}
```

(`chance` inside an `if` branch ends the rule, as at the top level: it is not in a `repeat`.
`$voxiverse:water` is M49's water flow rule used as a list: the eight water blocks, as
`game.water_level` accepts. `"blocks": ["$voxiverse:wheat"]`: a list is a matcher too. A
matcher in `blocks` that names a list is allowed by M49b's grammar; if M49b as built did not
allow it, this row adds it.)

Where the rules and the code meet, and why they agree:

- Grass: the old code returns before any draw when `above` is unloaded (`require loaded
  above`); its spread draws x, y, z in that order per try, four tries always, whatever the
  earlier tries found (`repeat 4` with `require` ending the round, never the rule); an
  unloaded `t` or `t + up` fails as `!t_loaded` and `!over_loaded` did.
- Farmland: `farmland_wet` reads y 0..1, z -4..4, x -4..4 and stops at the first water; the
  rule's `any box` is the same set (its read order is the same, (y, z, x), and it reads no
  RNG, so stopping early or not cannot change a result).
- Wheat: the old code reads `below` even when unloaded (`chunks_block` gives air, so chance
  6); the rule's `below is voxiverse:farmland_moist` is false when unloaded, so `chance 6`:
  the same draw.

The code that goes: `random_tick`'s `switch`, `farmland_wet`, and the uses of
`game.wheat_stage`, `game.wheat_block` and `game.block_is_farmland` in `random_ticks.odin`
(they stay in `common/game` while other code uses them: `plants.odin`, the hoe, drops).

## The order of the steps (M49e)

1. The differential reference: today's `random_tick` and `farmland_wet` copied into
   `server/random_rules_test.odin` as `reference_random_tick` (the only copy of the old code;
   the comment says it is the reference and why).
2. `growth.json`, `has_random_tick` and `random_tick` on rules; the code removed.
3. The differential test, then the unchanged tests and the bandwidth roots.
4. The budget scene.

## Left out (M49e)

Any change to what grass, farmland or wheat do; turning wheat or water into one block type
with states (that would change block ids, saves and roots); random rules on the client;
plants' support (`server/plants.odin`).

## Tests (M49e)

- `server/random_rules_test.odin`:
  - `test_random_rules_match_code`: two stepped worlds built from the same seed; 20 000
    random neighbourhoods (seed 49, each a 17 x 17 x 17 box filled from a palette of air,
    stone, dirt, grass, farmland, farmland_moist, wheat_0..7, the eight water blocks, glass
    and a lamp, with some neighbouring chunks unloaded); in each, one cell ticked by the
    reference in world A and by the rules in world B from equal `tick_rng` states: the
    changed blocks (positions and values, in order), the journal causes and the RNG state
    after are equal, case by case. A mismatch names the case's seed, cell, block and the
    first differing write.
  - `test_random_ticks_no_block_names`: `random_ticks.odin` names no block: the test reads
    the file (`#load`) and fails on any `game.Block` enumerator written as `.Name` that is a
    block (the enum's names from reflection), on `wheat_` and on `water_level`.
  - `test_pack_random_rule`: a test pack random rule, `sim_test:moss` on
    `voxiverse:cobblestone` (`require any box(-1..1, -1..1, -1..1) is $voxiverse:water`,
    `chance 4`, `set self voxiverse:stone_bricks`), on a 16 x 16 cobblestone floor with a
    row of water along one edge, `random_tick_speed` 300, 600 ticks: some cells became
    stone bricks, every one of them next to water, none elsewhere; two runs end with the same
    world hash. A pack's random rule, no engine code.
- Unchanged in every line and passing: `server/farming_test.odin` (`git diff --exit-code
  <the commit the session starts from> -- server/farming_test.odin`, quoted in the report),
  `server/liquids_test.odin`, `server/determinism_test.odin`, the bandwidth tests (roots and
  bytes exactly the committed baseline's: the session's farm at tick 3000 grows identically).

## Benchmarks (M49e)

ready, non-uniform chunks (a seeded mix of grass, dirt, farmland, wheat stages and water,

- `build determinism`, `build check`, the suite and CI green.
