# M50: entity framework v2 (archetype storage, pack kinds, collision, persistence, the spatial query service)

**Why.** Entities are a fixed struct with every kind's fields in it (`server/entities.odin`'s
`Entity`: body, brain, stack, shorn, genes, growth, love, wait, owner), kept in one
`[dynamic]Entity` of at most `MAX_ENTITIES` 512, found by a linear `entity_find`, walked by
a `switch` on a closed `Entity_Kind` enum (Sheep, Rocket, Item). A pack cannot add a kind,
a script cannot add data to one, and every "who is near" is a loop over all entities and
all clients. The survey:

- Ten loops over `w.entities.list` (merging, pickup, rocket hits, explosions, mates, the
  spawn cap, despawning, `/kill`, the ledger's sums, saving) and eight over `s.clients`
  for players near something (`nearest_player`, `anyone_within`, pickup, rocket hits,
  explosions, the spawn cap). None of it has a spatial index.
- All entities stay in memory forever; one whose chunk is not ready is frozen
  (`chunk_ready`). The save is one `entities.cfg` per world, a text line per entity.
- Movement is `game.body_step` over `sweep`, the axis-by-axis sweep players use; rockets
  are a ray from a point (`rocket_step`), not a box.
- Players are not entities at all: `Client.player` (`game.Player_State`) is the truth,
  replicated as `Player_Motion`.
- On the client, a remote entity or player is hidden once its track's newest snapshot is
  more than `STALE_TICKS` (2 s) old (`client/players.odin`, `track_view`). Since M39 the
  snapshot lane sends a record only when it changes, so silence means "unchanged": a
  dropped stack lying still, a sheep standing still and a player standing still appear to
  vanish after two seconds. (Found reading the code, not seen running; the first step
  checks it with a test and fixes it.)

**This milestone is split in two, decided now:** **M50** is the framework (storage,
kinds, systems, collision, persistence, handoff, the spatial service) with every kind
moved onto it; **M50b** is replication v2 (quantized motion with velocity, rates by
distance, the jitter buffer) and the load and loss tests. The PLAN's exit is divided
between them: memory flat over churn and 2 000 entities within the tick budget in M50;
the bandwidth budget and smooth motion under 10% loss in M50b.

**Design (M50).**

*Identity.* `game.Entity_Id :: distinct u32`, from `World.next_id` as today: the id on the
wire (the `Entity` and `Entity_Motion` keys), in commands, logs and saves; never reused
in a world (`next_id` saved with the world; at `max(u32)` spawning refuses and logs).
Inside the store an entity is a `base.Pool` handle (`Entity_Handle`); `by_id` is a fixed
map from id to handle, for lookup only. `MAX_ENTITIES` becomes 4 096 per world.

*Components* (`common/game/components.odin`, `Component :: enum u8`, at most 32, each a plain
struct the M39 codec can encode):

| Component | Fields | Who has it |
|---|---|---|
| `Transform` | `position: [3]f64, yaw, pitch: f32` | every entity |
| `Body` | `velocity: [3]f32, on_ground: bool` | physics `walker`, `item`, `projectile` |
| `Health` | `health: i32` | kinds with `health` |
| `Age` | `ticks: i32` | every entity |
| `Brain` | today's `Brain` (state, timer, path, step, goal, look_at, from, hurt, stuck) | brain `grazer` |
| `Wool` | `shorn: bool` | `with wool` |
| `Genes` | `genes: game.Genes` | `with genes` |
| `Breeding` | `growth, love, wait: i32` | `with breeding` |
| `Stack` | `stack: game.Stack` | physics `item` |
| `Owner` | `client: i16` (-1 none) | projectiles, dropped stacks |
| `Fields` | `data: [16]u8` | kinds declaring `field`s |
| `Player_Link` | `client: u16` | the player kind |
| `Natural` | (tag) | spawned by `spawn` (may despawn) |
| `Origin` | `action: u32` (M45's action that spawned it; its actor names the player, the world system or, from M52, the pack and script) | every entity spawned from M50 on |
| `Hurt_By` | `action: u32, entity: Entity_Id, cause: u8` (the last damage: who and how, kept 10 s) | kinds with `health` |
| `Frozen` | (tag) | its chunk, or the one below, is not ready |

*Storage* (`common/game/archetype.odin`, no server imports so scripts and the client may use it
later):

- An **archetype** is a `Component_Set` (`bit_set[Component; u32]`) with one table:
  `ids: []Entity_Id` and one column per component it has. Each column is its own
  virtual reservation of `MAX_ENTITIES * size_of(component)`, committed in 64-row steps
  and never shrunk: rows never move in memory except by swap-remove, and committed memory
  stops at the high-water mark (flat over churn). At most `MAX_ARCHETYPES :: 64` per
  world, found by `by_set` (a fixed map, lookup only), kept in creation order.
- `Entity_Store {slots: base.Pool(Entity_Slot, Entity_Handle), by_id, archetypes,
  by_set, commands, next_id}`; `Entity_Slot {id, archetype: u16, row: u32}`.
- API: `store_spawn(st, set, kind) -> (Entity_Id, Entity_Handle)`, `store_despawn`,
  `store_add(st, h, $T, value)`, `store_remove(st, h, Component)`, `store_get(st, h, $T)
  -> ^T` (nil if absent), and queries: `store_query(st, all: Component_Set, none:
  Component_Set) -> Query_Iter`, yielding `(^Archetype, rows)`, with typed column access
  `column(arch, $T) -> []T`. Adding or removing a component moves the entity to the
  archetype of its new set (appended there; swap-removed from the old).
- **Structural changes during a system are deferred**: spawns, despawns, adds and removes
  go into `commands` and `store_apply` runs them in issue order after each system. A
  spawned entity is first seen by the next system.
- **Determinism (M38):** archetypes in creation order, rows in row order, swap-remove,
  commands in issue order. No map is iterated. The `Entities` hash section becomes
  `next_id`, then for each archetype its set and count, then each row's id and its
  components in enum order (`hash_value`), so the dump names
  `entities[archetype 2].Body[5].velocity.x`; `perturb`'s `Entity_Yaw` takes the first
  row of the first archetype with a `Transform`.

*Kinds from packs.* M47's `entity` definitions (name, box, health, speeds, saved,
summonable, hittable) gain what makes a kind: its components and engine behaviours with
their numbers. `Entity_Kind` (the enum) is replaced by `Kind_Id :: distinct u16`, the
registry id (synced by M47's pack hash on joining); `game.ENTITY_INFO` by the registry's
`Kind_Info` table. The base pack's `base/entities/sheep.entity` (M47's syntax if it
differs):

```
entity base:sheep {
  box 0.8 0.9
  health 4
  saved true
  summonable true
  hittable true
  physics walker
  walk_speed 1.4
  run_speed 4.2
  jump 1.2
  step 0
  brain grazer
  with wool genes breeding
  looks shorn lamb black spotted in_love
  model sheep
  spawn {
    on base:grass
    day 0.27 0.73
    every 60
    chance 0.5
    cap 6 within 48
    distance 16 40
    group 1 3
  }
}
```

- `physics`: `walker` (the body physics with wish and jump), `item` (the body with no
  wish, horizontal velocity zeroed on the ground, plus the `item { pickup_delay 0.5
  owner_delay 2 range 1.5 merge 1.0 life 300 }` block: today's `ITEM_*`), `projectile`
  (`projectile { speed 32 gravity 3 life 6 explode 4 }`: today's `ROCKET_*`) or `none`.
- `brain`: `grazer` (today's sheep: `think`, `steer`, grazing, fleeing, mating, with
  today's constants) or `none`. New brains are engine code until scripts (M52).
- `step`: the step-up height for `collide_move` (0 keeps today's sheep).
- `with`: optional components (`wool`, `genes`, `breeding`).
- `looks`: up to 16 named looks the client draws by, each computed by the engine from
  components: `shorn`, `lamb`, `black`, `spotted`, `in_love` (today's `Sheep_Flags`,
  which goes). `Entity_Motion.flags` becomes `looks: u16`, bit i for the kind's i-th look.
- `field <name> u8|u16 <lo> <hi>`: up to 8 pack fields in `Fields` (16 bytes), saved,
  not replicated (scripts read them in M52).
- `model`: the client's drawing: `sheep`, `rocket`, `item`, `player`, or `box <r g b>`
  (a box the kind's size, so a pack kind is drawn with no client code).
- `spawn`: natural spawning by today's rule and draws (every `every` ticks, per player in
  client order: count of this kind's entities within `cap`'s radius horizontally, the
  `chance` draw, angle, distance, the column top, `on` block, `group` size, the ±1.5
  jitter); several spawn kinds run in registry order.
- Load-time checks (file, line, fix): a physics or brain the engine does not have, a look
  the kind cannot compute (`black` without `genes`), `brain grazer` without `physics
  walker`, a box over 4 x 4, more than 8 fields, `spawn on` a block that does not exist.
- The base pack also gets `base:rocket` (physics projectile, model rocket), `base:item`
  (physics item, model item, saved) and `base:player` (box 0.6 1.8, physics none, not
  saved, model player).

*Systems and their order* (`server/entity_systems.odin`, run where `entities_tick` was,
once per world, each followed by `store_apply`):

1. `spawn_natural` (kinds with `spawn`).
2. `despawn_far`: `Natural` entities with no player within `DESPAWN_DISTANCE` 80.
3. `life`: `Age` +1; breeding clocks (`sheep_life`); stacks past `life` expire (ledger
   `.Expire`); projectiles past `life` go off where they are.
4. `brains`: `grazer` think and steer (the A* budget as today), skipping `Frozen`.
5. `motion`: `walker` and `item` bodies through `collide_move`; `projectile`s through
   `cast_box` against blocks and `spatial_cast` against hittable entities (players
   included, the owner's 10-tick grace kept); hits become blasts.
6. `items`: merging (every 10 ticks of an item's age, with later ids only: today's
   "those after it in the list") and pickup (players within `range` through the spatial
   service).
7. `handoff` (below).
8. blasts: `explode` as today, its two loops one spatial query.

Before them, in the per-client loop after `simulate_player`, `player_entity_sync`
writes each playing client's `Transform` from `c.player` (players are spawned as
`base:player` entities on arriving in a world and despawned on departing). The player's
movement stays `game.player_step` on `Client.player` (prediction is untouched); the
entity is how everything else finds players: the spatial service, pickup, rockets,
explosions, spawn caps, `nearest_player`.

*Collision* (`common/game/collide.odin`, on M48's collision shapes):

- `collide_move(q, lo, hi: [3]f64, delta: [3]f64, step: f64) -> Collide {moved: [3]f64,
  hit: [3]bool, stepped: bool}`: per axis in the order y, x, z (today's), the delta is
  clipped against every collision box (M48's shape boxes in world space) of the cells the
  swept box crosses that overlap the box on the other two axes (with today's `EPS`
  1e-7). With `step > 0`, when the first try was on the ground (or hit downward) and a
  horizontal axis was blocked, a second try moves up by `step` (clipped), then x and z,
  then down by `step` plus the up move (clipped); it is kept if it went farther
  horizontally (squared distance, ties to the first). Players call it with `step` 0
  through `player_step`; bodies with their kind's `step`. M48's `sweep` goes; it is
  copied into `common/game/collide_test.odin` as the reference.
- `cast_box(q, lo, hi, delta) -> (fraction: f64, axis: int, hit: bool)`: the earliest
  time of impact of a box moving by `delta` against the shape boxes in its swept bounds
  (slab test per box, ties to the lowest axis).
- Entities do not push each other (left out).

*Persistence and handoff.*

- Every entity belongs to the chunk its position is in (the spatial service keeps it).
- `handoff` (each tick, for entities whose chunk changed this tick and for every entity
  of a chunk whose readiness changed): `Frozen` is added when the chunk or the one below
  is not ready and removed when both are (today's `chunk_ready`).
- **A chunk that unloads takes its entities with it.** On unload (`unload_unwanted`,
  `unload_left`, `regen`), the chunk's entities of saved kinds are encoded into
  `w.saved_entities[pos]` (heap bytes, as `w.saved` holds edited blocks), their stacks
  leave the ledger's scope (`.Scope_Out`), and they are despawned without a death; other
  kinds (a rocket in flight) are dropped. When the chunk is ready again, its saved
  entities come back in saved order (`.Scope_In`), keeping their ids. So memory holds only
  the entities of loaded chunks, and `held_sums`/`ledger_world_scope` count the store's
  stacks as before.
- **The save:** M46's region chunk record gains an `entities` section: `varint n`, then
  per entity `varint id`, `varint kind` (an index into the region's palette of kind
  names), `varint c`, then c components, each `varint component` (an index into a palette
  of component names), `varint length` and the value in the M39 codec's create encoding
  (every field absolute). Saved components are `Transform`, `Body`, `Health`, `Age`,
  `Wool`, `Genes`, `Breeding`, `Stack`, `Natural`, `Fields`, `Owner` (not `Brain`, not
  `Frozen`, not `Player_Link`). A chunk record may now hold entities and no blocks (an
  unedited chunk: its blocks regenerate). On load a kind the world no longer has is
  dropped with one warning per kind and region (a stack in it through the ledger's
  `.Void`); an unknown component is skipped by its length. `World.next_id` is saved with
  the world (M46's world record).
- **Migration:** M46's registry gets `entities.cfg` to region entities: the old file is read
  with today's parser (kept for this), each entity placed in the record of its chunk, and
  the file removed once the regions are written (M46's backup keeps it).
  `test_old_saves_have_sheep` keeps passing.

*The spatial query service* (`common/game/spatial.odin`, used by the server for its entities and
by the client for the entities it is told about):

- A grid of chunk-sized cells (16³): `cells: map[Chunk_Pos]u32` (fixed, lookup only),
  per cell an intrusive list through per-entry `next`/`prev` indices, entries indexed
  like the store's slots: `{id, position, half_width, height, kind, flags}`.
  `Spatial_Flags :: bit_set {Hittable, Player, Item, Natural, Saved, Frozen}`. Insert,
  move (re-bucketing only when the chunk changes) and remove are O(1); empty cells are
  deleted from the map.
- Queries, all returning ids in ascending order (so their order never depends on
  insertion order or the map; `nearest` breaks ties by id), filtered by `Spatial_Filter
  {kind: Kind_Id (0: any), all, none: Spatial_Flags, exclude: Entity_Id}`, results in the
  temp allocator:
  - `spatial_sphere(sp, center, radius, filter, out)`;
  - `spatial_cylinder(sp, center, radius, half_height, filter, out)`;
  - `spatial_box(sp, lo, hi, filter, out)` (boxes overlapping);
  - `spatial_nearest(sp, center, radius, filter) -> (Entity_Id, bool)`;
  - `spatial_count(sp, center, radius, filter) -> int`;
  - `spatial_cast(sp, origin, dir, max, half: f64, filter) -> (Entity_Id, f64, bool)`
    (the nearest box a ray, or a box of half size `half`, enters: a walk over the cells
    along it);
  - `spatial_chunk(sp, pos, out)`.
- Blocks: `cells_find(q, lo, hi, match, out, max_volume := 32_768)` and `cells_nearest(q,
  center, radius, match)` over a `Block_Query`, in (y, z, x) order, `match` a block, a
  state or a tag (M49b's matcher, shared).
- Moved onto it: `entities_put` (entities within `ENTITY_VIEW` of the client, nearest
  first, ids ascending among equals, at most `MAX_KNOWN_ENTITIES`), merging, pickup,
  rocket hits, `explode`, the spawn cap, `despawn_far`, `mate_for`, `nearest_player`,
  `anyone_within`, `/kill`'s radius; on the client, `entity_aimed`. Audio (M56) and
  triggers (M53) use it later. No loop over all entities or all clients is left in
  `server/entity_systems.odin`.

*What else moves.* `server/entities.odin`'s procedures split into
`server/entity_systems.odin` (systems), `server/entity_kinds.odin` (`sheep_use` and
`ENTITY_BEHAVIOUR` become behaviour procedures looked up by brain or physics name) and
`server/entity_store.odin` (spawn, despawn, find by id, the hash). `summon`, `/kill`,
`Use_Entity`, `Attack` and `fire` take kinds by registry name. The client's
`Other_Entity.kind` becomes a `Kind_Id` and `entities_draw` switches on the kind's model.
The client's `s.entities` becomes a fixed map of capacity `MAX_KNOWN_ENTITIES`
(`base.map_make_fixed`), so its memory is flat too.

*The client fix* (step 1): `track_view` no longer hides by silence. A remote player or
entity is shown while its record exists; a track whose newest snapshot is old shows that
snapshot. `world_test.odin`'s "stale players are hidden" becomes "a still player stays
shown", and a test drops a stack, waits 5 seconds and finds it still drawn.
**Done early (issue #27, before M50):** no age rule at all; each applied snapshot tells
every present track "unchanged as of this tick" (`track_hold`), so a thing that moves
after standing is interpolated from where it stood, not across the whole wait. What is
left of staleness is the connection's: no snapshot for `STALE_SECONDS` hides everyone
(`session_others_now`). `still_test.odin` runs two sessions on a stepped server (a
player and a sheep standing 8 s, then moving). The "drops a stack" test is still due.

**The order of the steps (M50)** (each leaves the suite passing):

1. The client fix and its tests.
2. `common/game/collide.odin` (`collide_move`, `cast_box`) against the copied `sweep`; players and
   bodies switched; the M38 roots unchanged (only the code moved).
3. `common/game/archetype.odin` and `common/game/spatial.odin` with their unit tests.
4. Kinds as data (`Kind_Id`, the registry fields, the base pack's four kinds), the
   components, the systems; sheep, items and rockets moved; players as entities. The
   behaviour tests pass; the roots change here (one commit, its message says why), and
   `build determinism` and the side-by-side run pass.
5. Handoff, unload and load with entities, the save section and the migration.
6. The memory and load tests (below); the bandwidth baseline re-recorded (bytes no more
   than before).

If the session must split anyway, the remainder is M50c: step 5 and the churn test, with
`test_entities_unload_with_chunks`, `test_entities_saved_in_regions` and
`test_memory_flat_over_churn` as its exit check.

**Left out (M50):** quantized motion, rates by distance, the jitter buffer (M50b);
entities pushing each other; riding and attaching; entities travelling between worlds;
new brains and AI (the navigation and AI tier); scripted behaviours (M52); block entities
(M48 has them; they are not entities); any new kind in the base pack.

**Tests (M50):**

- `common/game/collide_test.odin`: `test_collide_matches_sweep`: 10 000 random boxes and deltas
  (seeded `base.Rng`) in a random field of M48's shapes: `collide_move` with step 0 gives
  bit-identical moves to the copied `sweep` per axis; step-up climbs a slab (0.5) with
  `step 0.6`, not a full block; `cast_box` finds the face a fast box hits that the
  start-and-end test misses (a 0.3 box at 32 b/s through a one-block wall).
- `common/game/archetype_test.odin`: spawn, add, remove and despawn keep every component value
  with its entity across moves between archetypes; deferred commands apply in issue order;
  a query sees archetypes in creation order and rows in order; 100 000 random operations
  against a reference model agree; committed bytes after a second identical churn equal
  the first's.
- `common/game/spatial_test.odin`: every query against brute force over 2 000 random entries,
  results equal and ascending; re-bucketing at chunk borders; `nearest` ties by id; insert
  order does not change any result.
- Unchanged in their assertions and passing: `server/entity_test.odin`,
  `sheep_test.odin`, `breeding_test.odin`, `items_test.odin`, `spawn_test.odin`,
  `health_test.odin`, `ledger_test.odin`, `commands_world_test.odin`,
  `determinism_test.odin` (side by side, perturbations named with the new paths). A test

- `server/entity_store_test.odin`:
  - `test_pack_kind`: a test pack kind `sim_test:cube` (box 0.5 0.5, physics walker,

  - `test_entities_unload_with_chunks`: sheep and a stack in a chunk the player walks away

  - `test_entities_saved_in_regions`: entities in unedited chunks saved and loaded; an
