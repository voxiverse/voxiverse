# M50e: entity framework v2, part two (kinds as data, components, systems, players as entities, the spatial service everywhere)

**Why.** Split from M50 (2026-10-30, #85). M50 built the libraries (collision, the archetype
store, the spatial query service) with no change to the game. This row moves every entity
onto them: kinds become pack data, the fixed `Entity` struct becomes components, the
`switch` in `entities_tick` becomes systems, players become entities that the rest of the
server finds through the spatial service, and no loop over all entities or all clients is
left in the entity systems. Saving stays `entities.cfg` here (M50f moves it into the
regions).

**What this builds on:** M50 (`common/game/collide.odin`, `common/game/archetype.odin`,
`common/game/spatial.odin`, `cells_find`), M47 (the registry, `Content_Kind`, pack JSON,
`Pack_Error`), M49b's matchers, and today's entity code as surveyed in [M50](M50.md)
(`server/entities.odin`, `server/items.odin`, `server/weapons.odin`, `server/rewind.odin`,
`server/spawn.odin`, `common/game/entity.odin`, `client/players.odin`). **No pack `entity`
definitions exist** (checked 2026-10-30, #85: M47 made none; the registry has block entities
only), so this row adds the registry kind. The session first checks M50 as built and corrects
this spec in the same commit.

## Design (M50e)

### Kinds from packs

- A new registry kind `entity` (`Content_Kind.Entity`, files in `data/entities/*.json`, M47's
  rules for ids, load order, overrides and errors). `game.Entity_Kind` (the enum) is replaced
  by `Kind_Id :: distinct u16` (the registry index + 1; 0 is "none"), synced by M47's pack
  hash on joining; `game.ENTITY_INFO` by the registry's `kinds: []Kind_Info`.
- The base pack's `assets/packs/voxiverse/data/entities/animals.json` (today's numbers):

  ```json
  {
    "sheep": {
      "box": [0.8, 0.9],
      "health": 4,
      "saved": true, "summonable": true, "hittable": true,
      "physics": "walker",
      "walker": {"walk_speed": 1.4, "run_speed": 4.2, "jump": 1.2, "step": 0},
      "brain": "grazer",
      "with": ["wool", "genes", "breeding"],
      "looks": ["shorn", "lamb", "black", "spotted", "in_love"],
      "model": "sheep",
      "spawn": {"on": "voxiverse:grass", "day": [0.27, 0.73], "every": 60, "chance": 0.5,
                "cap": 6, "within": 48, "distance": [16, 40], "group": [1, 3]}
    }
  }
  ```

  and `data/entities/engine.json`: `rocket` (box 0.3 0.3, health 1, physics `projectile`,
  `"projectile": {"speed": 32, "gravity": 3, "life": 6, "explode": 4}`, model `rocket`),
  `item` (box 0.25 0.25, health 1, saved, physics `item`, `"item": {"pickup_delay": 0.5,
  "owner_delay": 2, "range": 1.5, "merge": 1.0, "life": 300, "throw": 9}`, model `item`),
  `player` (box 0.6 1.8, physics `none`, not saved, model `player`). The `ROCKET_*` and
  `ITEM_*` constants go; `ITEM_THROW` is the item kind's `throw`.
- Fields, each checked at load (a `Pack_Error` with file, line, column and the fix):
  - `box` [width, height], each 0.1..4.
  - `physics`: `walker` (`body_step`: wish, jump, `collide_move` with the kind's `step`),
    `item` (no wish, horizontal velocity zeroed on the ground), `projectile` (`cast_box`
    against blocks, `spatial_cast` against hittable entities) or `none`. Each has its block
    of numbers, required with it and refused without it. The set of physics, brains and
    models is an engine enum that later rows extend (M50c adds `structure`).
  - `brain`: `grazer` (today's sheep: `think`, `steer`, grazing, fleeing, mating, today's
    constants) or `none`; `grazer` requires `walker`. New brains are engine code until
    scripts (M52).
  - `with`: optional components (`wool`, `genes`, `breeding`).
  - `looks`: up to 16 names the client draws by, each computed by the engine from components:
    `shorn` (Wool), `lamb` and `in_love` (Breeding), `black` and `spotted` (Genes); a look
    the kind cannot compute is refused (`black` without `genes`). `game.Sheep_Flags` goes.
  - `fields`: up to 8 `{"name": {"type": "u8"|"u16", "min": n, "max": n}}` in the `Fields`
    component (16 bytes), saved, not replicated (scripts read them in M52).
  - `model`: `sheep`, `rocket`, `item`, `player`, or `{"box": [r, g, b]}` (a box the kind's
    size: a pack kind is drawn with no client code).
  - `spawn` (natural spawning, today's rule and draws): every `every` ticks, by day between
    the two `day` fractions, per playing client in client order: the count of this kind's
    entities within `within` blocks horizontally (`spatial_cylinder`) against `cap`; the
    `chance` draw (`rng_f32 > chance` skips); angle; distance in `distance`; the column top;
    the `on` matcher (M49b's); `group` size (`rng_int_range(lo, hi + 1)`); the ±1.5 jitter;
    `standable`. Several spawning kinds run in registry order. The cap counts every entity
    near the player, as today (`spatial_count` with no kind filter and `none = {Player}`: player entities are new and were never counted), so sheep spawn exactly
    as before; whether a cap should count only its own kind is a game-design question for
    the owner (open question 1), not decided here. `Config.no_sheep` becomes
    `no_natural_spawns` (every kind).
  - `saved`, `summonable`, `hittable` as today's `Entity_Info`.

### Components (`common/game/components.odin` for the shared ones; the server registers its own)

| Component | Fields | Who has it |
|---|---|---|
| `Transform` | `position: [3]f64` (bottom centre), `yaw, pitch: f32` | every entity |
| `Physics` | `velocity: [3]f32, on_ground: bool` | physics `walker`, `item`, `projectile` (named so `Body` is free for M50c) |
| `Health` | `health: i32` | every kind (today's `health`) |
| `Age` | `ticks: i32` | every entity |
| `Brain` | today's `Brain` (`server/entities.odin`: state, timer, path, step, goal, look_at, from, hurt, stuck); registered by the server (it holds `Path`) | brain `grazer` |
| `Wool` | `shorn: bool` | `with wool` |
| `Genes` | `genes: game.Genes` | `with genes` |
| `Breeding` | `growth, love, wait: i32` | `with breeding` |
| `Stack` | `stack: game.Stack` | physics `item` |
| `Owner` | `client: i16` (-1 none) | projectiles, dropped stacks |
| `Fields` | `data: [16]u8` | kinds declaring `fields` |
| `Player_Link` | `client: u16` | the player kind |
| `Natural` | (tag) | spawned by `spawn` (may despawn) |
| `Origin` | `action: u32` (M45's action that spawned it: today's `Entity.action`) | every entity spawned with an action |
| `Hurt_By` | `action: u32, entity: Entity_Id, cause: u8` (the last damage, kept 10 s) | kinds with `hittable` |
| `Frozen` | (tag) | its chunk, or the one below, is not ready |

`Kind` is not a component: the store's slot keeps `kind: Kind_Id` beside the id (every entity
has exactly one). `World.entities` becomes `Entity_World {store: Entity_Store, spatial:
Spatial, rng: base.Rng, budget: int}`; `MAX_ENTITIES` becomes 4 096 a world (the full arena
still refuses with a notice, `test_full_arena_and_one_blast`).

### Systems and their order (`server/entity_systems.odin`; `entities_tick(w)` runs them, each followed by `store_apply`)

0. `player_entity_sync` (in the per-client loop after `simulate_player`, before the
   systems): each playing client's `Transform` from `c.player` (players are spawned as
   `voxiverse:player` entities on arriving in a world and despawned on leaving it). The
   player's movement stays `game.player_step` on `Client.player` (prediction untouched); the
   entity is how everything else finds players. A system that moves a player writes
   `c.player` (through `Player_Link`) and this sync runs again before the next system reads
   it.
1. `spawn_natural` (kinds with `spawn`).
2. `despawn_far`: `Natural` entities with no player within `DESPAWN_DISTANCE` 80 (one
   `spatial_nearest` with `all = {Player}`).
3. `life`: `Age` +1; breeding clocks (`sheep_life`); stacks past `life` expire (ledger
   `.Expire`); projectiles past `life` go off where they are.
4. `brains`: `grazer` think and steer (the A* budget as today), skipping `Frozen`.
5. `motion`: `walker` and `item` bodies through `collide_move`; `projectile`s through
   `cast_box` against blocks and `spatial_cast` against hittable entities (players included,
   the owner's 10-tick grace kept); hits become blasts.
6. `items`: merging (every 10 ticks of an item's age, with later ids only: today's "those
   after it in the list") and pickup (players within `range`, `spatial_sphere`).
7. `freeze`: `Frozen` added or removed where `chunk_ready` changed (M50f makes it the
   handoff).
8. blasts: `explode` as today, its two loops one `spatial_sphere` each.

Moved onto the spatial service (each a query, no loop over all entities or clients):
`entities_put` (entities within `ENTITY_VIEW` of the client, `spatial_cylinder`, nearest
first, ids ascending among equals, at most `MAX_KNOWN_ENTITIES`), merging, pickup, rocket
hits, `explode`, the spawn cap, `despawn_far`, `mate_for`, `nearest_player`, `anyone_within`,
`/kill`'s radius, `/summon`'s cap (`store_count`), a chest's restore
(`block_entities.odin`: `spatial_sphere` with `RESTORE_REACH`, `kind` item), hitscan
(`weapons.odin`: `spatial_cast`, with lag compensation's frame), the rewind frame
(`rewind.odin`: one query over `Hittable`), and on the client `entity_aimed`. Whole-world
walks that stay walks, over store queries in row order: the ledger's sums, the journal's
lowest live `Origin` action, the hash, saving (`entities.cfg`, M50f moves it), `perturb`.

### What else moves

`server/entities.odin` splits into `server/entity_systems.odin` (the systems),
`server/entity_kinds.odin` (`sheep_use` and the physics and brain procedures, looked up by
the kind's enums), and `server/entity_store.odin` (spawn, despawn, find by id, the hash
section). `summon`, `/kill`, `Use_Entity`, `Attack` and `fire` take kinds by registry id
(`/summon voxiverse:sheep`; a bare `sheep` resolves in `voxiverse` as other commands do).
`entities.cfg` is written from the store and read back into it, the kind by registry id and
the fields as today plus a pack kind's `Fields` as hex (M50f replaces the file).

The wire (M39): `Entity_Record.kind` becomes `kind: u16` (a `Kind_Id`; the kind's `check`
refuses an id the registry does not have); `Entity_Motion.flags` becomes `looks: u16` (bit
i: the kind's i-th look). `PROTOCOL_VERSION` goes up; the dissector schema is regenerated
(`build schema`).

The client: `Other_Entity.kind` (`client/players.odin`) becomes a `Kind_Id`;
`entities_draw` switches on the kind's model (a `box` model drawn in its colour at its
size); `s.entities` becomes a fixed map of capacity `MAX_KNOWN_ENTITIES`
(`base.map_make_fixed`), so its memory is flat too.

**Determinism.** The `Entities` hash section becomes `store_hash` (M50) then `entities.rng`.
`perturb`'s `Entity_Yaw` takes the first row of the first archetype with a `Transform`. The
roots change once, in one commit whose message says why (row order replaces list order); `build determinism` and the side-by-side run pass after it.

## The order of the steps (M50e)

1. The `entity` registry kind, `Kind_Info`, the base pack's four kinds, the load checks and
   their tests (nothing uses them yet).
2. The components, `Entity_World`, the store and spatial service in the world; spawning and
   despawning through them; `entity_find` on `store_find`.
3. The systems; sheep, items and rockets moved; players as entities; the moved loops.
4. The wire and the client; the roots re-pinned (one commit).
5. The benchmark scene.

If the session must split anyway: no further split (this row is already a part); it works on
to the exit check.

## Left out (M50e)

Persistence in regions, handoff and unloading entities with chunks (M50f); quantized motion,
rates and the jitter buffer (M50b); entities pushing each other; riding (M50c); entities
travelling between worlds; new brains (scripts, M52); block entities (M48: not entities); any
new kind in the base pack.

  `breeding_test.odin`, `items_test.odin`, `spawn_test.odin`, `health_test.odin`,

  RNG stream and moves only because the order of entities changed is derived again, and the
  report names it (as M38 did); its assertion's meaning does not change.
- `server/entity_systems_test.odin`:
  - `test_pack_kind`: a test pack kind `sim_test:cube` (box 0.5 0.5, physics walker with
    step 0.6, brain none, model `{"box": [200, 40, 40]}`, a field `mood` u8 0..10) summoned
    by id falls, lands, climbs a slab, is replicated with its kind, and is written to and
    read from `entities.cfg` with its field.
  - `test_systems_scale`: the store counts the rows its queries yield and the spatial
    service the entries its queries examine (`Entity_World.visited`, test builds and the
    bench). With 500 and then 2 000 sheep spread at the same density, the rows and entries
    visited in a tick of `entities_tick` grow at most 4.5 times (linear, not quadratic: a
    loop over everyone inside a per-entity system would grow 16 times).
  - `test_spatial_matches_store`: after 600 ticks of 300 sheep, items and rockets with
    players walking, every spatial entry's box equals its entity's `Transform` and kind box,
    and every entity has exactly one entry.
  - `test_players_are_entities`: a player arriving, travelling through a gate and leaving
    is spawned, moved to the new world's store and despawned; their entity's `Transform`
    equals `c.player.position` after every tick.
- `client/world_test.odin`: a `box`-model kind is drawn at its size in its colour (the
  entity draw list, not pixels).
