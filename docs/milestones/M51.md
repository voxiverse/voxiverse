# M51: the script VM (split: M51a language and core VM, M51b collector, libraries and host API, M51c snapshots and fuzzers)

The language agents write gameplay in (the foundation arc's "Script language" decision): our
own Lua-like language, compiled to bytecode and run by a register VM in Odin, with metering,
an incremental collector and a heap that snapshots to bytes. M52 (capabilities, quotas,
events) and M53 (the declarative layer) build on it; nothing here knows about worlds, packs,
the journal or the tick. One VM is one script context: its own heap, globals and limits;
destroying it releases its memory in one call.

This is too large for one sitting (a compiler, a VM, a collector, libraries, snapshots and
fuzzers: some 15 000 lines with tests), so it is three milestones, each with its own exit
check, built in order. Each is one session; a session that cannot finish its own part splits
it once, as usual. The shared design comes first; each part's section then says what it
builds.

**Nomenclature.** A *script* is a `.vxs` source; compiling one gives a *module* (its top-level
function). The word "chunk" (Lua's) is never used: a chunk is 16³ blocks. A *run* is one host
call into the VM until it returns, errors, faults, suspends or yields; a *slice* is the
instruction budget one `call` or `resume` gets. *Native* is a function written in Odin.

**The language.** Lua 5.4 as models know it, with these differences (all of them, written
also into `docs/script.md`, M51a):

- Kept: `nil`, booleans, 64-bit integers and 64-bit floats as subtypes of number, strings,
  tables, functions with closures and upvalues, varargs (`...`, `select`, `table.pack`,
  `table.unpack`), multiple assignment and multiple returns, numeric and generic `for`,
  `while`, `repeat ... until` (the body's locals visible in `until`), `break`, methods
  (`a:b()`), integer division `//`, bitwise operators on integers (`& | ~ << >> ~x`), string
  escapes including `\z`, `\x`, `\ddd`, `\u{...}` (at most U+10FFFF), long strings and
  comments, coroutines (M51b), `pcall`, `xpcall`, `error` with any value.
- Added (from Luau, which models also write): `continue` (a reserved word; jumps to the
  loop's next iteration); compound assignment `+= -= *= /= //= %= ^= ..=` (the target's
  table and key are evaluated once); optional type annotations (below).
- Dropped, each with a compile error that says what to write instead: `goto` and labels
  ("goto is not supported: use 'continue' or 'break', or a flag variable"), the attributes
  `<const>` and `<close>`, hex float literals, `_ENV` as a name (globals are the module's
  environment table, set by the host), integer literals with underscores are not added.
- **No implicit string-number coercion in arithmetic**: `"10" + 1` is an error ("attempt to
  perform arithmetic on a string value (constant '10'); hint: convert it with tonumber()
  first"). Concatenation still formats numbers (`"x=" .. 3` is `"x=3"`).
- No ambient clock, randomness, I/O or code loading: no `io`, `os`, `package`, `require`,
  `load`, `loadstring`, `dofile`, `string.dump`, `math.random`, `math.randomseed`,
  `collectgarbage` beyond `collectgarbage("count")`, `debug` beyond `debug.traceback`.
  Calling one gives "'math.random' is not available in scripts: randomness comes from the
  world API" (a fixed table of these names and messages, so a model learns where to look).
  M52 adds world randomness, time in ticks, `require` within a pack.
- Deterministic everywhere: `pairs` and `next` visit the array part in index order, then the
  hash part in insertion order (below); `tostring` of a table, function or coroutine prints a
  per-VM sequence number (`table: 0x0000002a`), never an address; string comparison is
  bytewise (no locale); NaN results are canonical (`0x7FF8_0000_0000_0000`, so a NaN's bits are
  the same on x64 and arm64); `table.sort` is a stable merge sort (Lua's is an unstable
  quicksort: same results for strict orders, never "invalid order function").
- Library functions are raw where Lua's would call a metamethod from Odin: `ipairs`,
  `table.insert`, `table.remove`, `table.concat`, `table.unpack`, `table.move` and `#` inside
  them ignore `__index`, `__newindex` and `__len`. (Natives never call script code: see the
  host API.) `tostring`, `print` and `string.format`'s `%s` do honour `__tostring`, because
  they are written in the prelude.

*Grammar* (EBNF; `{x}` zero or more, `[x]` optional; terminals quoted):

```
module      = block EOF
block       = { stat } [ retstat ]
stat        = ';'
            | varlist '=' explist
            | var compoundop exp
            | functioncall
            | 'break' | 'continue'
            | 'do' block 'end'
            | 'while' exp 'do' block 'end'
            | 'repeat' block 'until' exp
            | 'if' exp 'then' block { 'elseif' exp 'then' block } [ 'else' block ] 'end'
            | 'for' binding '=' exp ',' exp [ ',' exp ] 'do' block 'end'
            | 'for' bindlist 'in' explist 'do' block 'end'
            | 'function' funcname funcbody
            | 'local' 'function' Name funcbody
            | 'local' bindlist [ '=' explist ]
            | 'type' Name '=' type              (* 'type' is a keyword only here *)
retstat     = 'return' [ explist ] [ ';' ]
compoundop  = '+=' | '-=' | '*=' | '/=' | '//=' | '%=' | '^=' | '..='
binding     = Name [ ':' type ]
bindlist    = binding { ',' binding }
funcname    = Name { '.' Name } [ ':' Name ]
varlist     = var { ',' var }
var         = Name | prefixexp '[' exp ']' | prefixexp '.' Name
prefixexp   = var | functioncall | '(' exp ')'
functioncall= prefixexp args | prefixexp ':' Name args
args        = '(' [ explist ] ')' | tablecons | String
explist     = exp { ',' exp }
exp         = 'nil' | 'false' | 'true' | Number | String | '...' | 'function' funcbody
            | prefixexp | tablecons | exp binop exp | unop exp
funcbody    = '(' [ parlist ] ')' [ ':' rettype ] block 'end'
parlist     = binding { ',' binding } [ ',' '...' [ ':' type ] ] | '...' [ ':' type ]
tablecons   = '{' [ field { fieldsep field } [ fieldsep ] ] '}'
field       = '[' exp ']' '=' exp | Name '=' exp | exp
fieldsep    = ',' | ';'
binop       = 'or' | 'and' | '<' | '>' | '<=' | '>=' | '~=' | '==' | '|' | '~' | '&'
            | '<<' | '>>' | '..' | '+' | '-' | '*' | '/' | '//' | '%' | '^'
unop        = '-' | 'not' | '#' | '~'

type        = optional { '|' optional }
optional    = simpletype [ '?' ]
simpletype  = 'nil' | Name [ '.' Name ] | '{' typebody '}' | '(' [ typelist ] ')' '->' rettype
            | '(' type ')'
typebody    = type                                   (* array: {T} *)
            | '[' type ']' ':' type                  (* map: {[K]: V} *)
            | Name ':' type { ',' Name ':' type } [ ',' ]   (* record *)
rettype     = type | '(' [ typelist ] ')'
typelist    = type { ',' type }
```

Precedence, low to high, as Lua 5.4: `or`; `and`; comparisons; `|`; `~`; `&`; shifts; `..`
(right); `+ -`; `* / // %`; unary; `^` (right). Reserved words: `and break continue do else
elseif end false for function goto if in local nil not or repeat return then true until
while` (`goto` reserved so it can be refused with its message). `type` is contextual (a
statement starting `type Name =`), so `type(x)` still calls the function. Type names in
annotations (`any nil boolean integer float number string table function thread handle` and
aliases) are **parsed into the AST and erased; nothing checks them in M51** (M54's static
validator may). An annotation never changes what code does.

*Numbers* (Lua 5.4's rules unless stated): integer literals that overflow i64 become floats;
hex integer literals wrap modulo 2^64. `+ - *` and unary `-` on two integers wrap (two's
complement); with a float operand they are float operations. `/` and `^` are always float.
`//` on integers is floor division, `%` is floor modulo (result has the divisor's sign);
both raise "attempt to perform 'n//0'" / "'n%%0'" for an integer zero divisor;
`math.mininteger // -1` is `math.mininteger`. Float `//` is `floor(a/b)`, float `%` is
`m := math.mod(a, b); if m != 0 && (m < 0) != (b < 0) {m += b}`. `^` is `base.pow` (below).
Comparisons between integers and floats are exact (Lua's `LTnum` logic: no rounding through
float); `1 == 1.0`. Bitwise operators accept floats with an exact integer value, else "number
has no integer representation"; shifts are logical, a shift by 64 or more gives 0, a negative
shift shifts the other way. Float to integer conversions (`math.tointeger`, `math.floor`,
`for` loops, table keys, bitwise operands) check range first (determinism rule 6). A float
table key with an integer value is that integer (`t[1.0]` is `t[1]`, `-0.0` is `0`); a NaN
key is an error, as is a `nil` key on assignment. Integer `for` loops precompute the
iteration count (no overflow); a float in any of the three makes a float loop; a zero step
is an error. Number formatting: integers `%d`; floats `%.14g`, then `.0` appended when the
result is only digits and a sign (`3.0`, `-0.0`, `1e+15`, `inf`, `-inf`, `nan`).

*`base.pow`.* `^` and `math.pow`-like uses need a deterministic power. M51a adds
`pow_f64 :: proc "contextless" (x, y: f64) -> f64` (and the `pow` group) to
`base/numbers.odin`: a port of FreeBSD's `e_pow.c` (the family `exp` came from), tested on
exact cases (`2^k` for k in -1074..1023, `10^k` for k in 0..22, `x^0.5` against `sqrt`, the
special cases of C99 Annex F) and listed in `docs/determinism.md` rule 2. Other math:
`sin`, `cos`, `exp` from base; `tan` as `sin/cos` from `base.sincos`; `sqrt`, `floor`,
`ceil`, `abs`, `mod`, `ln`, `asin`, `acos`, `atan2` from `core:math` (the allowed list).

**Values.** A tagged union in 16 bytes, not NaN-boxing (full 64-bit integers do not fit in a
NaN box, and a tag byte is cheaper to get right):

```odin
Tag :: enum u8 {Nil, Bool, Int, Float, Handle, String, Table, Function, Thread}
Ref :: distinct u32 // byte offset of an object in the VM's heap; 0 is none
Value :: struct {
	bits:  u64, // i64, f64 bits, bool (0/1), handle bits, or a Ref in the low 32
	tag:   Tag,
	_pad0: u8,
	kind:  u16, // a handle's kind; 0 otherwise
	_pad1: u32,
}
#assert(size_of(Value) == 16)
```

Tags from `.String` up carry a `Ref`. Padding is always zero (every constructor writes the
whole struct), so values hash and snapshot as bytes. Falsy: `nil` and `false`. Strings are
immutable and **all interned**: equal strings are the same `Ref`, so string equality and
table key comparison are one compare. Functions (script closures and native closures) share
`.Function`; the object header tells them apart. `.Handle` (M51b) is an opaque 64-bit id with
a host-defined kind: no heap object, compared by bits, given a metatable per kind by the host
(M52's entities, players, positions).

**The heap.** Each VM reserves one region of `limits.memory` bytes with
`core:mem/virtual.reserve` and commits it in 64 KiB steps as it grows; `vm_destroy` releases
it with one `virtual.release`. Every heap object lives in it and refers to others by `Ref`
(an offset), so the heap is position independent: a snapshot is a copy of its bytes. The
region never moves, so a `^T` made from a `Ref` stays valid while the object lives; the
only thing that moves is a thread's stack buffer when it grows (see the dispatch loop).

- A block is a `Header` (8 bytes: `size: u32` in bytes including the header, a multiple of
  16; `kind: Obj_Kind` u8; `mark: u8` colour; `flags: u8`; `_: u8`) and its payload, at a
  16-byte aligned offset; offset 0..15 is a reserved header so no object is at `Ref` 0.
  `Obj_Kind :: enum u8 {Free, String, Table, Closure, Native_Closure, Upvalue, Proto,
  Thread, Values, Bytes}`. `Values` is a buffer of `Value`s that its single owner traverses;
  `Bytes` holds no references (code, line tables, string bytes are inline in `String`).
- Allocation is deterministic: the size is rounded up to 16 (minimum 16); sizes up to 512 come
  from 32 exact-size free lists (16, 32, ... 512), larger ones from power-of-two class lists
  searched upward, first fit in list order, the remainder (if at least 16) split off and
  pushed to its list; otherwise bump `top`. Free blocks are zeroed. Same operations, same
  offsets, on every OS.
- When an allocation finds no room (`top + size > limits.memory`): M51a raises the memory
  fault at once; from M51b the collector first finishes its cycle and runs one full cycle,
  then retries once.
- Allocation is charged to the meter: one instruction unit per 64 bytes, rounded up.
- `heap_free(vm, ref)` is used directly only for buffers their owner replaces (a table's grown
  array part, a stack that moved); everything else is freed by the sweep (M51b).

**Objects** (`object.odin`; each starts with `Header`; field order as listed, padding explicit):

- `String`: `len: u32`, `hash: u32`, then `len` bytes and a zero byte. Hash: 64-bit FNV-1a over
  the bytes from `offset_basis ~ vm.seed`, then splitmix64's finalizer, low 32 bits.
- `Table`: `meta: Ref`, `arr: Ref` (`Values`), `arr_len, arr_cap: u32`, `entries: Ref`
  (`Values`, two per entry: key, value, in insertion order), `entries_len, entries_cap,
  live: u32`, `index: Ref` (`Bytes`: u32 slots, entry number + 1, 0 empty, power-of-two
  count, linear probing), `index_mask: u32`, `mm_absent: u16` (bit per metamethod known
  absent, cleared on any key insertion into this table), `id: u32` (the `tostring` number,
  given on first use from `vm.next_id`), `gclist: Ref`.
- `Proto`: `code: Ref` (`Bytes` of u32 instructions), `consts: Ref` (`Values`), `protos:
  Ref` (`Values` of nested protos), `upvals: Ref` (`Bytes`: `instack: u8, index: u8,
  name_const: u32` each), `lines: Ref` (`Bytes`: `line: u32, col: u16` per instruction),
  `locals: Ref` (`Bytes`: name const, start pc, end pc, register), `source, name: Ref`
  (strings), `line_defined, last_line: u32`, `num_params, is_vararg, max_stack: u8`,
  `gclist: Ref`. Immutable once made.
- `Closure`: `proto: Ref`, `env: Ref` (the globals table it reads and writes), `id: u32`,
  `nup: u16`, then `nup` upvalue `Ref`s.
- `Native_Closure`: `native: u32` (index into the VM's native table), `intrinsic: Intrinsic`
  (u8: `None, Pcall, Xpcall, Resume, Yield, Wrap`), `id: u32`, `nup: u16`, then `nup` values.
- `Upvalue`: `value: Value` (when closed), `thread: Ref`, `slot: u32`, `open: bool`,
  `next_open: Ref` (the thread's open list, sorted by slot, highest first).
- `Thread`: `stack: Ref` (`Values`), `stack_cap, top: u32`, `frames: Ref` (`Bytes` of
  `Frame`), `frame_count, frame_cap: u32`, `open_upvals: Ref`, `status: Thread_Status`
  (`Suspended, Running, Normal, Dead`), `resumer: Ref`, `id: u32`, `gclist: Ref`.
- `Frame` (plain integers, no `Ref`: the function is its stack slot): `func, base, top, pc:
  u32`, `nresults: i16` (-1 multiple), `cont: Cont` (u8: what finishes the caller's
  instruction when this frame returns: `None, Host, Store, Compare, Discard, Concat, Pcall,
  Xpcall, Xpcall_Handler, Resume`), `flags: u8` (`Protected`, `Native`, `Tail`), `nvarargs:
  u16`, `cont_arg: u32`.

**Tables.** An array part (`arr`, keys 1..`arr_len`) and an ordered hash part. Setting key
`arr_len + 1` appends to the array part and then moves any following integer keys out of the
hash part (so the hash part never holds `arr_len + 1`); setting `t[arr_len] = nil` shrinks
`arr_len` past trailing nils; a nil inside the array part is a hole. `#t` is `arr_len`, which
is always a border. The hash part keeps entries in insertion order: setting a key to nil
leaves its entry dead in place (so `next` can continue past it during a traversal), setting a
dead key again revives it in place, and when `entries` is full it is compacted (dead entries
dropped, order kept) if a quarter or more are dead, else doubled, and the index rebuilt.
`next` visits the array part (skipping holes), then live entries in order; a key that is not
in the table is "invalid key to 'next'". Each probe after the first costs one instruction
unit, so a crafted set of colliding keys only spends its own budget. `docs/script.md`
promises only: pairs order is deterministic, and sequences come first in index order.

**Metatables-lite.** Tables have metatables (`setmetatable`, `getmetatable`); strings share
one whose `__index` is the `string` table; handle kinds have one each (host-set, M51b); other
types none. The metamethods, all and only: `__index` (table or function; chains of tables up
to 100 deep, "'__index' chain too long; possible loop"), `__newindex` (table or function),
`__call`, `__tostring`, `__len`, `__eq` (both operands tables, or handles of one kind, not
raw-equal), `__lt`, `__le` (no `__le` from `not __lt`), `__unm`, `__add`, `__sub`, `__mul`,
`__div`, `__mod`, `__idiv`, `__pow`, `__concat`, `__metatable` (a protected metatable:
`getmetatable` returns the field, `setmetatable` refuses). Not supported: `__gc`, `__mode`
(weak tables), `__close`, `__pairs`, `__name`, bitwise metamethods. A metamethod runs as an
ordinary script frame with a continuation (`Frame.cont`) that finishes the interrupted
instruction when it returns (Lua 5.4's `luaV_finishOp`), so a metamethod can be suspended at
budget or yield like any code.

**Bytecode.** 32-bit instructions in Lua 5.4's layout (`lopcodes.h` is the reference the
implementer can read): `iABC` op(7) A(8) k(1) B(8) C(8); `iABx` op(7) A(8) Bx(17); `iAsBx`
(sBx = Bx - 65535); `iAx` op(7) Ax(25); `isJ` op(7) sJ(25, excess 2^24 - 1); sC = C - 127.
`R[x]` is a register, `K[x]` a constant, `RK(C)` is `K[C]` when k is set else `R[C]`,
`Up[x]` an upvalue, `Env` the closure's environment. The full list (`Op :: enum u8`, in this
order):

```
MOVE A B          R[A] := R[B]
LOADI A sBx       R[A] := sBx (integer)
LOADF A sBx       R[A] := sBx (float)
LOADK A Bx        R[A] := K[Bx]
LOADKX A          R[A] := K[EXTRAARG]
LOADFALSE A       R[A] := false
LFALSESKIP A      R[A] := false; pc++
LOADTRUE A        R[A] := true
LOADNIL A B       R[A .. A+B] := nil
GETUPVAL A B      R[A] := Up[B]
SETUPVAL A B      Up[B] := R[A]
GETGLOBAL A Bx    R[A] := Env[K[Bx]]              (K[Bx] a string)
SETGLOBAL A Bx    Env[K[Bx]] := R[A]
GETTABLE A B C    R[A] := R[B][R[C]]
GETI A B C        R[A] := R[B][C]
GETFIELD A B C    R[A] := R[B][K[C]]              (K[C] a string)
SETTABLE A B C k  R[A][R[B]] := RK(C)
SETI A B C k      R[A][B] := RK(C)
SETFIELD A B C k  R[A][K[B]] := RK(C)
NEWTABLE A B C k  R[A] := {} (B: hash size log2 + 1; C: array size, + EXTRAARG*256 if k)
SELF A B C k      R[A+1] := R[B]; R[A] := R[B][RK(C)]
ADDI A B sC       R[A] := R[B] + sC
ADDK SUBK MULK MODK POWK DIVK IDIVK  A B C    R[A] := R[B] op K[C]   (K[C] a number)
BANDK BORK BXORK  A B C                       R[A] := R[B] op K[C]   (K[C] an integer)
SHRI A B sC       R[A] := R[B] >> sC
SHLI A B sC       R[A] := sC << R[B]
ADD SUB MUL MOD POW DIV IDIV BAND BOR BXOR SHL SHR  A B C   R[A] := R[B] op R[C]
UNM BNOT NOT LEN  A B                         R[A] := op R[B]
CONCAT A B        R[A] := R[A] .. ... .. R[A+B-1]
CLOSE A           close upvalues >= R[A]
JMP sJ            pc += sJ
EQ LT LE A B k    if ((R[A] op R[B]) ~= k) then pc++
EQK A B k         if ((R[A] == K[B]) ~= k) then pc++
EQI LTI LEI GTI GEI A sB k   if ((R[A] op sB) ~= k) then pc++   (C: 1 if sB stands for a float)
TEST A k          if (not R[A] == k) then pc++
TESTSET A B k     if (not R[B] == k) then pc++ else R[A] := R[B]
CALL A B C        R[A .. A+C-2] := R[A](R[A+1 .. A+B-1])   (B 0: to top; C 0: all results)
TAILCALL A B C    return R[A](R[A+1 .. A+B-1])
RETURN A B        return R[A .. A+B-2]                      (B 0: to top)
RETURN0           return
RETURN1 A         return R[A]
FORLOOP A Bx      step the counters; if the loop goes on, pc -= Bx
FORPREP A Bx      check and prepare the counters; if it never runs, pc += Bx + 1
TFORPREP A Bx     pc += Bx
TFORCALL A C      R[A+3 .. A+2+C] := R[A](R[A+1], R[A+2])
TFORLOOP A Bx     if R[A+3] ~= nil then { R[A+2] := R[A+3]; pc -= Bx }
SETLIST A B C k   R[A][C+i] := R[A+i], 1 <= i <= B (B 0: to top; k: C += EXTRAARG*256)
CLOSURE A Bx      R[A] := closure(protos[Bx])
VARARG A C        R[A .. A+C-2] := vararg (C 0: all)
VARARGPREP A      move the fixed parameters above the varargs
EXTRAARG Ax       operand for the previous instruction
```

Differences from Lua 5.4 on purpose: no `MMBIN*` (an arithmetic instruction falls back to its
metamethod itself, with `Cont.Store`); globals are `GETGLOBAL`/`SETGLOBAL` on the closure's
`env` instead of `_ENV` upvalue indexing; no `TBC`; the generic `for` has three hidden slots
(no closing value). `RETURN` always closes open upvalues at or above its base (a check of
the thread's open list head, no flag). `opcodes.odin` has, per op, its format and operand
kinds (register, constant, upvalue, proto, jump, immediate), which the disassembler and the
verifier (M51c) read from one table.

**The compiler.** The parser builds an AST in a scratch `virtual.Arena` (freed when the
compile ends); the compiler walks it once per function and emits code. Structure as Lua
5.4's `lcode.c`/`lparser.c`, which the implementer may read for reference: an `Exp_Desc`
with kinds `Void, Nil, True, False, K, Int, Float, Str, Nonreloc (a register), Local,
Upval, Global, Indexed, Indexed_Int, Indexed_Str, Indexed_Up?` (no: globals use `Global`),
`Call, Vararg, Jmp (a comparison), Reloc (an instruction whose A is patched)`, with
true/false jump lists patched by `patch_list`; `exp_to_reg`, `exp_to_any_reg`,
`exp_to_rk`. Registers: locals occupy consecutive registers in declaration order; temporaries
are a stack above them (`free_reg`), released in reverse; `max_stack` is the high water.
Limits, each a compile error naming the limit and a fix: 255 registers, 200 locals and 255
upvalues per function, 200 levels of syntactic nesting (blocks, expressions, calls: the
parser's own recursion is bounded by this), 2^25 constants (`LOADKX` beyond 2^17), a jump
range of 2^24, 1 MiB of source. Upvalues are resolved at compile time as Lua does
(`instack`, index); a block whose locals are captured emits `CLOSE` on every exit (end,
`break`, `continue`); loop variables are fresh per iteration (closures capture each one).
Constant folding only of arithmetic on numeric literals, never when the result would be
NaN, -0, or a division by zero. Multiple assignment evaluates every right-hand expression
left to right, then assigns right to left (what Lua 5.4 does). `continue` in `repeat ...
until` is an error if a local declared after it in the body is used in the `until` ("continue
here would skip local 'x', which 'until' uses"). The compiler's output is `Proto` objects in
the heap, made at the end of the compile (constants interned then); a compile allocates
from the heap but never triggers a collection step.

**The dispatch loop** (`exec.odin`). One procedure, `execute(vm) -> Exec_Result`, a `for` loop
with a `switch` on the opcode, running the current thread's top frame until the run ends,
suspends or yields. It never recurses: a script call, a metamethod, `pcall` and coroutine
resume push frames (or switch thread) and continue the loop. The loop keeps `pc`, the
code slice and the frame's register slice in locals, and **reloads the register slice
after anything that can grow the stack** (a call, a native, a metamethod, a coroutine
switch, an allocation of stack space). Bounds checks stay on (no `#no_bounds_check` in M51;
the verifier of M51c makes it possible later). At the top of every iteration: `meter -= 1;
if meter < 0` save `pc` and return `Suspended`; every instruction boundary is a safe point,
because instructions are atomic and continuations are frames. Fast paths inline: integer
`ADD`/`ADDI`/`SUB`/comparisons, `GETFIELD`/`SETFIELD` on a table without a metatable,
`GETI`/`SETI` in the array part, `CALL` of a script closure, `FORLOOP` on integers.

**Calls.** Script-to-script calls push a `Frame`; arguments are adjusted (missing ones nil,
extra ones dropped or kept as varargs below the frame base, as Lua 5.4's `VARARGPREP`).
`TAILCALL` reuses the frame (tail calls do not count toward `call_depth`). Results are copied
to the function's slot and adjusted to `nresults`. A native call: the arguments are on the
stack, the native pushes its results on top, the VM moves them into place.

**Errors.** `error(v [, level])` raises any value; a string at level 1 or 2 gets `"source:line:
"` prepended (Lua's rule). On a raise, the VM finds the nearest frame flagged `Protected` in
the current thread below the host boundary; it closes upvalues above it, pops to it and
returns `false, v` (`pcall`), or first calls the `xpcall` handler in a frame with
`Cont.Xpcall_Handler` (an error inside the handler: "error in error handling"). If nothing
protects the raise, the run ends with `Error`, and the traceback is captured before
unwinding (the scan for a protected frame tells which case it is). A **fault** (instruction
limit, memory, call depth) is not catchable: it unwinds every frame of the run, through
`pcall` and coroutines, closes all upvalues and ends the run with `Error` of kind `.Limit`.
After an error or fault the VM is idle and usable: globals and everything reachable stay;
the run's frames are gone.

`Script_Error :: struct {kind: Error_Kind (.Syntax, .Runtime, .Limit), limit: Limit_Kind
(.None, .Instructions, .Memory, .Call_Depth), message: string, hint: string, source:
string, line, column: u32, traceback: []Trace_Frame, value: Value}`, its strings in an
allocator the host passes to `call`/`resume`/`compile`. `error_format(e, &b)` writes:

```
quests/intro.vxs:12:15: syntax error: 'do' expected after the 'while' condition, got 'then'
   12 |   while x < 10 then
      |                ^^^^
  hint: a while loop is written 'while <condition> do ... end'
```

```
quests/intro.vxs:30:9: runtime error: attempt to index a nil value (global 'playr')
   30 |   local h = playr.health
      |             ^^^^^
  hint: no global 'playr' exists; did you mean 'player'?
stack traceback:
  quests/intro.vxs:30: in function 'on_tick'
  quests/intro.vxs:41: in main module
```

Messages are Lua's where Lua has one (models know them), with the name description Lua's
`getobjname` gives (`local 'x'`, `global 'x'`, `field 'x'`, `upvalue 'x'`, `method 'x'`,
`constant 'x'`), found the same way: scanning the proto's code back from the failing
instruction for what loaded the register. Hints, always one line, for: a nil global or field
(the defined globals, or the table's string keys, within edit distance 2, sorted; "did you
mean"), a string in arithmetic (`tonumber`), calling a nil method (the keys of the
metatable's `__index` table, same rule), comparing different types, `n//0`, each library
argument error ("bad argument #2 to 'string.sub' (number expected, got string)"), every limit
fault (what the limit is and the usual fix: "use a loop or an explicit stack table instead of
deep recursion"). Syntax errors have a fixed table of common mistakes with their hints: `!=`
(use `~=`), `&&`/`||`/`!` (use `and`/`or`/`not`), `=` in a condition (use `==`), `else if`
leaving an `if` unclosed (named when the missing `end` is reported, with the `if`'s line),
`{` ... `}` as a block, `then`/`do` missing or swapped, `goto`, `<const>`, an unterminated
string or long string (with the line it began on), a malformed number, `function a.b()`
after `local`. The column is the token's (syntax) or the operator's, call's or index's
(runtime: each instruction carries the column of the AST node that made it). Only the first
syntax error is reported.

**Metering and limits.** `Limits` (in `Config`, per VM; snapshotted):

| Limit | Default | At the limit |
|---|---|---|
| `slice` (passed to each `call`/`resume`) | 100 000 instruction units (`DEFAULT_SLICE`) | the run **suspends**: state kept, `resume` continues exactly there |
| `run_instructions` (all slices of one run) | 10 000 000 (0: none) | **fault** `.Instructions` |
| `memory` (the heap region) | 16 MiB (256 KiB to 1 GiB) | full collection (M51b), then **fault** `.Memory` |
| `call_depth` (frames in a run, all threads) | 1 000 | **fault** `.Call_Depth` |
| `string_max` (any one string) | 1 MiB | runtime error "string too large" (catchable: nothing was made) |
| `output_max` (print output between drains) | 64 KiB | the rest dropped, counted, and one line `[output truncated: N bytes]` |
| pattern match steps (per call) | 1 000 000 | runtime error "pattern too complex" |

Units: one per instruction, one per extra hash probe, one per 64 bytes allocated, and what a
native declares (its `cost` and `charge` calls: string functions one per 64 bytes they read
or write, the pattern matcher one per 16 steps). A native runs to completion and may take
the meter below zero; the overshoot is bounded by the largest native (the string and pattern
caps) and the next instruction boundary suspends. 100 000 units is about a millisecond:
M52 sets the real per-script, per-tick numbers; these are defaults for tests and tools.

**The host API** (`vm.odin`, `api.odin`; everything takes `^VM`; a VM is used by one thread at a
time, and VMs share nothing, so two can run on two threads):

```odin
Config :: struct {limits: Limits, seed: u64, libs: bit_set[Lib], natives: []Native_Spec, gc_stress: bool}
vm_create  :: proc(config: Config, allocator := context.allocator) -> (^VM, Script_Error)
vm_destroy :: proc(vm: ^VM)
compile    :: proc(vm: ^VM, source, name: string, env := Value{}, scratch := context.temp_allocator) -> (Value, Script_Error)
call       :: proc(vm: ^VM, fn: Value, args: []Value, slice := DEFAULT_SLICE, allocator := context.allocator) -> Run_Result
resume     :: proc(vm: ^VM, values: []Value = nil, slice := DEFAULT_SLICE, allocator := context.allocator) -> Run_Result
abort      :: proc(vm: ^VM)  // ends a suspended or yielded run: frames gone, upvalues closed, idle
output_take :: proc(vm: ^VM, allocator := context.allocator) -> string
Run_Result :: struct {status: Run_Status (.Done, .Suspended, .Yielded, .Error), results: []Value, error: Script_Error}
```

- One run at a time per VM: `call` needs the VM idle; `resume` continues `Suspended` (no
  values) or `Yielded` (the values become the yielding native's results). `results` are
  valid until the next call into the VM; to keep a value longer, pin it (M51b).
- Natives: `Native :: #type proc(c: ^Native_Call) -> Native_Status`, `Native_Status :: enum
  u8 {Ok, Error, Yield}` (`.Ok` is zero, so `or_return` works), `Native_Spec :: struct
  {name: string, fn: Native, cost: i32}`. The standard libraries are constant tables of
  `Native_Spec` in their files; the host's natives come in `Config.natives`; a native's id is
  its index in the VM's combined table, and snapshots record natives **by name**.
  `native_value(vm, name) -> Value` makes a native closure for binding.
- Inside a native: `arg(c, i)`, `arg_count(c)`; `check_int`, `check_number`,
  `check_string`, `check_table`, `check_function`, `opt_int(c, i, default)` and
  `check_handle(c, i, kind)` (M51b), each `-> (T, Native_Status)` and writing the Lua-style
  "bad argument" error with the native's name when the argument is wrong; `push_nil`,
  `push_bool`, `push_int`, `push_float`, `push_string`, `push_value`, `push_table`;
  `raise(c, format, args)` -> `.Error`; `charge(c, units)`; `host_yield(c)` -> `.Yield`
  (M51b: the pushed values go to the host; the run ends `Yielded`).
- **Natives never call script code**, and an Odin local is never a root: everything a native
  makes is pushed on the stack (`push_table` returns the value it pushed), so a collection
  step during the native's allocations sees it. The library functions that must run script
  code are either *intrinsics* (`pcall`, `xpcall`, `coroutine.resume`, `coroutine.yield`, the
  function `coroutine.wrap` returns: native closures whose `intrinsic` field the dispatch
  loop handles by pushing a frame or switching thread) or written in the prelude.
- The prelude (`prelude.vxs`, `#load`ed) is compiled into every new VM and called once with a
  table of private natives (`rawtostring`, `write`, `format_raw`, `match_at`, ...) that only
  it can see; it defines `tostring`, `print`, `string.format`, `string.gsub`,
  `string.gmatch`, `table.sort` and anything else that calls script functions or
  metamethods.
- Host-side values outside a run: `new_string(vm, s)`, `new_table(vm)`, `table_get_raw`,
  `table_set_raw`, `set_global(vm, name, v)`, `get_global`. No collection step runs outside a
  run, so values the host makes stay alive until it passes them to `call` (which copies
  them onto the stack first).
- Pins (M51b): `pin(vm, v) -> Pin` (u32, an index into the registry table, a heap object
  rooted and snapshotted; freed slots reused lowest first), `pinned(vm, p) -> Value`,
  `unpin(vm, p)`. M52 keeps event handlers as pins; they survive snapshot and restore.
- Handles (M51b): `register_handle_kind(vm, name) -> u16` (in `Config` order, recorded by name
  in snapshots), `handle_value(kind, bits) -> Value`, `set_handle_metatable(vm, kind, mt)`.
  `type(h)` is `"handle"`; `tostring(h)` is `<kind name>: 0x<bits>` unless `__tostring`.

**Standard library** (exact lists; anything not listed does not exist):

- base (M51a): `assert, error, getmetatable, ipairs, next, pairs, pcall, print, rawequal,
  rawget, rawlen, rawset, select, setmetatable, tonumber, tostring, type, xpcall`,
  `collectgarbage("count")` (heap bytes in use / 1024, a float), `debug.traceback([msg])`.
  `tonumber(s [, base])`: decimal and hex integers, decimal floats, bases 2..36, surrounding
  whitespace allowed; anything else nil. `print` writes its arguments through `tostring`,
  tab-separated, newline-terminated, into the VM's output buffer.
- string (M51b): `byte, char, find, format, gmatch, gsub, len, lower, match, rep, reverse,
  sub, upper`, plus `split(s, sep)` (plain separator, Luau's). Patterns are Lua 5.4's
  (`lstrlib.c` ported: classes `%a %c %d %g %l %p %s %u %w %x` and their negations, ASCII
  only, sets, `%b`, `%f`, anchors, up to 32 captures, position captures), matching recursion
  bounded at 200, steps metered and capped. `format`: `%d %i %c %x %X %o %e %E %f %g %G %q %s
  %%` with flags `- + space # 0`, width and precision up to 99 (`%a` dropped); our own
  formatting on `strconv` (`write_float` with `'e'`/`'f'`, `%g` by C's rule from the `'e'`
  exponent, trailing zeros removed unless `#`, at least two exponent digits; the leading `+`
  `write_float` adds is stripped). No `pack`, `unpack`, `packsize`, `dump`.
- table (M51b): `concat, insert, move, pack, remove, sort, unpack` (raw; `sort` a stable
  merge sort in the prelude, comparator optional).
- math (M51b): `abs, ceil, floor, fmod, modf, sqrt, exp, log (x [, base]), sin, cos, tan,
  asin, acos, atan (y [, x]), max, min, tointeger, type, ult, pi, huge, maxinteger,
  mininteger`, from `base` and the allowed `core:math` functions (determinism rule 2;
  `log(x, 2)` and `log(x, 10)` are `ln(x) / ln(base)`, which may differ from Lua in the last
  bit: written down).
- utf8 (M51b): `char, charpattern, codepoint, codes, len, offset` (5.4, strict: no
  surrogates, at most U+10FFFF).
- coroutine (M51b): `create, resume, yield, status, wrap, isyieldable, running, close`. Each
  coroutine is a `Thread` with its own stack; resume and yield switch the current thread
  inside the one dispatch loop, so yields cross `pcall`, metamethods and the prelude freely.
  A budget suspension or a host yield inside a coroutine suspends the whole run (every
  thread in the resume chain keeps its state); `coroutine.yield` outside a coroutine is an
  error.

**The collector** (M51b, `gc.odin`). Incremental tri-colour mark and sweep over the heap,
non-moving, deterministic (its work is counted in bytes, never in time):

- Colours in `Header.mark`: two whites (current and other), gray, black. New objects are the
  current white. Phases: `Pause, Propagate, Atomic, Sweep`.
- Roots: the main thread, the current thread and its resume chain, the globals, the
  registry (pins), the string metatable, the handle metatables, the prelude's private table.
  The intern index is weak: it is not marked; the sweep removes dead strings from it (linear
  probing with backward-shift deletion).
- Gray objects (tables, closures, native closures, protos, threads) are linked through their
  `gclist` field (no side storage, so a snapshot holds the collector's exact state).
  Strings and `Bytes` turn black at once; `Values` buffers are marked and traversed by their
  owner; upvalues are marked and their value marked at once.
- Barriers: storing a white collectable key or value into a black table makes the table gray
  again on the `grayagain` list (backward barrier: in `table_set`, `SETLIST`, `rawset`,
  `table_set_raw`); storing into a black closed upvalue, or setting a metatable on a black
  table, marks the stored value (forward barrier). Thread stacks have no barrier: threads
  stay gray and are rescanned in the atomic step. The barrier calls exist from M51a as empty
  procedures (`barrier_back(vm, t)`, `barrier_forward(vm, owner, v)`) at every store, so M51b
  only fills them in.
- Atomic (one step): mark the roots again, traverse `grayagain` and every thread, propagate
  to empty; set stack slots above each thread's top to nil; flip the current white; set the
  sweep cursor to the heap start.
- Sweep: the cursor walks blocks in address order; an other-white block is freed (zeroed, its
  string removed from the intern index); adjacent free blocks are merged; live blocks get the
  current white. Free lists are rebuilt during the sweep (cleared at its start, filled as the
  cursor passes), so allocation during a sweep uses blocks behind the cursor or bumps `top`;
  a free run at the end of the heap lowers `top`.
- Pacing (`Gc_Params`, snapshotted): a cycle starts when bytes in use reach `max(256 KiB,
  estimate * PAUSE / 100)` with `PAUSE = 200` (`estimate`: bytes live after the last atomic
  step); during a cycle, every 8 KiB of allocation (`STEP_BYTES`) does `debt * STEPMUL / 100`
  units of work with `STEPMUL = 200` (marking: bytes of the objects traversed; sweeping: block
  bytes passed / 8). Steps run only at allocations inside a run (never inside a compile,
  never outside a run). `collect(vm)` runs a full cycle on an idle VM. `gc_stress` (tests):
  threshold 0 and `STEP_BYTES` 0, so the collector is always cycling.
- Out of memory: finish the current cycle, run a full one, retry the allocation once, then
  fault `.Memory`.
- `heap_check(vm) -> (ok: bool, problem: string)` walks the heap: headers sane, every `Ref`
  in every object on an object start of an allowed kind, free lists consistent, intern index
  entries live strings, in `Pause` every object the current white. Used by tests and fuzzers.
- What results may depend on the collector's timing: only `collectgarbage("count")` and
  whether a run hits the memory limit. Everything else is the same under `gc_stress`
  (tested).

**Snapshots** (M51c, `snapshot.odin`). `snapshot(vm, allocator) -> []u8` on a VM that is idle,
suspended or yielded; `restore(bytes, config, allocator) -> (^VM, Script_Error)` makes a new
VM from it (the prelude is not compiled again: it is in the heap). The format, little-endian,
version 1:

- `magic "VXSS"`, `version: u16`, `flags: u16`, `header_size: u32`, `checksum: u64`
  (`xxhash.XXH64` of everything after it, seed 0).
- Scalars: `seed`, `Limits`, `Gc_Params` and the collector's state (phase, current white,
  debt, estimate, sweep cursor, `gray` and `grayagain` heads), `top`, the free list heads, the
  roots (globals, registry, string metatable, handle metatables, prelude table, main thread,
  current thread), the intern index and count, `next_id`, the run state (status, meter,
  run instructions used, pending yield count), the pending output bytes.
- The native names in id order and the handle kind names in kind order (u16 length + bytes
  each).
- The heap bytes from offset 0 to `top`.

The heap is copied as it is, so equal VM states give equal bytes on every OS (64-bit
little-endian targets only: x64 and arm64; asserted at compile time). `restore` refuses,
each with a message naming the problem: wrong magic, a version it does not know ("snapshot
version 2; this build reads 1": snapshots are not migrated, see the notes), a bad checksum,
`top` beyond the configured memory, a native or handle kind name the new VM does not have
("snapshot needs native 'world.set_block', which this VM does not have"). It then validates
the structure before anything runs: a linear walk of headers (sizes, kinds, alignment, within
`top`) builds a bitmap of object starts; every `Ref` field and every reference-tagged `Value`
must land on an object start of an allowed kind; frames' integers within their thread's
stack; every proto through `verify_proto`; native ids remapped from names to the new VM's
table. A save file is our own output, but a damaged or edited one must not crash the server
(ground rule 6).

`verify_proto` (`verify.odin`): every instruction's opcode in range, registers below
`max_stack`, constant and proto indices in range and of the right type (`GETFIELD`'s a
string, `ADDK`'s a number), upvalue indices below `nup`, jump targets inside the code,
`EXTRAARG` after the ops that take one, the last instruction a return. Run after every
compile in tests and fuzzers, and on restore.

**The disassembler and the trace.** `disasm(vm, fn, &b)` and `build script disasm <file>`,
one block per function, nested functions after their parent:

```
function <quests/intro.vxs:10-24> on_tick (9 instructions; 1 param, 5 registers, 1 upvalue, 3 constants)
     1  [11:13]  GETGLOBAL    0 0        ; "player"
     2  [11:19]  GETFIELD     1 0 1      ; "health"
     3  [12:6]   LTI          1 10 0
     4  [12:6]   JMP          3          ; to 8
     5  [13:5]   GETUPVAL     2 0        ; count
     6  [13:5]   ADDI         2 2 1
     7  [13:5]   SETUPVAL     2 0        ; count
     8  [15:3]   RETURN0
constants (3): 0 "player"  1 "health"  2 10
locals (1): 0 self 1-8
upvalues (1): 0 count (in stack, register 2)
```

The trace (M51b, `trace.odin`): with `vm.trace` on, every executed instruction appends a line
to a trace buffer the host drains (`trace_take`; capped at 4 MiB between drains, the excess
counted and reported as one line), plus lines for calls, returns, errors, suspensions and
collector steps:

```
T 2 quests/intro.vxs:11 on_tick 2 GETFIELD 1 0 1 ; R1 = 20 (integer)
C 3 call native 'string.sub' args=3
G step mark work=16384 inuse=1.2MiB
S suspend meter=-3 depth=2
```

Deterministic text (no addresses, no times), so a test can compare a trace with a file.

**Fuzzing** (M51c, `fuzz.odin`; Odin has no libFuzzer, so our own, deterministic from a seed;
the fuzzers are targets of Q1's harness, `build fuzz script.source script.generated
script.bytecode script.snapshot`, not a harness of their own: #84, 2026-10-30):

- *Mutation of sources*: a corpus of every conformance file and the prelude; each case applies
  1-4 mutations from the seed's `base.Rng` (flip a byte, insert a token from the language's
  token list, delete or duplicate a span, splice in a span of another file, truncate, nest a
  span in `(` `)` or `do` `end` 300 times). Properties: `compile` returns a module or a
  `.Syntax` error whose line and column are inside the source and whose message is not
  empty; never a panic; every proto passes `verify_proto`; a module that compiles is run with
  a slice of 10 000 units and 1 MiB of memory and ends `Done`, `Error` or `Suspended` (then
  `abort`), and `heap_check` passes.
- *Generated programs*: a generator of well-formed programs from the grammar, tracking the
  locals in scope and their likely types, bounded in depth and size, with every loop bounded
  (a counter), covering mixed integer and float arithmetic (including the edges: `mininteger`,
  zero divisors inside `pcall`, NaN, -0), strings and the string library, tables (array and
  hash, nil assignments, `#`), closures capturing loop variables, metatables with each
  metamethod, `pcall`/`error`, varargs, coroutines. Each program ends by printing a digest of
  its values. Properties, comparing outputs: run straight == run in slices of random sizes
  1..97 == run with a snapshot, `vm_destroy` and `restore` at every suspension (also equal heap
  hashes at the end) == run under `gc_stress`; `heap_check` after each; no panic.
- *Snapshot mutation*: snapshots of generated programs at random suspensions, mutated (bytes
  flipped, truncated, fields swapped), restored with the checksum check skipped
  (`restore_unchecked`, test-only): refused, or restored to a VM that runs to any status
  without a panic.
- Q1's harness saves a crashing case under `build/fuzz/<target>/` and prints the target, seed
  and case; `build fuzz <target> --case <file>` replays it. A bug found becomes a file in
  `testdata/fuzz/<target>/regress/` that the suite replays (and, for sources, the conformance
  runner runs too).
- `--lua <exe>` (passed to `script.generated` after `--`) runs generated programs in the
  common subset (no `pairs` order, no extensions) under a reference Lua 5.4 and compares
  outputs; CI's "Fuzz (smoke)" step runs it with `lua5.4` (M51c).
- In the suite on every OS: `test_fuzz_smoke` (300 mutations, 200 generated programs, 100
  snapshot mutations, seed 51). In CI: Q1's "Fuzz (smoke)" step (fixed seed, every target
  including these) and "Fuzz · nightly" (the run number's seed, under AddressSanitizer).

**The conformance suite.** `common/script/testdata/conformance/<area>_<name>.vxs`, loaded with
`#load_directory`, run by `test_conformance` in name order, each in a fresh VM. Header lines
(comments) say what to expect: `--! expect: <text>` (each one a line of `print` output, in
order), `--! error: <text>` (a substring of the formatted error, and its kind), `--! limit:
instructions|memory|call_depth`, `--! slice: <n>`, `--! memory: <bytes>`, `--! lua` (in the
common subset: `build script conform --lua` runs it under a reference Lua too). Without
`--! error` a file must end `Done`; most use `assert`. Every file is also run in slices of 7
units (M51a), under `gc_stress` with `heap_check` after (M51b), and with snapshot and restore
at every slice (M51c), and the output must not change. Areas and examples (each area several
files; at least 120 files after M51a, 200 after M51b):

- `lex`: every escape; long strings with levels; `9223372036854775807`,
  `9223372036854775808` (a float), `0xffffffffffffffff` (-1); `1e308 * 10` (inf); comments.
- `arith_int`, `arith_float`, `arith_mixed`: wrapping; `7 // -2 == -4`, `-7 % 3 == 2`,
  `7.5 % -2 == -0.5`; `1 // 0` errors, `1 / 0` is inf, `1 // 0.0` is inf; `3 / 2 == 1.5`;
  `2^53 + 1` exactness; `math.maxinteger + 0.0 == 2^63`; `mininteger // -1`.
- `compare`: int/float exactness at 2^53 and 2^63; strings bytewise; errors comparing number
  and string; `__lt`, `__le`, `__eq` rules.
- `tostring`: `3.0`, `-0.0`, `1e+15`, `0.1`, `1/3` (`0.33333333333333`), `inf`, `nan`,
  `2^63` (`9.2233720368548e+18`), tables by sequence number.
- `bitwise`: shifts by 64 and negative, float operands with and without integer value.
- `string_basic`: concat with numbers, `#`, no arithmetic coercion (its message), methods on
  literals (`("x"):rep(3)`).
- `table`: constructors with trailing calls and varargs, `#` borders and holes, insertion
  order of `pairs` (with deletes during traversal, revival, compaction), `t[1.0]`, NaN key,
  nil key.
- `scope`, `upvalue`: shadowing, closures sharing an upvalue, a fresh loop variable per
  iteration, upvalues of upvalues, closing on `break` and `continue`.
- `vararg`, `call`: `select('#', nil, nil)`, adjustment of results in the middle and at the
  end, tail calls 100 000 deep without a fault, method calls.
- `control`: `while`, `repeat` with a body local in `until`, numeric `for` edge cases (step 0,
  float steps, overflow at `maxinteger`), generic `for`, `break`, `continue`, `continue` in
  `repeat` refused.
- `compound`: `t[f()] += 1` calls `f` once; `..=`.
- `meta`: every metamethod in the list, chains, `__index` loops refused, `__metatable`.
- `error`: values of every type, levels, nested `pcall`, `xpcall` with a handler, error in
  the handler, the messages naming locals, globals, fields, methods and upvalues, the
  "did you mean" hints.
- `syntax`: each common mistake in the table above, with its exact message and hint.
- `annot`: every annotation form parses and changes nothing; `type(x)` still a call.
- `absent`: `goto`, `io`, `os.time`, `math.random`, `load`, `require` with their messages.
- `limit`: `while true do end` suspends, resumes, then faults at `run_instructions`; an
  allocation bomb (`local t = {} while true do t[#t+1] = {} end`) faults `.Memory`; unbounded
  recursion faults `.Call_Depth` and `pcall` does not catch it; `string.rep("x", 2^30)`
  errors; a pattern bomb (`string.rep("a", 5000):find(string.rep("a?", 5000) ..
  string.rep("a", 5000))`) errors "pattern too complex" (M51b).
- M51b adds `string_lib`, `pattern`, `format`, `table_lib`, `sort` (stability, comparator
  errors), `math`, `utf8`, `coroutine` (generators, status, wrap, yield across `pcall` and
  metamethods, resume dead, errors inside, `close`), `gc` (cycles collected; strings freed;
  churn in flat memory), `host` (pins, handles, host yields).

**Performance.** `common/script/testdata/bench/*.vxs`, in the common subset so a reference Lua 5.4 can
run them unchanged: `fib` (recursive `fib(32)`), `loop` (integer sum to 10^8), `float`
(a float recurrence, 10^7 steps), `array` (fill and sum an array of 10^6, 20 times), `hash`
(10^6 string-keyed inserts and lookups), `closure` (10^7 calls of a closure updating an
upvalue), `method` (10^7 method calls through `__index`), `string` (`..` and `table.concat`
building, `string.format`, `find`, `gsub`). `build bench script` (`build script bench`) runs
each at `-o:speed` and records a `base.Bench_Result` (scenario `script`, a metric per program,
exact counts of instructions executed), so `build bench compare <ref> script` works like the
other scenarios. `--lua <exe>` also times each under that interpreter and prints the ratio.
**Target: at most 4x the time of PUC Lua 5.4 on each program, and at most 2.5x in geometric
mean, on the same machine** (a switch dispatch without computed goto, 16-byte values and
bounds checks on is expected to land between 1.5x and 3x; a program over 4x is a design
problem to fix in the milestone, not a number to relax). Gated in CI (2026-10-30, #83; was measured by hand): the Linux test job installs `lua5.4`
through the apt cache and "Benchmark check, script" runs `build bench script -check --lua
lua5.4` (the ratios above, and every `--! lua` conformance file printing the same under both);
on Windows and macOS the step checks each program's instruction count against its recorded
budget. The ratios are written in the row's history.md entry.
