# M52: the sandbox (capabilities, quotas, events, isolation)

What a script may do in a world is a list of capabilities: its pack declares them, the
world grants them, and every call into the engine checks one and charges a budget. Nothing
else is reachable from a script. Every world mutation a script makes goes through M45's
journal with the script as its cause. One session; the split point is at the end.

**What this builds on (assumed as their paragraphs say; names used below):**

- M51's VM, package `common/script/` (depends on `base` only), with the host API exactly as M51's
  section defines it (`vm_create(Config{limits, seed, libs, natives})`, `compile`, `call`,
  `resume`, `abort`, `Run_Result{status: .Done/.Suspended/.Yielded/.Error}`, natives as
  `Native_Spec{name, fn, cost}` with `check_*`, `push_*`, `raise`, `charge`, `host_yield`).
  Decided with M51 (planner, 2026-10-26):
  - **One VM per pack per world**, not per script: a pack's scripts share an author and its
    modules, so isolating them from each other buys nothing. Events for the pack queue on
    its VM and run one at a time; a run may take several slices across ticks. Budgets are
    still kept **per script** (the script whose handler the run is, recorded when the run
    starts) and per pack, and every effect's cause names both.
  - **A throttled call is parked, then done by the host:** the native records the pending
    call (its binding and checked arguments) and returns `host_yield`; the run ends
    `Yielded`; when the bucket holds the cost, the host performs the call itself and
    `resume`s the run with the results (M51: the values become the yielding native's
    results). Nothing is executed twice.
  - Running out of a slice is `.Suspended` (resumed next tick with no values); a limit
    fault (instructions per run, memory, call depth) is `.Error` and cannot be caught by
    the script's `pcall` (M51); what a fault does to the script is decided here.
  - Values: nil, bool, int (i64), float (f64), string, table, function; the host builds and
    reads tables with M51's table helpers (deterministic `pairs` order) and keeps functions
    across runs with M51b's pins (roots, part of a snapshot).
  - `Config.libs = {.String, .Math, .Table}`: the safe library subset; nothing else is in a
    new VM's globals (no `io`, `os`, `load`, `require`, `debug`, `package`).
  - M51c's snapshot and validated restore (fails as a value), pins included; snapshots are
    valid within one engine version only (M51), so a script's lasting state is pack data
    (M53's variables), and a snapshot is for a running world, not for upgrades.
- M45 as its section defines it: actions (`action_begin(w, Actor{kind, name, bypass},
  system)`), `Act`, the cause-taking `set_block`/`bulk_edit`, and `admit(w, act, p)`, the one
  enforcement point. Here: scripts act as `Actor_Kind.Script` with the name `<pack>:<script>`
  (M45 reserves it); `admit` gains `Over_Budget` and `No_Capability` (a script's capability
  for the region and its per-tick block quota) and nothing else checks them; and M45's
  journal, which holds block entries only, gains entry kinds for what scripts can also do:
  entity spawn and removal (M50's `Origin` and the removal's act), item gains and losses
  (linked to the ledger entry, M31), rule changes and time changes, each with its rollback,
  so a pack's effects can be undone by cause (`rollback script demo:main 10m`) and M54's
  revert restores the world hash.
- M46: atomic writes and the schema registry; a world's extra state files are written
  through it (its migration registry is not used: before 1.0 there are no migrations).
- M47: packs installed per universe (their content: blocks, items, kinds, universe-wide);
  a pack's behaviour is enabled per world, here: `worlds/<id>/world.cfg` gains `packs`, the
  ordered list of installed packs whose scripts and gameplay data run in that world
  (`World.packs: [dynamic]^Pack`, `Pack {id (the
  namespace), title, version, dir, hash}`), M47's text format parsed into nodes that
  carry file and line, `pack_error(node, ...)` producing `file:line: message (fix)`, and a
  way to load a pack from memory for tests (`pack_load_memory(files: map[string]string)`).
  The examples below are written in a short `key = value` / `name { ... }` notation for
  reading; the files are M47's pack JSON (JSON with comments and trailing commas), with the
  same keys and nesting: a block is an object, a repeated block an array of objects.
- M50: entity kinds by id, `entity_spawn(w, kind, pos, components, cause)`, components
  `Tags` (up to 4 short names) and `Origin {pack, script}`, generational entity handles
  (`Entity_Handle`, a `u32` index and a `u32` generation), death and hurt with the killer,
  and the spatial query service (`entities_query(w, center, radius, filter)`,
  `blocks_by_tag(w, box, tag)`).

**Script, pack, world.** A script is one source file of a pack, named
`<pack>:<name>` (`demo:main`), run in one world. A pack installed in two worlds runs two
copies that share nothing. Each pack in a world has one VM (its heap and snapshot), shared
by its scripts, which run one at a time; budgets are per script. Packs never share a heap.

budget is a token bucket (below). Implicit ones need no declaration.

The full binding list (name, capability, argument types, cost) is the `BINDINGS` table in
`common/game/capabilities.odin` (signatures) and `server/sandbox_bindings.odin` (the run
procedures, an enumerated array `[Binding_Id]Binding_Run`, so a signature without an
implementation does not compile). Argument types: `Int`, `Number` (int or float, finite),
`String` (max length per binding), `Bool`, `Table`, `Function`, `Block_Name`, `Item_Name`,
`Kind_Name` (checked against M47's registries), `Player` and `Entity` (handles, below),
`Box` (six integers, min not above max), and `Optional(T)`. Coordinates are integers for
blocks, finite floats under `game.WORLD_LIMIT` for positions.

*Handles.* Players and entities reach scripts as integers: an entity as its M50 handle
packed in an i64 (`index | generation << 32`), a player as `player_id | join_serial <<
16` (`join_serial` a new per-`Client` counter that changes on every join and every arrival
in a world). A binding resolves a handle **only in its own world's pools** and checks the
generation (entities) or that the client with that id is in this world with that serial
(players). A forged, stale or other-world handle is refused as `not found`.

*The manifest* (members `capabilities`, `scripts` and `limits` of the pack's `pack.json`):

```
capabilities {
  world.edit { region = -64 0 -64 64 128 64  per_tick = 32 }
  entity.spawn { kinds = base:sheep  alive = 8  per_second = 1 }
  item.give { items = base:wheat base:seeds  per_hour = 64 }
  chat.send
  optional ui.prompt
}
scripts {
  main = scripts/main.vl
  waves = scripts/waves.vl
}
limits { instructions_per_tick = 20000  memory = 4MiB }
```

- Parameter names are the budget names in the table (`per_tick`, `burst`, `per_second`,
  `per_minute`, `per_hour`, `per_player_per_hour`, `alive`, `radius`, `bytes`) plus
  `region` (up to 8 boxes, each six integers, inclusive, or the word `world`), `kinds`,
  `items`, `blocks`, `names` (lists of ids; `*` any), `any` (bool).
- `optional` marks a capability the pack works without; the rest are required.
- Validated at load with M47's errors: unknown capability (with the nearest name), unknown
  parameter, a number above its ceiling (`world.edit per_tick 9000 is above the ceiling
  4096`), a box with min above max, `base:item` in `entity.spawn kinds`, a missing or
  unparsable script file (with M51's diagnostics, file:line:column).
- Script source files have M51's extension (written `.vl` here).

*The grants* (`worlds/<id>/grants.cfg`, the line format of `permissions.cfg`; written by
the server, edited by `/pack grant`):

```
# What each pack's scripts and data may do in this world (see DEBUGGING.md)
pack demo
grant world.edit region=-64,0,-64,64,128,64 per_tick=32
grant item.give items=base:wheat per_hour=32
grant chat.send
pack arena
grant all
```

- `grant <capability> [param=value ...]`; lists comma-separated; `grant all` grants every
  capability the manifest declares at the manifest's parameters.
- **Effective** capability = declared and granted. Its parameters: regions intersected
  (box by box; an empty intersection removes the capability), lists intersected, numbers
  the least of manifest, grant and ceiling. A parameter the grant leaves out takes the
  manifest's.
- A required capability with no effective grant: the pack's scripts do not start, logged
  once at `warn` with every missing one and the command that would grant it (`pack demo
  needs world.edit, item.give in world <address>: /pack grant demo all`). Its data
  (M53) does not run either. An optional one missing: the scripts start without it.
- Universe ceilings and world pools in `universe.cfg` (new keys, defaults shown):
  `scripts = on` (off: no pack runs scripts or data anywhere), `scripts.max = 128` (per
  world), `scripts.instructions = 1000000` (all scripts of a world, a tick),
  `scripts.blocks = 2048` (a tick), `scripts.spawned_alive = 1024`, `scripts.chat = 10`
  (lines a second), `scripts.items_per_hour = 4096` (of each item, a world, all packs).
- A grant change applies at the next tick boundary. A revocation takes effect at once
  (call-time check); an added capability takes effect when the script restarts
  (`/script restart`), because what is registered in a VM is fixed at start.

*The binding layer* (`server/sandbox.odin`, `server/sandbox_bindings.odin`).

- At start, a pack's VM gets `Config.libs` and exactly the bindings of its
  implicit and effective capabilities, each registered as one trampoline with its
  `Binding_Id` as `data`. **Nothing else is registered**: what was not granted does not
  exist in the script's globals (calling it is the VM's "attempt to call a nil value").
- Every call goes through `sandbox_call(script, id, call)`, in this order:
  1. the script is `Running` (not halted or stopping);
  2. arguments against the signature (count, types, ranges, string lengths, handles
     resolved in this world);
  3. the capability is still effective (not revoked), and its parameters cover the call
     (`grant_covers(effective, binding, args)`: region contains every block, kind and item
     in the lists, own entity unless `any`);
  4. the cost (`Binding_Info.cost`: a fixed amount, or a procedure of the arguments: a
     fill's volume, a query's limit) against the script's bucket and the world pool;
  5. run: world mutations through `set_block(w, p, b, act)` with the script's action;
     everything else directly.
- The journal gate (`sandbox_gate`, set as `w.journal.gate`) refuses a mutation with a
  `Script` cause that `grant_covers` does not cover. It is the same procedure as step 3,
  called once more at the one enforcement point M45 provides; a mutation it refuses after
  step 3 passed is a bug, logged at `error`.
- Outcomes (`Call_Outcome :: enum {Done, Refused, Denied, Throttled, Halt}`):
  - **Refused** (bad arguments, not granted, revoked, outside the region, not found, not
    own): the native raises a script error (`raise`) with the reason, written for a
    model to act on (`world.set_block: (100, 64, 3) is outside this script's world.edit
    region -64 0 -64 .. 64 128 64`). The handler ends; the script stays. Logged at `warn`
    (`server script refused world=... script=demo:main call=world.set_block reason=...`),
    a `Script_Refused` telemetry event, a line in the script's log.
  - **Denied** (a hard cap: alive entities, the hourly faucet, pending timers,
    subscriptions, stored bytes, a cost larger than the bucket's capacity): the call
    returns `nil, message` (two results, Lua's idiom); nothing else happens. Logged at
    `debug`, counted per script.
  - **Throttled** (the bucket or the world pool is short now, but the cost fits its
    capacity): the native parks the call and returns `host_yield`; the run is parked until
    the tick its bucket holds the cost (computed exactly from the rate), when the host
    performs the call (from step 1) and resumes the run with its results. The tick never
    waits.
  - **Halt** (below): the script stops.
- Buckets are integers in thousandths of a unit (`Bucket {level, rate, capacity, last}`),
  refilled lazily from the world's script tick: `level = min(capacity, level + rate *
  (tick - last))`. Per-player budgets are buckets keyed by player id, made on first use
  and dropped when the player departs. Deterministic: no clock, no map order.
- **Halting.** A script is halted (state `Halted`, its VM kept for `/script log`, its
  entities left as they are) when: its memory budget is exceeded (`Out_Of_Memory`); one
  handler has run 300 ticks' worth of its instruction budget without finishing (an
  infinite loop: it yields every tick at its budget and is stopped after 10 s); it was
  refused 32 times within 900 ticks; a handler errors 32 times within 900 ticks; or its
  snapshot fails. Logged at `error` with the reason, a `Script_Halted` telemetry event,
  a notice to players holding `admin.scripts` in that world. `/script restart <id>` starts
  it fresh (its `store` kept).

*Scheduling and the fixed points of the tick* (`server/sandbox.odin`).

- Each world has `scripts: [dynamic]Script` in a fixed order (pack load order, then the
  order of the manifest's `scripts` block) and `script_tick: u64`, which counts the
  world's unfrozen ticks (timers and buckets use it, so a paused singleplayer world's
  scripts stand still with its entities).
- Two points in `server.tick` (`server/server.odin`), per world, both skipped while frozen:
  - **Point A, after the players** (after the `for &c in s.clients` loop of
    `simulate_player`/`health_tick`/`stats_tick`): region membership is updated
    (`regions.watch`, M53's regions), then the events raised since the last point
    (messages received this tick: chat, commands, edits, uses, answers; players' movement,
    damage and deaths) are delivered.
  - **Point B, after the world** (in the world loop, after `entities_tick` and
    `containers_tick`, before `gates_tick` and `changes_flush`): due timers, `tick`
    events, then the events raised since point A (entities died and hurt, block changes
    by the simulation and by point A's scripts). Effects made here reach clients in the
    same tick's `changes_flush` and `replica_flush`.
- Delivery: data (M53's triggers) first, then scripts. Scripts run round-robin starting
  at index `script_tick % len(scripts)`; each script handles its queued events and
  resumes a parked call while its tick budget lasts, then the next; when the world pool
  is spent, the rest wait for the next point, in order. A script whose events wait more
  than 30 ticks is reported in `/script list` as `starved`.
- **Events raised by a script's own effects are queued for the next point**, never
  delivered within the run that caused them, and a script never receives events it
  caused (`cause.id` is its own). No recursion inside a tick.
- A script's queue holds at most 1 024 events; filtered at enqueue (region, kind,
  name). On overflow the newest are dropped and counted; the script gets an
  `events_lost {count}` event first at its next delivery, and a `warn` line is logged once
  a minute per script.

`on(name, fn, filter)`; `fn` gets one table with `name` and the fields.

`on` for an event whose capability is not effective is refused. `events.emit(name,
data)`: `name` in the pack's own namespace; `data` is copied out of the sender's heap as
plain data (nil, bool, int, float, string, tables of those; depth 8, 256 entries, the
byte budget); functions, cycles and anything over the limits are refused; metatables are
dropped.

*Isolation (why each escape is impossible).*

- **Other worlds.** A script holds a `^World` it cannot name or change; no binding takes a
  world, an address or a path; coordinates are always its own world's. Handles resolve
  only in its world's pools (a player who travelled away has a new `join_serial` and is
  not in this world: refused). `events.emit` and chat reach only this world. Script
  state, buckets and stores are per world. Test: the same pack in two loaded worlds.
- **The file system, network and clock.** The VM has no I/O (M51), `Config.libs` adds no
  I/O, and the sandbox registers no binding that touches them. Time is `world.tick` and
  `world.time`, both simulation state. Snapshots and stores are written by the server to
  paths it builds from ids it validated (`worlds/<id>/scripts/<pack>/<name>.snap`,
  `.../store.dat`), never from script strings. A test lists every global of a script with
  every capability and compares it with the expected set, so a new binding cannot appear
  unnoticed.
- **Other scripts.** One heap each; the only channels are `events.emit` (copied data) and
  the world itself (blocks, entities, `store` is per pack). No binding returns another
  script's values or functions.
- **The engine's memory.** The VM is memory-safe and metered (M51); bindings validate
  every argument before use (ground rule 6) and return copies, never views into server
  memory. A script's heap is its own arena, capped by its memory budget.
- **Forged effects.** The cause is set by `sandbox_call` from the script's id; no binding
  takes a cause. Chat from a script is a system line prefixed with the pack's title in
  brackets (`[Demo Quests] ...`), run through `chat_clean`, so it cannot pass for a player
  or the server. Items enter only through `item.give` (ledger reason `Script_Give`) and
  leave through `item.take` (`Script_Take`); `entity.spawn` of `base:item` is refused, so
  there is no second faucet.
- **The tick.** Budgets are in instructions and units, never time; a script cannot hold
  the tick past its budget, and the world pool caps all of them together.

*The ledger.* `game.Reason` gains `Script_Give` and `Script_Take` (appended). `item.give`
charges three buckets: the script's per-item hourly one, the per-player hourly one and the
world's `scripts.items_per_hour` pool for that item (one per world, all packs). `Ledger`
entries keep the universe-wide counts as today; the world's per-pack totals for
`/pack info` are counters in the world's stats (`scripts.items.<pack>.<item>`). Stack
origin tags (an item remembering it was made by a script) are not built: see the notes.

*Persistence.* On world save and unload each running script's snapshot (M51) is written
to `worlds/<id>/scripts/<pack>/<name>.snap` with the pack's hash, the script tick and its
buckets (M46's atomic write). On load: same pack hash, restored and given `load {reason =
"restore"}`; another hash or a restore that fails, started fresh with `reason =
"updated"` (logged at `info`, or `warn` for a failed restore). Stores are a separate file
per pack (`store.dat`, M46's schema: a map of string keys to plain values) and per
character inside the character file (`"store": {"<world dir>": {"<pack>": {...}}}`; the field is
part of the new format, and no migration reads an older character file).

*Commands* (`server/sandbox_commands.odin`, in `ADMIN_COMMANDS`):

- `/script list` (this world's scripts: state, instructions a tick averaged over a minute,
  refusals, denials, throttled ticks, queued events), `/script log <id> [lines]` (the
  last of its 256-line log), `/script stop <id>`, `/script restart <id>`: node
  `admin.scripts`.
- `/pack list`, `/pack info <pack>` (manifest, effective capabilities with their numbers,
  what is missing), `/pack grant <pack> <capability> [param=value ...] | all`, `/pack
  revoke <pack> <capability>`: node `admin.packs`. The admin role has both through `*`.

**Order of the steps** (each leaves the suite passing):

1. `common/game/capabilities.odin`: `Capability`, `CAPABILITIES`, `Script_Event`, the binding
   signatures; manifest and grants parsing with their errors; effective capability
   computation; buckets. Unit tests only.
2. The host: `Script` (VM state, buckets, queue, log, state), start from a pack, the
   trampoline and `sandbox_call` steps 1-5 with `Refused`/`Denied`/`Throttled`/`Halt`,
   the scheduler and the two points in `server.tick`, timers, `on`/`off`, `load` and
   `tick` events, the implicit bindings. A first script runs in a stepped server.
3. `Actor_Kind.Script` in the journal and `sandbox_gate`; `world.*` and `entity.*` bindings and

**The benchmark** (`server/sandbox_bench_test.odin`, `test_hundred_scripts`, built with
`-o:speed` in CI's test step as the other budget tests are). One world, 100 copies of
`server/testdata/scripts/everything.vl` (each in its own pack, every capability granted at
the defaults, regions 16x16 columns apart), two test players walking a fixed path, 900
ticks stepped. Each copy, every tick: a `tick` handler with 64 block reads, 2 block edits
(alternating two blocks), 1 entity query; every second: a spawn and a removal, a
`chat.say`, an `item.give` and an `item.take` of one wheat, a `store.set`, a timer, a
`ui.notice`; every 10 s an `events.emit` received by the next copy. Asserted:

- no script refused, denied, halted or starved; every expected effect present (counts of
  edits, spawns, chat lines, ledger entries);
- the script phase (both points) p99 at most 25% of the tick period (8.3 ms) and the whole
  tick p99 under the period, measured with `base.metric_scope(.Server_Scripts)` (a new
  metric);
- two runs give the same M38 root hash (determinism);
- the ledger audit balances.

**Other tests** (`server/sandbox_test.odin`, `common/game/capabilities_test.odin`):

- Manifest and grants: every error message (exact text, file and line); effective
  parameters by intersection, min and ceiling, table-driven; `grant all`.
- Buckets: refill exactness over 10 000 ticks; throttle wake tick exact; per-player
  buckets made and dropped.
- Scheduling: round-robin start rotates; pool exhaustion carries the rest to the next
  point in order; events from a script's effects arrive at the next point; frozen world
  runs nothing; event overflow gives `events_lost`.
- Every event kind raised once by its engine site and received with its fields; filters
  (region, kind, item, name, `every`).
- Persistence: save with three scripts mid-timer, reload, the timers fire on the same
  script tick as without the reload; changed pack hash starts fresh.
- Journal: a script's edits roll back by cause (`rollback script <id>`) to the
  pre-script hash.
- The global-name list test (isolation above).
- Revocation mid-run refuses at the next call; a grant added applies after restart.
