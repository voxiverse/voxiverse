# M52b: the sandbox, part two (players' health and modes, notices and prompts, rules, store, commands, custom events, persistence, the hostile rest, the 100-script benchmark)

The second half of [M52](M52.md), at the split point M52 named. Everything here uses M52's
capability table, binding layer, buckets, scheduler, events and hostile-suite harness as
built; the session first checks M52's code against this spec and corrects names in the same
commit.

**What this builds on:** M52 as built (`common/game/capabilities.odin`,
`server/sandbox.odin`, `server/sandbox_bindings.odin`, `Sandbox_Script`, `sandbox_call`,
`Bucket`, the two points, the hostile harness in `server/sandbox_hostile_test.odin`); the
party systems' procedures (`server/damage.odin`: `damage`, `heal_player`, `respawn`,
`kit_give`; `server/modes.odin`: `set_game_mode`, `Mode_Cause`; `rule_set` in
`server/commands_world.odin`); M51b's pins and M51c's snapshots; M46's atomic writes; M53's
`Prompt` record does not exist yet (below).

**Bindings built here** (their rows are in M52's table; API version 1):

- `player.damage(p, amount, cause?)`, `player.heal(p, amount)` (`player.health`): through
  `damage` and `heal_player` only; a script never calls `die` or sets `Client.health`. The
  cause is `base:script` when omitted; otherwise it must be one of the pack's own causes
  (M53 adds pack causes; until then only `base:script`). Charged per player in health
  points.
- `player.set_mode(p, mode)` (`player.mode`, `modes` parameter): through `set_game_mode(s,
  c, mode, {"script", "<pack>:<script>"})`; `Mode_Result` other than ok is returned as `nil,
  message`. `player.respawn(p)` (`player.respawn`): through `respawn`, refused unless the
  player is dead. `kit.give(p, kit)` (`item.give`, every item of the kit in `items`).
- `ui.notice(p, text)`: a toast on that player's screen through the existing toast path
  (`overlay_toasts.odin`, a new server-to-client event `Notice {pack_title, text}`, text
  through `chat_clean`, 256 bytes), prefixed with the pack's title like chat.
- `ui.prompt(p, {text, choices})`, `ui.close(p, id)`, the `prompt_answer` event: the open
  prompt is stored per player and pack (`Open_Prompt {id, pack, text, choices}`, at most one
  per pack per player) and sent as a notice of its text until M53 replaces the sending with
  its `Prompt` record and the drawn dialog; an answer is the existing chat command path
  `/answer <id> <choice>` (permission-free, validated: the id must be the player's open
  prompt), so M52b needs no new client UI. M53 keeps the binding and the event unchanged.
- `rules.get(name)`, `rules.set(name, value)` (through `rule_set`, journalled with the
  script as actor; base rules only when listed in `names`), the `rule_changed` event.
- `world.set_time(t)` (`world.time`), journalled (the time-change entry kind, below).
- `store.get(key)`, `store.set(key, value)` (world scope), `store.character(p)` returning a
  handle with `get`/`set` (per character, per world, per pack). Keys are strings of at most
  64 bytes; values plain data (M52's `events.emit` rule: nil, bool, int, float, string,
  tables of those; depth 8, 256 entries a table); sizes charged in encoded bytes.
- `command.register(name, help)`, the `command` event: names `[a-z][a-z0-9_]{0,23}`, never
  an engine command (`ADMIN_COMMANDS`, `server/admin.odin`, and the client's words), used as
  `/<pack>:<name>` and, when no other pack registered it, `/<name>`.
- `events.emit(name, data)`, the `custom` event: `name` in the pack's own namespace; `data`
  copied out of the sender's heap as plain data (functions, cycles and anything over the
  limits refused; metatables dropped).

**The journal's other entry kinds** (`common/game/journal.odin`, `server/journal.odin`):
item gains and losses by script (linked to the ledger entry, M31), rule changes and time
changes, each with its rollback, so `/rollback script <id>` undoes every effect a script
can make and M54b's revert restores the world hash. `JOURNAL_FORMAT` goes up (no reading of
older segments: before 1.0).

**Persistence.** On world save and unload each running script's snapshot (M51c) is written
to `worlds/<address>/scripts/<pack>/<name>.snap` with the pack's hash, the API version, the
script tick, its buckets, timers and pins (M46's atomic write, inside the save transaction
so a crash leaves the old or the new generation, M46's crash points extended to the new
files). A script mid-run at save time (suspended or parked) is snapshotted at the end of its
run: the save captures the tick (M46b) and the snapshot is taken at the next point where the
VM is idle, at most 30 ticks later; past that, the script is aborted and restarted on load
with `reason = "updated"` (logged). On load: same pack hash and API, restored and given
`load {reason = "restore"}`; another hash or a restore that fails, started fresh with
`reason = "updated"` (logged at `info`, or `warn` for a failed restore). Stores are a
separate file per pack (`store.dat`, a versioned header, a CRC, plain values) and per
character inside the character file (`"store": {"<address>": {"<pack>": {...}}}`; the field
is part of the new format, no migration).

**Commands** (`server/sandbox_commands.odin`, in `ADMIN_COMMANDS`):

- `/script list` (this world's scripts: state, instructions a tick averaged over a minute,
  refusals, denials, throttled ticks, queued events, starved), `/script log <id> [lines]`
  (the last of its 256-line log), `/script stop <id>`, `/script restart <id>` (its `store`
  kept): node `admin.scripts`.
- `/pack list`, `/pack info <pack>` (manifest, API version, effective capabilities with
  their numbers, what is missing, items given per hour), `/pack grant <pack> <capability>
  [param=value ...] | all`, `/pack revoke <pack> <capability>`, `/pack enable <pack>` and
  `/pack disable <pack>` (this world's `packs`): node `admin.packs`. The admin role has both
  through `*`. `/answer` needs no node.

**The benchmark** (`server/budget_scripts.odin`: `budget_scripts`, a headless scene like the
others in `server/budgets.odin`; judged by `tools/bench/budgets.odin` and gated by CI's
"Benchmark check, budgets" step, which already runs on the three OSes). One world, 100 copies
of `server/testdata/scripts/everything.vxs` (each in its own pack, every capability granted
at the defaults, regions 16x16 columns apart), two scripted players (`Fake_Client`s of the
harness) walking a fixed path, 900 ticks stepped. Each copy, every tick: a `tick` handler
with 64 block reads, 2 block edits (alternating two blocks), 1 entity query; every second: a
spawn and a removal, a `chat.say`, an `item.give` and an `item.take` of one wheat, a
`store.set`, a timer, a `ui.notice`; every 10 s an `events.emit` received by the next copy.

- What the scene returns and a test asserts (`test_hundred_scripts`, no timing): no script
  refused, denied, halted or starved; every expected effect present (counts of edits,
  spawns, chat lines, ledger entries); two runs give the same M38 root; the ledger audit
  balances.
- What the bench judges (`build bench budgets -check`, CPU time of the thread): the script
  phase (both points) p99 at most 25% of the tick period (8.3 ms) and the whole tick p99
  under the period; the save of the 100 snapshots under the save capture's budget
  (`budget_save`'s capture limit). The limits sit beside the others in
  `tools/bench/budgets.odin`.
- A smaller form (10 copies, 300 ticks) is what `test_hundred_scripts` runs, so the suite
  stays fast; the bench runs the full one.

**Other tests** (`server/sandbox_test.odin`):

- Every event kind M52b raises received with its fields; `rule_changed` and `mode_changed`
  filters.
- Persistence: save with three scripts mid-timer, reload, the timers fire on the same script
  tick as without the reload; a changed pack hash starts fresh; a script parked at save time
  is snapshotted at its next idle point; `test_save_survives_crashes` with the script files
  (the crash points cover them; every point loads the old or the new generation).
- Journal: rollback by cause undoes a script's items (ledger balanced after), rules and time.
- Commands: `/script` and `/pack` output (exact lines), permission refusals, `/pack grant`
  writing `grants.cfg` and taking effect at the next tick, a restart re-registering an
  added capability.
- Store: round trip of every value type; per-character store travels with the character
  file and stays per world and pack.

**Left out:** client scripts and messaging (M52c, M52d); M53's drawn prompt dialog (the
binding is final, its drawing is M53's); pack causes (M53); signing (M54).
