# M52e: the stable script API (versions, deprecation, compatibility tests)

**Why.** The owner's decision of 2026-10-30 (#83): experiences players make must keep
running as the engine changes. The script API is the one exception to *Before 1.0, no
compatibility*: a pack written for API version N keeps working, with the same results,
while version N is supported. This row makes that a mechanism with a test, not a promise.

**What this builds on:** M52, M52b, M52c, M52d as built: `pack.json`'s `api` (M52 reads and
checks it, `Pack_Behaviour.api`), the `BINDINGS` tables (server and client), `Script_Event`
and `Client_Event`, channel schemas (M52d), the manifest parser; M51's language and standard
library; the harness (`server/harness.odin`) and T3's scenario runner
(`server/scenario_test.odin`); the generated-file pattern of the dissector's schema block
(`./build.sh schema`, compared in `check`, pinned LF in `.gitattributes`).

**What the API is.** Everything a pack's code or manifest can observe:

1. the language and standard library (M51's syntax, semantics and library lists);
2. the manifest members (`api`, `capabilities`, `scripts`, `limits`, `client_*`,
   `channels`) with their parameter names, units, defaults and ceilings;
3. every binding: name, side, capability, argument types, results, outcome on refusal
   (raise), denial (`nil, message`) and throttle (parked);
4. every event: name, fields, filters, the tick point it is delivered at;
5. channel schema types and the message codec's bytes;
6. the scheduling contract scripts can see: events from a script's own effects arrive at the
   next point, a script never receives its own, `load` reasons, round-robin order.

Not the API (may change in any build, written in the reference): error message text (its
shape is: a string), instruction costs and the instruction count a run takes, the
collector's timing, internal names, snapshots (valid within one engine build, M51c), the
numbers of engine ceilings within a version (raising is allowed; lowering is a new version).

**The description** (`common/game/script_api.odin` and generated files):

- `BINDINGS` rows gain `since: u16` and `deprecated: u16` (0: not), events and manifest
  members the same; a binding whose behaviour changes gets a new row with the same name and
  a later `since`, and the old row gets `until: u16`. Dispatch picks the row by the pack's
  `api` once, at VM start, when registering natives: two packs on two API versions in one
  world each see their own version, at no per-call cost.
- `./build.sh scriptapi` writes `docs/script_api/v<N>.json` for every supported version
  (machine-readable: every item of the list above, for a model or a tool to read) and
  `docs/script_api.md` (the human reference, generated, with *since* and *deprecated* on
  every item). `check` runs the generator in memory and fails when the committed files differ
  (`lint_script_api`), so a binding cannot change without its description and the
  description cannot drift from the code. Both are pinned LF.
- `CURRENT_API :: 1`, `OLDEST_API :: 1` (`common/game/script_api.odin`). A version, once
  released in a tagged build, is frozen: `lint_script_api` also compares
  `docs/script_api/v<N>.json` for every N below `CURRENT_API` with the generator and refuses
  any change to a frozen version (a frozen version's file is regenerated byte for byte or the
  check fails). Adding to the API means a new version `CURRENT_API + 1`.

**Deprecation.** A deprecated binding, event or member keeps working in every version that
has it. Using one logs one `info` line per pack at load (`demo uses world.fill, deprecated
since API 3: use world.fill_box`), shows in `/pack info`, and is a warning in M54g's static
validator. **No version is ever dropped without the owner's decision**: `OLDEST_API` moves
only by an owner's decision recorded in the plan; until then every version since 1 is
supported.

**The compatibility suite** (`server/script_api_compat_test.odin`;
`server/testdata/api/v<N>/<fixture>/`):

- A fixture is a pack written against version N plus a recorded session: the harness's
  inputs (players' inputs, edits, chat, channel messages) on `worldgen.Flat`, and the
  expected outcome: the scripts' logs, the journal entries caused by scripts (kind, position,
  block, item, count), the messages delivered to clients (pack, channel, data), and the
  ledger's script totals. Not the world hash: worldgen, physics and other engine changes
  may move it; the outcome is what the scripts did.
- `test_api_compat` replays every fixture of every supported version against the current
  engine and compares the outcome exactly. A difference fails and prints the first item that
  differs.
- Coverage: the replay counts every binding, event and manifest member exercised per
  version; `test_api_coverage` fails when a supported version has one that no fixture
  exercises, so a new binding comes with its fixture.
- Version 1's fixtures are written in this row, at least one per capability (server and
  client), plus the hostile rows' refusals and denials (their *outcomes*, not their message
  text).
- `./build.sh scriptapi --record <fixture>` re-records a fixture's expected outcome; a
  fixture of a frozen version may not be re-recorded (`check` compares the expected-outcome
  files of frozen versions against git's copy at the version's tag, by the tag named in
  `docs/script_api/v<N>.json`'s `frozen_at`).

**Freezing at a release.** The Friday tag (*Versions*, the loop script) is when a version
becomes frozen: the session that adds `CURRENT_API + 1` writes `frozen_at` into the previous
version's file. Nothing else in the release process changes.

**Order of the steps:**

1. `since`, `deprecated`, `until` on bindings, events and members; dispatch by version at VM
   start; `CURRENT_API`, `OLDEST_API`.
2. The generator, `./build.sh scriptapi`, `docs/script_api/v1.json`, `docs/script_api.md`,
   `lint_script_api` (and its own tests in `tools/build/lints_test.odin`).
3. The fixture format, the recorder, `test_api_compat`, `test_api_coverage`, version 1's
   fixtures.
4. Deprecation's load line and `/pack info`; a test version (below).

**Tests:** the generator's output for a small table (exact text); `lint_script_api` failing
on a changed binding without regeneration and on a changed frozen version; dispatch: a test
build with a `TEST_API` version 2 (under `when ODIN_TEST`) where `world.fill` changes
behaviour, two packs (api 1 and 2) in one world each getting their own; a deprecated binding
logs once; `test_api_compat` failing when a binding's behaviour is changed on purpose in a
test (the exit check's mutation, reverted); `test_api_coverage` failing when a fixture is
removed.

**Left out:** a public SDK, editor integrations and type stubs beyond the JSON (a later row
for creator tools may generate them from it); semantic versioning of packs themselves (a
pack's `version` stays a label); compatibility of saves and the protocol (still none before
1.0).

**Threat model and fuzzing (Q1, Q5; #84):** mark the threat rows this milestone's defences
answer `built` in `docs/threat_model.md`, with their covers (tests, fuzz targets), in the same
commit; an untrusted input it adds gets a target in `build fuzz` (Q1's harness) and a line in
`docs/fuzzing.md`. `lint:quality_docs` fails otherwise.

**Exit check:** `lint_script_api` passes and fails as tested; `test_api_compat` and
`test_api_coverage` pass with version 1's fixtures; changing `world.set_block`'s behaviour
on purpose fails `test_api_compat` (done once, reverted, quoted in the report); the suite,
`build check`, `build determinism`; CI green.

**Check by hand:** none.
