# M53: the declarative gameplay layer (triggers, quests, spawners, dialogue, loot, the mechanism for modes and death)

Data the engine interprets so agents write less code. Every effect of data runs through
M52's binding layer as its pack's **data runner** (one per pack per world, id
`<pack>:data`), so the pack's capabilities, budgets, journal cause and logs apply to data
exactly as to scripts.

**Superseded in part (2026-10-28, issue #52):** the owner decided the LAN party's survival
rules (issue #52) and M48f-M48g build game modes (as data,
per player), abilities, one damage pipeline, one rules table, death messages and a real death
screen in Odin first. This milestone **re-expresses** them on the declarative layer (the
`game_mode` registry kind is M48f's `data/game_modes`; `base:death`'s dialogue shows the
cause M48g's screen shows) instead of building them; where this spec says "no death message"
or "damage off by default", M48g's behaviour wins. Everything else the owner decides stays
a hard stop.

**Mechanism only for what the owner decides.** The plan's hard-stop list is a hard
stop: survival's rules and numbers, death and respawn (what you keep, where you wake, any
penalty), health's look. This milestone builds the *mechanism* (data can express what
happens on a death and a world has a game mode) and chooses **no rules**: the base pack's
`base:creative` and `base:survival` list no rules, no death cause has a chat line, and
today's behaviour (damage off by default, instant respawn at the spawn, `death_drops` as
the rule it is today) is unchanged and not improved until the owner designs it. A session
that wants a number, a message or a penalty here does not pick one.

Two sessions: **M53** (the data model and its runtime: regions,
triggers, conditions, actions, variables, pack rules, the game-mode mechanism, loot, quests,
death causes as ids) and **M53b** (dialogue and prompts with their UI, the placeholder death screen,
spawners and encounters, the quest tracker, the two-player UDP exit). Both are written here; the
notes ask for the table row to be split before M53 starts.

**What this builds on:** M52 (all of it; `Script_Event` and the two tick points), M47
(registries, the pack format, file:line errors), M48 (block entities: containers for
`loot into`), M50 (pack-defined entity kinds, `Tags`, `Origin`, killer on death, spatial
queries), M46 (character and world state through versioned schemas), M42 (focus
navigation for the prompt), M40 (`rules.damage` off by default, the health bar hidden
then).

**Where the data lives.** New M47 registry kinds, each a directory of text files in a
pack: `region`, `trigger`, `quest`, `dialogue`, `spawner`, `encounter`, `loot_table`
(M47 lists the kind; its format is here), `death_cause`, `game_mode`, `rule`. Ids are
`<pack>:<name>`. Gameplay registries are per world (the world's pack list), as scripts
are. Types and parsers in `common/game/gameplay.odin` (shared: M54's validator reads them);
runtime in `server/gameplay.odin` (triggers and actions), `server/quests.odin`,
`server/loot.odin`, `server/modes.odin`, `server/death.odin`; in M53b
`server/dialogue.odin`, `server/spawners.odin`, `client/prompt_ui.odin`.

Common argument forms:

- `pos`: `x y z` (integers or floats), or `~dx ~dy ~dz` relative to the event's player;
  `box`: `x1 y1 z1 x2 y2 z2` inclusive; `region`: a box or a region id.
- `item`, `block`, `kind`: registry ids (`base:wheat`); `count`: 1..4 096; `ticks`:
  1..1 080 000 (10 hours).
- Text: at most 256 bytes (1 024 for dialogue text), chat's `&` codes allowed, fields in
  braces: `{player}`, `{item}`, `{count}`, `{killer}`, `{cause}`, `{quest}`, `{stage}`,
  `{world}`, `{var:<name>}` (the pack's character variable), `{wvar:<name>}` (world
  variable). An unknown field is a load error.
- Limits: 1 024 triggers, 256 quests, 256 dialogues, 64 spawners, 32 encounters, 256 loot
  tables, 256 regions per world; 16 conditions per trigger; 64 actions per list; nesting
  of blocks (`if`, `delay`, `any`, `not`) at most 4 deep.

**Regions** (`data/region/*.txt`): `region well { box = 10 60 10 20 70 20 }` (up to 8
boxes). Each player's membership is a bit set per region (`Client.regions`), updated at
M52's point A with a chunk-column index of the boxes, raising `region_enter` and
`region_leave` for data and for scripts watching them.

**Triggers** (`data/trigger/*.txt`):

```
trigger find_well {
  on = region_enter
  region = demo:well
  once = per_character        # always (default) | per_character | per_world
  cooldown = 600              # ticks, per character (per world for events with no player)
  if {
    quest_stage demo:village = 1
    has_item base:wheat 1
  }
  do {
    message "You found the old well, {player}."
    quest_advance demo:village
  }
  else { message "Nothing here yet." }
}
```

| `command` | `name` (registers `/name` as M52's `command.register` does; same refusals) , `args` (count) | the player; `{arg1}`..`{arg4}` |

**Conditions** (all must hold; `any { }` and `not { }` combine). `op` is one of `= != < <=
> >=`.

| Condition | Holds when |
|---|---|
| `quest_state <quest> <unknown\|active\|completed\|failed>` | the player's quest is in that state |
| `quest_stage <quest> <op> <n>` | active and its stage compares |
| `objective_done <quest> <objective>` | that objective of the current stage is done |
| `has_item <item> <count>` | the player holds at least count (slots, cursor) |
| `wearing <item>` | in an equipment slot |
| `in_region <region>` | the player is inside |
| `rule <name> <op> <value>` | a base rule (`damage`) or pack rule (`demo:wolves`) compares; bools with `=`/`!=` |
| `var <name> <op> <n>`, `wvar <name> <op> <n>` | the pack's character or world variable (absent: 0) |
| `time_between <from> <to>` | the world's time of day is in [from, to) (wrapping past 1) |
| `chance <p>` | the world's gameplay RNG draws under p (0..1) |
| `health <op> <n>` | the player's health compares |
| `mode <id>` | the world's game mode is that one |
| `players_in <region> <op> <n>` | count of players inside compares |
| `alive <tag> <op> <n>` | count of this pack's entities with the tag (M50 query) compares |
| `permission <node>` | the player is allowed the node |
| `any { ... }`, `not { ... }` | any of them holds; none of them holds |

A condition needing a player in a context without one is a load error (`time` with `for =
world` cannot use `has_item`).

**Actions**, each with the M52 capability it runs under (`ACTION_INFO` in
`common/game/gameplay.odin`; a pack whose data uses an action whose capability its manifest does
not declare is refused at load: `data/trigger/well.txt:9: action give needs capability

| Action | Does | Capability |
|---|---|---|
| `message <text>` | a notice to the player | `ui.notice` |
| `say <text>` | a system line to the world, prefixed with the pack's title | `chat.send` |
| `give <item> <count>` | into the inventory (overflow at the feet); ledger `Script_Give` | `item.give` |
| `take <item> <count>` | from the inventory; sink `Script_Take`; with `else { }` when they hold fewer (nothing taken) | `item.take` |
| `loot <table> [at <pos> \| into <pos>]` | rolls a loot table into the player, as item entities at pos, or into a container (M48) | `item.give` (plus `world.read` for `into`) |
| `set_block <pos> <block>`, `fill <box> <block>` | world edits | `world.edit` |
| `explode <pos> <radius>` | an explosion | `world.explode` |
| `spawn <kind> <pos> [count] [tag <t>]` | entities | `entity.spawn` |
| `remove_tagged <tag>` | removes this pack's entities with the tag | `entity.control` |
| `teleport <pos>` | the player | `player.teleport` |
| `damage <amount> [cause]`, `heal <amount>` | the player (cause default `base:script`, else one of the pack's causes) | `player.health` |
| `quest_start`, `quest_advance`, `quest_set <stage>`, `quest_complete`, `quest_fail`, `quest_reset` `<quest>` | the player's quest state | (own data) |
| `objective_add <quest> <objective> [n]` | progress on a `flag` objective | (own data) |
| `var_set <name> <n>`, `var_add <name> <n>`, `wvar_set`, `wvar_add` | the pack's variables (i64, names `[a-z_]{1,32}`, 64 per scope) | `store` |
| `rule_set <name> <value>` | a rule | `rules.set` |
| `mode_set <mode>` | the world's mode, as `/gamemode` without the permission check | `rules.set` (with every rule the mode sets in its `names`) |
| `trigger_enable <trigger>`, `trigger_disable <trigger>` | the pack's own triggers (world-wide, saved) | (own data) |
| `emit <name> [key=value ...]` | an `events.emit` with a flat table of strings and integers | `events.emit` |
| `if { conditions } { actions } [else { actions }]` | branches | |
| `delay <ticks> { actions }` | runs later with the same context (a player gone by then: actions needing one skip, logged at debug) | |
| `dialogue <dialogue> [node]`, `close_dialogue` | opens a dialogue for the player (M53b) | `ui.prompt` |
| `spawner_start`, `spawner_stop <spawner>`, `encounter_start`, `encounter_stop <encounter>` | M53b | `entity.spawn` |
| `respawn` | only in the death screen's choice (M53b); does what today's respawn does | (engine) |

*The action runner.* Matching triggers (at M52's two points, data before scripts, pack
order then file order) queue an `Action_Run {pack, list, pc, ctx}` (ctx: the player's
handle, the event's position, entity, item, count, quest). Runs execute in queue order:
each action is one `sandbox_call` on the pack's data runner. **Throttled** suspends the
run at that action until the bucket allows (the rest of the queue goes on; one run per
pack waits at a time, the later ones of that pack wait behind it, so the order of a
pack's effects is kept). **Refused** (a relative position outside the region, a player
gone) and **Denied** (a cap) skip that action, log it with the trigger's file and line,
and go on; a `take` that cannot take runs its `else`. The data runner halts as a script
does (32 refusals in 900 ticks), stopping only that pack's data. Data cannot loop: a
trigger's actions raise events for the next point only, and `delay` needs at least 1 tick.

**Variables and pack rules.**

- Variables: world ones in the pack's `store` (keys `var.<name>`), character ones in its
  `store.character`. Scripts of the same pack read the same keys.
- Pack rules (`data/rule/*.txt`): `rule wolves { type = bool  default = true  help =
  "wolves attack players" }`, or `type = int|float` with `min`, `max`, `default`. A pack
  rule is a variable of the world: listed and set by `/rule` (`/rule demo:wolves false`),
  read by `rule` conditions and `rules.get`, set by `rule_set` and `rules.set`, chosen by
  game modes. Saved in `world.cfg` as `rules.demo.wolves = true` after the base rules;
  lines for rules whose pack is gone are kept and written back unchanged (a pack removed
  and added back finds its values). Not replicated: the client's prediction reads only
  base rules. Changing one raises `rule_changed` and goes through the journal (cause the
  command, the script or the data runner).

**Game modes** (`data/game_mode/*.txt`).

- Two base rules are added to `game.Rules` (with `RULES_VARS` rows, help text and
  tooltips' wording): `catalog` (bool, default true: "the Creative tab offers every item")
  and `infinite_items` (bool, default true: "placing uses nothing up and breaking gives
  nothing"). Today's checks of `items.catalog` and `items.infinite` (server
  `actions.odin`, `items.odin`, `entities.odin`; client `session_controls.odin`,
  `inventory_ui.odin`, `items.odin`) become `rules.X && allowed(node)`: the rule says what
  the world offers, the permission who may take it. `DEFAULT_PERMISSIONS` gains `grant
  items.catalog` and `grant items.infinite` in the default role for new universes; an
  existing `permissions.cfg` is not changed, so an existing server's players keep what
  they have.
- The base pack's modes are **`base:creative` and `base:survival`, and both list no rules**:
  the owner has not designed survival (its rules, numbers and gathering), so choosing a
  mode records it and changes nothing else; today's behaviour, whatever the world's rules
  are, stays. A mode's rule list is the mechanism: a pack's mode may set any base or pack
  rule, and the tests use test packs' modes for that. `catalog` and `infinite_items` default
  true, which is today's behaviour; no base mode sets them until the owner designs
  survival. Hunger and break times do not exist and are not added.
- Format: `game_mode survival { title = "Survival"  selectable = true  rules { damage =
  true ... } }`. A mode naming an unknown rule or a value out of the rule's range is a
  load error with the range.
- A world records its mode in `world.cfg` (`mode = base:survival`). A new world takes
  `universe.cfg`'s `mode` (new key, default `base:creative`), applied over the defaults
  when it is made (the default `damage` stays off as M40 made it). A `world.cfg` without a `mode` line
  is a load error (no reading of worlds saved before M53: before 1.0 there is no compatibility).
- `/gamemode` shows the world's mode and the selectable ones (node `info.rules`, which
  the default role has). `/gamemode <name>` (`survival` finds `base:survival`; an
  ambiguous short name lists the candidates) needs `world.gamemode.<pack>.<name>` (e.g.
  `world.gamemode.base.survival`; the admin role has them through `*`, the default role
  none; the singleplayer owner has every node). A mode with `selectable = false` is set
  only by `mode_set` and `rules.set`. It sets the listed rules in one journal mutation
  (cause `Command`), records the mode, sends the `Rules` record (M39) and announces to the
  world as a system line: `Alice switched this world to Survival.` Unchanged: a notice
  `This world is already in Survival.`
- `/gamemode` replaces the "not taken from Minecraft" note of M26b; `/help` lists it.

**Loot tables** (`data/loot_table/*.txt`):

```
loot_table ruin {
  rolls = 2 4                 # uniform, inclusive
  entry base:wheat  weight = 10  count = 1 3
  entry base:seeds  weight = 6   count = 2 5
  entry table demo:rare  weight = 1
  entry nothing  weight = 5
  budget { per_hour = 32 }     # items from this table, per world
}
```

- Each roll picks an entry by weight with the world's gameplay RNG; `count` uniform
  inclusive; `table` rolls that table once (nesting at most 4; a cycle is a load error);
  `nothing` gives nothing. Weights 1..10 000, total above 0.
- Budgets: the table's own bucket (items an hour per world, capacity `per_hour`, refilled
  per tick), then M52's `item.give` buckets for each item (script, per player, world
  pool). What does not fit is not made: the roll gives what remains, logged at `debug`;
  if nothing was given the action's `else { }` runs (`else { message "The ruin is empty
  for now." }`). Every item of every table must be in the pack's `item.give items` list
  (or `*`): checked at load.
- Ledger reason `Loot` (appended to `game.Reason`), so the audit and the `faucets` report
  show loot apart from script gives.
- `loot ... into <pos>` fills a container's empty slots in order (M48's block entity at
  pos, inside the pack's `world.read` region); what does not fit is not made.
- Entity drops by loot table (a kind's `drops = <table>` in M50's pack data) are left to
  content: sheep keep their wool as today.

**The gameplay RNG and state.** Each world has `gameplay: Gameplay_State` (`rng:
base.Rng` seeded from the world seed and the constant string `gameplay` through
`game.Hasher`; trigger `once = per_world` flags and enabled/disabled triggers by id; loot
buckets by table id; spawners and encounters, M53b). Saved with the world through M46's
schema as `worlds/<id>/gameplay.dat` and included in M38's state hash. Per character, per
world, in the character file (a field of the new format, `"gameplay": {"<world dir>":
{"quests": {...}, "once": [...], "store": {...}}}`; no migration, before 1.0): quest states, `once = per_character`
flags. Cooldowns are not saved (a restart clears them).

**Quests and objectives** (`data/quest/*.txt`):

```
quest village {
  title = "The well and the den"
  repeatable = false
  stage find "Find the old well" {
    objective well reach { region = demo:well }
  }
  stage den "Drive off the sheep of the den" {
    on_start { spawner_start demo:den }
    objective sheep kill { kind = base:sheep  tag = den  count = 3 }
  }
  stage back "Return to the elder" {
    objective talk talk { dialogue = demo:elder  node = done }
    on_done { spawner_stop demo:den }
  }
  on_complete { loot demo:reward  say "{player} helped the elder." }
}
```

- Objective kinds: `reach` (`region`), `kill` (`kind`/`tag`, `count`; counts kills by
  this player only), `break`, `place` (`block`, `count`), `collect` (`item`, `count`:
  progress is what the player holds, checked when their inventory changes and when the
  stage starts), `deliver` (`item`, `count`: done by the `deliver` dialogue action, M53b,
  which takes the items), `talk` (`dialogue`, `node`: reaching that node), `use`
  (`block` or `kind`/`tag`), `wait` (`ticks` since the stage started), `flag` (`count`,
  advanced by `objective_add`). At most 8 objectives a stage, 32 stages a quest; a stage
  with `any = true` completes when one objective is done.
- State machine per character, per world, per quest: `Unknown -> Active(stage,
  progress[8], started) -> Completed | Failed`. `quest_start` from `Unknown` (or from
  `Completed`/`Failed` when `repeatable`) enters the first stage and runs its `on_start`.
  When the current stage's objectives are done: its `on_done`, then the next stage's
  `on_start`; past the last stage `Completed` and `on_complete`. A stage's `time_limit =
  <ticks>` fails the quest (`on_fail`) when passed, checked at point B. `quest_advance`
  completes the current stage regardless of objectives; `quest_set` jumps (no
  `on_done`); `quest_reset` returns to `Unknown`. Each transition raises the
  `quest_stage`/`objective_done` triggers and telemetry kinds `Quest_Started`,
  `Quest_Stage`, `Quest_Completed`, `Quest_Failed` (text: the quest; n0: the stage;
  appended).
- Saved as `{"state": "active", "stage": 2, "progress": [1, 0], "started": <script tick>,
  "times": 0}` under the quest id. A quest the pack no longer has: its entry is kept and
  ignored. A stage index past the quest's end reads as its last stage.
- Replicated with a new state kind `Quests` (reliable, singleton, M39: `Quests_Record
  {text: string net:"max=2048"}`): one line per active quest, most recently changed
  first, at most 8, `title \t stage text \t progress` (progress from the objectives:
  `2/3 sheep`, `found`), put each tick and sent only when changed. (M53b draws it.)

**Death causes** (`data/death_cause/*.txt`): the mechanism, with no messages and no rules.

- `death_cause fall { name = "fall" }`: an id that names why damage happened, for events,
  triggers and telemetry. `damage_player(s, c, amount, cause)` takes a
  `Damage_Source {cause: Death_Cause_Id, killer: string}` instead of a string; the two
  callers pass `base:fall` and `base:explosion`. Telemetry `Damage` and `Death` keep a
  text, now the cause's id.
- The base pack registers `base:fall`, `base:explosion`, `base:script` (what a script's or
  data's `damage` uses by default) and `base:generic` (the fallback), and no others: a
  cause for lava, drowning, a mob or hunger comes with the mechanic and the owner's design.
  **No chat line, no death message, no message bag**: nothing new is shown on a death.
- What a death does stays what `die` does today (the inventory dropped by the
  `death_drops` rule, full health, the spawn, the `Player_Died` event). Data may *express*
  more: the `death` trigger (event `player_died`, optional `cause`) runs any actions, and
  the `damage`, `heal`, `give`, `teleport` and `message` actions exist already; a pack
  that wants a penalty or another respawn point writes it. The base pack writes none.
- `/damage <player> <amount> [cause]` (node `world.damage`, admin only) hurts with any
  registered cause, for tests and packs' authors.

**Malformed packs.** Every load error is M47's `file:line: message (fix)`, the pack is
refused for that world (its scripts and data do not run, its other packs do), and the
whole list is logged and sent as notices to players with `admin.packs`. The table test
(`server/gameplay_load_test.odin`, packs built in memory with `pack_load_memory`) checks
each message exactly:

| Broken | Message (shape) |
|---|---|
| `on = regoin_enter` | `trigger/well.txt:2: unknown trigger 'regoin_enter' (did you mean region_enter?)` |
| `quest_advance demo:vilage` | `...: no quest demo:vilage in this world's packs (did you mean demo:village?)` |
| `give` without `item.give` declared | `...: action give needs capability item.give, which pack.cfg does not declare` |
| `has_item` in a `time` trigger for the world | `...: has_item needs a player; time triggers with for = world have none (use for = each_player)` |
| a stage with no objectives | `quest/village.txt:7: stage den has no objectives` |
| a loot cycle a -> b -> a | `loot_table/a.txt:4: loot tables loop: demo:a -> demo:b -> demo:a` |
| all weights 0 | `...: loot table ruin has no weight to roll` |
| a loot item not in `item.give items` | `...: base:diamond is not in item.give's items in pack.cfg` |
| `{playr}` in a text | `...: unknown field {playr} (fields: player, item, count, ...)` |
| a box with min above max | `region/well.txt:1: box min 20 60 10 is above max 10 70 20` |
| a mode setting `gravty` | `game_mode/fast.txt:3: unknown rule gravty (did you mean gravity?)` |
| a mode with `reach = 900` | `...: reach 900 is outside 1..64` |
| a dialogue choice to a missing node (M53b) | `dialogue/elder.txt:9: no node 'fnd' in dialogue elder (did you mean found?)` |
| nesting 5 deep | `...: blocks nest 5 deep; at most 4` |
| a literal position outside the manifest's region | `...: set_block at 500 64 0 is outside world.edit's region in pack.cfg` |

**Order of the steps (M53):**

1. `common/game/gameplay.odin`: types, parsers and validation for region, trigger, condition,
   action, quest, loot table, death cause, game mode, rule; the malformed-pack table test
   for those kinds.
2. Regions and membership; triggers on M52's events at both points; conditions; the
   action runner on the data runner; variables; `delay`, `if`.
3. Pack rules (`/rule`, `world.cfg`), `catalog`/`infinite_items`, game modes,
   `/gamemode`, `universe.cfg`'s `mode`.
4. Loot tables and `Loot`.
5. Quests and objectives, character persistence, the `Quests` record.
6. Death causes (ids only), `Damage_Source`, `/damage`, the `death` trigger, the base pack's data.

**Tests (M53)** (`server/gameplay_test.odin`, stepped server):

- Each trigger kind fires from its event with the right context; `once`, `cooldown`,
  `else`, `trigger_disable` (saved).
- Each condition, table-driven, holding and not; `chance` deterministic by seed.
- Each action's effect, its capability refusal when not granted, its throttle (a
  `give` of 200 with `per_tick`-style limits completes over later ticks in order).
- Variables round-trip through save and load; pack rules in `world.cfg`, including a
  removed pack's lines kept.
- `test_mode_switch_exact`: for creative -> survival (both list no rules: nothing differs
  but the recorded mode) -> a test pack's `demo:adventure` (`damage true, allow_flying
  false, catalog false, infinite_items false, death_drops false, drops false,
  demo:wolves true`) -> creative, the set of rules that differ before and after each
  switch is exactly the mode's listed rules that had other values; every unlisted rule
  unchanged; the announcement sent; the permission refusal names the node; `selectable =
  false` refused by `/gamemode`. The base pack's two modes are asserted to list no rules.
- Catalog: under the test pack's `demo:adventure` the catalog take is refused for the owner;
  in `base:creative` allowed; on a universe whose `permissions.cfg` predates M53 a default
  player has no catalog.
- Loot: 10 000 rolls match the weights within 2% (fixed seed: exact counts in a golden
