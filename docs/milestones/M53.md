# M53: the declarative gameplay layer, part one (the format, regions, triggers, conditions, actions, variables, pack rules, loot, death causes as data)

Data the engine interprets so creators and agents write less code. Every effect of data runs
through M52's binding layer as its pack's **data runner** (one per pack per world, id
`<pack>:data`), so the pack's capabilities, budgets, journal cause and logs apply to data
exactly as to scripts.

**The split (2026-10-30, #86).** The declarative layer is three rows, each one session with its
own exit check: **M53** (this row: the format, regions, triggers, conditions, actions, the
action runner, variables, pack rules, loot tables, death causes as data); **[M53b](M53b.md)**
(quests and objectives, dialogue and prompts with their UI, the quest tracker); **[M53d](M53d.md)**
(spawners, encounters, the demo pack and the two-player UDP exit). The old two-row text put
quests here and spawners in M53b; quests moved to M53b because they need dialogue's `talk` and
`deliver` and are the bulk of a session on their own.

**Checked against the code (2026-10-30, #86; corrections made in this revision):**

## Design (M53)

### Where the data lives

New `Content_Kind`s (appended; `KIND_DIRS` rows): `Region` (`server/regions`), `Trigger`
(`server/triggers`), `Loot_Table` (`server/loot_tables`), `Pack_Rule` (`server/rules`),
`Death_Cause` (`data/death_causes`); M53b adds `Quest` and `Dialogue`, M53d `Spawner` and
`Encounter`. Each file is a JSON object of named definitions, as every kind's is
(`{"find_well": {...}, "leave_well": {...}}`); ids are `<pack>:<name>`. Definitions are
universe-wide like all registry content (M47: fixed while the server runs, reloaded by
M47i's hot reload with the rest); they **run** only in worlds whose `world.cfg` `packs` list
the pack (M52). Types, parsers and validation in `common/game/gameplay.odin` (shared: M54's
validator reads them) and `common/game/gameplay_statements.odin` (conditions and actions);
the runtime in `server/gameplay.odin` (regions, triggers, the action runner),
`server/gameplay_state.odin` (`Gameplay_State`, save, hash), `server/loot.odin`,
`server/pack_rules.odin`.

**API version.** Gameplay data is part of the stable API (M52e): a pack with any gameplay
kind must declare `api`, the vocabulary below (trigger kinds and their parameters, conditions,
actions, text fields) is listed under `"data"` in `docs/script_api/v<N>.json` by `./build.sh
scriptapi`, and M52e's compatibility suite gains a data-only fixture (`server/testdata/api/v<N>/
data_only/`: a region, a trigger, a loot table, a pack rule, run for 600 ticks to a recorded
root). If API 1 was already released in a tagged build when this row runs, the vocabulary is
API 2 (`CURRENT_API` 2, `since = 2` on every item); otherwise it joins 1. The session reads
`git tag` and says which in the report.

### The statement strings

A condition or an action is a short string in the statement language of M49b, lexed by
`sim_lexer.odin`, its errors `Pack_Error`s at the exact token. This row adds two token kinds
to the lexer and nothing else: a decimal literal (`[0-9]+\.[0-9]+`, so `1..3` still lexes as
`1 .. 3`) and `~` (relative positions). M49b's lexer tests stay unchanged and passing.
Statements that carry text or a nested list are JSON objects with one fixed key, because a
text inside a JSON string would need escapes:

```json
{
  "find_well": {
    "on": "region_enter",
    "region": "demo:well",
    "once": "per_character",
    "cooldown": 600,
    "if": ["var visits < 3", "has_item voxiverse:wheat 1"],
    "do": [
      {"message": "You found the old well, {player}."},
      "var_add visits 1",
      {"if": ["chance 0.25"], "do": ["give voxiverse:feather_charm 1"]}
    ],
    "else": [{"message": "Nothing here yet."}]
  }
}
```

Argument forms: `pos` is `x y z` (integers or decimals) or `~dx ~dy ~dz` (relative to the
event's player); `box` is `x1 y1 z1 x2 y2 z2` inclusive; `region` is a region id; `item`,
`block`, `kind` are registry ids (a bare name is the pack's own, then `voxiverse`, refused when
both have it, M49b's rule); `count` 1..4 096; `ticks` 1..1 080 000 (10 hours).

**Text** (a JSON string, never lexed): at most 256 bytes (1 024 for dialogue in M53b), chat's
`&` codes allowed, fields in braces: `{player}`, `{item}`, `{count}`, `{killer}`, `{cause}`,
`{world}`, `{arg1}`..`{arg4}`, `{var:<name>}` (the pack's character variable), `{wvar:<name>}`
(world variable); M53b adds `{quest}`, `{stage}`. An unknown field is a load error listing
the fields. Fields are filled on the server, through `chat_clean`.

**Limits** (constants in `gameplay.odin`, `GAMEPLAY_LIMITS`, read by M54g's validator): per
world, 1 024 triggers, 256 regions, 256 loot tables, 64 pack rules per pack; per trigger 16
conditions; 64 actions per list; nesting of blocks (`if`, `delay`, `any`, `not`, `else`) at
most 4 deep; a region at most 8 boxes; a statement at most 64 tokens (M49b's).

### Regions (`server/regions/*.json`)

`{"well": {"boxes": [[10, 60, 10, 20, 70, 20]]}}` (1 to 8 boxes). Each player's membership is
a bit set per world (`Client.regions: bit_set` over the world's region indices, 256 bits),
updated at M52's point A from a chunk-column index of the boxes (`Region_Index`: column to
the region indices whose boxes touch it, built when the world's packs start), raising
`region_enter` and `region_leave` (M52's events: data and scripts both receive them; a
script's `regions.watch` boxes are unchanged).

### Triggers (`server/triggers/*.json`)

Members: `on` (required), its parameters, `once` (`always` default, `per_character`,
`per_world`), `cooldown` (ticks, per character; per world for events with no player),
`enabled` (default true), `if` (conditions), `do` (actions, required), `else` (actions).

`on` is a `Script_Event` name (M52's vocabulary, one list for scripts and data) or one of the
data-only kinds; each is fed by the event of the same name:

| `on` | Parameters | Player in context |
|---|---|---|
| `region_enter`, `region_leave` | `region` (required) | the player |
| `region_inside` (data only) | `region`, `every` (ticks) | each player inside |
| `item_used`, `item_picked` | `item`, `count` (at least; `item_picked`) | the player |
| `block_broken`, `block_placed`, `block_used` | `block`, `region` (both optional) | the player |
| `entity_used` | `kind` and/or `tag` | the player |
| `entity_died` | `kind` and/or `tag`; `by_player` (bool: a player killed it) | the killer, when a player |
| `player_died` | `cause` (optional), `by_player` (optional) | the one who died |
| `player_respawn`, `player_arrive`, `player_depart` | `how` (`join`, `travel`, `leave`; arrive and depart) | the player |
| `mode_changed` | `to` (optional mode id) | the player |
| `rule_changed` | `name` (optional) | none |
| `time` (data only) | `at` (a time of day 0..1, as `/time set` reads it) or `every` (ticks); `for` = `world` (default) or `each_player` | none, or each player |
| `command` | `name` (registers `/name` exactly as M52b's `command.register`, same refusals), `args` (count, 0..4) | the player; `{arg1}`..`{arg4}` |
| `custom` | `name` (an `events.emit` name) | the event's `player` field, if any |

M53b adds `quest_stage`, `objective_done`, `dialogue`; M53d `encounter_cleared`,
`encounter_failed`, `spawner_empty`. A trigger needs the capability its event needs (M52's
*Needs* column: `player.read` for player events, `world.read` for block events inside its
region, `entity.read`, `chat.read`, `command.register`, `rules.read`, `events.custom`); a
missing one is a load error naming it.

### Conditions

All in `if` must hold; `{"any": [...]}` and `{"not": [...]}` combine. `op` is one of `= != <
<= > >=`.

| Condition | Holds when |
|---|---|
| `has_item <item> <count>` | the player holds at least count (slots, equipment, cursor) |
| `wearing <item>` | in an equipment slot |
| `in_region <region>` | the player is inside |
| `rule <name> <op> <value>` | a base rule (`pvp`) or pack rule (`demo:wolves`) compares; bools only with `=` and `!=` |
| `var <name> <op> <n>`, `wvar <name> <op> <n>` | the pack's character or world variable (absent: 0) |
| `time_between <from> <to>` | the world's time of day is in [from, to), wrapping past 1 |
| `chance <p>` | the world's gameplay RNG draws under p (0..1) |
| `health <op> <n>` | the player's health compares |
| `mode <mode>` | the player's game mode is that one (`Client.mode`) |
| `ability <name>` | the player's derived abilities hold it (`derive_abilities`: the way systems ask, M48f) |
| `players_in <region> <op> <n>` | the count of players inside compares |
| `alive <tag> <op> <n>` | the count of this pack's entities with the tag (M50e) compares |
| `permission <node>` | the player is allowed the node |
| `cause <cause>` | the event's damage cause is that one (`player_died`, `player_hurt`) |

A condition needing a player in a context without one is a load error (`time` with `for =
world` cannot use `has_item`). Conditions read state; they need `player.read`, `rules.read`,
`entity.read` as M52's bindings for the same reads do (the table `CONDITION_INFO` holds each
one's capability).

### Actions

Each with the capability it runs under (`ACTION_INFO` in `gameplay_statements.odin`, read by
M54g's validator; a pack whose data uses an action whose capability its manifest does not
declare is refused at load: `server/triggers/well.json:9:7: action give needs capability
item.give, which pack.json does not declare`):

| Action | Does | Capability |
|---|---|---|
| `{"message": text}` | a notice to the player (M52b's `ui.notice` path) | `ui.notice` |
| `{"say": text}` | a system line to the world, prefixed with the pack's title | `chat.send` |
| `give <item> <count>` | into the inventory (overflow at the feet); ledger `Script_Give` | `item.give` |
| `take <item> <count>`, `{"take": "<item> <count>", "else": [...]}` | from the inventory; ledger `Script_Take`; `else` when they hold fewer (nothing taken) | `item.take` |
| `loot <table> [at <pos> \| into <pos>]`, `{"loot": "...", "else": [...]}` | rolls a table into the player, as item entities at pos, or into a container | `item.give` (plus `world.read` for `into`) |
| `set_block <pos> <block>`, `fill <box> <block>` | world edits | `world.edit` |
| `explode <pos> <radius>` | an explosion | `world.explode` |
| `spawn <kind> <pos> [count] [tag <t>]` | entities | `entity.spawn` |
| `remove_tagged <tag>` | removes this pack's entities with the tag | `entity.control` |
| `teleport <pos>` | the player | `player.teleport` |
| `damage <amount> [cause]`, `heal <amount>` | the player, through `damage` and `heal_player` (cause: `voxiverse:script` by default, or one of the pack's own causes) | `player.health` |
| `mode_set <mode>` | the player's mode, through `set_game_mode` with `Mode_Cause {"data", "<pack>:data"}` | `player.mode` (the mode in its `modes`) |
| `var_set`, `var_add`, `wvar_set`, `wvar_add` `<name> <n>` | the pack's variables (i64, names `[a-z_]{1,32}`, 64 per scope) | `store` |
| `rule_set <name> <value>` | a rule, through `rule_set` | `rules.set` (base rules only when in its `names`) |
| `trigger_enable <trigger>`, `trigger_disable <trigger>` | the pack's own triggers (world-wide, saved) | (own data) |
| `emit <name> [key=value ...]` | an `events.emit` with a flat table of strings and integers | `events.emit` |
| `{"if": [...], "do": [...], "else": [...]}` | branches | |
| `{"delay": <ticks>, "do": [...]}` | runs later with the same context (a player gone by then: actions needing one skip, logged at `debug`) | |

M53b adds the quest actions, `dialogue`, `close_dialogue`, `prompt`; M53d `spawner_start`,
`spawner_stop`, `encounter_start`, `encounter_stop`. There is no `respawn` action: the
Respawn button is M48g's, and `player.respawn` stays a script binding (M52b).

*The action runner.* Matching triggers (at M52's two points, data before scripts, pack order
then file order then name order) queue an `Action_Run {pack, list, pc, ctx}` (ctx: the
player's handle, the event's position, entity, item, count, cause, args). Runs execute in
queue order; each action is one `sandbox_call` on the pack's data runner, with arguments
already typed (the runner fills M52's checked-argument record directly; it does not build VM
values: `sandbox_call_typed` if M52's entry only takes VM values). **Throttled** suspends
the run at that action until the bucket allows (the rest of the queue goes on; one run per
pack waits at a time, the later ones of that pack wait behind it, so the order of a pack's
effects is kept). **Refused** (a relative position outside the region, a player gone) and
**Denied** (a cap) skip that action, log it with the trigger's file, line and column, and go
on; a `take` or `loot` that cannot runs its `else`. The data runner halts as a script does
(M52: 32 refusals within 900 ticks), stopping only that pack's data; `/script list` shows it
as `<pack>:data`. **Data cannot loop:** a trigger's effects raise events for the next point
only (M52's rule), `delay` needs at least 1 tick, and at most 4 096 actions run per pack per
point (the rest wait, counted as starved).

### Variables and pack rules

- Variables: world ones in the pack's `store` (keys `var.<name>`), character ones in its
  `store.character`. Scripts of the same pack read the same keys.
- Pack rules (`server/rules/*.json`): `{"wolves": {"type": "bool", "default": true, "help":
  "wolves attack players"}}`, or `"type": "int"|"float"` with `min`, `max`, `default`. A pack
  rule is a setting of the world: listed and set by `/rule` (`admin_rule` today lists the
  base table; it lists pack rules after it: `/rule demo:wolves false`), read by `rule`
  conditions and `rules.get`, set by `rule_set` and `rules.set`. Saved in `world.cfg` as
  `rules.demo.wolves = true` after the base rules (`save.odin`'s reader sends `rules.<ns>.*`
  keys to the pack rules, so `vars_read` does not warn of them); lines for rules whose pack
  is gone are kept and written back unchanged. Not replicated: the client's prediction reads
  only base rules. Changing one raises `rule_changed` and goes through the journal (M52b's
  rule entry; cause the command, the script or the data runner).

### Game modes: mechanism only

Modes stay M48f's (per player, abilities, kits). This row adds the `mode` and `ability`
conditions, the `mode_set` action and the `mode_changed` trigger; nothing else. A mode's
`rules` member stays reserved (`{}` only): modes are per player and rules per world, so what a
mode's rules would mean is the owner's (open question 1). The base modes are unchanged; the
test asserts their files are byte-identical to before.

### Loot tables (`server/loot_tables/*.json`)

```json
{
  "ruin": {
    "rolls": [2, 4],
    "entries": [
      {"item": "voxiverse:wheat", "weight": 10, "count": [1, 3]},
      {"item": "voxiverse:seeds", "weight": 6, "count": [2, 5]},
      {"table": "demo:rare", "weight": 1},
      {"nothing": true, "weight": 5}
    ],
    "per_hour": 32
  }
}
```

- Each roll picks an entry by weight with the world's gameplay RNG; `count` uniform inclusive
  (a single integer is exact); `table` rolls that table once (nesting at most 4; a cycle is a
  load error); `nothing` gives nothing. Weights 1..10 000, total above 0.
- Budgets: the table's own bucket (items an hour per world, capacity `per_hour`, refilled per
  tick; optional), then M52's `item.give` buckets for each item (script, per player, world
  pool). What does not fit is not made: the roll gives what remains, logged at `debug`; if
  nothing was given the action's `else` runs. Every item a table can give must be in the
  pack's `item.give` `items` (or `*`): checked at load.
- Ledger reason `Loot` (appended to `game.Reason`, `reason_name` "loot"), so the audit and the
  `faucets` report show loot apart from script gives.
- `loot ... into <pos>` fills a container's empty slots in order (M48b's container block
  entity at pos, inside the pack's `world.read` and `world.edit` regions); what does not fit
  is not made.
- Entity drops by loot table are left to content: sheep keep their wool as today.

### Death causes as data (`data/death_causes/*.json`)

- A cause is an id with the four lines `Death_Line` holds today:
  `{"fall": {"others": "{victim} fell", "you": "You fell", "by": "{victim} was knocked off by
  {attacker}", "by_you": "You were knocked off by {attacker}"}}` (fields `{victim}`,
  `{attacker}`, `{weapon}`; `by` and `by_you` optional, falling back to `others` and `you`).
  The base pack's file holds `fall`, `explosion`, `weapon`, `command`, `void` and M52b's
  `script` with **exactly today's lines** (`DEATH_LINES` and M52b's, as built), and no others:
  a cause for lava, drowning or hunger comes with the mechanic and the owner's design.
- `Source_Kind`, `damage_source_name`, `damage_source_parse` and `DEATH_LINES` are removed.
  `Damage_Source.kind` becomes `cause: Cause_Id` (a `u16` index into `reg.death_causes`);
  engine callers name base causes through `reg.base_causes: Base_Causes {fall, explosion,
  weapon, command, void, script: Cause_Id}`, filled when the registry is built (a base cause
  missing from the base pack is a registry error). `death_text(reg, cause, victim, attacker,
  weapon, viewer_is_victim)` reads the cause's lines. No code tests a cause by name (the
  `lint_mode_names` lint gains the base causes' ids).
- `Player_Died.cause` carries the cause's id (`voxiverse:fall`; `net:"max=64"`, from 32);
  `client/state_apply.odin` finds it in its registry (an unknown id, from a newer server,
  shows `others`/`you` of `voxiverse:command`). `PROTOCOL_VERSION` +1. Telemetry `Damage`
  and `Death` keep a text, now the id.
- A pack may add causes with its own lines; the `damage` action and `player.damage` may name
  `voxiverse:script` (the default) or one of **the pack's own** causes, never an engine cause
  (`fall`, `explosion`, `weapon`, `command`, `void`) or another pack's: refused (`damage cause
  voxiverse:fall belongs to the engine; name one of demo's causes or none`). This replaces
  M52b's `Source_Kind.Script`-only rule; M52b's hostile row 29 (`damage_forge`) keeps its
  expectations and adds "another pack's cause refused, its own accepted".
- `/damage <player> <amount> [cause]` (`admin_damage`, node unchanged): any registered cause,
  `voxiverse:command` by default, for tests and authors.
- A death does what `die` does today (the cause's chat line, the inventory by `drop_on_death`
  and `keep_inventory`, M48g's death screen with the cause line, Respawn, the kit). Data may
  *add* to it: the `player_died` trigger runs any actions. The base pack has none.

### The gameplay RNG and state

Each world has `gameplay: Gameplay_State`: `rng: base.Rng` seeded from the world seed and the
constant string `gameplay` through `game.Hasher`; `once = per_world` flags and
enabled/disabled triggers by id; loot buckets by table id; pending `delay` runs (their list,
pc and context by ids, so they survive a save); M53b and M53d add theirs. Saved as
`worlds/<address>/gameplay.dat` (a versioned header, a CRC, ids as strings) through M46's
atomic write inside the save transaction (M46's crash points extended to the file), and a
section of M38's state hash. Per character, per world, per pack in the character file, an
optional member `"gameplay": {"<address>": {"<pack>": {"once": [...]}}}` (absent: nothing;
no format bump). Cooldowns are not saved (a restart clears them). A trigger, table or rule
the pack no longer has: its state is kept and ignored.

### Malformed packs

Every load error is a `Pack_Error` at file, line and column, with the fix; the pack is
refused for that world (its scripts and data do not run, its other packs do), and the list is
logged and sent as notices to players allowed `server.packs` (M52b's `/pack` node). The table test
(`common/game/gameplay_load_test.odin`, packs from `pack_files_memory`) checks each message
exactly:

| Broken | Message (shape) |
|---|---|
| `"on": "regoin_enter"` | `server/triggers/well.json:3:11: unknown trigger 'regoin_enter' (did you mean region_enter?)` |
| `var_add` with `store` not declared | `...: action var_add needs capability store, which pack.json does not declare` |
| `has_item` in a `time` trigger for the world | `...: has_item needs a player; time triggers with for = world have none (use for = each_player)` |
| `give voxiverse:wheet 1` | `...: no item voxiverse:wheet (did you mean voxiverse:wheat?)` |
| a loot cycle a -> b -> a | `server/loot_tables/a.json:4:9: loot tables loop: demo:a -> demo:b -> demo:a` |
| all weights 0 | `...: loot table ruin has no weight to roll` |
| a loot item not in `item.give` `items` | `...: voxiverse:rifle is not in item.give's items in pack.json` |
| `{playr}` in a text | `...: unknown field {playr} (fields: player, item, count, ...)` |
| a box with min above max | `server/regions/well.json:2:14: box min 20 60 10 is above max 10 70 20` |
| `rule_set gravty 3` | `...: unknown rule gravty (did you mean gravity?)` |
| `rule_set reach 900` | `...: reach 900 is outside 1..64` |
| nesting 5 deep | `...: blocks nest 5 deep; at most 4` |
| a literal position outside the manifest's region | `...: set_block at 500 64 0 is outside world.edit's region in pack.json` |
| `damage 5 voxiverse:fall` | `...: damage cause voxiverse:fall belongs to the engine; name one of demo's causes or none` |
| a death cause with `{atacker}` | `data/death_causes/zap.json:3:12: unknown field {atacker} (fields: victim, attacker, weapon)` |
| a statement of 70 tokens | `...: statement too long (over 64 tokens): split it` (M49b's) |
| an escape in a statement | `...: a statement may not contain escapes or control characters: write it plainly` |
| gameplay data without `api` | `demo/pack.json:1:1: a pack with gameplay data needs "api" (supported: 1)` |
