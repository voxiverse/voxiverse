## Design (M53b)

### Quests and objectives (`server/quests/*.json`)

```json
{
  "village": {
    "title": "The well and the den",
    "repeatable": false,
    "stages": [
      {"name": "find", "text": "Find the old well",
       "objectives": [{"name": "well", "reach": "demo:well"}]},
      {"name": "den", "text": "Drive off the sheep of the den",
       "on_start": ["spawner_start demo:den"],
       "objectives": [{"name": "sheep", "kill": "voxiverse:sheep", "tag": "den", "count": 3}]},
      {"name": "back", "text": "Return to the elder",
       "objectives": [{"name": "talk", "talk": "demo:elder", "node": "done"}],
       "on_done": ["spawner_stop demo:den"]}
    ],
    "on_complete": ["loot demo:reward", {"say": "{player} helped the elder."}]
  }
}
```

(`spawner_start` is M53d's; until then M53b's test pack's quest uses `spawn`.)

- Objective kinds (one key names the kind): `reach` (a region), `kill` (`kind`/`tag`,
  `count`; kills by this player only, from M50e's `Entity_Death.killer`), `break`, `place`
  (`block`, `count`), `collect` (`item`, `count`: progress is what the player holds, checked
  when their inventory changes and when the stage starts), `deliver` (`item`, `count`: done by
  the `deliver` dialogue action, which takes the items), `talk` (`dialogue`, `node`: reaching
  that node), `use` (`block` or `kind`/`tag`), `wait` (`ticks` since the stage started),
  `flag` (`count`, advanced by `objective_add`). At most 8 objectives a stage, 32 stages a
  quest, 256 quests a world; a stage with `"any": true` completes when one objective is done.
- The state machine per character, per world, per quest: `Unknown -> Active(stage,
  progress[8], started) -> Completed | Failed`. `quest_start` from `Unknown` (or from
  `Completed`/`Failed` when `repeatable`) enters the first stage and runs its `on_start`.
  When the current stage's objectives are done: its `on_done`, then the next stage's
  `on_start`; past the last stage `Completed` and `on_complete`. A stage's `time_limit`
  (ticks) fails the quest (`on_fail`) when passed, checked at point B. `quest_advance`
  completes the current stage regardless of objectives; `quest_set <quest> <stage>` jumps (no
  `on_done`); `quest_reset` returns to `Unknown`. Each transition raises the `quest_stage` and
  `objective_done` triggers (data only) and telemetry kinds `Quest_Started`, `Quest_Stage`,
  `Quest_Completed`, `Quest_Failed` (appended; text the quest, n0 the stage).
- New actions (own data, no capability): `quest_start`, `quest_advance`, `quest_complete`,
  `quest_fail`, `quest_reset` `<quest>`, `quest_set <quest> <stage>`, `objective_add <quest>
  <objective> [n]`. New conditions: `quest_state <quest> <unknown|active|completed|failed>`,
  `quest_stage <quest> <op> <n>` (stages count from 1), `objective_done <quest> <objective>`.
  New text fields `{quest}` (its title) and `{stage}` (its text).
- Saved in the character file under M53's member: `"gameplay": {"<address>": {"<pack>":
  {"once": [...], "quests": {"<id>": {"state": "active", "stage": 2, "progress": [1, 0],
  "started": <script tick>, "times": 0}}}}}`. A quest the pack no longer has: its entry is
  kept and ignored; a stage index past the quest's end reads as its last stage.
- Replicated by a new state kind `Quests` (reliable, singleton, M39): `Quests_Record {text:
  string net:"max=2048"}`, one line per active quest, most recently changed first, at most
  8: `title \t stage text \t progress` (progress from the objectives: `2/3 sheep`, `found`),
  put each tick and sent only when changed. `PROTOCOL_VERSION` +1 with the message below.

### Dialogue and prompts (`server/dialogues/*.json`)

```json
{
  "elder": {
    "speaker": "Elder Ama",
    "nodes": {
      "start": {
        "text": "Travellers again. Will you help an old woman?",
        "choices": [
          {"label": "I will.", "if": ["quest_state demo:village = unknown"],
           "do": ["quest_start demo:village"], "goto": "bye"},
          {"label": "I found the well.", "if": ["quest_stage demo:village = 2"], "goto": "well"},
          {"label": "The den is quiet now.", "if": ["quest_stage demo:village = 3"], "goto": "done"},
          {"label": "Goodbye.", "goto": "end"}
        ]
      },
      "well": {"text": "Then the den is next.", "choices": [{"label": "On my way.", "goto": "end"}]},
      "done": {"text": "Thank you. Take this.", "do": ["quest_advance demo:village"],
               "choices": [{"label": "Farewell.", "goto": "end"}]},
      "bye": {"text": "Find the old well first.", "choices": [{"label": "Goodbye.", "goto": "end"}]}
    }
  }
}
```

- A node: `title` (optional), `text` (at most 1 024 bytes), 1 to 6 choices, `do` (runs when
  the node is reached). A choice: `label` (at most 96 bytes), `if` (hidden when false,
  evaluated when the node is sent), `do`, `goto` (a node or `end`, which closes), `leave`
  (bool: the client leaves the world after answering). Dialogue members: `speaker`, `style`
  (`dialogue`, the default, or `screen`), `closable` (default true: Escape or Back answers -1
  and closes), `range` (default 8: blocks from the entity that opened it, when one did;
  further away closes it). The first node is `start` (required).
- Actions: `dialogue <dialogue> [node]` and `close_dialogue` (capability `ui.prompt`);
  `{"prompt": {"text": ..., "choices": [...]}}`, a one-node dialogue written inline;
  `{"deliver": "<quest> <objective>", "else": [...]}` (a choice's action: takes the
  objective's items and marks it done; `else` when the player holds too few; `item.take`).
- `ui.prompt` (M52b) accepts the optional members `speaker`, `title`, `style`, `closable`
  beside `text` and `choices`; they join the API version M53's data vocabulary joined (M53's
  *API version* rule).
- **One prompt shown per player** (`Client.prompt: Shown_Prompt {seq: u32 (new for every node
  sent), source (a dialogue id and node, or a pack's script prompt id), the visible choices'
  indices, the entity and its position}`). M52b's `Open_Prompt` per pack stays the
  bookkeeping of scripts' prompts; the shown one is the newest from any source. A new prompt
  replaces the shown one, and the replaced one answers -1 to its source. It closes on travel,
  leave, death (M48g's screen covers everything; while dead nothing opens) and range.
- New state kind `Prompt` (reliable, singleton): `seq: u32, style: u8, closable: bool,
  speaker: string net:"max=64", title: string net:"max=64", text: string net:"max=1024",
  choices: string net:"max=768"` (one line per visible choice: `-` or `L` (leave), a space,
  the label); `seq` 0 means closed. Text is formatted on the server.
- New client message `Answer {seq: u32, choice: i8}` (appended to `Client_Kind`). The server
  accepts it only for the shown prompt's `seq`, while alive, with a choice in range or -1
  when closable; anything else is refused (logged at `debug`, counted, not a disconnect: an
  answer can cross a replaced prompt). Rate: at most 10 answers a second per player (the
  rest dropped and counted). An answer runs the choice's `do`, then `goto`; reaching a node
  raises the `dialogue` trigger (`dialogue`, `node`) and `talk` objectives; for a script's
  prompt it raises `prompt_answer` to that pack.
- `/answer` and M52b's notice-sending of prompts are removed.

### The client

- `client/overlay_prompt.odin`: `Overlay.Prompt` (`takes = {.Keyboard, .Mouse}`, `in_game =
  true`; the world goes on; below the game menu and the death screen). `dialogue` style: a
  panel at the bottom centre, 640 px wide at UI scale 1, the speaker in the theme's accent
  colour, the text wrapped, the choices as a column of buttons numbered 1-6 (keys 1-6 pick
  them). `screen` style: the backdrop dims the screen, the title large in the centre, the text
  under it, the buttons centred below. Focus starts on the first choice; M42's navigation
  moves it, confirm answers, Back and Escape answer -1 when closable and do nothing otherwise
  (Escape still opens the game menu over a screen-style prompt, so Leave stays reachable).
  Glyphs follow the last device (M42). It opens and closes with the record; the client sends
  `Answer` once and greys the buttons until the next record.
- `client/hud_quests.odin`, the tracker: the `Quests` record at the top right, up to three
  quests, the title in the accent colour, the stage text, the progress dimmed; nothing when
  empty; hidden with the rest of the HUD while dead, paused or with F1. Through the theme
  (M40), so `theme_scope` reaches it. It never overlaps the chat or the player list (both are
  laid out from the same screen rect; a layout test asserts it).
