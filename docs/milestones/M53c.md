# M53c: Ogg Vorbis in Odin

One session (owner's decision, 2026-10-28, #44). Pack sounds (M47b, M47i) arrive from
servers and were decoded by miniaudio's C decoder: the one place untrusted network data
meets C code. M47b refused `stb_image` for pack PNGs for the same reason. This milestone
puts a Vorbis I decoder and an Ogg reader in Odin, bounds-checked, that refuses malformed
input with an error and never crashes, and sends every Ogg the game reads through it.
miniaudio keeps opening the output device until *Audio devices in Odin* (the next tier),
which removes it. The decision row is *Third-party code in the game* (locked, in the
foundation arc's table).

Why before M54: M54's validator and moderation hooks look at pack sounds, and they should
look at the output of the code that will play them. Nothing in M54 depends on this, so it
sits where it costs no one else's order.

## The package: `common/ogg/`

Shared, because the server validates a pack's sounds (`game.ogg_check`) and the client
plays them. Imports `base` only. Files: `ogg.odin` (pages), `vorbis.odin` (headers, packets),
`codebook.odin`, `floor.odin`, `residue.odin`, `mdct.odin`, `ogg_test.odin`, `fuzz_test.odin`.

```odin
Error :: enum {None, Bad_Page, Bad_Crc, Not_Vorbis, Bad_Header, Bad_Setup, Unsupported,
	Over_Limit, Bad_Packet, Truncated, Bad_Seek}

Info :: struct {rate: u32, channels: u8, frames: u64 /* 0 when unknown */, bitrate: u32}

open     :: proc(data: []byte, allocator := context.allocator) -> (d: ^Decoder, err: Error)
close    :: proc(d: ^Decoder)
info     :: proc(d: ^Decoder) -> Info        // of the link being read
read     :: proc(d: ^Decoder, out: []f32) -> (frames: int, err: Error) // interleaved; 0 and .None = end
seek     :: proc(d: ^Decoder, frame: u64) -> Error   // frame counted from the start of the first link
scan     :: proc(data: []byte) -> (info: Info, links: int, err: Error) // no decode: what ogg_length needs
```

The input is a whole file in memory (every caller has one: packs, the committed music, the
streams, which already hold the file). No file or reader interface; nothing blocks.

### Ogg pages (`ogg.odin`)

- A page: the `OggS` capture, version 0, header type flags (continued, first, last), the
  granule position (i64, -1 when no packet ends on it), serial, sequence, CRC-32 (the Ogg
  polynomial 0x04C11DB7, computed over the page with the CRC field zeroed; a table built at
  compile time), segment count and table, up to 255 segments. A bad CRC is `.Bad_Crc`: a
  page is never trusted unchecked. Lost sync after a good page is an error, not a search
  (a file with junk between pages is not a valid Ogg; this is a game's data, not a
  recovery tool).
- Packets are rebuilt from segments across pages (a packet continues while a segment is 255
  bytes long) into one fixed buffer, `MAX_PACKET` = 64 KiB (a Vorbis packet is far smaller
  for blocks up to 8192 at any sane bitrate); longer is `.Over_Limit`.
- A **link** (a chained stream) starts at a page with the first-page flag and ends at its
  last-page flag. Chained links are decoded in order; a new link has its own headers, rate
  and channel count (`info` follows the link being read). Grouped streams (several serials
  open at once) are `.Unsupported`; so is a link that is not Vorbis (Theora, Opus, FLAC:
  `.Not_Vorbis`). A sequence-number gap or a page of another serial inside a link is
  `.Bad_Page`.
- At `open` the file is walked once, page header by page header (no packet decoding), into
  a fixed index of links: first page offset, granule of its last page, rate and channels.
  `MAX_LINKS` = 64, `MAX_PAGES_INDEXED` = 1 << 16 (a seek table, one entry per 64 pages
  and per link's first and last; the walk itself has no limit but the file size). More
  links is `.Over_Limit`. This gives `info.frames` (the sum of each link's last granule
  minus its first-audio start) without decoding, and seeking without a scan.
- Trimming: the first audio packet of a link outputs nothing (Vorbis's overlap needs a
  previous block); a last page's granule below the decoded count cuts the end (the file's
  true length), and a first-page granule above zero means the link starts that many frames
  in (a cut stream: those frames are dropped). A granule that makes the length negative or
  larger than the data could decode is `.Bad_Page`.

### Vorbis I (`vorbis.odin` and the rest)

Everything in the Vorbis I specification: the identification, comment (skipped, length
checked) and setup headers; codebooks (lookup types 0, 1 and 2, the Huffman tree built from
lengths, which must be fully specified or a single used entry; over- and under-specified
trees are `.Bad_Setup`); floor 0 and floor 1; residue 0, 1 and 2; mappings with channel
coupling (square-polar inverse) and submaps; the modes; the windows (the long and short
block shapes by block flag and neighbours); the inverse MDCT; overlap-add. Blocksizes are
any pair of powers of two from 64 to 8192 with the first not above the second. A decode
never reads a bit past a packet's end: running out of bits in a residue or floor is the
spec's *end of packet*, which zeroes the rest of the block (the spec says so and the
reference decoders do the same); in the headers it is `.Bad_Header` or `.Bad_Setup`.

**Limits (all constants in `vorbis.odin`, the whole reason a malformed file cannot make
the decoder allocate):**

| What | Limit |
|---|---|
| Channels | 8 (the game plays 1 or 2; more is decoded and mixed down by the caller) |
| Codebooks | 256; one codebook 1 << 16 entries, dimension 16; all lookup tables together 4 MiB |
| Floors, residues, mappings, modes | 64 each (the spec's maxima) |
| Floor 1 partitions and X points | the spec's (31 partitions, 65 points); floor 0 order 64, 256 amplitude bits |
| Residue partitions and classifications | 64 classifications, a book per pass; partition size up to the block |
| Packet | 64 KiB, as above |
| Setup header | 1 MiB |

`open` computes the decoder's whole memory from the identification and setup headers (the
codebook tables, the window slopes, the MDCT twiddles for the two blocksizes, per-channel
overlap and spectrum buffers, the packet buffer), checks it against `MAX_DECODER_BYTES` =
8 MiB (`.Over_Limit` beyond), and makes **one** allocation of that size from the given
allocator; the decoder carves it into slices (an arena over a single block, freed by
`close`). `read`, `seek` and `scan` allocate nothing. A decoder is one thread's; streams
make theirs on the decoder thread.

**Bit-exactness and determinism.** The decoder uses `f32` throughout and is written to be
bit-identical on every OS and optimization level, as M38's state tier is: `base.sin`,
`base.cos` and `base.exp` for the window slopes, twiddles, floor 0's curve and floor 1's
dB table (never `core:math`'s; no fused multiply-add: the same rule as `docs/determinism.md`),
the floor 1 inverse-dB table computed at open by `base.exp` (256 entries) rather than a
constant pasted from another decoder, and a fixed summation order in the IMDCT (a plain
split-radix-free radix-2 butterfly structure written once). So the golden digests below hold
on all three OSes with no per-OS checksum.

### Callers

- `game.ogg_length` and `game.ogg_check` (`common/game/pack_assets.odin`) become `ogg.scan`
  plus the existing byte and length limits (1 MiB and 5 s). A pack sound is now *fully
  validated* by `scan` (every page's CRC, the headers parsed and checked, the granules) and,
  for a pack, `ogg_check` also decodes it once, to the end, into a discard buffer, so a file
  whose pages are good but whose audio packets are not is refused when the pack loads (the
  file named in the existing message, plus the `ogg.Error`), not when the sound first plays.
  The decode is metered: at most the 5 s allowed plus one block of output.
- `audio.decode_clip` (`client/audio/clip.odin`): `ogg.open`, `read` in blocks, mixed down
  to mono at the file's own rate, as before; the `max_seconds` check stays. No `vendor:`
  import.
- `audio/stream.odin`'s `Decoder`: `ogg.open` on the stream's data, `info` for rate and
  channels, `read` for the ring's refills, `seek` for the start-over and the loop. The
  channel-count retry (open as mono, then as two) goes: the decoder reports the channels
  and the stream mixes down itself. A chained music file keeps working: the end of a link
  continues into the next without a gap (a stream's length is the whole file's `frames`).
  The decoder thread is the only caller, as before.
- `client/music_files_test.odin`'s `music_decode`: the same, through `ogg`.
- Nothing else in the game imports `vendor:miniaudio` for decoding after this; `device.odin`
  keeps it for the output device until the next tier.

## Tests

`common/ogg/ogg_test.odin`, run by the suite (the committed files are read from `assets/`):

- **Golden digests.** For every Ogg in `assets/music/` and the generated sounds, and each
  edge-case file below: the decode's `f32` samples hashed (the repo's FNV-1a over the little
  endian bytes) and compared with a committed table, `common/ogg/testdata/digests.txt`
  (`<file> <rate> <channels> <frames> <hash>` per line; LF, pinned in `.gitattributes`). A
  digest changes only by an edit to the decoder that its author says is meant (the table is
  regenerated by `build ogg digests`, which prints the diff). Bit-exact on all three OSes,
  at both optimization levels (`ODIN_TEST` runs `-o:none`; the CI optimized job runs the
  same digests).
- **Against the reference.** `common/ogg/testdata/reference/` holds, per edge-case file and
  per three seconds of each music file (chosen so the whole repository adds under 4 MiB:
  decoded to 16-bit, a 1 s window at the start, the middle and the end of every music file
  and the whole of each edge-case file), the PCM that the **reference decoder** (libvorbis
  through `ffmpeg`, found on the PATH, used only by `build ogg reference`; the output is
  committed, so no one else needs it) produced. The test rounds our `f32` to 16 bits
  (round to nearest even, clipped) and compares.

  **Decision (owner asked for bit-exact; written here because it cannot be met as
  worded):** the Vorbis I specification defines the decoder in floating point, so two
  conforming decoders (libvorbis, stb_vorbis, ffmpeg, ours) differ in the last bits of the
  `f32` and disagree on a few samples by one 16-bit step; no decoder is bit-exact with
  another's float output and the specification does not ask it. The pass criteria, then:
  **bit-exact against our own committed digests** (above, which is what catches any
  regression) and **against the reference at 16 bits: at least 99.9% of samples equal and
  no sample more than 1 step away** on every file. The test prints the figures. A decoder
  that passes this is as exact as the format allows; a hole that were audible would show as
  more than one step.
- **Edge-case files** (made once by `build ogg make-test-files`, a small Vorbis *encoder*
  in `tools/oggmake`: floor 1, residue 1, one fixed codebook set, a chosen blocksize pair
  and a chosen signal; committed under `common/ogg/testdata/`, each under 20 KB; their
  digests and references as above):
  - every blocksize: each of the 8 powers of two from 64 to 8192 appears as a short or a
    long size in at least one file, and equal pairs, both extremes and the transitions
    long-short-long and short-long-short are covered: (64,64), (64,128), (128,512),
    (256,2048), (512,1024), (1024,1024), (2048,4096), (4096,8192), (8192,8192), (64,8192);
  - tiny files: one audio packet; a stream of headers only (zero frames, decodes to an empty
    result with `.None`); a one-sample stream (granule 1 trims a whole block to one frame);
    a stream whose last-page granule cuts mid-block;
  - a stream whose first page granule is above zero (a cut stream);
  - a mono, a stereo with channel coupling, and a six-channel file;
  - chained: two links with the same rate; two links of different rates and channel counts
    (`info` changes; `read` crosses without a gap); three links, the middle one empty;
  - floor 0 (the encoder writes one) and residue types 0 and 2;
  - a packet split over a page boundary, one spanning three pages, and a page with 255
    segments of 255 bytes.
- **Refusals** (`test_ogg_refuses`): each of these returns its error, with nothing
  allocated beyond `open`'s one block (a tracking allocator checks the count) and no read
  outside the file (the tests run with `-sanitize:address` where the toolchain supports it,
  and always with bounds checks on): empty input; 3 bytes; `OggS` alone; a bad CRC (one
  flipped bit in the first, a middle and the last page); a sequence gap; a page of another
  serial; a continued packet with nothing before it; a packet over `MAX_PACKET`; an Opus,
  a FLAC and a Theora head page (`.Not_Vorbis`); two interleaved Vorbis serials
  (`.Unsupported`); an identification header with 0 channels, 0 rate, a blocksize not a
  power of two, 4096 above 8192, short above long, no framing bit; a comment header whose
  length field points past the packet; a setup with: 257 codebooks, a codebook of 70 000
  entries, an over-specified and an under-specified Huffman tree, a lookup type 3, a
  lookup table over the 4 MiB total, a floor with 64 partitions, a residue naming a book
  that does not exist, a mapping naming a floor or mode that does not exist, a mode with
  a non-zero window or transform type; a file whose setup would need over `MAX_DECODER_BYTES`;
  a granule that is negative for the last page; 65 chained links; `seek` past the end.
  (Truncating a file at every byte offset is the fuzz test's job.)
- **Truncation and the end-of-packet rule**: a valid file cut after each of its first 200
  bytes (headers: an error every time, never a crash) and after each page boundary
  (decodes what is whole, then `.Truncated` once, never a partial garbage block); a packet
  whose residue is cut mid-vector decodes to the same samples a reference decoder gives
  (the spec's zero-fill rule), compared to the committed reference of a deliberately cut
  packet.
- **Seek**: `seek(n)` then `read` equals the samples at `n` of a straight decode, for a
  hundred seeded positions in each music file and each chained file (including positions in
  the second link and the very last frame); seeking to 0 after reading everything works.
- **Allocation**: `test_ogg_allocates_once` (a tracking allocator: one allocation at
  `open`, none during `read`, `seek` and `scan`; `close` frees it; the byte count is within
  `MAX_DECODER_BYTES` and, for the music files, below 1 MiB).

`common/ogg/fuzz_test.odin` (**the small harness now**; M51c's fuzzers later adopt this
target and its corpus by calling `ogg.fuzz_one(data)`, which they take over without a
change here):

- `fuzz_one(data: []byte)`: `open` then `read` to the end (metered at 10 million output
  frames), `seek` to three places derived from the data's hash, `scan`; the only contract is
  no crash, no out-of-bounds, no allocation beyond `open`'s block, and an `Error` or a
  clean end. A trap, an assertion or a bounds-check failure is the failure.
- `test_ogg_fuzz`: a seeded corpus (the committed files above plus every
  refusal file) mutated by a seeded `base.Rng`: bit flips, byte replacement, truncation at
  a random offset, a chunk duplicated, a chunk deleted, a page header field set to an
  extreme value (a length, a segment count, a granule, a blocksize, a codebook count), the
  setup header's bytes shuffled, and two files spliced at a page boundary. **The CRC is
  repaired after each mutation** in half of the runs (a mutated page with a bad CRC is
  refused at once and would never reach the decoder otherwise). 20 000 iterations in the
  suite (about five seconds in the optimized build), and `build ogg fuzz --seed N
  --iterations N` for a longer run from the command line. The seed and the iteration
  count are printed on failure and the failing input is written to `build/fuzz/` (outside
  git; promote it to `testdata/regress/` and the suite replays that folder first).
- A crash found here is fixed in this milestone; the regression file is committed.

**The decode speed** (`build bench ogg`, a bench scenario like the others): the music
set decoded whole by `ogg` and, for comparison, by `vendor:miniaudio` (the bench file
`tools/bench/ogg_miniaudio.odin`, the last place the game's tree decodes with miniaudio; it
is deleted by *Audio devices in Odin* along with the rest of miniaudio), each three times,
the best kept; reported in the history entry as seconds of audio decoded per second of CPU
for both and their ratio, no hardware named. There is no pass bar: the figure is
reported, and if ours is more than twice as slow as miniaudio's the entry says where the
time goes (the IMDCT and the codebook's Huffman decode are the usual two) and the
cheapest next step. A decode at several hundred times real time is what the game needs;
the 5 s pack sound is the only decode the server ever does for a client's data.

## Not in this milestone

Encoding (the music pipeline keeps `ffmpeg` or `oggenc`, build time only), seeking by
time on very large files beyond the index above, Ogg FLAC or Opus, grouped streams,
streaming from a socket or a file (the whole file is in memory), the audio device (the
next tier), and a SIMD or threaded IMDCT (measured first, then maybe).

Exit check: `common/ogg`'s tests (golden digests, the reference comparison at the stated
bounds, every edge-case file, the refusals, truncation, seek, the single allocation) and
`test_ogg_fuzz` pass; the existing audio, stream, music-files and pack-asset tests pass with
their assertions unchanged except where they named miniaudio; no file under `client/`,
`common/` or `server/` imports `vendor:miniaudio` for decoding (a `build check` rule:
`vendor:miniaudio` may appear only in `client/audio/device.odin` and `tools/bench/`); the
bench figure is in the history entry; `./build.sh check` and the suite pass; CI green on
the three OSes.
