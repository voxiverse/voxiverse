# M54: packs signed and checked (signing, trust list, the static validator, the agent API, moderation hooks)

**Why.** An agent writes a pack somewhere else and a server runs it. Before M54b's dry run
spends minutes on a pack, the server has to know three things: who signed it, that nobody
changed it since, and that it does only what it says (capabilities used equal declared,
references resolve, constructs are bounded, sizes are capped). A model has to be able to
read the refusal and fix the pack without a person. M52's sandbox decides what a running
script may do. M54 decides whether the pack runs at all. The survey for this section found:

- Ed25519 is already used: `common/game/account.odin` (`Account_Key`, `account_sign`,
  `account_verify`, a context string per use: `PROOF_CONTEXT :: "voxiverse join v1"`).
  Pack keys reuse that type with their own context string, so one key can never sign for
  the other purpose.
- M47 compares pack hashes on joining. Its section names the hash (assumed: one per pack, of
  its files). M54 defines the hash exactly and makes it the one M47 uses (below).
- Nothing in the tree writes JSON Schema, and there is no `docs/agent/`. The pattern for
  generated files that must stay current already exists: `tools/schema` splices the
  dissector's block, and `test_dissector_schema_current` fails while it is stale.
- Machine-readable results today: `base/bench_result.odin` (one JSON file per run),
  telemetry's JSON lines. M54's reports follow those conventions: one JSON document, a
  version field, a schema shipped beside it.

**Layout.** Two new places, added to PLAN.md's Layout:

```
agent/      the agent surface: pack validator, error table, schema and docs generator
docs/agent/ what a model reads: guides, generated schemas and error list, example packs
```

`agent/` imports `base`, `game` and M51's compiler package (assumed `script/`). `server/`
imports `agent/`, since installing a pack validates it. `agent/` never imports `server/`.

**Design.**

*The canonical pack hash* (`common/game/pack_sign.odin`, shared):

- What counts: every regular file under the pack directory except `pack.sig`. A symlink, a
  directory or file whose name starts with `.`, or a path outside the path rule (lowercase
  `[a-z0-9_.-]` segments joined by `/`, at most 128 bytes, no `..`, no empty segment) is
  an error (`file.path_invalid`, `file.symlink`). It is never skipped: a skipped file would
  be unsigned content.
- Order: by path, comparing bytes.
- `file_hash = SHA-256(content)` over the raw bytes, with no newline normalization. Packs
  in the repo are pinned to LF in `.gitattributes`: `docs/agent/examples/** text eol=lf` and
  `agent/testdata/** text eol=lf`, so a Windows checkout hashes the same.
- `root = SHA-256("voxiverse pack v1" 0x00 || for each file: u16 len(path) || path ||
  u64 size || file_hash)`, integers little-endian.
- `Pack_Hash :: distinct [32]u8`, `pack_hash_dir(dir) -> (Pack_Hash, []Pack_File, Pack_Error)`
  with `Pack_File :: struct {path: string, size: u64, hash: [32]u8}`.
- This is the hash M47 compares on joining. If M47 shipped a different one, M54 replaces it
  and bumps `PROTOCOL_VERSION`.

*Signatures.* `pack.sig` is a text file in the pack's root, LF, one field per line:

```
voxiverse-pack-signature 1
pack lighthouse 1.0.0
hash <64 hex: root>
key <64 hex: the signer's public key>
signed <unix seconds>
file <64 hex> <size> <path>        (one per file, in hash order)
sig <128 hex>
```

- The signed message is `"voxiverse pack signature v1" 0x00 || u8 len(namespace) ||
  namespace || u8 len(version) || version || root || i64 signed`. The `file` lines are not
  signed one by one: the root covers them. They exist so that a verifier names the file
  that changed, appeared or went missing instead of saying only "hash differs".
- `pack_sign(dir, key: ^Account_Key, now_unix) -> (Pack_Signature, Pack_Error)` writes `pack.sig`.
- `pack_verify(dir, trust: ^Trust_List) -> Pack_Verdict`. It re-hashes the files on disk,
  compares them with the `file` lines and the root, checks the signature, then the trust.
- `Pack_Verdict :: struct {ok: bool, code: Error_Code, file: string, detail: string}`. Each
  refusal is one of the error codes below.
- Namespace and version come from `pack.json`. They must equal the `pack` line
  (`signature.manifest_mismatch`).

*Keys.*

- A pack key is an `Account_Key` kept in a text file:
  `voxiverse-pack-key 1\nprivate <64 hex seed>\npublic <64 hex>\n`.
- `voxiverse-server pack keygen <file>` writes it (mode 0600 on POSIX; refused if the file
  exists) and prints the public key.
- An account key may sign packs too: the contexts differ, so a pack signature can never be
  replayed as a join proof or the other way round.
- The agent service keeps its own key. The engine never sees it.

*The trust list* is `<universe>/trust.cfg`, LF text, `#` comments:

```
trust <64 hex key> <label> [namespaces=<pattern>,<pattern>]   (pattern: a name, or a prefix ending in *)
revoke <64 hex key> <reason...>
```

- No `namespaces=` means any namespace except the reserved ones (`base`, `vx`, `voxiverse`,
  `minecraft`: only the engine's built-in packs use them).
- `trust_read(path) -> (Trust_List, []Trust_Line_Error)`. A malformed line is reported with
  its line number and skipped. The file is otherwise used: one typo must not untrust every
  key.
- `trust_allows(t, key, namespace) -> Error_Code` (`.None`, `.Signature_Untrusted_Key`,
  `.Signature_Revoked`, `.Signature_Scope`).
- Commands: `/trust list`, `/trust add <key> <label> [namespaces]`, `/trust remove <key>`,
  `/trust revoke <key> <reason>`. All need the permission `server.trust` (owner only by
  default). They rewrite the file.
- Built-in packs (the base pack, inside the engine) are trusted by being built in. They carry
  no signature.
- Unsigned packs are accepted only where `universe.cfg` has `packs.unsigned 1`. That is the
  default for universes the client makes (singleplayer: the player's own files on their own
  machine) and 0 for dedicated servers. Each unsigned pack loaded is logged at warn level
  once.
- A revoked key's packs that are already installed keep running, with a warning at every
  start and in `/pack list`. New installs and updates by that key are refused. Disabling
  content a world already holds is the owner's decision (M54b's revert), not an automatic
  one.

*When verification runs.*

- On `pack install` (M54b).
- On every universe start, for each installed pack. Hashing 16 MiB costs tens of
  milliseconds, and it catches files changed on disk.
- By `voxiverse-server pack verify <dir> --trust <file>` on its own.

Clients never verify. They trust the server they joined, and M47's hash comparison tells
them they hold the same bytes.

*The validator* (`agent/validate.odin`):

- `validate_pack(dir, opts: Validate_Options) -> Validation_Report`.
- `Validate_Options`: `grants: Maybe(World_Grants)` (M52's grants of a target world, for the
  install-time checks), `text: ^game.Text_Checker`, `packs_dir` (where the dependencies
  are).
- It runs the rules below in order and collects every finding, so one pass shows all the
  errors. A rule that needs an earlier one's output (references need parsed files) is
  skipped for a file that already failed. The rules:

1. **Manifest.** `pack.json` exists and decodes as `Pack_Manifest`:
   - `format` (1);
   - `namespace` (`[a-z][a-z0-9_]{1,31}`, not reserved);
   - `version` (`MAJOR.MINOR.PATCH`);
   - `api` (the `vx` API version it needs; the engine supports `AGENT_API_VERSION :: 1`);
   - `title`, `description` (player-visible text);
   - `depends` (namespaces with versions);
   - `overrides` (ids from other packs it replaces);
   - `capabilities` (M52's manifest entries, with their parameters);
   - `faucets` (`{item, per_character?, per_hour?}`: every item the pack can create, with its
     cap);
   - `budgets` (what it asks of M52's quotas).

   Codes: `pack.manifest_missing`, `pack.namespace_invalid`, `pack.namespace_reserved`,
   `pack.version_invalid`, `pack.api_unsupported`, `pack.dependency_missing`,
   `pack.dependency_cycle`.
2. **Files and sizes.** These are constants in `agent/limits.odin`, decisions rather than
   variables:

   | Limit | Value |
   |---|---|
   | Pack size | 16 MiB (`pack.too_large`) |
   | Files | 1024 (`file.too_many`) |
   | One text file | 1 MiB |
   | One script's source | 256 KiB |
   | One image | 1024 x 1024 and 4 MiB |
   | One sound | 4 MiB and 60 s (`file.too_large`, naming the limit) |
   | JSON nesting | 32 levels |
   | A string | 4096 bytes; player-visible text 1024 |
   | An array | 4096 items |
   | An id | 64 bytes |
   | Capabilities | 32 |
   | Triggers | 1024 |
   | Quests | 256 |
   | Spawners | 256 |

   Every file must sit in a directory that M47 or M53 gives a kind (`blocks/`, `items/`,
   `quests/`, `scripts/`, `textures/`, ... from the `PACK_FILE_KINDS` table below).
   Anything else is `file.unknown_kind`, which lists the known directories.
3. **Schema.** Each data file decodes into its kind's Odin type with a strict decoder:
   - `schema.syntax`, with line and column;
   - `schema.unknown_field`, with "did you mean" the nearest field by edit distance, at most
     2 apart;
   - `schema.missing_field`;
   - `schema.type`;
   - `schema.range` (min and max from field tags);
   - `schema.enum` (lists the allowed names);
   - `schema.too_deep`, `schema.string_too_long`, `schema.array_too_long`.

   This is M47's loader in strict mode, if it is not strict already. The finding's `path` is
   a JSON pointer (`/objectives/2/count`).
4. **References.** Every id a file names resolves in this pack, its declared dependencies or
   the base pack, and is of the right kind:
   - `ref.unknown_id`, with the nearest id of that kind;
   - `ref.wrong_kind` ("`lighthouse:keeper` is an entity, a loot table was expected");
   - `ref.duplicate_id`;
   - `ref.override_undeclared` (it replaces another pack's id without listing it in
     `overrides`).
5. **Scripts** (M51's compiler, run on each `scripts/*.vxs`): `script.syntax` and
   `script.compile` with M51's own messages, and `script.too_large` (bytecode over 65 536
   instructions). Capability inference walks the compiled code for API references:
   - Every `vx.<module>.<name>` read as a constant path maps to a capability through M52's
     binding table, which gains a `capability` column if it lacks one.
   - Indexing `vx` or a module table with a non-constant key, assigning them to anything,
     passing them as values, or `rawget` on them is `script.dynamic_api`. Inference would be
     unsound, so it is an error.
   - A name that is not in the API is `script.unknown_api`, naming the nearest.
6. **Capabilities used equal declared.** The used set is the union of every script's inferred
   capabilities and what the data's actions need (M53's action table gains the capability
   each action needs: `give_item` needs `items.give`, `set_block` needs `blocks.edit`, ...).
   - `capability.undeclared`: used, not in `pack.json`. It names the first call site.
   - `capability.unused`: declared, never used. Equality is required, so an agent cannot ask
     for more than it needs.
   - `capability.unknown`.
   - `capability.region_invalid`: a region parameter that is empty, inverted or larger than
     M52's ceiling.
   - With `grants` given: `capability.over_grant`, for asking more than the target world
     grants (a capability, a region outside the granted one, a budget over the world's).
7. **Bounded constructs.** In data:
   - `data.trigger_cycle`: the graph "trigger T's actions emit events that trigger U listens
     to" has a cycle with no `cooldown` (ticks, at least 1) on any trigger in it. The finding
     lists the cycle.
   - `data.quest_cycle`: a non-repeatable quest can restart itself.
   - `data.repeat_unbounded`: a repeatable quest or trigger with neither `cooldown` nor
     `max`.
   - `data.loot_cycle`: a loot table that includes itself, through others too.
   - `data.loot_depth`: nesting over 8.
   - `data.dialogue_dead_end`: a dialogue node with no options that is not an end. This is
     an error: it is a softlock by construction.
   - `data.dialogue_unreachable`: a warning.
   - `data.spawner_over_budget`: a spawner's max alive times its count over the declared
     spawn budget.

   In scripts, warnings only, because M51's metering is what actually bounds them:
   - `script.unbounded_loop`: `while`/`repeat` in an event handler whose condition is
     constant-true and whose body has no `break`, `return` or yield.
   - `script.recursion`: a function that calls itself, directly or through another, in one
     file.
8. **Economy.**
   - `economy.faucet_undeclared`: an item that a `give_item` action, a loot table, a quest
     reward or a script `vx.items.give` with a constant item can create, missing from
     `faucets`. A non-constant item in `vx.items.give` needs `faucets` to list `"*"` with a
     `per_hour`, else this error.
   - `economy.faucet_unbounded`: a faucet entry with neither `per_character` nor `per_hour`.
9. **Quests can be finished (static).**
   - `quest.unobtainable`: an objective names an item nothing can produce (no loot table,
     reward, faucet, recipe or base-world source in M47's registry tags), or an entity kind
     nothing spawns (no spawner, no natural spawn rule).
   - `quest.region_outside`: a region outside the world's bounds (y -256..256).
10. **Text.** Every player-visible string in data goes through `opts.text`, the moderation
    check below. Data strings include titles, dialogue lines, item and entity names, death
    messages and notices. Script string literals passed straight to a text API also go
    through. `text.invalid` covers control characters, bidi overrides and invalid UTF-8,
    `text.too_long` the length limit, and `text.refused` a refusal by the checker, with its
    category, not the text itself.

`Validation_Report` (JSON, `validation-report.schema.json`):

```json
{"report": "validation", "report_version": 1, "engine": "<base.version_text()>",
 "pack": {"namespace": "lighthouse", "version": "1.0.0", "hash": "<hex>"},
 "verdict": "pass" | "fail",
 "findings": [{"code": "capability.undeclared", "severity": "error" | "warning",
   "file": "scripts/lamp.vxs", "line": 12, "column": 5, "path": null,
   "message": "lamp.vxs calls vx.blocks.set, which needs the capability blocks.edit; pack.json does not declare it.",
   "fix": "Add {\"capability\": \"blocks.edit\", \"region\": ...} to \"capabilities\" in pack.json, or remove the call.",
   "docs": "docs/agent/capabilities.md#blocks-edit"}],
 "capabilities": {"declared": ["..."], "used": ["..."]},
 "stats": {"files": 0, "bytes": 0, "scripts": 0, "instructions": 0, "strings_checked": 0}}
```

The verdict is `fail` if any finding is an error. Warnings never fail.

*Errors written for a model* (`agent/errors.odin`):

- `Error_Code :: enum u16`, append-only, and `ERROR_INFO: [Error_Code]Error_Info`. Each row
  has an `id` (`"capability.undeclared"`), a `severity`, a `message` template, a `fix`
  template (both with `{name}` holes filled from the finding's arguments), and a `docs`
  anchor.
- Every code above has a row. A test fails on a code without a message, a fix or a docs
  anchor that exists in the docs.
- Each message says what was found, where, and why it matters, in one sentence. Each fix
  says what to change, naming the field or call. No message refers to engine internals the
  agent cannot see.
- Human output, one line per finding then its fix:

  ```
  scripts/lamp.vxs:12:5: error[capability.undeclared]: <message>
    fix: <fix>
  ```

  `--json` prints the report instead.

*The agent API: schemas, docs and examples.*

- `PACK_FILE_KINDS` (`agent/kinds.odin`) is a table with one row per pack file kind: the
  name (`quest`), the directory (`quests/`), the Odin type it decodes into (M47 and M53's
  types), and a one-line description. The manifest is a row of its own.
- `agent/schemas.odin` generates JSON Schema 2020-12 from those types by `core:reflect`, as
  M39's schema derives the codec:
  - a struct becomes an `object` with `properties`, `required` (fields without an
    `optional` tag) and `additionalProperties: false`;
  - an enum becomes a string `enum` of its names in snake case;
  - integers and floats get `minimum` and `maximum` from tags, strings `maxLength`, arrays
    `maxItems`;
  - a union becomes `oneOf` with a `type` discriminator;
  - ids are `$ref: "#/$defs/id"` (pattern `^[a-z][a-z0-9_]*:[a-z0-9_/]+$`);
  - `description` comes from a `doc:"..."` field tag. A field without one fails the
    generator's test, so every field is explained.

  `$id` is `voxiverse:pack/<format>/<kind>`, so the version is in the name.
- `build agent-docs` (a `case` in `tools/build/main.odin` that runs `tools/agentdocs`)
  writes these, generated and LF:
  - `docs/agent/schemas/<kind>.schema.json` for every kind;
  - `pack.schema.json`;
  - `validation-report.schema.json` and `dryrun-report.schema.json` (M54b), from the report
    types;
  - `docs/agent/errors.md`, every code with its meaning, fix and an example;
  - the limits table inside `docs/agent/packs.md` between `<!-- limits begin -->` and
    `<!-- limits end -->`.

  `test_agent_docs_current` fails while any of them is stale, as the dissector's test does.
- Hand-written, short and plain, for a model to read first:
  - `docs/agent/README.md`: what a pack is, the pipeline (write, `pack check`, sign, dry
    run, install, revert), how to read a report, where everything else is;
  - `packs.md`: layout, manifest, ids, overrides, limits;
  - `data.md`: M53's triggers, quests, spawners, dialogue, loot, rules, modes, one example
    each;
  - `scripting.md`: M51's language as it differs from Lua 5.4, and the `vx` API;
  - `capabilities.md`: each capability, what it allows, its parameters and budgets (one
    `##` per capability: the anchors the error table points at);
  - `dryrun.md` (M54b).
- Examples: `docs/agent/examples/lighthouse/`, the example agent-style pack (below; its
  scripts and quest data are finished in M54b, its manifest and data validate here), and
  `docs/agent/examples/minimal/` (one item, no script).
- The engine ships them in two ways. The packages (`tools/build/package.odin`) carry
  `docs/agent/`. The server binary embeds the folder (`#load_directory`), and
  `voxiverse-server pack docs --out <dir>` writes it out, so a lone binary is a complete
  agent toolkit.

*The command line* (`dedicated/pack_cli.odin`; `voxiverse-server pack <verb>`):

- `keygen <file>`, `sign <dir> --key <file>`, `verify <dir> --trust <file>`;
- `check <dir> [--grants <universe> <address>] [--json] [--words <file>]`;
- `docs --out <dir>`.

Exit codes: 0 passed, 1 refused or failed, 2 usage or I/O error (3 is M54b's crash). A
verb's `--json` output is one document on stdout and nothing else. Logs go to stderr.

*Moderation hooks.* Generated text is text a pack or script makes, not what a player types.
Player chat keeps M13's checks, and `moderation.chat 1` in `universe.cfg` puts chat through
the same hook too (default 0).

- `common/game/moderation.odin`, the types:
  - `Text_Use :: enum u8 {Name, Chat, Notice, Dialogue, Quest, Item_Name, Entity_Name,
    Death_Message, Title, Other}`;
  - `Text_Origin :: struct {pack, script, player: string}`;
  - `Text_Verdict :: struct {allowed: bool, category: string}` (a constant: `"control"`,
    `"bidi"`, `"length"`, `"word"`, `"external"`, `"timeout"`, `"unavailable"`);
  - `Text_Checker :: struct {data: rawptr, check: proc(data: rawptr, text: string, use:
    Text_Use, origin: Text_Origin) -> Text_Verdict}`.
- `text_check_basic(text, use)`: valid UTF-8, no C0 or C1 controls (tab excepted in
  `Dialogue`), no bidi overrides or isolates (U+202A-202E, U+2066-2069), at most 4
  zero-width characters, and length per use (names 32 bytes, others 1024).
- `Word_List` (`word_list_load(path)`): one word or phrase per line. A match is
  case-insensitive and whole-word, after folding `0→o 1→i 3→e 4→a 5→s 7→t @→a $→s`, and
  also checked with separators between single letters removed (`b.a.d`).
- No word list is committed (choosing one is the owner's or the service's job). The tests
  use `agent/testdata/words.txt` with made-up words.
- `server/moderation.odin`, the hook: the basic check, then `<universe>/moderation/words.txt`
  if present, then an external checker if `universe.cfg` has `moderation.command <command
  line>`.
- The external protocol is JSON lines over the child's stdin and stdout:
  - in: `{"id": n, "text": "...", "use": "dialogue", "pack": "lighthouse", "script": "lamp"}`;
  - out: `{"id": n, "allow": true|false, "category": "..."}`.

  One long-lived child, started with the universe. A reader thread puts answers on a
  `base.Queue`. The tick never waits.
- Rules for the external checker:
  - Answers older than 2 s count as refused (`timeout`).
  - A dead child is restarted at most once a minute. While it is down, generated text is
    refused (`unavailable`, fail closed) and that is logged once a minute.
  - At most 256 texts are pending per world. More are refused (`unavailable`).
- Where it applies:
  - Static strings are checked when the pack is validated and installed, synchronously, the
    external checker included (`pack check --moderation-command`), so data text never waits
    at run time.
  - Templates with `{player}`-style holes are checked with the holes empty: names are
    checked when characters are made.
  - Text a script builds at run time (`vx.chat.send`, `vx.ui.notice`, ...) is held until its
    verdict, then delivered or dropped. A refusal is logged with the origin and the category,
    never the text, and the script gets `false` from the call at the next event point.
    Scripts are told this in `scripting.md`.

**The order of the steps** (each leaves the suite passing):

1. `common/game/pack_sign.odin`: hash, signature file, key file, trust list and their tests.
2. Verification wired into the universe's pack loading (M47's loader): built-in packs exempt,
   `packs.unsigned`, warnings for revoked keys, `/trust` commands.
3. `agent/errors.odin` and `agent/limits.odin`, then the validator's rules 1 to 4 (manifest,
   files, schema, references) on M47 and M53's types.
4. Rules 5 to 9 (scripts, capability inference, bounded constructs, economy, quests).
5. `common/game/moderation.odin`, word lists, rule 10, `server/moderation.odin` with the external
   protocol over an in-process stream pair, then the process.
6. `agent/kinds.odin`, the schema generator, `build agent-docs`, the hand-written docs, the
   two example packs (lighthouse's data only), the docs embedded in the server binary.
7. `voxiverse-server pack keygen|sign|verify|check|docs`.

**Left out:**

- The bot harness, the dry run, installing and reverting (M54b).
- Uploading a pack over the network. A signed pack reaches a server by being copied into
  `<universe>/incoming/` (the service's job, scp or similar).
- Key rotation tooling beyond add, remove and revoke. Certificates, chains, expiry.
- Clients verifying signatures.
- A general JSON Schema validator in the engine (the strict decoders are the validator; the
  schemas are for agents).
- A committed word list. Image moderation.

**Tests:**

- `common/game/pack_sign_test.odin`:
  - the hash of a fixed tree equals a golden value, the same on every OS (`agent/testdata`
    is LF-pinned);
  - order and path rules (a symlink, a `.hidden` file and `..` are refused by code);
  - sign then verify passes;
  - one byte changed in a file is refused as `signature.hash_mismatch` naming that file;
  - a file added or removed is refused as `signature.file_added` or `signature.file_missing`;
  - a key not in the trust list is refused as `signature.untrusted_key`;
  - a revoked key is refused as `signature.revoked`;
  - a namespace outside the key's patterns is refused as `signature.scope`;
  - a signature with one bit flipped is refused as `signature.invalid`;
  - a manifest whose namespace differs from `pack.sig` is refused;
  - a pack signature checked as an account proof fails, and the other way round;
  - a malformed `trust.cfg` line is reported with its number while the other lines still
    count.
- `agent/validate_test.odin`: one broken pack per code under `agent/testdata/packs/<code>/`.
  Each gives exactly that error code, with file, line and path where the code has them. Then:
  - `good` and both examples pass;
  - `capability.undeclared` and `capability.unused` each name their call site or entry;
  - `script.dynamic_api` catches `local m = vx[name]`;
  - `data.trigger_cycle` lists the cycle;
  - with grants, `capability.over_grant` is given for a region outside the granted one.
- `agent/docs_test.odin`:
  - `test_agent_docs_current`;
  - every `Error_Code` has a message, a fix and an existing docs anchor;
  - every field of every kind has a `doc` tag;
  - `agent/schema_check_test.odin`, a checker of only the keywords the generator emits:
    every example pack's files are valid under their schemas, and each `schema.*` testdata
    file is invalid under its schema, so schemas and decoders agree.
- `common/game/moderation_test.odin`: controls, bidi, zero-width, length per use, folding
  (`b4dw0rd`, `b.a.d.w.o.r.d`), whole-word (a list word inside a longer word passes).
- `server/moderation_test.odin`, over the stream pair:
  - a fake checker that refuses one word: the held script text is dropped and logged without
    the text, an allowed one is delivered;
  - no answer within 2 s means refused;
  - a closed stream means everything refused, with one log line a minute;
  - the 257th pending text is refused.
- `dedicated` test: `pack check --json` on a broken pack prints one JSON document that

**Exit check:**
