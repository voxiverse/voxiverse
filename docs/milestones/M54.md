# M54: packs signed and trusted (the pack root, signatures, key files, the trust list, verification at load, `voxiverse-server pack keygen|sign|verify`)

**Why.** An agent or a creator writes a pack somewhere else and a server runs it. Before
anything else (M54g's validator, M54j's dry run) spends time on a pack, the server has to
know who signed it and that nobody changed it since. M52's sandbox decides what a running
script may do; M54-M54i decide whether the pack runs at all.

**The split (2026-10-30, #86).** The old M54 was four systems; each is one row with its own
exit check, in this order: **M54** (this row: the pack root, signatures, key files, the trust
list, verification when a universe loads its packs, the `pack` verbs `keygen`, `sign`,
`verify`); **[M54g](M54g.md)** (the static validator: error codes written for a model, the
rules over manifests, data, scripts, client scripts and channels, `pack check`); **[M54h](M54h.md)**
(moderation hooks for generated text and pack media); **[M54i](M54i.md)** (the agent surface:
JSON Schemas generated from the loader's field tables, `docs/agent/`, the example packs, the
docs in the server binary). M54c (experiences) needs only this row's signing; M54j and M54k need all
four.

**Checked against the code (2026-10-30, #86; corrections made in this revision):**

- The server binary is `voxiverse-server` (`tools/build/main.odin`: `SERVER_NAME`; package
  `dedicated`). `dedicated/main.odin` has no verbs today: it parses flags only
  (`flags.parse_or_exit` over an `Options` struct: `--universe`, `--port`, `--check`,
  `--export`, ...). `voxiverse-server pack <verb>` is a dispatch on `os.args[1]` before the
  flags are parsed, in a new `dedicated/pack_cli.odin`.
- Ed25519 and SHA-256 are Odin's `core:crypto/ed25519` and `core:crypto/hash`
  (`common/game/account.odin`, `pack_archive.odin`). `account.odin` signs only a `Nonce`
  under the file-private `PROOF_CONTEXT :: "voxiverse join v1"` (`account_sign(k, nonce)`,
  `account_verify(account, nonce, sig)`); there is no general signing procedure. This row
  adds one, keyed by a context from one table (below).
- The joining client's hash is M47b's: `pack_hash(archive) -> [32]u8`, SHA-256 of the
  archive of `pack.json`, `assets/` and `data/` (`pack_archive_make`, `PACK_ARCHIVE_MAGIC
  "VXPK"`), carried in `Pack_Entry.sha256` and checked by `pack_fetch_part`; the registry's
  `content` hash is compared in `pack_ready`. It stays exactly as it is: clients never see
  `server/` and never verify signatures. The old text's "M54 replaces M47's hash and bumps
  `PROTOCOL_VERSION`" is dropped. The signature covers **every** file, `server/` included,
  through a second hash with its own name (the *pack root*, below).
- Names taken: `game.Pack_File {path, data}` and `game.pack_hash` exist. The old text's
  `Pack_File {path, size, hash}`, `Pack_Hash` and `pack_hash_dir` become `Signed_File`,
  `Pack_Root` and `pack_root`.
- Packs are read by `server/pack_dir.odin`'s `pack_read_dir(dir) -> (Pack_Source,
  []Pack_Error)` (walks in name order, refuses symlinks and oversized files without reading
  them); a pack is `<universe>/packs/<namespace>/` (the directory must equal `pack.json`'s
  `namespace`), listed by `universe.cfg`'s `packs` (`server/universe_packs.odin`:
  `packs_registry`, `universe_registry`). The path rule `valid_path`
  (`registry_load.odin`) allows `[a-z0-9_./-]` up to `MAX_PACK_PATH` 128 but **does not
  refuse `..` or empty segments**; dotfiles are read and fail the layout check later. This
  row tightens `valid_path` (no `..`, no empty segment, no leading `.` in a segment) for every
  pack, and the layout check accepts `pack.sig` at the root (never sent: `pack_archive_sent`
  excludes it).
- The only reserved namespace is `BASE_NAMESPACE` (`voxiverse`); the old text's `base`, `vx`
  and `minecraft` were never reserved and are not added here. Built-in packs (the base pack,
  loaded from the binary by `base_pack.odin`) carry no signature and are trusted by being
  built in.
- `universe.cfg` is `key = value` lines (`server/save.odin`), and `write_universe_file`
  **rebuilds the whole file** from the server's state on every save: a new key such as
  `packs.unsigned` must be a field of the server's config, read and written, or the next save
  drops it. Atomic writes are `store_write(s, path, data)` (`server/save_tx.odin`), which
  uses `base.disk_replace`.
- Permission nodes are dotted names (`server.packs` for `/pack`, `info.packs` for `/packs`;
  `DEFAULT_PERMISSIONS` in `server/permissions.odin`, roles `default`, `mod`, `admin`, the
  admin with `grant *`). `/trust` needs a new node `server.trust` (the admin role has it
  through `*`; the default and mod roles do not).
- Timing is never asserted in a test (T5): hashing cost is a budgets scene.

**What this builds on:** M47 and M47b as above; M46's atomic writes; the account keys
(`account.odin`); Q1's fuzz harness (`base/fuzz`, `tools/fuzz/targets.odin`); Q5's threat
model (`docs/threat_model.md`, area `PACK`).

## Design (M54)

### Signing contexts, one table (`common/game/signing.odin`)

Every Ed25519 signature the engine makes or checks signs `context || 0x00 || message`, with
the context from one table, so a signature for one use can never be replayed as another:

| Context | Use | Row |
|---|---|---|
| `voxiverse join v1` | the account proof at join (today's, no `0x00`: kept byte for byte until M55 makes it `voxiverse join v2`) | built; M55 |
| `voxiverse pack signature v1` | a pack's `pack.sig` | M54 |
| `voxiverse experience signature v1` | an experience's `experience.sig` | M54c |
| `voxiverse server v2` | the server's identity in the handshake | M55 |

- `SIGNING_CONTEXTS :: [Sign_Context]string` (`Sign_Context :: enum u8 {Join, Pack,
  Experience, Server}`; rows appended by their rows), `sign_message(key: ^Account_Key, ctx:
  Sign_Context, message: []u8) -> Signature`, `verify_message(account: Account, ctx,
  message, sig) -> bool`. `account_sign`/`account_verify` call them with `.Join` and the
  join's exact bytes (the join test vectors unchanged). `PROOF_CONTEXT` moves into the table.
- Hash domains (not signatures) are listed beside it for the same reason: `voxiverse pack v1`
  (the pack root), `voxiverse bot v1` (M54b's bot keys), M55's `voxiverse transport v2`,
  `voxiverse keys v2`, `voxiverse binding v2`.
- `test_signing_contexts`: every context and domain distinct, none a prefix of another; a
  signature made under each context fails under every other.

### The pack root (`common/game/pack_sign.odin`)

- Input: the `Pack_Source` `pack_read_dir` returned (the same bytes the registry is then
  built from, so nothing can change between verifying and loading), every file except
  `pack.sig`.
- Order: by path, comparing bytes. `file_hash = SHA-256(content)` over the raw bytes, with
  no newline normalization; packs in the repo are pinned LF in `.gitattributes`
  (`server/testdata/packs/** text eol=lf`, `agent/testdata/** text eol=lf`,
  `docs/agent/examples/** text eol=lf`), so a Windows checkout hashes the same.
- `root = SHA-256("voxiverse pack v1" 0x00 || for each file: u16 len(path) || path || u64
  size || file_hash)`, integers little-endian. `Pack_Root :: distinct [32]u8`,
  `Signed_File :: struct {path: string, size: u64, hash: [32]u8}`, `pack_root(src:
  Pack_Source) -> (Pack_Root, []Signed_File)`.

### `pack.sig`

LF text in the pack's root, one field per line:

```
voxiverse-pack-signature 1
pack lighthouse 1.0.0
root <64 hex>
key <64 hex: the signer's public key>
signed <unix seconds>
file <64 hex> <size> <path>        (one per file, in path order)
sig <128 hex>
```

- The signed message (under `Sign_Context.Pack`) is `u8 len(namespace) || namespace || u8
  len(version) || version || root || i64 signed`. The `file` lines are not signed one by one:
  the root covers them. They let the verifier name the file that changed, appeared or went
  missing instead of saying only "root differs".
- Namespace and version come from `pack.json` (`Pack_Info`); they must equal the `pack` line.
  A version is a label (any string up to 32 bytes, as M47 reads it), not semver.
- Parsing is strict: every line in order, exactly once, no blank lines, no trailing data, at
  most 1 024 `file` lines and 1 MiB; anything else is `signature.malformed` with the line.
- `pack_sign(src, key, now_unix) -> ([]u8, Sign_Error)` makes the file;
  `pack_verify(src, sig_text, trust: ^Trust_List, now) -> Pack_Verdict`: re-hashes the
  files, compares them with the `file` lines (naming the first difference), the root, the
  signature, then the trust. `Pack_Verdict :: struct {ok: bool, code: Sign_Code, file:
  string, detail: string}`.
- Codes (`Sign_Code :: enum u8`, append-only; M54g's error table gives each its message and
  fix): `None`, `Unsigned`, `Malformed`, `Manifest_Mismatch`, `File_Changed`, `File_Added`,
  `File_Missing`, `Root_Mismatch`, `Invalid` (the signature does not verify),
  `Untrusted_Key`, `Revoked`, `Scope` (the namespace is outside the key's patterns),
  `Path_Invalid`.

### Key files

- A key file is `voxiverse-<use>-key 1\nprivate <64 hex seed>\npublic <64 hex>\n`; this row's
  use is `pack` (M55's server key reuses the reader with `server`). `key_file_read(path,
  use) -> (Account_Key, Key_Error)` checks the header, that the public key matches the seed,
  and (POSIX) that the file is not readable by group or others (refused with the `chmod`
  that fixes it).
- `voxiverse-server pack keygen <file>` writes it (mode 0600 on POSIX; refused if the file
  exists) and prints the public key.
- An account key may sign packs: the contexts differ.

### The trust list (`<universe>/trust.cfg`)

```
# Keys whose packs this universe runs (see docs/debugging.md)
trust <64 hex key> <label> [namespaces=<pattern>,<pattern>]   (a name, or a prefix ending in *)
revoke <64 hex key> <reason...>
```

- No `namespaces=` means any namespace except `voxiverse`. `trust_read(text) -> (Trust_List,
  []Trust_Line_Error)`: a malformed line is reported with its number and skipped; the rest of
  the file still counts (one typo must not untrust every key). `trust_allows(t, key,
  namespace) -> Sign_Code`.
- `/trust list`, `/trust add <key> <label> [namespaces]`, `/trust remove <key>`, `/trust
  revoke <key> <reason>`: node `server.trust`; they rewrite the file with `store_write`
  (comments kept).
- **Unsigned packs** load only where `universe.cfg` has `packs.unsigned = 1`: the default for
  universes the client makes (singleplayer: the player's own files on their own machine) and
  0 for dedicated servers (`voxiverse-server --universe` creating a universe). Each unsigned
  pack loaded is logged at `warn` once per start. A refusal names the fix: `pack demo is not
  signed; sign it (voxiverse-server pack sign) or set packs.unsigned = 1 in universe.cfg`.
- A revoked key's installed packs keep running, with a `warn` at every start and in `/packs`;
  installs and updates by that key are refused (M54k). Disabling content a world already holds
  is the owner's decision (M54k's revert), not an automatic one.

### When verification runs

- At every universe start, for each listed pack, inside `packs_registry` after
  `pack_read_dir` and before `registry_build`: a refused pack is not loaded and the universe
  goes on without it (as a pack with load errors does today), its refusal logged with code,
  file and fix, and sent as a notice to players allowed `server.packs` when they join.
- By M47i's hot reload (`server/pack_reload.odin`): a changed file in a signed pack is a
  `File_Changed` refusal and the reload keeps the old registry (a creator edits unsigned,
  `packs.unsigned = 1`, packs).
- By `voxiverse-server pack verify <dir> [--trust <file>]` on its own, and by M54k's install.
- Clients never verify: they trust the server they joined, and M47b's hash tells them they
  hold the same bytes.

### The command line (`dedicated/pack_cli.odin`)

`voxiverse-server pack keygen <file>`, `pack sign <dir> --key <file>`, `pack verify <dir>
[--trust <file>] [--json]`. Exit codes: 0 passed, 1 refused, 2 usage or I/O error. `--json`
prints one document on stdout (`{"verdict": "pass"|"fail", "code": "...", "file": "...",
"detail": "..."}`) and nothing else; logs go to stderr. M54g adds `check`, M54i `docs`, M54j
`dryrun` and M54k `install`.

## The order of the steps (M54)

1. `common/game/signing.odin`: the contexts table, `sign_message`/`verify_message`,
   `account_sign`/`account_verify` on them (join vectors unchanged); `test_signing_contexts`.
2. `valid_path` tightened; `pack.sig` accepted at the root and never sent.
3. `common/game/pack_sign.odin`: the root, `pack.sig` writing and parsing, `pack_verify`, key
   files, `trust.cfg`; their tests and the hostile table.
4. Verification in `packs_registry`, `packs.unsigned` read and written, `/trust` and
   `server.trust`, hot reload refusing a changed signed pack.
5. `dedicated/pack_cli.odin`: `keygen`, `sign`, `verify`; the `dedicated` test.
6. The fuzz targets, the budgets scene, the threat rows.

## Benchmarks (M54)

`budget_pack_verify` in `server/budgets.odin` (judged by `build bench budgets -check`, metrics
appended to `base.Metric`, limits in `BUDGET_LIMITS`, `BUDGETS_VERSION` bumped): a generated
pack at the limits (1 024 files, 16 MiB) read, rooted and verified ten times, and a small one
(the `signed` test pack) a thousand times.

| Metric | What | Limit |
|---|---|---|
| `Pack_Verify_Large` | mean ms to root and verify the 16 MiB pack from memory | 250 |
| `Pack_Verify_Small` | mean us to root and verify the small pack | 500 |

Limits are set from the first measured run (the commit quotes it); if the median is over a fifth
of a limit, the limit stays and the report says so; a limit is never raised to pass.

## Exit check (M54)

- A forged pack (signed by an untrusted key) and an altered one (one byte changed after
  signing) are refused, by `pack verify` and when the universe loads them, each with its code
  and the file named; every row of the hostile table as listed.
- `test_pack_root_golden` passes on the three OSes; `test_signing_contexts` passes; the join
  tests unchanged and passing.
- The fuzz smokes clean; `build bench budgets -check` within `Pack_Verify_Large` and
  `Pack_Verify_Small`.
- The whole suite and `build check`; CI green.

## Left out (M54)

The validator (M54g); moderation (M54h); schemas and agent docs (M54i); installing, updating,
downgrade refusal (an update whose `signed` is older than the installed one's) and reverting
(M54k); uploading a pack over the network (a signed pack reaches a server by being copied into
`<universe>/incoming/`, the service's job); key rotation beyond add, remove and revoke;
certificates, chains, expiry; clients verifying signatures.

**For M54b (found while checking, #86; corrected by #88 in M54j and M54k):** M54b installed to
`packs/<namespace>@<version>/`, which breaks the rule that a pack's directory is its namespace;
its example uses `scripts/lamp.vxs` and `blocks.edit` (now `server/scripts/` and
`world.edit`); its `death` trigger is M53's `player_died`, and the base pack does have death
messages (#52).

## Check by hand (M54)

On a dedicated server (`voxiverse-server --universe <dir>`), copy a pack into `packs/`, list
it, start: it is refused as unsigned with the fix in the log. `voxiverse-server pack keygen
k.key`, `pack sign <pack> --key k.key`, then `/trust add <key> me` in the chat of a player with
`server.trust` (or add the `trust` line to `trust.cfg` by hand), restart: it loads. Edit one of its files, restart: refused, the file named.
