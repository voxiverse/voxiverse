# M54c: experiences (a world with its packs and scripts as one signed package)

**Why.** The owner's decision of 2026-10-30 (#83): a creator packages a world with its packs
and scripts as one experience, which someone else can open and play. Sharing beyond one
server waits for online services; this row makes the package, its checks and its import, so
an experience moves as one file.

**What this builds on:** M46b's export and import (`server/export.odin`: `.vxu`,
`EXPORT_FORMAT` 2, `universe_export(dir, out, d, journal)`, `export_write`,
`universe_import(file, dest, d, limits)`, `IMPORT_LIMITS` (16 GiB, 100 000 files, 1 GiB a
file, 8 path parts of 64 bytes), `import_check_packs`); pack archives
(`common/game/pack_archive.odin`: `.vxpack`, `pack_archive_make`, `pack_archive_read`,
`pack_hash`; `pack_archive_sent` leaves `server/` out, so experiences need the full form
below); M54's signing (`common/game/pack_sign.odin`: `pack_sign`, `pack_verify`, the trust
list `trust.cfg`, `trust_allows`, `packs.unsigned`, key files, contexts per use); M52-M52e
(worlds' `packs`, `grants.cfg`, `store.dat`, the API versions a pack declares and the
server supports); the universes screen's Import field (`client/screen_universes.odin`, M48e:
an import by a path); the save layout (`docs/saves.md`: `universe.cfg`,
`worlds/<address>/{world.cfg, regions/, protections.cfg, grants.cfg, scripts/}`).

**What an experience is** (engineering, decided): one world of a universe, as its creator
left it, with every pack it needs. Not players: no characters, accounts, permissions,
community data, bans, journal, backups, telemetry, analytics, script snapshots (valid only
within one engine build) or the lock. Its `store.dat` files are included (they are the
experience's authored state). Opening an experience makes a **new universe** whose default
world is that world; playing it never changes the package.

**The package** (`.vxexp`, `server/experience.odin`, `EXPERIENCE_FORMAT :: 1`):

```
"VXEX" u32 format
header:   engine version text, save format, the world's address and its world.cfg,
          the universe.cfg keys that shape play (seed, mode, rules, scripts.* pools),
          the packs (namespace, version, api, SHA-256 of each full archive), in load order
packs:    each pack as a full archive (`pack_archive_make(..., full = true)`: pack.json,
          assets/, data/, server/, pack.sig), canonical bytes
world:    each file of worlds/<address>/ that the list above keeps, with its size and CRC
manifest: the SHA-256 of everything above (the root)
sig:      an `experience.sig` like M54's `pack.sig`: the root, the signer's key, the time,
          the signature over "voxiverse experience signature v1" 0x00 || root || time
"VXEE"
```

- A new archive mode `full` for `pack_archive_make` (the `server/` folder included,
  canonical order unchanged); a full archive's hash differs from the sent one's, and both
  are recorded.
- Signing uses M54's key files and a new context string, so an experience signature can
  never be replayed as a pack signature or a join proof, and the other way round.

**Export:** `/experience export <file name>` (node `server.export`, the world the player is
in), the dedicated server's `--export-experience <address> <file> --key <key file>`, and
`experience_export(universe_dir, address, out, key, d) -> Export_Error`. Refused when a pack
the world enables is unsigned and no key is given, when the world has a script snapshot only
(scripts are stopped and their stores written first: the export saves the world), or when
the sizes pass the import limits.

**Import:** the universes screen's Import field accepts `.vxexp` beside `.vxu` (the same
field: the file's magic decides); the dedicated server's `--import-experience <file>
<universe dir>`; `experience_import(file, dest, trust, d, limits) -> Import_Error`. In
order, refusing with a code and the file named on the first failure, writing nothing until
everything checked (into a temporary directory renamed at the end, M46's disk layer):

1. magic, format, sizes and path rules (M46b's `IMPORT_LIMITS` and path checks);
2. every section's length and CRC, the root, the signature, the signer against the
   importing side's trust list (`trust_allows`; an untrusted signer is refused with the key
   and the command that would trust it, exactly as M54 refuses a pack);
3. every pack archive's hash against the header, each pack's own `pack.sig` (M54), its
   `api` supported by this engine (M52e: `OLDEST_API..CURRENT_API`);
4. the registry built from the packs (`packs_registry`), the world's region files read
   (`universe_check`, M46), `grants.cfg` and manifests parsed;
5. written: a new universe with `universe.cfg` from the header, the packs under `packs/`,
   the world under `worlds/<address>/`, the importing player as its owner (singleplayer) or
   no owner (dedicated: the operator grants).

`Experience_Error` codes (`experience.format`, `.size`, `.path`, `.crc`, `.root`,
`.signature`, `.untrusted`, `.pack_hash`, `.pack_signature`, `.api_unsupported`,
`.registry`, `.world`, `.grants`) are values with the file and detail, like M54's.

**Order of the steps:**

1. The full archive mode; `server/experience.odin`: writer, reader, root, signature.
2. Export (command, dedicated flag), import (the five checks, the screen's field, the
   dedicated flag).
3. Tests, the fuzz.

**Tests** (`server/experience_test.odin`):

- `test_experience_round_trip`: a world with two packs (server scripts, client scripts,
  channels, a store, a body from M50d, grants) exported, imported into a new universe on the
  harness, and played with M52e's fixture inputs: the scripts' outcome and the world's hash
  after the first tick equal the original's after its first tick.
- Every refusal code from a package built to fail it (truncated at every section boundary,
  one byte flipped in each section, a renamed path with `..`, an untrusted signer, a pack
  with `api` 99, a region file with a bad CRC); nothing is written for any of them.
- A package with the original universe's characters, journal or permissions cannot be made
  (the writer's list is tested against the save layout: every file kind in `docs/saves.md`
  is either listed as kept or as left out, so a new save file forces a decision).
- `test_experience_fuzz` (fixed seed, 5 000 mutations of a small package; also the target
  `save.experience` in `build fuzz`, Q1's harness, for longer runs): every case refused with a code or imported, no crash,
  no file left outside the temporary directory, the allocator flat.

**Open questions for the owner** (none blocks this row):

1. What should an experience show before it is opened (a title, a description, an image,
   the creator's name), and where?
2. When a player opens the same experience again, should it start fresh (a new universe, as
   built here) or continue their last play?
3. Should a player be able to open an experience signed by a key they have not trusted,
   after a warning, in singleplayer? (Built here: refused, with the command to trust it.)

**Left out:** sharing (a catalogue, downloads, ratings: online services); updating an
installed experience in place; several worlds in one experience (one world now; the format's
header is per world so a later version can list more).

**Threat model and fuzzing (Q1, Q5; #84):** mark the threat rows this milestone's defences
answer `built` in `docs/threat_model.md`, with their covers (tests, fuzz targets), in the same
commit; an untrusted input it adds gets a target in `build fuzz` (Q1's harness) and a line in
`docs/fuzzing.md`. `lint:quality_docs` fails otherwise.

**Exit check:** the round trip, every refusal and the fuzz pass; the suite, `build check`;
CI green.

**Check by hand:** export `server/testdata/experiences/lift_demo` from a singleplayer world
with `/experience export lift`, then import `exports/lift.vxexp` from the universes screen:
the new universe opens in the same world with the lift working.
