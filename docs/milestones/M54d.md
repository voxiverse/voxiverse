# M54d: creator tools, the edit mode and test-play

**Why.** The owner's decision of 2026-10-30 (#83): a build/edit mode and test-play. A creator
builds a world with its scripts paused, presses play to try it as a player would, and comes
back to the world exactly as it was before the test.

**What this builds on:** the building commands that exist (`server/selection.odin`: `/pos1`,
`/pos2`, `/sel`; `server/edits.odin`: `bulk_edit`, `/setblock`, `/fill`, `/replace`,
`/sphere`; `server/structures.odin`: `/structure save|paste|list`; `server/rollback.odin`:
`/undo`, `/redo`, `/rollback`, `/history`; `server/protect.odin`), game modes as data
(`data/game_modes/`, `set_game_mode`), the world's freeze (`world_paused`, the scripts'
`script_tick` standing still while frozen, M52), M52-M52d (scripts, stores, client scripts),
M47i's pack reload (`server/pack_reload.odin`: `pack_watch`, `/pack reload`, swap at a safe
tick, `Packs_Changed`), M46b's save capture (one tick, sliced encode) and M46's restore
(`universe_restore`, backups as hard links), M50d's bodies.

**The design (engineering, decided):**

- **A world is in `edit` or `play`** (`world.cfg` `state`, default `play`; a new world
  of an experience being made is set to `edit` by `/edit`). In `edit`: the pack scripts and
  data (M52, M53) do not run, client scripts do not start, bodies do not move, random ticks,
  liquids and entities are frozen (the world's existing freeze), time stands still; edits go
  through the journal as always (undo and redo work); the editing players' modes are their
  own (the edit state does not set a mode). In `play`: as today.
- **Commands** (node `world.edit_mode`, granted to the owner by `*`): `/edit` (play → edit:
  scripts are stopped with their stores written, the world frozen), `/play` (edit → play:
  scripts start fresh with `reason = "start"`), `/test` (edit → test-play, below), `/stop`
  (test-play → edit, restoring). No new UI in this row (the owner's question 1).
- **Test-play** saves the world first (M46b's capture, so the files on disk are the edit
  state at a tick), copies it with hard links (M46's backup mechanism) to
  `worlds/<address>/.edit/` together with the testing players' character files, then runs
  the world as `play`. `/stop`, or the last tester leaving, stops the world's scripts,
  unloads it, restores `worlds/<address>/` and the characters from `.edit/` (M46's restore
  path, one world), and loads it again in `edit`. The world after `/stop` is byte for byte
  the world before `/test`; the testers stand where they stood with what they held.
- **Scripts reload while editing.** In `edit`, a change to a pack's files (the watch of
  M47i, enabled for any world in `edit` state, not only dev builds) rebuilds the pack at a
  tick boundary; a pack whose ids changed is refused with M47i's message. In test-play, a
  change restarts that pack's scripts with `reason = "updated"`; their compile errors go to
  the editors as chat lines with `file:line:column` (M51's diagnostics) and to the script log.
- **Crash safety.** A server that stops during test-play finds `.edit/` on load and restores
  it before anything else (logged), so a crash never leaves the test's changes as the edit
  state. M46's crash points are extended to `/test` and `/stop`.

**Order of the steps:**

1. `world.cfg` `state`, `/edit` and `/play`, the freeze of scripts, client scripts and bodies.
2. Test-play: `/test`, `/stop`, the copy and restore, characters, recovery on load.
3. Pack watching in `edit` state; compile errors to editors.
4. Tests.

**Tests** (`server/edit_mode_test.odin`, on the harness):

- `test_test_play_restores_exactly`: in `edit`, build, then `/test`, then play with scripts
  that edit blocks, spawn, give items, move a body, write stores; `/stop`: the world's files
  and M38 root equal those before `/test`, the testers' character files equal theirs, the
  ledger audit balanced.
- A crash at each new crash point (M46's harness) restores to the edit state on load.
- In `edit`: a script's timer does not advance, a body does not move, water does not flow;
  undo and redo of edits work; `/play` starts scripts with `reason = "start"`.
- A pack file changed in `edit` is reloaded at the next tick boundary; in test-play its
  scripts restart; a compile error reaches the editor with its line.
- Permissions: a player without `world.edit_mode` is refused each command.

**Open questions for the owner** (none blocks this row):

1. What does the edit mode look like and offer beyond today's commands: buttons or a bar for
   edit, test and stop, building tools (a selection box, copy and paste, a palette), a
   different HUD?
2. Can several creators edit one world together (built here: anyone with
   `world.edit_mode` in that world), and does test-play take every player in the world or
   only the one who pressed it (built here: every player in the world)?

**Left out:** new building tools and their UI (question 1); editing scripts in the game
(M54e, M54f); packaging (M54c).

**Exit check:** the tests pass, including the exact restore and the crash points; the
suite, `build check`, `build determinism`; CI green.

**Check by hand:** in a singleplayer world with `server/testdata/packs/lift_demo`, `/edit`,
place a few blocks, `/test`, ride the lift and break blocks, `/stop`: the world is as it was
after the placing, and you are back where you typed `/test`.
