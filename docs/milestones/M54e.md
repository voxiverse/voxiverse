# M54e: creator tools, part three (a multi-line text area and the clipboard)

**Why.** Editing scripts in the game (the owner's decision of 2026-10-30, #83) needs two
engine pieces that do not exist: a multi-line text widget (the UI has only single-line
`text_input` and the console's `Line_Editor`) and the system clipboard (the platform layer
has none: M48i's LAN dialog shows its address because nothing can be copied). Split from the
editor itself ([M54f](M54f.md)) by the sizing rule: each is a session.

**What this builds on:** `client/ui` (`text_input`, `Text_Edit {id, active, cursor,
anchor}`, the private `edit_text` and word and rune helpers in `widgets.odin`, the on-screen
keyboard, `push_clip_rect`, `measure_text`, `font_line_metrics`, the Theme), the platform
interface (`client/platform/`: one file per OS: `platform_x11.odin`, `platform_win32.odin`,
`platform_darwin.odin`, events, text input), the console's `Line_Editor`
(`client/line_edit.odin`).

**The clipboard** (platform interface, all three backends): `clipboard_set(text: string)`,
`clipboard_get(allocator) -> (string, bool)` (UTF-8 text only).

- X11: the `CLIPBOARD` selection with `UTF8_STRING` (owning it and answering
  `SelectionRequest` with `INCR` for text over the request size limit; reading with
  `ConvertSelection` and waiting for `SelectionNotify` in the event pump, at most 100 ms,
  never blocking the frame longer).
- Win32: `OpenClipboard`, `CF_UNICODETEXT` (UTF-16 converted both ways), retrying `Open`
  three times when another process holds it.
- AppKit: `NSPasteboard generalPasteboard`, `NSPasteboardTypeString`.
- Text over 1 MiB is refused (`false`), and text with NUL is cut at it; nothing from the
  clipboard is ever executed or parsed beyond UTF-8 validation.
- The console's and chat's `Line_Editor` and `text_input` gain Ctrl+C, Ctrl+X, Ctrl+V
  (Cmd on macOS), the editing keys every text field has. No copy button is added anywhere
  (M48i's LAN dialog stays as it is: a new control is the owner's).

**The text area** (`client/ui/text_area.odin`): `text_area(ctx, id, buffer: ^Text_Buffer,
r, options) -> Text_Area_Result`.

- `Text_Buffer`: lines in a gap buffer of runes' bytes (UTF-8), at most 1 MiB and 20 000
  lines; an undo history of edits (coalesced by word, 1 000 steps); a cursor and an anchor
  (selection); a scroll position.
- Editing: typing (from the text input stream), Enter, Tab (inserts spaces to the next
  multiple of the indent), Backspace and Delete, arrows, Home and End, Page Up and Down,
  Ctrl+arrows by word, Ctrl+Home/End, Shift for selection, mouse click and drag, double
  click selects a word, Ctrl+A, Ctrl+Z and Ctrl+Y (or Shift+Ctrl+Z), Ctrl+C, X, V through
  the clipboard, Ctrl+F (find with the next and previous match), Ctrl+G (go to line).
  Cmd on macOS. With a pad: the cursor moves by the stick and the d-pad, the on-screen
  keyboard types.
- Drawing: line numbers in a gutter, the text in the engine's font and the Theme's text
  colour (no syntax colouring: the owner's question), the selection with the Theme's focus
  colour, the cursor, a vertical scroll bar; only visible lines are measured and drawn, so a
  20 000-line buffer costs what a screen of it costs. Marks: a caller-given list of `{line,
  column, kind}` underlines (M54f shows compile errors with them).
- No allocation per frame beyond the frame arena; the buffer's memory is the caller's.

**Order of the steps:** the clipboard on the three backends with the existing single-line
editors; `Text_Buffer` with its editing operations; `text_area` drawing and input; tests.

**Tests:** `Text_Buffer` operations table-driven (insert, delete, selection, word moves,
undo coalescing, find, go to line, limits: the 1 MiB+1 insert refused) and a fuzz of 100 000
random operations against a plain-string model (equal after each); `text_area` UI tests (a
click places the cursor at the right column, drag selects, scroll follows the cursor, a
20 000-line buffer draws only the visible lines: vertex count bounded); the clipboard: a
round trip on Linux under xvfb in the smoke suite (`smoke/clipboard_test.odin`: set, read
back from a second X connection, read text set by a second connection); Windows and macOS
build in CI and their round trip is a hand check. Benchmark: a `text_area` scenario in
`client/benchmark.odin` (typing into and scrolling a 20 000-line buffer); limit: 0.2 ms of
CPU a frame at p99.

**Open questions for the owner** (none blocks this row): should the editor colour script
syntax, and with which colours (built here: the Theme's text colour only)?

**Left out:** the script editor overlay, files, saving and errors (M54f); rich text; right
to left text; input methods beyond the platform's text events.

**Exit check:** the tests and fuzz pass; the smoke clipboard test passes in CI's Linux job;
the scenario within its limit; the suite, `build check`; CI green.

**Check by hand:** on Windows and on a Mac: type a line in chat, select it with Shift+Home,
Ctrl+C (Cmd+C), and paste it into another program; copy a line from another program and paste
it into chat with Ctrl+V (Cmd+V).
