# M54f: creator tools, part four (scripts edited in the game)

**Why.** The owner's decision of 2026-10-30 (#83): editing scripts in the game. A creator
opens a pack's script in an overlay, edits it, saves, and sees it reload into the world with
its errors at their lines, in singleplayer and on a server they are allowed to edit.

**What this builds on:** M54e (`text_area`, `Text_Buffer`, marks, the clipboard), M54d (the
`edit` state, test-play, pack watching in `edit`, compile errors to editors), M52-M52c
(server and client scripts, M51's diagnostics with file, line and column), M47i's pack
reload (rebuild, id check, `Packs_Changed`, clients re-fetching), the overlays
(`client/overlay.odin`), the protocol (validated messages, `PROTOCOL_VERSION`).

**The design (engineering, decided):**

- **The server is the only writer**, in singleplayer too (its in-process server), so one
  path serves both and the client never writes into a universe. Messages (client to server):
  `Pack_File_List {pack}`, `Pack_File_Read {pack, path}`, `Pack_File_Write {pack, path,
  bytes, base_hash}`; answers `Pack_Files`, `Pack_File`, `Pack_File_Written {path, hash,
  diagnostics}`. Node `packs.edit` (the owner has it by `*`), and only for packs enabled in
  a world the player is in that is in `edit` state or test-play (M54d).
- **Paths are checked on the server**: relative, within the pack's folder, under
  `server/scripts/`, `assets/scripts/` or `data/` (a pack's JSON), no `..`, no absolute
  path, at most 8 parts of 64 bytes, a known extension (`.vxs`, `.json`); a file at most
  256 KiB (M52c's limit for client scripts, applied to every editable file). A write is
  atomic (M46's disk layer) and refused when `base_hash` is not the file's current hash (two
  editors: the second is told to reload, nothing is lost silently).
- **After a write**, the server compiles the file (M51's compiler, without running it) and
  answers with the diagnostics; then M54d's watch reloads the pack at the next tick
  boundary (scripts restart in test-play; nothing runs in `edit`), and clients re-fetch the
  changed archive as M47i does.
- **The overlay** (`Overlay.Script_Editor`, `client/overlay_script_editor.odin`): a file
  list of the pack (from `Pack_Files`), the `text_area` with the file, Save (Ctrl+S),
  Revert, Close (Escape asks before discarding changes, through the engine's existing
  confirm dialog), diagnostics as marks and a list under the text (clicking one moves the
  cursor to its line). Opened with `/script edit <pack> [path]`. The look is the Theme's
  (the owner's question).

**Order of the steps:** the messages, the server's checks, write and compile; the overlay;
tests.

**Tests** (`server/pack_edit_test.odin`, `client/script_editor_test.odin`):

- Hostile writes, each refused at the edge with nothing written (a test lists the universe
  directory before and after): `../universe.cfg`, `/etc/x`, `C:\x`, `server/scripts/../../x`,
  a name with NUL, a 257 KiB file, an unknown extension, a pack not enabled in the player's
  world, a world in `play` state, a player without `packs.edit`, a stale `base_hash`.
- A write of a script with an error: the diagnostics arrive with the line and column the
  compiler gives; the pack is not reloaded with a script that does not compile (the running
  scripts keep the previous version) and the editor says so.
- A good write in test-play: the scripts restart with `reason = "updated"`; a second
  client (UDP) receives the changed archive (client scripts) and restarts its client VM.
- UI: open, edit, save, revert, Escape with changes asks, a diagnostic click moves the
  cursor; the whole overlay by pad (M42's harness).

**Open questions for the owner** (none blocks this row):

1. How does a creator reach the editor besides `/script edit` (a button in the edit mode's
   UI, M54d's question 1)?
2. May players with `packs.edit` on a multiplayer server edit server scripts, or should
   editing be singleplayer only? (Built here: allowed with the node, which only the owner
   has unless granted.)

**Left out:** creating and deleting files and packs from the game (a later row if asked);
autocomplete and documentation popups (M52e's `api.json` makes them possible later);
debugging (breakpoints, stepping).

**Exit check:** the tests pass; the suite, `build check`; CI green.

**Check by hand:** in a singleplayer world in `edit` with `server/testdata/packs/lift_demo`,
`/script edit lift_demo`, change the lift's speed in `main.vxs`, save, `/test`: the lift moves
at the new speed; add a syntax error and save: the error shows at its line and the lift
keeps the old script.
