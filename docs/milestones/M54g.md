# M54g: the static validator (error codes written for a model; manifests, data, scripts, client scripts and channels; `pack check`)

The second of the four signing-and-checking rows ([M54](M54.md), M54g, [M54h](M54h.md),
[M54i](M54i.md); split by #86). Before a pack runs anywhere (M54b's dry run, an install, a
creator's test-play in M54d), one pass says everything wrong with it, each finding with a
stable code, the place, why it matters and the fix, so a model can repair the pack without a
person.

**Checked against the code and the specs before it (2026-10-30, #86; corrections from the old
M54 text):**

- **There is no manifest struct and no tagged decoding.** `pack.json` is read field by field
  in `read_pack_manifest` (`common/game/registry_load.odin`) into `Pack_Info {namespace,
  version, title, description, requires, files}`; `PACK_FIELDS` is `format`, `namespace`,
  `version`, `title`, `description`, `requires`. Definitions are read by field lists
  (`BLOCK_FIELDS`, `ITEM_FIELDS`, `MODE_FIELDS`, ...; `Def_Field`, `Merged_Def`, `rd_*` in
  `registry_resolve.odin`). The loader is **already strict**: unknown fields refused with
  `suggestion` ("did you mean", within 2 edits by `edit_distance`), duplicate keys, types,
  ranges, ids resolved with the nearest; JSON caps `JSON_MAX_DEPTH` 32, `JSON_MAX_STRING`
  4 096, `JSON_MAX_ENTRIES` 4 096, `JSON_MAX_FILE` 1 MiB (`pack_json.odin`). So the old rule
  3 ("M47's loader in strict mode, if it is not strict already") and its own schema codes are
  replaced by the loader's errors gaining codes (below), and nothing is decoded twice.
- The manifest the validator checks is what the rows before it define: M47's members, M52's
  `api`, `capabilities`, `scripts`, `limits`, M52c's `client_scripts`, `client_capabilities`,
  `client_actions`, `client_limits`, M52d's `channels`. The old text's `depends` is M47's
  `requires` (namespaces, no versions, loaded earlier); `overrides` is M47's per-definition
  `"override": true`, not a manifest list; `faucets` and `budgets` do not exist: what a pack
  can create is M52's `item.give` `items` with its `per_hour`, and its budgets are its
  capabilities' parameters and `limits`. `version` is a label, not semver. The only reserved
  namespace is `voxiverse`.
- **There is no `vx` global.** M52 registers one global table per namespace (`world`,
  `entity`, `player`, `item`, `chat`, `ui`, `store`, `rules`, `timer`, ...), holding only the
  granted bindings. Inference reads `<namespace>.<name>` paths.
- Capability names are M52's (`item.give`, `world.edit`, ...), not `items.give`,
  `blocks.edit`. Server scripts live in `server/scripts/*.vxs`, client scripts in
  `assets/scripts/*.vxs` (M52c); `.vxs` is also the extension of structure templates
  (`server/structures/*.vxs`, `structure.odin`): the validator compiles scripts by directory,
  never by extension.
- The API version is M52e's (`CURRENT_API`, `OLDEST_API`, `BINDINGS` rows with `since`,
  `deprecated`, `until`); the old `AGENT_API_VERSION` is dropped. Deprecated bindings are
  warnings here, as M52e says.
- The limits are the loader's constants (`MAX_PACK_BYTES` 16 MiB, `MAX_PACK_FILES` 1 024,
  `MAX_PACK_PATH` 128, `TEXTURE_SIZE` 16 exactly, `MAX_PNG_BYTES` 64 KiB, `MAX_OGG_BYTES` 1 MiB,
  `MAX_SOUND_SECONDS` 5, `MAX_PACK_SOUND_FILES` 128 in `registry.odin` and
  `pack_assets.odin`; M53's `GAMEPLAY_LIMITS`; M52c's client-script sizes). The old table (1 024
  x 1 024 images, 60 s sounds) contradicted them; the validator restates **none**: it reads
  the constants, and M54i's docs print them.
- `tools/packcheck` (`./build.sh packs`) already calls itself "the validator a pack author (or
  an agent) runs": it reads packs and builds a registry. It becomes a thin front for this
  row's validator, so there is one validator.
- Layout: the old `agent/` top-level package becomes `common/agent/` (shared code that
  imports `base`, `common/game` and M51's `common/script`; never `server/` or `client/`),
  added to `PACKAGES`, `TEST_PACKAGES` and the plan's Layout.

**What this builds on:** M54 (`pack_root`, `pack_verify`, `Sign_Code`); M47 and M47b (the
loader, `Pack_Error`, `registry_build`, `pack_read_dir`); M51 (`compile` and
`Script_Error {kind, message, hint, source, line, column}`; the compiled form, to walk); M52
(`CAPABILITIES`, `BINDINGS`, `Script_Event`, the manifest and grants parsers, effective
capabilities); M52c (`Client_Event`, client capabilities, `client_*` members); M52d
(`channels`, the schema parser in `common/game/script_message.odin`); M52e (`since`,
`deprecated`); M53-M53d (`ACTION_INFO`, `CONDITION_INFO`, the gameplay kinds and their load
errors).

## Design (M54g)

### Codes on every load error

- `Pack_Error` gains `code: Pack_Code` (`common/game/pack_codes.odin`, `enum u16`,
  append-only; `.None` is a bug). Every `fail`/`fail_field` call in the loader, M53's parsers,
  M52's manifest and grants parsers and M52d's channel schemas passes one. The codes are
  classes, not call sites: `json.syntax`, `json.too_deep`, `json.too_long`, `json.duplicate`,
  `layout.unknown_dir`, `layout.path_invalid`, `file.too_large`, `file.too_many`,
  `pack.manifest_missing`, `pack.namespace_invalid`, `pack.namespace_reserved`,
  `pack.requires_missing`, `pack.requires_order`, `pack.api_missing`, `pack.api_unsupported`,
  `field.unknown`, `field.missing`, `field.type`, `field.range`, `field.choice`, `id.unknown`,
  `id.wrong_kind`, `id.duplicate`, `id.override_undeclared`, `asset.png`, `asset.ogg`,
  `asset.size`, `statement.syntax`, `statement.too_long`, `statement.nesting`,
  `capability.undeclared` (M53's action check), `capability.unknown`, `capability.param`,
  `capability.region_invalid`, `channel.schema`, `text.field_unknown`, `data.loot_cycle`,
  `data.no_weight`, `script.syntax`, `script.compile`. A `check` lint
  (`lint_pack_codes`) fails on a `fail(` call without a code argument.
- `Pack_Error.path`: the JSON pointer of the value (`/stages/1/objectives/0/count`), which the
  loader knows from its `Json_Value` walk; empty for whole-file errors.

### The validator (`common/agent/validate.odin`)

`validate_pack(src: game.Pack_Source, opts: Validate_Options) -> Validation_Report`.
`Validate_Options`: `deps: []game.Pack_Source` (the packs it `requires`; the base pack is
always there), `grants: Maybe(game.World_Grants)` (M52's grants of a target world, for
install-time checks), `trust: ^game.Trust_List` (optional: signature checked when present),
`text: Maybe(Text_Checker)` (M54h fills it). It runs every rule and collects every finding, so
one pass shows all of them; a rule that needs an earlier one's output is skipped for a file
that already failed. At most 500 findings (the rest counted).

1. **Load.** `registry_build` over the deps and the pack with the server's side: every
   `Pack_Error` becomes a finding with its code, file, line, column and path. Then the client
   side (`Registry_Side.Client`) over what `pack_archive_sent` would send: a definition that
   loads on the server and not on the client (a `data/` file referring to a `server/` id) is
   `layout.side`.
2. **Signature** (with `trust`): `pack_verify`'s code as a finding (`signature.*`, one per
   `Sign_Code`); `signature.unsigned` is a warning when `trust` is absent.
3. **Scripts.** M51's `compile` on each `server/scripts/*.vxs` and `assets/scripts/*.vxs`:
   `script.syntax`, `script.compile` with M51's own message and hint; `script.too_large`
   (M51's instruction cap, M52c's client sizes). Then **capability inference** over the
   compiled form: every global read `<namespace>.<name>` (a constant path, through local
   aliases of the namespace table within one function) maps to a binding of `BINDINGS` and so
   to its capability; server bindings in client scripts and client bindings in server scripts
   are `script.wrong_side`. Indexing a namespace table with a non-constant key, storing it in
   a table, passing it as a value, returning it or `rawget` on it is `script.dynamic_api`
   (inference would be unsound, so it is an error). A name not in `BINDINGS` is
   `script.unknown_api` with the nearest; a binding whose `since` is above the pack's `api`
   is `script.api_too_new`; one with `deprecated` set is the warning `script.deprecated`
   naming the replacement; `on("<event>", ...)` with a constant event name that is not a
   `Script_Event` (server) or `Client_Event` (client) is `script.unknown_event`.
4. **Capabilities used equal declared.** Used: the union of every server script's inferred
   capabilities, the needs of its event subscriptions, and what the data's actions,
   conditions and triggers need (`ACTION_INFO`, `CONDITION_INFO`, M53's trigger table); the
   same for the client side against `client_capabilities`.
   - `capability.undeclared`: used, not declared (naming the first call site or statement).
   - `capability.unused`: declared and never used (an error: a pack asks for no more than it
     needs; an `optional` one too).
   - With `grants`: `capability.over_grant`, for more than the target world grants (a
     capability, a region outside the granted one, a number above it).
5. **Channels** (M52d): every constant channel name a script sends on is declared with the
   right direction (`channel.undeclared`, `channel.direction`); a declared channel nobody
   sends on or nobody handles is the warning `channel.unused`; a constant table literal sent
   on a channel is checked against its schema (`channel.payload`: a missing field, a type, a
   string over its length), a non-constant one is left to the runtime.
6. **Bounded constructs** (data). `data.trigger_cycle`: the graph "trigger T's actions emit or
   cause an event that trigger U listens to" has a cycle with no `cooldown` on any trigger in
   it (the runtime bounds it to one hop a point; the validator says it is a cycle that runs
   forever); `data.quest_cycle`: a non-repeatable quest can restart itself;
   `data.dialogue_no_exit`: a non-closable dialogue with no path from `start` to `end` (a
   softlock by construction, an error); `data.dialogue_unreachable`: a node no path reaches (a
   warning); `data.spawner_over_budget`: the spawners' `max_alive` summed over the pack is
   above its `entity.spawn` `alive`. In scripts, warnings only (M51's metering is what bounds
   them): `script.unbounded_loop` (`while true`/`repeat ... until false` in a handler whose
   body has no `break`, `return` or yield) and `script.recursion` (a function that calls itself
   in one file, directly or through another).
7. **Economy.** Every item a script can create with a constant argument (`item.give`,
   `item.drop`, `kit.give`'s kit items) is in `item.give` `items` (`economy.item_undeclared`;
   data's are already a load error, M53); a non-constant item with `items` other than `*` is
   the warning `economy.item_dynamic` (the runtime refuses what is not listed).
8. **Quests can be finished (statically).** `quest.unobtainable`: an objective names an item
   nothing can produce (no loot table, give, kit, recipe, block drop or base source in the
   registry) or an entity kind nothing spawns (no spawner, spawn action, script spawn with that
   constant kind, or natural spawning); `quest.region_outside`: a region outside the world's
   vertical bounds.
9. **Text** (M54h's rule; skipped here when `opts.text` is empty).

### The report (`Validation_Report`, one JSON document)

```json
{"report": "validation", "report_version": 1, "engine": "<base.version_text()>",
 "pack": {"namespace": "lighthouse", "version": "1.0.0", "root": "<hex>", "archive": "<hex>"},
 "verdict": "pass",
 "findings": [{"code": "capability.undeclared", "severity": "error",
   "file": "server/scripts/lamp.vxs", "line": 12, "column": 5, "path": "",
   "message": "lamp.vxs calls world.set_block, which needs the capability world.edit; pack.json does not declare it.",
   "fix": "Add \"world.edit\": {\"region\": [[x1, y1, z1, x2, y2, z2]]} to \"capabilities\" in pack.json, or remove the call.",
   "docs": "docs/agent/capabilities.md#world-edit"}],
 "capabilities": {"server": {"declared": [], "used": []}, "client": {"declared": [], "used": []}},
 "stats": {"files": 0, "bytes": 0, "scripts": 0, "instructions": 0, "statements": 0, "findings_dropped": 0}}
```

`verdict` is `fail` if any finding is an error; warnings never fail. `root` is M54's pack
root, `archive` M47b's archive hash. Written by `report_json(r) -> string` with a fixed member
order, so two runs over the same pack give the same bytes.

### Errors written for a model (`common/agent/errors.odin`)

- `ERROR_INFO: [Error_Code]Error_Info` over every `Pack_Code`, `Sign_Code` and validator code
  (`Error_Code` is the union's enum, append-only): `id` (`"capability.undeclared"`),
  `severity`, `message` and `fix` templates (holes `{name}` filled from the finding's
  arguments) and a `docs` anchor (M54i writes the docs the anchors point at; until M54i the
  anchor names the planned file and the test checks the format only).
- Each message says what was found, where and why it matters, in one sentence; each fix says
  what to change, naming the field or call. No message names engine internals a pack author
  cannot see (a lint over the templates refuses `.odin`, `proc`, `Client.`, `s.`, `w.`).
- Human output, one line per finding then its fix:

  ```
  lighthouse/server/scripts/lamp.vxs:12:5: error[capability.undeclared]: <message>
    fix: <fix>
  ```

### The command line

`voxiverse-server pack check <dir> [--with <dir>...] [--grants <universe> <address>]
[--trust <file>] [--json]` (M54's `dedicated/pack_cli.odin`); exit 0 passed, 1 failed, 2 usage
or I/O. `./build.sh packs [dirs...]` (`tools/packcheck`) prints the same human lines for every
pack it is given, with the base pack as the dependency.

## The order of the steps (M54g)

1. `Pack_Code` and `Pack_Error.code` and `.path` through the loader, M52's, M52c's, M52d's and
   M53's parsers; `lint_pack_codes`; every existing loader test still passing, now also
   asserting codes.
2. `common/agent`: the report, `ERROR_INFO`, rules 1-2; `pack check`; `tools/packcheck` on it.
3. Rule 3 and capability inference; rule 4.
4. Rules 5-8.
5. The testdata packs, one per code; the fuzz target; the budgets scene; the threat rows.

## Tests (M54g)

- `common/agent/validate_test.odin`: one broken pack per code under
  `common/agent/testdata/packs/<code>/` (LF-pinned), each giving exactly that code (and no
  other error), with file, line, column and path where the code has them; a test fails when a
  code has no testdata pack. Then:
  - the base pack, M53d's demo pack, `server/testdata/packs/quest_test` and M54's `signed`
    pack pass with no error;
  - `capability.undeclared` and `capability.unused` name their call site or entry;
  - `script.dynamic_api` catches `local m = world; m[name](...)`, `f(world)`, `t.w = world`,
    `rawget(world, "x")`, and accepts `local w = world; w.set_block(...)`;
  - `script.wrong_side` for `world.set_block` in an `assets/scripts/` file;
  - `data.trigger_cycle` lists the cycle in order; adding a cooldown clears it;
  - with grants, `capability.over_grant` for a region outside the granted one;
  - two runs over the same pack give byte-identical JSON.
- `common/agent/errors_test.odin`: every `Error_Code` has a message, a fix and an anchor of the
  form `docs/agent/<file>.md#<anchor>`; every template's holes are filled by its finding's
  arguments (rendered for each testdata pack, no `{` left); the internals lint over the
  templates.
- `common/game/registry_test.odin` and the other loader tests: every refusal they already
  check now also checks its code; `test_every_load_error_has_a_code` runs Q1's `pack.registry`
  corpus and asserts no `.None`.
- `dedicated/pack_cli_test.odin`: `pack check --json` on a broken pack prints one JSON
  document that parses, verdict `fail`, exit 1; on the demo pack exit 0.
- Fuzz (Q1's harness): `pack.validate` (`fuzz_validate` in `common/agent/fuzz.odin`): packs
  from Q1's `pack.registry` generator plus scripts from M51c's `script.generated` generator and
  channel schemas; the oracle: a report (never a panic), findings within the cap, every
  finding's file inside the pack, the JSON parses. `test_fuzz_pack_validate_smoke` (200 cases,
  seed 84) and its regression files.

## Benchmarks (M54g)

`budget_validate` in `server/budgets.odin` (`build bench budgets -check`): the demo pack, and a
generated pack at the limits (1 024 files: 64 scripts of 4 000 lines, 1 024 triggers, 256
quests), validated five times each.

| Metric | What | Limit |
|---|---|---|
| `Validate_Demo` | mean ms to validate the demo pack | 200 |
| `Validate_Large` | mean ms for the large pack | 5 000 |

Limits are set from the first measured run as the other budgets are; a limit is never raised to
pass.

## Exit check (M54g)

- Every validator testdata pack fails with exactly its own code; the base, demo, quest_test
  and signed packs pass; `test_every_load_error_has_a_code` and `lint_pack_codes` pass.
- `pack check --json` gives one parseable document with the right exit code.
- `test_fuzz_pack_validate_smoke` clean; `build bench budgets -check` within `Validate_Demo`
  and `Validate_Large`.
- The whole suite and `build check`; CI green.

## Check by hand (M54g)

Give a broken pack's `pack check --json` report (from `common/agent/testdata/packs/`) to a model
with no other context and ask it to fix the pack: it does in one try. A failure means reword the
message or the fix, not the code; write what was reworded in the report.
