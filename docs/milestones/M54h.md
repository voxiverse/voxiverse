# M54h: moderation hooks (generated text and pack media; the external checker; the validator's text rule)

The third of the four signing-and-checking rows ([M54](M54.md), [M54g](M54g.md), M54h,
[M54i](M54i.md); split by #86). The engine owns the **hooks**; moderation itself is the
service's job (the plan's *Pack media moderation* decision, 2026-10-27, #31): no word list and
no classifier is committed.

**Checked against the code and the specs before it (2026-10-30, #86; corrections from the old
M54 text):**

- Player chat is cleaned by `chat_clean` (`server/chat.odin`: drops invalid UTF-8, C0 controls
  and DEL, trims) and filtered by mutes and ignores (`s.community`); nothing checks bidi
  overrides or zero-width runs today. Scripts' chat (M52) is a system line through
  `chat_clean`, prefixed with the pack's title.
- Player-visible pack text today and from the rows before this one: block and item names
  where the loader has them, game mode labels, M53's `message` and `say` texts and death-cause
  lines, M53b's quest titles, stage texts, dialogue speakers, texts and labels, `pack.json`'s
  `title` and `description`, M52's chat and notices from scripts, M52b's prompts, M52c's client
  scripts' HUD strings (drawn on the client, from the pack's own `assets/scripts/`), M52f's
  and M52g's UI text. The old list's `Death_Message` and `Entity_Name` uses map onto these.
- The game's binaries spawn no process today; the tools do, through `core:os/os2`
  (`tools/build`, `tools/music`). The external checker is the first child process of the
  server: `os2.process_start` with pipes, behind a small `server/moderation_process.odin` so
  tests use an in-process stream pair instead.
- `universe.cfg` is rewritten whole on save (M54's note): every key below is server config
  state, read and written.
- Pack media are M47b's: PNGs exactly `TEXTURE_SIZE` 16 x 16 (`MAX_PNG_BYTES` 64 KiB) and
  Oggs up to `MAX_OGG_BYTES` 1 MiB and `MAX_SOUND_SECONDS` 5, decoded by Odin only (M53c).

**What this builds on:** M54g (`validate_pack`, `Validate_Options.text`, the report, codes);
M54 (verification at load, where the media check joins); M52, M52b, M53b (the bindings and
actions that make text at run time); M46's `store_write`; Q1's harness.

## Design (M54h)

### Types (`common/game/moderation.odin`)

- `Text_Use :: enum u8 {Pack_Title, Name, Chat, Notice, Prompt, Dialogue, Quest, Death_Line,
  Item_Name, Hud, Other}`; `Text_Origin :: struct {pack, script, player: string}`;
  `Verdict :: struct {allowed: bool, category: string}` (a constant: `control`, `bidi`,
  `zero_width`, `length`, `word`, `external`, `media`, `timeout`, `unavailable`).
- `Text_Checker :: struct {data: rawptr, check: proc(data: rawptr, text: string, use: Text_Use,
  origin: Text_Origin) -> Verdict}`; `Media_Kind :: enum u8 {Image, Sound}`; `Media_Checker`
  the same shape over `(kind, sha256: [32]u8, path: string, origin)`.
- `text_check_basic(text, use) -> Verdict`: valid UTF-8; no C0 or C1 controls (tab allowed in
  `Dialogue`); no bidi controls (U+202A-202E, U+2066-2069, U+200E, U+200F, U+061C); at most 4
  zero-width characters (U+200B-200D, U+2060, U+FEFF); length per use (names 32 bytes, labels
  96, others 1 024).
- `Word_List` (`word_list_load(text)`): one word or phrase per line, `#` comments. A match is
  case-insensitive and whole-word after folding (`0→o 1→i 3→e 4→a 5→s 7→t @→a $→s`), also with
  separators between single letters removed (`b.a.d`). The tests use
  `common/game/testdata/words.txt` of made-up words.

### The hook (`server/moderation.odin`)

- Per universe: the basic check, then `<universe>/moderation/words.txt` if present, then the
  external checker if `universe.cfg` has `moderation.command = <command line>`.
  `moderation.chat = 1` (default 0) puts players' chat through the same hook (after
  `chat_clean`); otherwise players' chat is unchanged.
- **The external protocol:** JSON lines over the child's stdin and stdout. In: `{"id": n,
  "text": "...", "use": "dialogue", "pack": "lighthouse", "script": "lamp"}` or `{"id": n,
  "media": "image", "sha256": "<hex>", "path": "<absolute path in the installed pack>",
  "pack": "lighthouse"}`; out: `{"id": n, "allow": true|false, "category": "..."}`. One
  long-lived child, started with the universe; `moderation.media_command` may name another
  command for media (default: the same child). A reader thread parses answers (a line at most
  4 KiB; anything else is a protocol error counted and logged once a minute) and puts them on
  a `base.Queue`; the tick never waits.
- Answers older than 2 s (counted in ticks, `2 * TICK_RATE`, so tests step it) are refused
  (`timeout`). A dead child is restarted at most once a minute; while it is down, text that
  needs it is refused (`unavailable`, fail closed), logged once a minute. At most 256 texts
  pending per world; more are refused (`unavailable`).

### Where it applies

- **Static pack text** (every player-visible string the loader reads: field-table entries get
  a `visible: Text_Use` column, so which strings are checked is data, and M54i prints it) is
  checked by M54g's rule 9 when a pack is validated (`pack check --moderation-command <cmd>`
  runs the external checker synchronously, 2 s a text, then fails closed) and when it is
  installed (M54b). Templates with fields (`{player}`) are checked with the fields empty;
  names are checked when characters are made. Findings: `text.invalid` (the basic check's
  category), `text.too_long`, `text.refused` (with the category, never the text).
- **Text a script or data builds at run time** (`chat.say`, `chat.tell`, `ui.notice`,
  `ui.prompt`'s strings, M53's `message`/`say` with fields filled, quest and dialogue text with
  fields) is held until its verdict, then delivered or dropped; a refusal is logged with the
  origin and the category, never the text, and raises `text_refused {binding, category}` to
  the script (a new `Script_Event`, appended; it joins the API version as M53's *API version*
  rule says). Text without fields that was checked statically is not asked again (a set of
  checked hashes per universe).
- **Client scripts' text** is drawn on the client from the pack's own files: its string
  literals are checked statically (rule 9); text a client script builds at run time is not
  moderated (the client has no checker; M52c's client scripts cannot send text to other
  players except through M52d's channels, which reach the server's scripts, whose text is
  moderated when they show it).
- **Media** (decided in #31): when a pack is validated with a media command and when it is
  installed or first loaded, every PNG and Ogg not yet in `<universe>/moderation/media.txt`
  is asked about (synchronously, at load: a universe start waits at most 2 s a file and fails
  closed). Verdicts are kept by the file's SHA-256 in `media.txt` (`allow <hex>`, `deny <hex>
  <category>`, written with `store_write`), so a file is judged once and an altered byte is
  judged again; a hand-written `deny` line is honoured. A `deny`, a timeout or a dead checker
  refuses the pack with `media.refused` (the file, its hash and the category named, never the
  content). The base pack is exempt; so is a pack with no media.
- A universe with no media command refuses a pack that has media unless `universe.cfg` has
  `packs.unmoderated_media = 1` (default 0; logged at `warn` at every start), the same shape as
  `packs.unsigned`. A singleplayer universe's owner may set it (the old text's rule, kept:
  the default is 0 everywhere; open question 1).

## The order of the steps (M54h)

1. `common/game/moderation.odin`: types, `text_check_basic`, `Word_List`; their tests.
2. The field tables' `visible` column; M54g's rule 9; `pack check --moderation-command`.
3. `server/moderation.odin` over a stream pair: the hook, held text, timeouts, fail closed,
   `text_refused`; then the process (`server/moderation_process.odin`).
4. The media hook: `media.txt`, `media.refused`, `packs.unmoderated_media`, the load and
   install wiring.
5. The fuzz targets, the budgets scene, the threat rows.

## Tests (M54h)

- `common/game/moderation_test.odin`: each control, bidi and zero-width class; length per use;
  folding (`b4dw0rd`, `b.a.d.w.o.r.d`); whole-word (a list word inside a longer word passes);
  a phrase; comments in the list.
- `server/moderation_test.odin`, over the stream pair (a fake checker refusing one word and one
  hash), stepped:
  - held script text: the refused one is dropped and logged without the text, the allowed one
    delivered on the tick its answer arrives; `text_refused` reaches the script;
  - no answer within 2 s of ticks: refused (`timeout`); a closed stream: everything refused,
    one log line a minute; the 257th pending text refused; a restart at most once a minute;
  - a malformed answer line, an answer with an unknown id, a 1 MiB line: counted, ignored, the
    reader goes on;
  - statically checked text is not asked again;
  - `moderation.chat = 1` puts a player's line through the hook, `0` does not.
- The media hook over the same pair: a pack holding the refused PNG is refused with
  `media.refused` naming the file and the hash; a pack with other media passes; neither verdict
  is asked twice (`media.txt` has the lines; a second start asks nothing); a changed byte is a
  new hash and is asked again; a timeout and a closed stream refuse and cache nothing; no media
  command: refused, and with `packs.unmoderated_media = 1` it loads with the warning; a pack
  with no media loads either way; a hand-written `deny` refuses without asking.
- `common/agent/validate_test.odin`: rule 9's three codes, each with its testdata pack and a
  fake checker.
- `dedicated` test: a real child process (the test builds a tiny checker,
  `server/testdata/moderation/checker.odin`, refusing one word) through `os2`: allowed and
  refused text, killed mid-run and restarted.
- Fuzz (Q1): `moderation.answers` (the reader's line parser: random JSON lines, long lines,
  partial lines) and `moderation.media_cache` (`media.txt`); smoke tests at seed 84 and their
  regression files.

## Benchmarks (M54h)

`budget_moderation` in `server/budgets.odin`: 100 scripts each sending one notice a second for
900 ticks through the stream-pair checker answering at once.

| Metric | What | Limit |
|---|---|---|
| `Moderation_Tick` | mean CPU us a tick for the hook (queueing, matching answers, delivery) | 300 |
| `Text_Check_Basic` | mean us for `text_check_basic` and a 1 000-word list on a 1 KiB text | 50 |

Limits are set from the first measured run as the other budgets are; a limit is never raised to
pass.

## Exit check (M54h)

- A pack with a PNG the fake checker refuses is not loaded, with the code and the hash; the
  media and text hook tests pass; held script text is dropped or delivered as listed.
- Rule 9's testdata packs fail with their codes; the process test passes on the three OSes.
- The fuzz smokes clean; `build bench budgets -check` within `Moderation_Tick` and
  `Text_Check_Basic`.
- The whole suite and `build check`; CI green.

## Left out (M54h)

A committed word list or any classifier (the service's); moderating text a client script
builds at run time; moderation of voice (none exists); uploading crash or moderation data.

## Open questions for the owner

1. **Singleplayer media.** As the old text decided, a universe with no media checker refuses
   packs with media unless `packs.unmoderated_media = 1`, default 0 everywhere, so a player who
   copies a pack with its own textures into a singleplayer universe must set the key first.
   `packs.unsigned` defaults to 1 for universes the client makes. Should
   `packs.unmoderated_media` default to 1 there too (the player's own files; friends joining
   by Open to LAN would see the host's pack media unchecked), or stay 0?
