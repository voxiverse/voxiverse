# M54i: the agent surface (JSON Schemas from the loader's field tables, `docs/agent/`, the example packs, the docs in the server binary)

The last of the four signing-and-checking rows ([M54](M54.md), [M54g](M54g.md),
[M54h](M54h.md), M54i; split by #86). A model that has never seen the engine reads
`docs/agent/`, writes a pack against generated schemas, runs `pack check`, and fixes what it
says. Everything a model reads about formats is generated from the code that reads them, so it
cannot drift.

**Checked against the code and the specs before it (2026-10-30, #86; corrections from the old
M54 text):**

- **Schemas cannot come from `core:reflect`:** definitions are not decoded into tagged structs
  but read field by field (`BLOCK_FIELDS`, `ITEM_FIELDS`, `MODE_FIELDS`, ... are lists of
  names in `registry_load.odin`; types and ranges live in the `rd_*` calls of
  `registry_resolve.odin` and M53's parsers). So the field lists become **field tables**
  (`Field_Spec {name, type, min, max, choices, required, doc, visible}`) that the readers
  consult for type and range, and the schema generator reads the same tables: the decoder and
  the schema are one table. `visible` is M54h's column.
- The kinds table is `Content_Kind` and `KIND_DIRS` (with M50e's `entities`, M52f's `assets/ui`,
  M52g's `data/containers`, M53-M53d's gameplay kinds); the old `PACK_FILE_KINDS` is that
  table. Packs are `pack.json` plus `<side>/<kind>/<file>`.
- The generated-file pattern exists: `tools/schema` splices the dissector's block and
  `test_dissector_schema_current` (`common/game/protocol_test.odin`) fails while it is stale;
  LF pins in `.gitattributes`. M52e adds `./build.sh scriptapi` and `docs/script_api/v<N>.json`
  (the script API, which these docs link to, never copy). There is no `build agent-docs` yet;
  build cases are in `tools/build/main.odin`.
- `#load_directory` is not recursive (`base_pack.odin` loads one directory per category), so
  embedding `docs/agent/` loads each of its directories; `tools/build/package.odin` copies no
  `docs/` today.
- M54b's `dryrun-report.schema.json` and `docs/agent/dryrun.md` are M54b's: this row's
  generator takes a list of report types, and M54b adds its own.

**What this builds on:** M54g (the report types, `ERROR_INFO`, `pack check`), M54h (`visible`,
the moderation docs), M52e (`docs/script_api/`), M53d's demo pack, M47i (packs in the export).

## Design (M54i)

### Field tables (`common/game/registry_fields.odin`)

- `Field_Type :: enum u8 {Bool, Int, Float, String, Id, Ids, Choice, Object, List, Statement,
  Statements, Text, Box, Boxes}`; `Field_Spec :: struct {name: string, type: Field_Type, of:
  Content_Kind (for ids), min, max: f64, max_len: int, choices: []string, required: bool, doc:
  string, visible: Text_Use, fields: []Field_Spec (objects and lists of objects)}`.
- One table per kind (`FIELDS: [Content_Kind][]Field_Spec`) and `PACK_JSON_FIELDS` (M47's, M52's,
  M52c's and M52d's members). The readers take type and range from the table (`rd_field(m, &spec)`)
  instead of literals; a field read that is not in its table fails a test
  (`test_fields_cover_readers` runs every testdata pack with a tracking hook on `field_of`).
- Every field has a `doc` of one sentence: a field without one fails `test_fields_documented`.

### Schemas (`tools/agentdocs`, `./build.sh agent-docs`)

- JSON Schema 2020-12 from the tables: an object with `properties`, `required`,
  `additionalProperties: false`; a `Choice` an `enum`; numbers `minimum`/`maximum`; strings
  `maxLength`; lists `maxItems`; ids `$ref: "#/$defs/id"` (`^[a-z0-9_]{1,32}:[a-z0-9_]{1,48}$`,
  M47's id rule) with `x-kind` naming the kind; statements `type: string` with `x-statement`
  (their grammar is in `data.md`, not in a schema); `description` from `doc`. `$id` is
  `voxiverse:pack/<format>/<kind>`.
- Written, generated and LF: `docs/agent/schemas/<kind>.schema.json` for every kind,
  `pack.schema.json`, `validation-report.schema.json` (from M54g's report, by a table of its
  members), `docs/agent/errors.md` (every code: meaning, fix, an example finding from its
  testdata pack), the limits table in `docs/agent/packs.md` between `<!-- limits begin -->` and
  `<!-- limits end -->` (from the loader's constants and `GAMEPLAY_LIMITS`), and the visible-text
  table in `docs/agent/moderation.md`.
- `test_agent_docs_current` fails while any of them is stale (the generator run in memory and
  compared), like `test_dissector_schema_current`; `.gitattributes` pins `docs/agent/** text
  eol=lf`.

### Hand-written docs (`docs/agent/`, short and plain, for a model to read first)

`README.md` (what a pack is; the pipeline: write, `pack check`, sign, dry run, install, revert;
how to read a report; where the rest is), `packs.md` (layout, sides, the manifest, ids,
overrides, `requires`, limits), `data.md` (M53-M53d's kinds with one example each, the
statement language, text fields), `scripting.md` (M51's language as it differs from Lua 5.4,
the namespaces, the events; links `docs/script_api.md`), `client.md` (M52c's client scripts and
M52d's channels), `capabilities.md` (one `##` per capability: what it allows, its parameters and
budgets; the anchors M54g's error table points at), `signing.md` (keys, `pack sign`, trust),
`moderation.md`. Every anchor `ERROR_INFO` names exists (`test_error_anchors_exist`); every code
block marked `json` in them parses, and every one marked `pack` is a pack file that validates
(`test_agent_doc_examples`).

### Examples

`docs/agent/examples/minimal/` (one item, no script) and `docs/agent/examples/lighthouse/` (a
keeper with a dialogue, a quest, a loot table, a server script that lights a lamp at night, a
client script for a HUD line, a channel between them): both pass `pack check` with no finding;
M54b runs lighthouse in its dry run.

### Shipping

The server binary embeds `docs/agent/` (`#load_directory` per directory) and
`voxiverse-server pack docs --out <dir>` writes it out, so a lone binary is a complete agent
toolkit; `./build.sh package` copies `docs/agent/` into the archive.

## The order of the steps (M54i)

1. Field tables for every kind and `pack.json`; the readers on them; `test_fields_cover_readers`,
   `test_fields_documented`; every loader test unchanged and passing.
2. `tools/agentdocs`, `./build.sh agent-docs`, the generated files, `test_agent_docs_current`.
3. The hand-written docs and the two examples; the doc tests.
4. `pack docs`, the embedding, the package copy.

## Tests (M54i)

- `test_fields_cover_readers`, `test_fields_documented`, `test_agent_docs_current`,
  `test_error_anchors_exist`, `test_agent_doc_examples` (above).
- `common/agent/schema_check_test.odin`: a checker of only the keywords the generator emits:
  every file of both examples, the base pack and the demo pack is valid under its schema; every
  `field.*` and `id.*` testdata pack of M54g is invalid under its schema at the same JSON
  pointer the loader names (schemas and decoder agree, both ways).
- `dedicated/pack_cli_test.odin`: `pack docs --out` writes a tree equal to `docs/agent/`.
- `tools/build` test: the package archive holds `docs/agent/README.md`.

## Benchmarks (M54i)

None: nothing here runs in a tick or a frame (the generator runs at build time).

## Threat model and fuzzing (Q1, Q5; #84)

No new untrusted input (the docs are the engine's own). Mark nothing; `docs/quality.md` gains
the line for `test_agent_docs_current` if Q5's quality bar lists generated docs.

## Exit check (M54i)

- `test_agent_docs_current` and the schema-agreement tests pass; both examples pass `pack check`
  with no finding; every field documented; every error anchor exists.
- `pack docs --out` writes the docs; the package holds them.
- The whole suite and `build check`; CI green.

## Left out (M54i)

A general JSON Schema validator in the engine (the loader is the validator; the schemas are for
agents); the dry-run report's schema and docs (M54b); translations of the docs.

None.

## Check by hand (M54i)

Give `docs/agent/README.md` (only) to a model with no other context and ask for a pack that adds
a quest with a dialogue and a reward: its first `pack check` has at most three findings, and it
fixes them from the report alone. Write in the report what the model got wrong first.
