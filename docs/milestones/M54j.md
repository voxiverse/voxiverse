# M54j: the dry run (bots play a candidate pack or experience and a report says what broke)

The second of three rows ([M54b](M54b.md), M54j, [M54k](M54k.md); split from M54b by #88).
After M54b (its bots), before M54k (staged rollout, which can require a dry run's report).

**Why.** A pack can pass every static check (M54g) and still be unwinnable, run an item
faucet away once its triggers interact, or blow its script budget under real events. The dry
run plays it with bots on a stepped server and reports, as JSON written for a model, what it
found, with the same finding format as `pack check`.

**What this builds on:** M54b's `bot/` (`Bot`, verbs, `Behaviour`, harness parties); T2's
harness (`server/harness.odin`: `harness_start(h, config)`, `harness_step`, `Simnet`, no clock
read, no thread); M54's signing and `voxiverse-server pack` subcommands; M54g's validator
(`common/agent/validate.odin`: `validate_pack`, `Validation_Report`, the finding
`{code, severity, file, line, path, message, fix, docs}`); M54h's runtime text checker; M54i's
schema generator and `docs/agent/`; M52's usage counters and buckets (per script:
instructions, memory, edits, spawns, messages; suspensions as `Script_Halted`), its ledger
reasons `Script_Give`/`Script_Take` and per-pack counters `scripts.items.<pack>.<item>`;
M53/M53b/M53d's quests, objectives, dialogue, triggers and spawners (their server state is
what progress is read from); M31's `audit`; M46b's export and M54c's experiences
(`server/experience.odin`: `.vxexp`, `experience_open`); Q3's crash bundles.

## Checked against the code (2026-10-30, #88; corrections to the old M54b text)

- **The world** is a harness (`harness_start` with a `Config` the dry run builds: the
  scratch generator or a copied world, `stepped`, `workers = 0`), not a server with extra
  pipes; bots are `bot.Bot` parties over `Simnet`. A dry run is therefore a function of the
  pack, the seed and the options, by construction.
- **Item origins:** M52 does not build stack origin tags (they wait for the economy's
  content wave). Faucets are read from the ledger's `Script_Give` entries and the per-pack
  counters, not from items.
- **The example pack** is M54i's `docs/agent/examples/lighthouse/` (a keeper with a
  dialogue, a quest, a loot table, a server script lighting a lamp at night, a client
  script, a channel). M54j runs it as it is; the old M54b text's own lighthouse (wool quest,
  `scripts/lamp.vxs`, `blocks.edit`, a `death` trigger) is superseded: paths are
  `server/scripts/`, the capability is `world.edit`, deaths are M53's `player_died`.
- **Experiences** (M54c, before this row in the order) are something the dry run takes: a
  `.vxexp` is opened into a temporary universe and its world played with all its packs.
- **Timing:** the report's tick times are CPU times read with `base.thread_cpu_us` and are
  report content, never a test assertion (T5). The supervisor's wall-clock limit is a
  process guard, not a measurement.

## Design

### Where the code lives

The dry run's core (world setup, the explorer, measurements, findings, the report) is in
`server/` (`server/explorer.odin`, `server/dryrun.odin`): it needs the harness, the registry
and the pack's data, `server` may import `bot` (never the other way), and `build bench
budgets` can reach it there (`tools/bench` imports `server`; `dedicated` is a main package).
`dedicated/dryrun.odin` holds only the supervisor and the `pack dryrun` and `pack
dryrun-child` commands.

### The explorer (`server/explorer.odin`, a `bot.Behaviour`)

It needs the pack's data, so it lives beside the dry run, not in `bot/`.

- Each step it lists **affordances**, each a key (`dialogue:<node>:<option>`,
  `reach:<region>`, `hunt:<entity kind>`, `use_entity:<kind>`, `use_block:<kind>`,
  `collect:<item>`, `command:<trigger>`, `wait`), from: an open dialogue prompt's options;
  the bot's active objectives (M53b's records) joined with their definitions in the pack;
  entities with a use in view; blocks with a use within 32 blocks (from the chunks it keeps);
  region and command triggers of the pack it has not fired yet.
- It picks the first of: dialogue options not chosen yet; affordances serving an active
  objective, fewest attempts first; untried trigger affordances; a random wander (its `rng`).
- It moves with `/tp @s x y z` (the dry run's `bot` role has `teleport.tp`, `chat.send` and
  `world.edit` and nothing on items or rules), lands beside the target and walks the last
  blocks: there is no navigation.
- `collect:<item>` breaks a block, or kills or uses an entity, that the registry and loot
  tables say drop it; it never `/give`s, so the ledger sees only the pack's faucets and the
  world's.
- An attempt ends at success or after 600 ticks; attempts are counted per key.

### The dry run (`server/dryrun.odin`; the supervisor in `dedicated/dryrun.odin`)

- **Inputs:** a pack directory, a `.vxpack`, or a `.vxexp` (`--experience`; every pack in it
  checked and installed, findings carrying a `pack` field). The world: a scratch world from
  `--address` and `--seed` (defaults: the base pack's default world, seed 54), a copy of a
  real world (`--world <universe> <address>`, through M46b's export into a temporary
  directory), or the experience's own world.
- **Rules:** `harness_rules()`'s still rules except what the pack's mode sets; `no_sheep`
  unless the pack relies on natural spawns. The pack is activated in that world with its
  manifest's requested grants capped at M52's ceilings (as M54k's install will).
- **Bots:** `--bots` (default 4) explorers named `bot1`..., joining 60 ticks apart.
- **Length:** `--ticks` (default 18 000: ten minutes of game time).
- **Deterministic:** the same input, seed and options give the same report byte for byte once
  the `timing` fields are removed (they are grouped under `timing` for that).
- **Process model:** `voxiverse-server pack dryrun <input> ...` is a supervisor. It verifies
  (M54) and validates (M54g) first; a failed validation ends there with its findings. It then
  runs itself as a child (`pack dryrun-child <args>`, `os.process_start`). Every 600 ticks the
  child writes its report so far to `<tmp>/progress.json` (replaced by rename, never torn) and
  logs to `<tmp>/child.log`. A child that exits non-zero, dies of a signal (a Q3 crash bundle
  is written), or runs past `max(120 s, 50 ms x ticks)` of wall time (killed) gives
  `engine.crash` or `engine.timeout`, with the exit code or signal, the last tick reached and
  the last 50 log lines; the rest of the report is the last progress. A crash is an engine
  bug, never the pack's: it fails the verdict and says "an engine bug: report it". DEV builds
  take `--crash-at <tick>` (a deliberate panic) for the test of this path.
- **Measured** on the server side (the child reads the server's state; bots are not trusted
  to report):
  - `script.error`: M51 runtime errors per script, the first three with their lines.
  - Budgets per script from M52's counters: instructions per tick (p99, max), memory (max),
    edits, spawns and messages per tick (max), suspensions. Per world: tick CPU time p50, p99,
    max (in `timing`), edits and spawns per tick. Findings: `budget.suspended` (error),
    `budget.near` (p99 over 80% of a budget: warning), `tick.over_budget` (tick p99 over
    `game.TICK_DURATION`: error; judged from CPU time, so it is the only timing-dependent
    finding, and it is left out of the deterministic comparison).
  - The ledger: `audit` every 600 ticks and at the end; any difference is
    `economy.imbalance` (item, held, ledger). Items created by reason and pack give a rate per
    game hour. `economy.faucet`: a pack's `Script_Give` total over its declared `faucets` cap
    (per character, or per hour scaled to the run) or over the world's
    `scripts.items_per_hour`; `economy.faucet_capped` (warning): M52's bucket held but the
    pack hit it.
  - Progress per bot (the tick of its last progress: an objective advanced or completed, a
    quest started or completed, a dialogue node first reached, a first item of a kind, a
    region first entered), read from the server's quest and objective state (M53b), never
    from the bot. `progress.softlock`: a bot has an active unfinished quest, no progress for
    6 000 ticks, and has tried every affordance at least twice; it names the bot, quest,
    objective, last progress tick and the affordances with their attempts.
    `progress.loop`: a quest completed more than its `repeat.max`, or more than 6 times a
    game hour if it says none; or a trigger M52 suspended for firing over budget.
    `progress.unreached` (warning): a quest no bot started.
  - `needs_universe_install` (info): the pack carries content kinds (blocks, items, entity
    kinds: universe-wide, M47), so M54k installs it in the universe first.
  - Text refused at run time by M54h's checker: `text.refused_runtime` (origin, use,
    category).
- **The report** (`dryrun-report.schema.json`, generated through M54i's list of report
  types; `docs/agent/dryrun.md` explains every section and code):

```json
{"report": "dryrun", "report_version": 1, "engine": "<version>", "pack_hash": "<root>",
 "config": {"seed": 54, "address": "...", "ticks": 18000, "bots": 4, "world": "scratch" | "copy" | "experience"},
 "verdict": "pass" | "fail",
 "findings": [{"code": "progress.softlock", "severity": "error", "pack": "lighthouse", "tick": 9120,
   "bot": "bot2", "quest": "lighthouse:wool", "objective": "bring_wool", "message": "...", "fix": "...", "docs": "..."}],
 "crash": null | {"exit_code": 0, "signal": "", "tick": 0, "log_tail": ["..."]},
 "budgets": {"scripts": [{"id": "lighthouse:lamp", "instructions": {"p99": 0, "max": 0, "budget": 0},
     "memory": {"max": 0, "budget": 0}, "suspensions": 0, "errors": 0}],
   "world": {"edits_per_tick_max": 0, "spawns_per_tick_max": 0}},
 "ledger": {"balanced": true, "audits": 30,
   "faucets": [{"item": "lighthouse:lantern", "pack": "lighthouse", "count": 4, "per_hour": 24, "cap": "1 per character"}]},
 "progress": {"quests": [{"id": "...", "started": 4, "completed": 4, "completions_max": 1}],
   "bots": [{"name": "bot1", "last_progress_tick": 0, "stuck": false,
     "tried": [{"affordance": "dialogue:keeper:0:1", "attempts": 2}]}]},
 "text": {"checked": 0, "refused": [{"origin": "lighthouse:lamp", "use": "notice", "category": "word"}]},
 "timing": {"tick_us": {"p50": 0, "p99": 0, "max": 0, "budget": 33333}, "wall_s": 0}}
```

  `--out <file>` writes it; `--json` prints it, else a human summary. Exit codes: 0 pass, 1
  fail, 2 usage or I/O, 3 the child crashed or timed out.

## The order of the steps

1. The explorer on the harness against the lighthouse pack; its affordance test.
2. The dry-run child: world setup (scratch, copy, experience), measurements, findings,
   progress file, report.
3. The supervisor, its crash and timeout paths, `pack dryrun`, the schema, `dryrun.md`.
4. The testdata packs (`server/testdata/dryrun/`), the tests, the fuzz target, the bench
   scene; history.md.

## Tests (`server/dryrun_test.odin`, each a stepped dry run signed with a key made in the test; the supervisor's, `crash` and `timeout`, in `dedicated/dryrun_test.odin`)

- `test_explorer_affordances`: on a fixed pack state, the affordance list and the pick order
  are exactly the expected keys (a table test).
- `lighthouse` (M54i's example), 2 bots, 6 000 ticks: verdict `pass`, every quest completed by
  every bot, ledger balanced, no suspension, every faucet within its cap.
- `loop`: a repeatable quest without cooldown whose completion restarts it and gives an
  emerald, passing M54g (it declares `repeat.max: 1000` and `faucets.per_hour: 100000`):
  `progress.loop` and `economy.faucet` (over the world's cap), verdict `fail`.
- `faucet`: a time trigger every tick giving a diamond within the declared `per_hour`:
  `economy.faucet_capped` or `economy.faucet`, and `budget.suspended`.
- `softlock`: the quest's NPC is spawned by a trigger that fires once at tick 100 and
  despawns at 200; the quest starts at 300. M54g passes (the kind has a spawner).
  `progress.softlock` names the quest and the objective.
- `crash` (DEV, `--crash-at 500`): `engine.crash`, exit code 3, `crash.tick` 500, a log tail,
  a crash bundle written.
- `timeout` (DEV, a child told to hang: `--hang-at 100` with the limit lowered by
  `--wall-limit 2`): `engine.timeout`, exit code 3, the child killed and reaped.
- `experience`: an experience made in the test (M54c's `experience_make`) with the lighthouse
  and `loop` packs: the findings carry `pack`, `loop`'s and none of lighthouse's.
- `test_dryrun_deterministic`: lighthouse twice with the same seed: byte-identical reports
  without `timing`; with another seed, `config.seed` and nothing structural differs.
- `test_dryrun_report_schema`: every report above validates under the generated schema
  (M54i's checker); a mutated report (a missing field, a wrong type) does not.
- **Fuzzing (Q1):** the supervisor reads the child's `progress.json`: target `dryrun_progress`
  (random and mutated reports: refused cleanly or read; never a crash).

## Budgets (`build bench budgets`; T5)

`budget_dryrun` (`server/budgets.odin`, beside the other scenes): the lighthouse dry run, 2 bots, 6 000 ticks, CPU time of the stepping
thread. Metric `Dryrun_Lighthouse` (ms for the whole run) limit **20 000**, so an agent's
default 18 000-tick, 4-bot run stays near a minute; `Dryrun_Tick_P99` (us) reported. Its test
calls the scene for what it does (verdict `pass`).

## Left out

Navigation; dry runs in parallel or over many seeds (one per run; the agent service may run
several); bots using client scripts' UI (they speak the protocol, not M52f's toolkit).

## Exit check (M54j)

**Gated in CI:** the dry-run tests above (lighthouse passes; `loop` and `faucet` fail with
their codes; `softlock` names its quest; crash and timeout give exit code 3; the experience
run attributes findings per pack; reports deterministic and schema-valid); the fuzz target's
seed run; `build bench budgets -check` with `Dryrun_Lighthouse` in budget; `build check`, the suite and CI
green on the three OSes.
