# M54k: staged rollout (a pack installed into one world, recorded, and reverted by cause)

The third of three rows ([M54b](M54b.md), [M54j](M54j.md), M54k; split from M54b by #88).
After M54j, before M55.

**Why.** A server that takes packs from agents or creators installs one into one world at a
time, live, and can take it out again with everything it did undone and every player's own
work kept. The journal (M45) already records every change with its cause; M52 and M52b give
every script effect a cause and an entry kind; this row adds the markers, the install path
and the revert.

**What this builds on:** M45's journal (`common/game/journal.odin`: record types `Tick`,
`Actor`, `Action`, `Changes`, `Save`, `Params`, `Entity`; `Actor_Kind.Script`; rollback by
cause, `server/rollback.odin`), M52's entity spawn and removal entries, M52b's item, rule and
time entry kinds with their rollbacks (`/rollback script <id>`), M50c/M50d's `Edit_System.Body`
captures and releases, M53's data actions under the actor `<pack>:data`, M52b's per-world
`store.dat` and script snapshots (`worlds/<address>/scripts/<pack>/`), M52's worlds' `packs`
and `grants.cfg`, M54's `pack_verify` and `trust.cfg`, M54g's validator with a world's grants,
M54j's report, M46's atomic writes and save transaction, M47's missing-content placeholder.

## Checked against the code (2026-10-30, #88; corrections to the old M54b text)

- **Install directory.** The old text installed to `packs/<namespace>@<version>/`, which
  breaks the rule that a pack's directory is its namespace (found by M54's check, #86).
  Decided: `<universe>/packs/<namespace>/`, one version at a time; an update is a revert and
  an install.
- **Markers are journal record types:** `Journal_Record_Type` gains `Pack_Install` and
  `Pack_Revert` (appended; `JOURNAL_FORMAT` goes up after M52b's, no reading of older
  segments before 1.0). A marker holds the pack, version, hash and the world's state hash.
- **Items:** M52 builds no stack origin tags. Revert takes back what the pack gave through
  M52b's item entries (each linked to its ledger entry): the item is taken from where the
  entry says it went if it is still there; what a player has since moved, used or crafted is
  left and counted as `items_moved` (a conflict).
- **Bodies:** M50d journals a body's capture and release but not its motion (state, kept in
  the save). A pack that moves a body that existed before the install would leave it moved.
  Decided (engineering): the first time after an install that an actor of the pack moves a
  body it did not spawn, a `Body_Pose` entry records the pose before; revert puts it back.
  Bodies the pack spawned are removed by their spawn entries.
- **Quest state** is M53b's per-character state in the world; the pack's `store.dat` and
  script snapshots are M52b's files.

## Design

### Install (`server/pack_install.odin`)

`/pack install <dir under incoming/> <world address>` and offline `voxiverse-server pack
install <dir> --universe <dir> --world <address>`; both need `server.packs`.

1. Verify against `trust.cfg` (M54).
2. Validate with that world's grants (M54g, `Validate_Options.grants`).
3. With `packs.require_dryrun 1` in `universe.cfg` (default 0; 1 recommended for servers that
   take agent packs): refuse unless `<dir>/dryrun.json` exists, has verdict `pass`, the same
   pack hash and this engine's version.
4. Copy the pack to `<universe>/packs/<namespace>/`, read-only afterwards (re-verified at every
   start, M54).
5. At the next tick boundary: the `Pack_Install` marker with the world's state hash; the pack
   added to the world's `packs` list (`world.cfg`) and its behaviour activated (scripts and
   gameplay data, grants as validated). A pack with content kinds (M54j's
   `needs_universe_install`) is first installed in the universe (`universe.cfg`, a restart).

Every effect of the pack is journaled under an actor naming it (`<pack>:<script>`,
`<pack>:data`), so a pack's effects are the actions whose actor's prefix is the pack.

`worlds/<address>/packs.jsonl` records each step, one line each (M46's append with fsync):
`{"t": <unix ms>, "tick": n, "action": "install" | "revert", "pack": "lighthouse", "version":
"1.0.0", "hash": "...", "key": "...", "by": "<character or console>", "world_hash": "...",
"journal": <marker sequence>}`; a revert's line adds `"undone": {"blocks": n, "entities": n,
"items": n, "quests": n, "rules": n, "bodies": n, "conflicts": n, "items_moved": n,
"placeholders": n}`. `/pack history <world>` prints them; `/pack list [world]` lists installed
packs, keys and revoked-key warnings.

### Revert

`/pack revert <namespace> <world address>` (`server.packs`), at a tick boundary:

1. Deactivate: scripts stopped (no snapshot), triggers and spawners off, no new effects.
2. Rollback by cause (every actor of the pack) since the install marker, newest first: block
   edits, block entities, entity spawns and removals, items, rules, time, body captures,
   releases and `Body_Pose`s. A block a non-pack cause changed after the pack did is left and
   counted in `conflicts`, its position logged.
3. The pack's per-character quest state in this world deleted; its `store.dat` and script
   snapshots deleted.
4. Off the world's `packs` list. Blocks of the pack's own kinds placed by players become
   M47's placeholder, counted.
5. The `Pack_Revert` marker; the `packs.jsonl` line.

**The guarantee:** with no non-pack cause in between, the world's state hash after a revert
equals the hash at install. In general every journaled effect of the pack is undone and every
player's own effect stays.

## The order of the steps

1. The two record types, `Body_Pose`, the marker write and read; journal tests.
2. Install (offline and live), `require_dryrun`, `packs.jsonl`, `/pack list|history`.
3. Revert, its conflicts and counts.
4. The end-to-end test, the property test, the fuzz targets, the bench scene; docs
   (`docs/saves.md`: `packs/<namespace>/`, `packs.jsonl`; `docs/agent/`: installing and
   reverting); history.md.

## Tests

- `server/pack_install_test.odin`:
  - an unsigned pack where `packs.unsigned` is 0 is refused; a forged and an altered pack are
    refused at install, nothing written;
  - `require_dryrun` refuses a missing report, a failing one, one for another hash and one
    from another engine version;
  - install writes the marker (read back from the segment) and the `packs.jsonl` line;
  - `test_revert_restores_hash`: a still world; the hash taken; lighthouse installed; one bot
    (M54b) completes its quest, so the lamp edits, the keeper, the reward, the rules or time
    the script touched and the quest state all exist; revert: the state hash equals the
    install's, the bot holds no reward, the ledger audit balances, `store.dat` and snapshots
    gone;
  - a conflict: a player breaks a lamp block after the pack lit it; revert leaves the
    player's air and counts one conflict; the player moves the reward into a chest: revert
    takes it from the chest; the player places it in the world: `items_moved` 1, a
    placeholder if its kind leaves with the pack;
  - a body: the test pack moves a body that existed before the install; revert puts it back
    (pose equal), and removes a body the pack spawned.
- `test_revert_property`: 200 seeds; a seed draws up to 300 interleaved effects of a test pack
  (edits, spawns, gives, rule and time changes, body moves) and of players (edits, picking up,
  moving items); after revert: every block either the install's value or a player's last
  write, no entity of the pack, the ledger balanced, no leak; with no player effects the hash
  equals the install's.
- `test_pack_pipeline_end_to_end` (`dedicated`, a temporary directory): `pack keygen`; `pack
  sign` lighthouse; `pack verify` with a trust list holding the key; `pack check --json`
  verdict `pass`; `pack dryrun --json --ticks 6000 --bots 2` verdict `pass`, schema-valid;
  `pack install` into a universe with `require_dryrun 1`; a stepped server on it, two bots over
  `Simnet` finishing the quest; `/pack revert`, the hash equal to the install's;
  `/pack history` showing both lines.
- **Fuzzing (Q1):** `packs_jsonl` (the file is read by `/pack history` and at start: a
  corrupted line is skipped with a warning naming it, never a crash) and `dryrun_report` (the
  report `require_dryrun` reads from an untrusted pack directory); both in `build fuzz` and
  `docs/fuzzing.md`. Q1's journal target gains the two record types.

## Budgets (`build bench budgets`; T5)

`budget_pack_revert` (`server/budgets.odin`): a pack's 100 000 journaled block edits over 64
chunks plus 1 000 item gives and 200 spawns, reverted in one tick boundary, CPU time of the
thread. Metric `Pack_Revert` (ms) limit **400**; the scene's test calls it for what it does
(the hash restored). A revert larger than the scene's is spread over ticks as M45's rollback
already is.

## Left out

Updating a pack in place while keeping script state; removing a pack's content kinds from a
world; rolling back players' own effects with a pack; network upload of packs (a pack reaches
`incoming/` by being copied there: the service's job).

## Exit check (M54k)

**Gated in CI:** `test_pack_pipeline_end_to_end`; the forged and altered refusals;
`test_revert_restores_hash`, the conflict and body tests, `test_revert_property`; the fuzz
targets' seed runs; `build bench budgets -check` with `Pack_Revert` in budget; `build check`,
the suite, `build determinism` and CI green on the three OSes.
