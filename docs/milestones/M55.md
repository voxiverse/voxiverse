# M55: secure transport (an encrypted, authenticated netcode, server identity, the account proof bound to the channel)

The first of two rows (M55, [M55d](M55d.md); split by #88 at the joint the old M55 spec
named: its steps 1-3 and 4-7). In the order of 2026-10-30 it comes after M54k; M55d follows
it, then M55b. M55c's identity abstraction wraps this row's binding (below, *Accounts tied to
the channel*; M55c says the same).

**Why.** Since M27 the netcode has been authenticated at the door and plain on the wire. M27
accepted that for telemetry and wrote "if that changes, the cost is in the netcode, once,
for everything". With agent packs, accounts, script messages (M52d) and economies, it
changes now. Anyone on the path can read chat, and a forged `Disconnect` with the visible
token kicks a player. Nothing proves the server is the one the player joined before, and an
account proof can be relayed.

## Checked against the code (2026-10-31, #88)

- `common/netcode/host.odin`: a stateless cookie handshake (`Connect` padded to
  `CONNECT_SIZE :: 300`, `Challenge`, `Response` with an HMAC password proof, `Accept` with a
  random token), `HANDSHAKES_PER_SECOND :: 200`; peers found by source address;
  `Host_Event :: union {Peer_Connected, Peer_Message, Peer_Disconnected}`.
- `common/netcode/conn.odin`: `MAGIC :: u32(0x31565856)` ("VXV1"), `MTU :: 1200`,
  `DATA_HEADER :: 4 + 1 + 4 + 2 + 2 + 4 + 2` (19), `FRAGMENT_SIZE :: MTU - DATA_HEADER -
  RECORD_HEADER`, u16 sequence numbers, 32 bits of acks, `Conn_Stats.duplicates`.
- `common/netcode/link.odin` (the client side), `simnet.odin` (T2's simulated network: the
  harness's remote players and M54b's bots ride it, so every harness test runs the crypto).
- The account proof (`common/game/account.odin`): `PROOF_CONTEXT :: "voxiverse join v1"`,
  `account_sign(k, nonce)`, `account_verify(account, nonce, sig)`, spoken in game messages
  after the handshake (`server/server.odin`'s `handle`: `Hello` → `Challenge{nonce}` →
  `Proof`), and the same in the telemetry collector (`server/collector/collector.odin`,
  `upload.odin`) and the client (`client/session_net.odin`). Bound to nothing about the
  connection.
- Captures (`common/netcode/capture.odin`) are written by the socket (`socket.odin`), so
  they would hold ciphertext. The dissector (`tools/wireshark/voxiverse.lua`, `check.lua`)
  and CI's step "Multiplayer and Wireshark" read them. DEBUGGING.md is now
  `docs/debugging.md`.
- `core:crypto` in the pinned Odin has `x25519`, `hkdf`, `chacha20poly1305`, `ed25519`,
  `sha2`, `hmac` (and `noise`, `mlkem`: see *Left out*).
- Not here any more (moved to M55d): validation, rate limits, lag compensation, the hostile
  client. Lag compensation for hitscan already exists (`server/rewind.odin`, M48h).
- **No timing in tests (T5):** crypto cost is a `build bench budgets` scene (below) and a
  metric in the `server` bench scenario; no test reads a clock.

## Design

### The handshake, net version 2

- `MAGIC :: 0x32565856` ("VXV2"), and the game's `PROTOCOL_VERSION` is bumped. A VXV1
  packet is ignored, as any stray one is.
- Keys from `core:crypto`: `x25519`, `hkdf` (SHA-256), `chacha20poly1305`, `ed25519`, `sha2`.
  `core:crypto/noise` was considered and not taken: its transport uses implicit nonces, which
  UDP loss and reordering break, and its handshake keeps state before the cookie proves the
  address.

| Packet | From | Contents | Size |
|---|---|---|---|
| Connect | client | salt u64, client ephemeral X25519 public `ce` [32], net version u16; padded | 300 |
| Challenge | server | salt, cookie [16] = HMAC-SHA256(secret, address, port, salt, `ce`, window)[:16] | 29 |
| Response | client | salt, cookie, `ce`, password proof [16]; padded | 300 |
| Accept | server | salt, token u32, server ephemeral `se` [32], server identity key `sk` [32], signature [64], confirm tag [16] | 161 |
| Deny | server | salt, reason (unauthenticated, as today; only while handshaking) | ≤ 213 |

- The server keeps no state until a Response carries a good cookie, as today. Answers stay
  smaller than asks.
- On a good Response, the server:
  1. Makes `se`, computes `shared = X25519(se_priv, ce)`, and refuses an all-zero result
     (a low-order point) without answering.
  2. Computes `T = SHA-256("voxiverse transport v2" || salt || ce || se || sk || token ||
     cookie)`.
  3. Derives `keys = HKDF-SHA256(ikm = shared, salt = T, info = "voxiverse keys v2", 64)`:
     client-to-server key `keys[0:32]`, server-to-client key `keys[32:64]`.
  4. Signs `"voxiverse server v2" || T` with its identity key.
  5. Computes the confirm tag: the AEAD tag of an empty message under the server-to-client
     key at packet number 0.
  6. Stores the Accept bytes in the `Peer`, so a repeated Response (a lost Accept) gets the
     same Accept, as today's resend does.
- The channel binding is `B = SHA-256("voxiverse binding v2" || T)`, kept as `Conn.binding:
  [32]u8`.
- The password proof becomes `HMAC-SHA256(password, cookie || ce)[:16]`, bound to this
  handshake. It can still be guessed offline from a sniffed Response; accepted: passwords are
  a LAN convenience, and the account is the identity.
- The client checks, in order: the signature under `sk`; `sk` against what it pinned for this
  server; the confirm tag. A failure is `Failed` with a reason, and no data is sent.
- The signing contexts (`voxiverse transport v2`, `voxiverse keys v2`, `voxiverse server v2`,
  `voxiverse binding v2`, `voxiverse join v2`) join M54's list of signing contexts, which a
  test keeps distinct.

### Server identity and pinning

- A universe has `<universe>/server.key` (M54's key file format, header
  `voxiverse-server-key 1`), made on first start with M46's atomic write, mode 0600. A server
  with no save directory (tests, scratch, the harness) makes one per run.
- The collector has `<dir>/collector.key`.
- `netcode.host_open` takes the identity (`^ed25519.Private_Key`). `link_connect` takes
  `pinned: Maybe([32]u8)` and reports `l.server_key`.
- The client keeps `known_servers.txt` beside its settings (`client/settings.odin`'s
  directory): `<host>:<port> <64 hex key> <first seen unix>`. Trust on first use, as SSH.
  Read with a parser of its own that skips and logs a malformed line (fuzzed, below).
- A different key is refused with: "This server's identity changed since you last joined
  (now ab12..., was cd34...). If its owner reset or moved it, remove its line from
  known_servers.txt." LAN-discovered servers pin the same way. The uploader pins the
  collector in the same file.
- Singleplayer's in-process pipe has no transport and a zero binding.

### Accounts tied to the channel (and how M55c wraps it)

- `account_sign(k, nonce, binding)` and `account_verify(account, nonce, binding, sig)` sign
  `"voxiverse join v2" || nonce || account || binding`.
- The server's proof check moves out of `handle` into one procedure,
  `identity_prove(s, c, proof: game.Proof) -> (ok: bool, reason: string)`
  (`server/identity.odin`, new), which reads the binding from `host_conn(...).binding` (zero
  on the pipe) into `c.binding` at `Peer_Connected`. A man in the middle who relays the
  server's nonce to a victim gets a proof for the victim's channel, which fails on its own.
- **M55c:** its `Identity_Provider.verify(hello, proof, session_binding)` is given
  `c.binding`; the `Offline` provider's `verify` is this row's `identity_prove` body moved
  unchanged, and every provider must bind its proof to `session_binding` (M55c's `Test`
  provider proves `HMAC-SHA256(token, binding)`). `test_account_proof_bound` is written
  against `identity_prove` here and runs through the interface, for every provider, in M55c.
- The collector's proofs change the same way.

### Data packets

- The clear header is the AEAD's associated data: magic 4, kind 1, token 4, packet number
  `pn` u64 8 bytes, 17 bytes in all.
- Then, sealed: ack u16, ack bits u32, reliable ack u16, the records. Then the 16-byte tag.
- The nonce is `[4]u8{} || pn` (little-endian). The keys differ per direction, so the nonces
  may repeat across directions.
- `pn` starts at 1 in both directions (0 is the confirm tag). The reliability layer's u16
  sequence is `u16(pn)`, so `conn.odin`'s ack logic is unchanged.
- `DATA_HEADER` becomes 41 bytes (was 19) and `FRAGMENT_SIZE` 1154 (was 1176), 1.9% of a
  full packet. M39's snapshot parts follow `FRAGMENT_SIZE` by construction; the bandwidth
  baseline (`assets/baselines/net/bandwidth.txt`) is re-accepted with the change explained.
- `Disconnect` has the same clear header with a sealed reason. An unauthenticated one is
  ignored, so a forged kick no longer works.
- `Discover` and `Discover_Reply` stay plain: what a LAN server tells everyone is public.
- Receiving, in this order: the magic and kind; the peer by address, and the token; the
  replay window, as a cheap precheck; the AEAD open, in place; then, and only then, `pn`
  marked in the window; `conn_packet` on the plaintext.
- The replay window is per direction per connection: the highest `pn` seen and 256 bits
  behind it. Refused: 0, anything 256 or more behind, and anything already marked.
- Counters in `Conn_Stats`: `auth_failed`, `replayed`, `too_old`. The old `duplicates`
  becomes `replayed`: `Simnet`'s and the conn tests' simulated duplicates now land there.
- Sealing happens in `conn_flush`, in place, each packet grown by the tag. `Conn` always
  encrypts; there is no plaintext mode. `conn_test.odin` makes keys with
  `conn_keys_for_test(seed)`.
- `Simnet` carries sealed packets like UDP: the harness pays the crypto, so the determinism
  roots (state hashes) do not move, and the bandwidth baseline moves by the header only.

### Debugging encrypted traffic

- The capture records plaintext. Non-data packets (the handshake, discovery) are captured by
  the socket as today; the socket no longer captures Data or Disconnect; `host.odin` and
  `link.odin` capture them after opening (received) and before sealing (sent), with kind
  `Data_Plain` (`0x81`) or `Disconnect_Plain` (`0x87`). Those values are never valid on the
  wire. The packet keeps its clear header (`pn` included) and has no tag.
- So the dissector needs no crypto (Wireshark's Lua has none). It learns VXV2, the header with
  `pn`, the plaintext kinds and the new handshake fields. `check.lua` keeps decoding every
  packet, and CI's tshark step is unchanged.
- A capture holds everything said in clear: a debugging tool on a server one owns. The file
  is made with mode 0600 and `docs/debugging.md` says so.
- `netdump` reads M39's in-process trace and is unaffected.

## The order of the steps

1. The crypto in `conn.odin` (keys, seal and open, the replay window, the new header) with
   test keys; `conn_test.odin` passing on it.
2. The handshake in `host.odin` and `link.odin`, server identity and pinning,
   `known_servers.txt`, `identity_prove` and the binding in the account proof, the collector.
   `host_test.odin`, `simnet_test.odin`, `server/net_test.odin`, the harness's and
   scenario runner's tests and `collector_test.odin` pass; the bandwidth baseline
   re-accepted.
3. Plaintext captures, the dissector, `check.lua`, `docs/debugging.md`. CI's Wireshark step
   checked locally with `lua5.4` if present.
4. The proxy (`common/netcode/proxy_test_helpers.odin`) and its attack tests, the fuzz
   targets, the budget scene, `Net_Crypto_Us` in the `server` scenario; history.md.

## Tests

- `common/netcode/conn_test.odin`, on test keys: every old test, plus:
  - a byte flipped in each region (the clear header's every field, the ciphertext, the tag)
    is refused and counted in `auth_failed`, and the connection survives;
  - a replay within the window and one past it, counted (`replayed`, `too_old`);
  - packets reordered within 256 are accepted; `pn` 0 is refused;
  - known-answer vectors: `conn_seal` of a fixed plaintext under fixed keys and `pn` gives
    fixed bytes (pins the header layout and nonce construction);
  - property, 500 seeds: random loss, duplication and reordering on both directions for 2 000
    packets; every reliable record delivered once in order, `auth_failed` 0.
- `common/netcode/host_test.odin`:
  - handshake end to end; the derived keys equal on both sides (test hook) and differ per
    direction;
  - a bad server signature, a wrong pinned key and a bad confirm tag each fail the link with
    their reasons;
  - a low-order point and a Response whose `ce` differs from its Connect's get no answer;
  - a forged Disconnect is ignored; another connection's token is refused;
  - the Accept is resent after a lost one and is identical;
  - the 201st handshake in a second (stepped clock) is not answered;
  - every answer is no larger than its ask (amplification), over all handshake packets.
- Proxy tests (`common/netcode/proxy_test.odin`; a UDP proxy on loopback between a link and a
  host, `proxy_test_helpers.odin`): flip any one byte of a Data packet; resend a captured
  packet at once and 300 packets later; a forged `Disconnect` with the right token and no key;
  a Data packet with another connection's token; a Response whose `ce` differs from its
  Connect's; a low-order point; 1 000 Connects in a second. Each refused and counted; the
  link and the host stay up, the targeted connection untouched.
- `server/net_test.odin`:
  - `test_account_proof_bound`: a relaying middle man (two links and a host) passes the
    server's nonce to a victim client and its proof back. The server refuses with "the
    account's proof is wrong" and logs it.
  - Every UDP and `Simnet` suite (chat, items, gates, sheep, the scenarios, `test_party`,
    the M54b bot tests) passes unchanged on the encrypted transport.
- `server/collector/collector_test.odin`: the collector's proof bound the same way; a relayed
  proof refused.
- `client` test: `known_servers.txt` is written on first join; a changed key is refused with
  the message above; removing the line lets the client join again; a malformed line is
  skipped with a warning.
- `common/game/account_test.odin`: the signing contexts are pairwise distinct and none is a
  prefix of another (M54's list included).
- `build determinism`: roots unchanged (the transport is below the state).

## Fuzzing (Q1)

Targets in `build fuzz` and lines in `docs/fuzzing.md`, beside Q2's protocol targets:

- `net.handshake_server`: random and mutated Connect and Response datagrams into a host:
  never a crash, never state kept before a good cookie, every answer no larger than its ask.
- `net.handshake_client`: random and mutated Challenge, Accept and Deny into a connecting
  link: refused or failed with a reason, never a crash.
- `net.sealed`: random and mutated Data and Disconnect datagrams from a connected peer's
  address with its token: refused and counted, the connection survives.
- `known_servers`: random and mutated files: lines kept or skipped, never a crash.

## Budgets (`build bench budgets`; T5)

`budget_transport` (`server/budgets.odin`, calling `netcode` directly), CPU time of the
thread (`base.thread_cpu_us`):

- `Net_Seal_Open` (us per full 1 200-byte packet sealed and opened, mean over 100 000)
  limit **10**;
- `Net_Handshake` (us of the server's work per accepted handshake: the X25519, the HKDF, the
  signature, the confirm tag; mean over 1 000) limit **1 000**, so `HANDSHAKES_PER_SECOND`
  costs at most a fifth of a core.

`Net_Crypto_Us` (sealing and opening per server tick) is added to the `server` bench
scenario (`dedicated/bench.odin`) and reported in `build bench compare`; M55e's load run
budgets it at 3% of the tick.

## Left out

- Address migration (a client whose NAT rebinds reconnects); rekeying (a u64 packet number
  never runs out).
- Post-quantum key exchange: `core:crypto/mlkem` exists, but ML-KEM-768's public key (1 184
  bytes) does not fit a padded Connect under the "answers no larger than asks" rule without
  growing Connect to the MTU; a later row if the owner wants it.
- Encrypting LAN discovery; protecting passwords from offline guessing.
- Validation, rate limits, melee lag compensation and the hostile client (M55d).

## Exit check (M55)

**Gated in CI:** the conn, host and proxy tests (tampered, replayed and forged packets refused
and counted); `test_account_proof_bound` and the collector's; the client's pinning test;
every UDP and `Simnet` suite passing encrypted; `build determinism` roots unchanged; the four
fuzz targets' seed runs; `build bench budgets -check` with `Net_Seal_Open` and
`Net_Handshake` in budget; CI's Wireshark step decoding the plaintext capture with no
malformed packet; `build check`, the suite and CI green on the three OSes.

## Check by hand

- A LAN game, Linux host and a Windows or macOS client: join, play ten minutes, open the
  host's `--capture` file in Wireshark with `tools/wireshark/voxiverse.lua`: every packet
  decodes, chat lines readable in the plaintext records.

  "identity changed" message, and joins again after its line in `known_servers.txt` is
  removed.
