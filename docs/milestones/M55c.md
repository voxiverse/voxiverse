# M55c: hooks for online services (the identity abstraction, headless start and stop)

**Why.** The owner's decision of 2026-10-30 (#83): engine hooks for later online services,
with no online service built now. Two seams: who a player is (today only an offline
keypair, M16) must come from an interface an online provider can implement later; and a
server must be startable, observable and stoppable by an orchestrator without a person (an
experience server started on demand, drained and stopped).

**What this builds on:** accounts (`common/game/account.odin`: `Account` (an Ed25519 public
key), `Account_Key`, `account_sign`, `account_verify`, `nonce_make`, `PROOF_CONTEXT`; the
handshake in `server/server.odin`: `Hello` → `Challenge{nonce}` → `Proof` →
`account_verify` → `proved` → `enter`, with bans checked by `banned(s, name, address,
account)`; characters in `characters/<account hex>/<name>.json`; permissions by
`account:<hex>` lines (`server/permissions.odin`: `ACCOUNT_PREFIX`, `account_key`); the
client's `account.key` (`client/account.odin`)), M55's secure transport and
`test_account_proof_bound` (the proof bound to the session's keys), the dedicated server
(`dedicated/main.odin`: `Options`, `run`, `catch_stop`, SIGINT and SIGTERM in
`stop_posix.odin` and `stop_windows.odin`, the 60-second status line from `server.stats`;
`server.start`, `server.stop`, `s.refusal`), M54c's experience import, the `smoke/` package
(real processes allowed there, T4b, T6).

**The identity abstraction** (`common/game/identity.odin`, `server/identity.odin`):

- `Identity :: struct {provider: Provider_Id, subject: [32]u8}`; text form
  `<provider>:<hex>` (`offline:3fa1...`). `Provider_Id :: enum u8 {Offline, Test}` (append
  only; an online provider is added by the row that builds it).
- Server side: `Identity_Provider :: struct {id, begin: proc(...) -> Challenge, verify:
  proc(hello, proof, session_binding) -> (Identity, Identity_Error)}`; the handshake calls
  the provider named in `Hello` (refused if the server does not accept it: `Config.identity`
  lists the accepted providers, default `{Offline}`); `Offline` is today's code moved, the
  nonce proof unchanged and bound as M55 binds it. Everything that keys on an account
  (characters' directory, permissions' `account:` lines, bans, `is_owner`, telemetry's
  anonymous id) keys on `Identity` instead; the files say `offline:<hex>` where they said
  `<hex>` (before 1.0: a new format, no migration; older saves refused with M47a's message).
- Client side: `Credential_Source :: struct {provider, hello, prove}`; the offline source is
  today's `account.key`. The client offers the source the server accepts (the server lists
  them in its first answer); with no match the join is refused with both lists named.
- `Test` provider (compiled only `when ODIN_TEST`): subjects from a token table, to prove a
  second provider works end to end without the network.

**Headless control** (`dedicated/control.odin`): `--control stdio` makes the dedicated
server read commands from stdin and write events to stdout as JSON lines (one object a line,
documented in `docs/control.md`), for an orchestrator that starts it as a child process.
Local only by construction: no network listener, nothing but the process's own pipes.

- Commands: `{"cmd": "status"}`, `{"cmd": "save"}`, `{"cmd": "drain"}` (refuse new joins,
  tell players with the engine's existing kick message path when stopping), `{"cmd": "stop",
  "grace": <seconds 0..600>}` (drain, wait for players to leave or the grace to pass, save,
  stop), `{"cmd": "players"}` (count and identities' text form, no names unless
  `--control-names`).
- Events: `ready` (port, universe, engine version, protocol, accepted providers), `status`
  (every 10 s and on request: players, tick p99, memory, worlds loaded), `saved`,
  `draining`, `stopped` (exit code), `error` (a line for every `error` log line, its text).
- Starting: the orchestrator starts the process with `--universe <dir>` or
  `--experience <file.vxexp> --universe <new dir>` (M54c's import, then run); exit codes are
  defined (0 stopped, 1 refused at start with `s.refusal` in an `error` event first, 2
  crashed) and listed in `docs/control.md`.
- Malformed input lines are answered with `{"event": "error", "detail": ...}` and ignored;
  a line over 64 KiB is refused; stdin closing means `stop` with a 30 s grace.

**Order of the steps:** `Identity` and the providers on the server, the handshake through
them, the save formats' keys; the client's credential sources; the `Test` provider and its
tests; `--control stdio` and `docs/control.md`; the smoke tests.

**Tests:** every account test unchanged in assertions and passing through the interface
(`server/account_test.odin`, permissions, bans, characters); the `Test` provider: a join
with a token, a forged token refused, a server accepting only `Offline` refusing a `Test`
client with both lists named; permissions and bans keyed by `test:` identities; M55's
`test_account_proof_bound` through the interface. Control (`smoke/control_test.odin`, a real
child process): start, `ready` within the limit `run_limited` gives, `status`, `save`,
`drain` refusing a join, `stop` with a grace exiting 0 with a `stopped` event; a malformed
line answered; stdin closed stops it; an `--experience` start serving the experience's
world. A fuzz of the control parser (10 000 random lines, fixed seed) in `dedicated`'s tests.

**Open questions for the owner** (none blocks this row): none; which online provider comes
first, and whether servers announce themselves to a service, belong to the online-services
rows that are not planned yet.

**Left out:** any online provider, tokens from a service, the service's API, server
discovery and listing, remote control over the network.

**Exit check:** the tests and smoke tests pass; the suite, `build check`, `build smoke`; CI
green.

**Check by hand:** none.
