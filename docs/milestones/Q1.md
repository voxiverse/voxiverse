# Q1: the fuzz harness, and packs and saves fuzzed

**Why.** The owner's aim (2026-10-30, #84): every claim about this engine is backed by
evidence anyone can rerun. Ground rule 6 says untrusted input is validated at the edge; this
row makes that a checked claim. It builds one harness every parser joins, runs it seeded on
every push and longer every night, and fuzzes the inputs a pack or a save brings: pack JSON,
the registry built from it, PNG and Ogg assets, pack archives, region files, journal
segments, save transactions, player records, structure templates, export archives and the
universe's config files. Q2 adds the network protocol, commands and the text parsers players
reach. M51c's script fuzzers register here instead of having a harness of their own.

**What this builds on (as they are in the code now):**

- `common/ogg/fuzz.odin`: `fuzz_one(data, allocator, max_frames)`, the mutations, the
  `build ogg fuzz [--seed N] [--iterations N]` command (`tools/ogg`) and `test_ogg_fuzz`.
  The Ogg target becomes a harness target; `build ogg fuzz` is removed (its options are the
  harness's), `test_ogg_fuzz` becomes the target's smoke test below.
- The decoders, each fuzzed through its public entry: `json_parse`
  (`common/game/pack_json.odin`), `registry_build` (`common/game/registry_load.odin`, with
  `common/game/pack_testdata.odin`'s test packs), `read_image_texture`
  (`registry_resolve.odin`: the header check, then `core:image/png`), `pack_archive_read`
  (`pack_archive.odin`), `region_open` and `read_chunk_payload` (`save.odin`,
  `block_entity.odin`), `journal_read_segment` and `decode_record` (`journal.odin`),
  `tx_decode` (`server/save_tx.odin`), `player_parse` and `kit_parse`
  (`server/player_data.odin`), `template_decode` (`structure.odin`), `universe_import`
  (`server/export.odin`, with its `IMPORT_LIMITS`), `permissions_parse`
  (`server/permissions.odin`), `grants_parse` (`common/game/permissions.odin`),
  `packs_parse` (`server/universe_packs.odin`), `counters_read` (`server/stats.odin`).
- `common/base/crash_posix.odin`, `common/base/crash_windows.odin` and `base.crash_report`: the fuzzer
  hooks the crash path to save the input that crashed (below).
- `-sanitize:address` (`./build.sh build --sanitize` already passes it for the game).
- `build test`'s per-package time limit and `ODIN_TEST_FAIL_ON_BAD_MEMORY` (#46, #54).

**Coverage guidance: decided.** Odin's pinned compiler has no coverage instrumentation
(`odin build -help`: `-sanitize` offers address, memory and thread only; no
SanitizerCoverage, no libFuzzer). Building the targets as LLVM IR and linking them with
clang's `-fsanitize=fuzzer` would add clang and libFuzzer (C++) to the build, work on Linux
only, and depend on an unsupported output path with Odin's runtime, against the decisions
*Third-party code in the game* and *Native Odin*. So the harness is ours, in Odin, guided by
**outcome signatures**, not edge coverage: each target returns a `u64` signature of what the
input made the decoder do (the error value or refusal code, the stage reached, a bucket of
bytes consumed: `bits.len(consumed)`), and an input whose signature the run has not seen joins
the run's corpus. This finds the decoder's distinct paths through its errors, which is where a
hostile file goes. When Odin gains coverage instrumentation, the harness adds edge coverage
as a second signature source; nothing else changes. Written in `docs/fuzzing.md` (new) and
in the plan's *Decisions*.

**The harness** (package `base/fuzz`, files `fuzz.odin`, `mutate.odin`, `corpus.odin`,
`minimize.odin`; imports only `base` and `core:`):

- `Target :: struct {name: string, run: proc(data: []u8, allocator: runtime.Allocator) -> u64, seeds: string, dictionary: []string, max_len: int, generate: proc(rng: ^base.Rng, out: ^[dynamic]u8) /* optional */}`.
  `name` is `<area>.<thing>` (`pack.json`, `save.region`). `seeds` is the directory of the
  committed seed corpus, `testdata/fuzz/<name>/`. `max_len` caps an input (the decoder's own
  cap plus 1 KiB, so the cap itself is fuzzed). `generate`, where given, makes a structured
  input (valid JSON, a valid region file, a valid archive) that mutations then break.
- The run's contract for every target: no panic, no failed assert, no bounds failure, no
  read outside its input (AddressSanitizer in the nightly build), no leak (each case runs
  under a tracking allocator that must be empty after the case: a leak is a failure naming
  the allocation's line), no allocation past the target's cap (a capping allocator:
  `max_len * 64` bytes unless the target states another number in its table row), and no
  case longer than 2 s of the thread's CPU time (`base.thread_cpu_us`; a watchdog thread
  ends the process with the input saved). An `Error` or a refusal is a pass.
- Mutations (`mutate.odin`, from `base.Rng`, never `core:math/rand`): flip a bit, set a byte
  to an interesting value (0, 1, 0x7f, 0x80, 0xff), set 2, 4 or 8 bytes to an interesting
  integer (0, -1, `max`, `max`+1, 2^31, 2^63 in both endians), insert or delete a run, copy
  a run within the input, splice with another corpus input, insert a dictionary token. One to
  eight mutations a case.
- Corpus (`corpus.odin`): starts from the seeds and the generator; an input with an unseen
  signature joins (at most 4 096 inputs a target in memory). `--keep <dir>` writes the
  corpus out (by hand, to grow the committed seeds; not in CI).
- Crashes: before each case the harness copies the input into a preallocated buffer; a crash
  hook (`base.crash_hook_set`, a new procedure called by `crash_report` before it logs)
  writes that buffer to `build/fuzz/<target>/crash-<XXH64 of input>.bin` with raw writes (no
  allocation) and the target's name and seed to `crash-<hash>.txt`. An assert or panic goes
  through the same hook (`base`'s `assertion_failure`).
- Minimizer (`minimize.odin`): `build fuzz <target> --minimize <file>` re-runs the case in a
  child process, and removes runs (halving, then single bytes) and replaces bytes with 0
  while the same failure (same first line of the report) holds; writes
  `<file>.min`.
- The driver: `tools/fuzz` (an executable importing every target's package) and
  `build fuzz` (`tools/build/fuzz.odin`, which builds it and supervises it: after a crash it
  records it and starts the fuzzer again on the next case, so one crash does not end the
  run). Commands:
  - `build fuzz --list`: the targets, one a line.
  - `build fuzz [<target>...] [--seed N] [--cases N | --seconds N] [--sanitize]`: every target
    (or the named ones) in turn, `N` cases or seconds each; `--sanitize` builds with
    `-sanitize:address` (Linux). Prints per target: cases, corpus size, distinct
    signatures, failures. Exit 1 on any failure, with the files' paths.
  - `build fuzz <target> --case <file>`: one input, its result and signature.
  - Options after `--` go to the targets named (a target's own switches, e.g. M51c's
    `--lua <exe>`); a target refuses an option it does not know.
  - `build fuzz <target> --minimize <file>`.
  - `build fuzz --smoke`: every target, 2 000 cases at seed 84, then every regression file
    (below). This is CI's push step.
- Every crash found becomes a regression test: the minimized input is committed as
  `testdata/fuzz/<target>/regress/<short name>.bin` (a name saying what it caught, e.g.
  `region-palette-count-past-4096.bin`) with the fix in the same commit. The suite replays
  every regression file of every target (below), on all three OSes.

**The targets** (each `fuzz_<thing>` procedure lives in the package it fuzzes, in a file
`fuzz.odin` beside the decoder, so the suite and the tool call the same code; the harness's
table `tools/fuzz/targets.odin` lists them):

| Target | Entry | Generator | Notes |
|---|---|---|---|
| `pack.json` | `json_parse` | random JSON values to depth 40 (past the parser's depth cap), long strings, escapes, numbers at the edges | dictionary: `{ } [ ] : , " \u0000 \ud800 1e999 -0 true null` |
| `pack.registry` | `registry_build` over a pack from `pack_files_memory` (added here if M52 has not: `pack_files_memory(files: map[string]string) -> []game.Pack_Source`) | the base pack's files with one to four values replaced (a number by a string, an id by an unknown id, an array by a 10 000-element one, a state list past its cap) | the result is a registry or `Pack_Error`s, each with a file, line and column inside the input |
| `pack.png` | `read_image_texture`'s path on the bytes as a pack texture | a valid 16x16 PNG from `common/base/png.odin`, then mutated chunks (IHDR sizes, IDAT lengths, CRCs) | |
| `pack.ogg` | `ogg.fuzz_one` | the 26 edge-case files of M53c as seeds | moved from `build ogg fuzz` |
| `pack.archive` | `pack_archive_read` | a valid archive of three files | names with `..`, absolute paths, NUL, duplicate names and sizes past the limits are refusals |
| `save.region` | `region_open` on the bytes as a file in `build/tmp/fuzz/`, then `read_chunk_payload` of every chunk it lists | a region with four chunks written by the save code | |
| `save.journal` | `journal_read_segment` | a segment of 64 records of every kind written by the journal | |
| `save.tx` | `tx_decode` | a transaction of three operations | |
| `save.player` | `player_parse`, `kit_parse` | a player record written by `player_data.odin` | |
| `save.structure` | `template_decode` | a template written by `/structure save` | |
| `save.import` | `universe_import` of the bytes as an export file into `build/tmp/fuzz/import/` | an export of a two-world universe | refused imports leave nothing in `dest` (checked by the target) |
| `save.config` | `permissions_parse`, `grants_parse`, `packs_parse`, `counters_read` | each file as the server writes it | |

Where a decoder needs a file on disk, the target writes it under `build/tmp/fuzz/<target>/`
and removes it after the case; nothing outside `build/` is touched.

**What the fuzzing will find.** Each failure is fixed at its cause in the decoder (a missing
length check, an unchecked enum, a count trusted before allocation), never by catching it in
the target, and gets its regression file. A failure inside `core:` (for example
`core:image/png`) is fixed in our layer by checking what we hand it (that is ground rule 6,
not an exemption), and written in `docs/fuzzing.md` with the input, for the owner to report
upstream.

**CI.**

- "Fuzz (smoke)" in "Test · Linux x64", after Test: `./build.sh fuzz --smoke` (fixed seed:
  a push never fails on a seed nobody has seen; a seed that finds something does so in the
  nightly run, which names it).
- The regression files run in the suite on all three OSes:
  `test_fuzz_regressions` in each package with targets reads its targets' `regress/`
  directories and runs every file through the target with the same contract; and each
  target has `test_fuzz_<target>_smoke` (200 cases at seed 84), so `./build.sh test` alone
  exercises every target. `test_ogg_fuzz`, `test_decode_fuzz` and `test_state_decode_fuzz`
  stay until Q2 moves the last two.
- A nightly workflow, `.github/workflows/nightly.yml` (new): `on: schedule` (cron `17 3 * * *`,
  UTC) and `workflow_dispatch`, on `main` only. Job "Fuzz · nightly" (ubuntu-latest, timeout
  150 minutes): `./build.sh fuzz --sanitize --seconds 240 --seed ${{ github.run_number }}`
  (every target 4 minutes under AddressSanitizer), then uploads `build/fuzz/` as an artifact
  when anything failed. A failed nightly run is a bug like any failed run: the session that
  takes it minimizes the input, commits it as a regression file with the fix. (How a nightly
  failure reaches the loop is the loop's harness's business, outside the repository: listed
  under *Open questions*.)
- The harness's own tests (`base/fuzz/fuzz_test.odin`): the mutator is deterministic for a
  seed; a toy target that panics on input `"boom"` reached by mutation from `"bool"` is found,
  saved, minimized to exactly `"boom"`; a leaking toy target fails naming the line; a toy
  target over the allocation cap fails; a toy target that spins is ended by the watchdog with
  its input saved (in a child process: `smoke/`, since it ends the process); the signature
  rule keeps an input with a new signature and drops one with a seen signature.

**Steps, in order** (each leaves the suite passing):

1. `base/fuzz`: mutations, corpus, contract checks, crash hook, watchdog, minimizer; its
   tests.
2. `tools/fuzz`, `build fuzz` with its commands; `pack.ogg` moved onto it, `build ogg fuzz`
   removed.
3. The pack targets; fix what they find.
4. The save targets; fix what they find.
5. The suite's regression and smoke tests; CI's "Fuzz (smoke)" step; `nightly.yml`.
6. `docs/fuzzing.md`: the decision above, how to run, reproduce and minimize, how a crash
   becomes a regression file, and the target table (the same table as here, kept current:
   Q5's lint checks it against `build fuzz --list`).

**Left out:** the network protocol, commands and text parsers (Q2); the script VM's
fuzzers (M51c registers them here); coverage instrumentation (decided above); running the
nightly on Windows and macOS (the fuzzed code is the same Odin on every OS, and the
regression files and smoke tests run there in the suite); fuzzing the renderer's inputs
(shaders are ours, not untrusted).

**Open questions** (none blocks this row): how a failed nightly run reaches the loop
(the loop's harness reads `gh run list`; the scheduled run's event is `schedule`, not `push`).

**Tests:** the harness's tests above; every target's smoke test and the regression replay;
`./build.sh fuzz --smoke` clean.

**Exit check:** `./build.sh fuzz --smoke` passes, and `./build.sh fuzz --sanitize --seconds 60`
on Linux finds nothing (every failure it found on the way fixed with its regression file); the
suite, `build check` and CI green. (`nightly.yml`'s first scheduled run reports on its own;
the session does not wait for it.)

**Check by hand:** none.
