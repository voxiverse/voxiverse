# Q2: the network protocol, commands and players' text fuzzed

**Why.** Q1's harness covers what packs and saves bring. The other untrusted inputs reach the
engine over the network: every message a client sends the server, every message and state
record a server sends a client (a client joins servers it does not run; a hostile server is
a threat to players), the packet layer under both, the commands players type and the text
parsers chat and commands reach. The owner asked for "the network protocol (every message,
on both sides)" (#84). This row fuzzes them on Q1's harness, decoding alone and decoding
followed by handling, so a message that decodes but breaks a handler is found too.

**What this builds on:** Q1 (`base/fuzz`, `tools/fuzz`, `build fuzz`, the CI steps, the
regression files); the codec (`common/game/protocol.odin`: `Client_Message` with its 25
variants, the server's messages, `decode_server_t`, `decode_client_t`; `codec.odin`'s
`Reader`); the state model (`delta.odin`, `state_kinds.odin`, `replica.odin`: records and
their deltas); netcode (`common/netcode`: `conn_packet`, `conn_receive`, `host.odin`'s
handshake, `simnet.odin`); T2's deterministic harness (`server/harness.odin`:
`harness_start`, `harness_step`, `harness_local`); the client session's receive path
(`client/session_net.odin`: `receive`, `welcome`, `packs_begin`, `packs_part`;
`client/state_apply.odin`: `apply_received`); the commands (`server/admin.odin`: `admin`,
`command_usage`; `commands_people.odin`, `commands_places.odin`, `commands_world.odin`;
`rollback.odin`'s `parse_where`); the text parsers (`format_parse`, `address_parse`,
`id_parse`, `state_parse`, `account_parse`, `ability_parse`, `parse_time_of_day`,
`damage_source_parse`, `chat.odin`'s `parse_count`). The existing loops
`test_decode_fuzz` (`protocol_test.odin`) and `test_state_decode_fuzz` (`delta_test.odin`)
become targets here and are deleted as loops (their inputs become seeds).

**The targets** (as in Q1: `fuzz_<thing>` in a `fuzz.odin` beside the code, listed in
`tools/fuzz/targets.odin`):

| Target | What one case does | Generator |
|---|---|---|
| `net.client_decode` | `decode_client_t` on the bytes | one valid encoding of each of the 25 `Client_Message` variants, fields at their limits |
| `net.server_decode` | `decode_server_t` on the bytes (with the chunk scratch array) | one valid encoding of every server message, chunk messages with every palette size |
| `net.state` | the state record decoder on the bytes against a replica holding one value of every state kind | a valid record and a valid delta of every kind |
| `net.packets` | `conn_packet` on a connection in each state (fresh, mid-handshake, established with messages in flight and fragments half received), then `conn_receive` and `conn_flush` | packets written by `conn_flush` from a peer sending reliable and unreliable messages, fragmented and not |
| `net.handshake` | the host's handling of a datagram from an unknown address (`host.odin`: challenge, token, info query) | valid first datagrams of each kind |
| `net.server_session` | a stepped server (`harness_start`, flat world) with one fuzzed seat: the case is a sequence of client messages (each a valid message with one to three fields mutated, or raw mutated bytes; framed by a length byte), sent one a tick for up to 64 ticks, then `harness_step` | sequences recorded from the scripted session (`build determinism`'s), cut at random points |
| `net.client_session` | a headless client session (`client` package, no window, no GPU: the session's receive path only) fed a sequence of server messages and records as the server would send them, mutated as above, including the pack phase (`Packs`, `Pack_Part` with wrong sizes, hashes and order) | the messages a stepped server sends one client over its first 200 ticks |
| `commands.player` | `admin` with the bytes as one command line, by a guest (no permissions) and by an operator, on a stepped server | a command name from `command_usage`'s list and arguments drawn from each command's usage shape (numbers at the edges, `~` coordinates, selectors, ids known and unknown, very long words) |
| `text.parsers` | each of `format_parse`, `address_parse`, `id_parse`, `state_parse` (base registry), `account_parse`, `ability_parse`, `parse_time_of_day`, `damage_source_parse`, `parse_count`, `parse_where`, chosen by the first byte | the valid examples in each parser's tests |

The contract is Q1's (no panic, no bounds failure, no leak, the allocation cap, the time
limit), plus, for the stateful targets (`net.server_session`, `net.client_session`,
`commands.player`), invariants checked after every case:

- the server: still stepping (a further `harness_step` succeeds); its state hash computes;
  the item ledger's audit balances (M31: no items made by a refusal); the fuzzed seat was
  kicked with a logged reason or is still connected, never a half-removed client (its
  handle valid or freed, never dangling); no other seat (a second, well-behaved seat runs a
  scripted walk) is kicked or desynced (its prediction checks pass);
- the client: the session either fails with a reason shown to the player (`fail`) or keeps
  running; its replica's pools are within their caps; no file is written outside the pack
  cache directory (the pack phase's archives land only under `packs_cache_dir()`, a test
  directory here);
- commands: an operator's command that changes the world is journaled with the operator as
  its actor; a guest's changes nothing (the state hash before and after is equal unless the
  command is one a guest may run, by the permissions table).

A case's cost is kept small: the stepped server is built once per run and reset between
cases from a snapshot of its fresh state (M46b's save capture of one tick restored into a
fresh `Harness`), so a case is milliseconds, not a world generation. If that restore is not
cheap enough for 2 000 smoke cases in under a minute on CI's runner, the target builds a
fresh harness every 50 cases and runs those 50 on it (the invariants still checked after each
case).

**What the fuzzing will find.** As in Q1: each failure fixed at its cause in the decoder or
the handler (ground rule 6: handlers receive validated types only), with its regression file.
A handler that trusts a decoded value (an index, a handle, a count) gets the check at the
edge, in the decoder or validator, not in the handler.

**CI:** the targets join Q1's "Fuzz (smoke)" step and the nightly job with no change to
either (they run every target). The regression replay and each target's smoke test run in
the suite on all three OSes. `test_decode_fuzz` and `test_state_decode_fuzz` are removed in
the commit that adds their targets.

**Steps, in order:**

1. The decode targets (`net.client_decode`, `net.server_decode`, `net.state`); the old loops
   removed; fix what they find.
2. `net.packets` and `net.handshake`; fix what they find.
3. `net.server_session` with its invariants and the reset; fix what it finds.
4. `net.client_session`: the headless receive path (only what the client package already
   has; if receiving needs a window or a device, that dependency is cut at the session's
   edge, never stubbed inside the code it tests); fix what it finds.
5. `commands.player` and `text.parsers`; fix what they find.
6. `docs/fuzzing.md`'s table gains the targets.

**Left out:** fuzzing over real UDP sockets (the packet target covers the bytes; the UDP
socket code is the OS's); M55's secure transport (its own target joins when M55 builds it:
M55's spec says so); script messaging (M52d) and client scripts (M52c), whose targets their
own rows add; the dissector (a dev tool).

**Open questions:** none.

**Tests:** each target's smoke test and the regression replay; `./build.sh fuzz --smoke`.

**Exit check:** `./build.sh fuzz --smoke` passes with the new targets, and
`./build.sh fuzz --sanitize --seconds 60 net.client_decode net.server_decode net.state net.packets net.handshake net.server_session net.client_session commands.player text.parsers`
finds nothing (every failure found on the way fixed with its regression file); the suite,
`build check`, `build determinism` and CI green.

**Check by hand:** none.
