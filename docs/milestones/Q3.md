# Q3: crash bundles (a crash leaves a report on disk; the next start offers it)

**Why.** The owner (#84): a crash should leave everything needed to fix it, and players
should be able to hand it over. Today a crash logs the signal or exception and the crashing
thread's stack (`base.crash_report`), and the log file sits beside the executable, which a
player does not know to look for. This row writes a **bundle**: one folder per crash with the
stack of every thread, the log's tail, the build, the OS and GPU, and the player's last
actions; and the next start of the game offers it. **Nothing is uploaded:** uploading is the
owner's decision (*Open questions*); only the local bundle is built.

**What this builds on:** `base/crash_posix.odin` (fatal signals on an alternate stack,
`SA_RESETHAND`, re-raised), `base/crash_windows.odin` (the vectored exception handler),
`base/debug.odin` (`crash_report`, `log_stack_trace` via `core:debug/trace`, the `Debug`
state with its logger and log file, `debug_attach`, `assertion_failure`);
`base/thread_context.odin` (every thread we start gets `base.thread_context()`);
`base/version.odin` (the version and commit stamped in); `machine_facts` (CPU, cores, OS);
`client/gpu/gpu.odin` (`device_name`; the driver version and API version from the same
`VkPhysicalDeviceProperties`); the action layer (`client/actions.odin`); the console
(`overlay_console.odin`); screens (`screen_title.odin`) and dialogs with pad support (M42's
focus and prompts); the string table (M48d); `settings_path`'s config directory
(`os.user_config_dir`); the CI step "Crash handler" (`--exec crash`).

**The bundle.** One directory per crash:
`<config dir>/voxiverse/crashes/<UTC yyyy-mm-dd_hh-mm-ss>-<pid>/` for the game, and
`<universe dir>/crashes/<same>/` for the dedicated server (it has no player; its operator
reads it there). Files, all UTF-8 text:

- `crash.txt`: what happened (signal and address, or exception code and address, or the
  assert or panic message and its source location); which thread (its name); the build
  (version, commit, profile: development, release, sanitize); the OS (`machine_facts`), the
  CPU and its cores; the GPU (device name, driver version, Vulkan API version; "none yet"
  if the crash came before the device); uptime in seconds; the screen or session state
  (title, loading, in a world: the world's address; singleplayer or which server address
  is **not** written, only "singleplayer", "LAN" or "remote").
- `threads.txt`: every registered thread's stack, our frames only (as `log_stack_trace`
  filters them), each thread headed by its name, the crashing thread first.
- `log.txt`: the last 256 KiB of the log (below).
- `actions.txt`: the last 256 actions, oldest first, each `t=<seconds since start> <kind>
  <detail>`: an action pressed or released (`ACTION_INFO`'s name; never typed text: a key
  typed into a text field is not an action), a screen or overlay opened or closed, a world
  joined or left, a console command's name (its first word only: arguments can hold chat or
  names). The dedicated server's records: joins and leaves (counts, not names), saves,
  commands' names.

**What is never in a bundle:** the account key or any key, chat text, typed text, player
names, server addresses, file paths under the user's home other than the bundle's own
(paths in the log tail are written relative to the config directory where the log has them
absolute: the log writer's bundle copy replaces the home prefix with `~`). The offer dialog
says what is in it (below).

**Writing it at crash time** (`base/crash_bundle.odin`, `crash_bundle_posix.odin`,
`crash_bundle_windows.odin`):

- Everything the writer needs is allocated at start: `crash_bundle_init(dir, app_facts)`
  reserves the log ring (256 KiB, written by the logger as it logs, so the tail does not
  depend on a log file), the action ring (256 records of 96 bytes), one 64 KiB text buffer
  per file, and a 4 MiB arena for symbol resolution. The crash path allocates nothing else
  and formats with `fmt.bprintf` into those buffers; files are written with raw OS calls
  (`posix.open`/`write`/`close`, `CreateFileW`/`WriteFile`), the directory made with
  `posix.mkdir`/`CreateDirectoryW`.
- **Every thread's stack.** A fixed table of up to 64 threads (`base.thread_register(name)`,
  called at the start of every thread we start: `base.thread_context()` sites get a name
  argument; the main thread registers in `debug_begin`). On POSIX the crashing thread sends
  `SIGUSR2` to each registered thread (`pthread_kill`); that thread's handler (on its own
  alternate stack, installed at registration) captures its frames (`trace.capture`) into its
  slot and sets a flag; the crashing thread waits for the flags at most 500 ms in total, then
  resolves every slot with the arena. A thread that did not answer is listed as "did not
  answer" with its name. On Windows the crashing thread suspends each registered thread
  (`SuspendThread`), reads its context (`GetThreadContext`) and walks its stack with
  `RtlLookupFunctionEntry` and `RtlVirtualUnwind` (x64), then resumes nothing (the process is
  ending). No minidump is written: a minidump holds process memory, which can hold chat,
  names and keys.
- Asserts and panics (`assertion_failure`, the runtime's panic) write a bundle the same way;
  under `odin test` no bundle is written (the test runner owns those).
- `crash_report` keeps logging what it logs today, then writes the bundle, then the default
  action runs as now (the process still dies with its signal or exception: CI's check that a
  crash fails the run stays true).
- Retention: at start, bundles beyond the newest 10 are deleted.

**The next start offers it** (`client/overlay_crash.odin`): when the title screen first
shows and a bundle exists without a `seen` file in it, a dialog opens over the title:

- Title: "Voxiverse closed unexpectedly". Body: "A crash report was saved on this computer.
  It holds the error, the game's recent log and your recent actions in menus and controls;
  no chat, names or keys. Nothing has been sent anywhere." Then the bundle's path.
- Buttons: "Open folder" (the OS's file manager on the bundle's directory: `xdg-open`,
  `explorer`, `open`, as a child process; a failure shows a toast with the path) and
  "Close". (No "Copy path": the clipboard is M54e's, later; the path is in the text.) Every
  button writes `seen` into the bundle so the dialog shows once per crash. Several unseen
  bundles: the dialog names the newest and says "and N earlier".
- Pad and keyboard as every dialog (M42): focus starts on "Close"; Escape and B close.
- The strings go in the string table. The dialog's look is the existing dialog style
  (`overlay_quit.odin`'s); nothing new is drawn.
- The dedicated server prints one line at start for an unseen bundle (`crash report from
  the last run: <path>`) and writes `seen`.

**Tests:**

- `base/crash_bundle_test.odin`: the writer called directly with a fake crash (no signal)
  writes the four files with the exact headings; the log ring keeps exactly the last 256 KiB
  across wrap-around; the action ring keeps the last 256 in order; the home prefix in a log
  line becomes `~`; retention keeps the newest 10; the arena and buffers are the only memory
  touched (a tracking allocator around the write sees no allocation).
- `smoke/crash_bundle_test.odin` (child processes, on the three OSes in CI's Smoke step):
  a fixture program (`smoke/crash_fixture`, like `panic_fixture`) starts four named threads,
  then (by argument) segfaults on the main thread, segfaults on a worker, fails an assert,
  or overflows a stack on a worker; each run exits by its signal or exception and leaves a
  bundle whose `threads.txt` names all five threads with at least one frame of ours each
  (the overflowing worker: its name and "stack overflow" at least), and whose `crash.txt`
  names the crashing thread.
- `client/overlay_crash_test.odin` (UI tests, headless as the overlay tests are): an unseen
  bundle opens the dialog on the title; "Close" writes `seen` and a second start shows
  nothing; three unseen bundles name the newest "and 2 earlier"; the dialog is reachable and
  closable by pad only.
- CI's "Crash handler" step also checks the bundle: after `--exec crash`, the newest bundle
  under the test config directory (`VX_SETTINGS` points it at `build/tmp/crash-home/`) has
  `crash.txt` with `signal=SIGSEGV`, `threads.txt` with the main thread and the server thread,
  `log.txt` and `actions.txt` non-empty.

**Steps, in order:** the rings and the writer with its unit tests; thread registration at
every thread-starting site; the POSIX and Windows stack collection with the smoke tests;
asserts and panics; the dialog and the dedicated server's line; the CI step.

**Left out:** uploading (the owner's decision); symbol files for release builds shipped
separately (release builds keep their line tables, as `--symbols` does, only if the owner asks:
today a release build's stacks are addresses, written as such with the module's base address
so a matching build can resolve them; `docs/debugging.md` says how); crashes of the GPU
driver that do not reach our handlers (a device-lost is logged by the renderer already);
a crash inside the crash writer (the default action runs: the OS's core dump or report).

**Open questions** (none blocks this row): whether bundles are ever uploaded, to where, with
what consent (the owner's decision); whether release builds ship line tables (bigger
executables, readable stacks).

**Exit check:** the unit, smoke and UI tests above pass on the three OSes in CI; CI's "Crash
handler" step checks the bundle; the suite and `build check` green.

**Check by hand:** on Windows, run `voxiverse.exe --exec crash` from the package, start the
game again: the dialog opens on the title, "Open folder" opens Explorer on a folder holding
the four files, and `threads.txt` lists the main, server and job threads with frames. On
macOS, the same with the `.app` (Finder opens the folder).
