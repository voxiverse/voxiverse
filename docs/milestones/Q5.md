# Q5: the threat model and the quality bar, in the docs and checked by CI

**Why.** The owner (#84): a threat model for user content (packs, scripts, client scripts,
messaging) in the docs, each threat mapped to the test or check that covers it and kept
current as M52-M54 and the client-script rows land; and a quality bar in the docs, enforced
by CI: zero validation errors, sanitizer-clean, fuzz-clean, budgets met, no flaky test (one
failure is a bug). Both are claims; this row makes CI hold the docs to the code, so a claim
with nothing behind it fails `build check`.

**What this builds on:** the plan's foundation-arc section *Threat model (what the script
and agent surface must survive)* (its attackers and its layered defences, each naming the
milestone that builds it); Q1 and Q2 (`build fuzz --list`, the targets, the CI steps "Fuzz
(smoke)" and "Fuzz · nightly"); the hostile suites the specs define (M52's rows 1-20 and 27,
M52b's 21-26 and 28-34, M52c's client rows 1-16, M52d's messaging rows 1-10, M55's proxy and
hostile-client tests, M54's forged and altered packs); T1's lints in `check`
(`tools/build/lints.odin`); CI's workflows (`.github/workflows/ci.yml`, `nightly.yml`) and
their step names; the validation layer in "Game · Linux x64" (any finding fails the run);
"AddressSanitizer"; the "Benchmark check" steps; `ODIN_TEST_FAIL_ON_BAD_MEMORY`; the
plan's rows table (a row is done when its line carries `(done`, as the loop reads it).

**`docs/threat_model.md`** (new; the plan's section becomes a short summary that links it,
so the threats have one home):

1. *What we protect:* players' machines (no code from content runs outside the VMs; no
   file is written outside the game's directories), the server's state and its history, the
   economy (the ledger), players' accounts and keys, and other players' play (no player or
   pack can ruin a world it was not granted).
2. *Who attacks, and through what:* a hostile pack author or a prompt-injected agent
   (packs, server scripts, client scripts, generated text); a hostile player (client
   messages, chat, commands, script messages); a hostile server (everything a client
   receives, including packs and client scripts it sends); a hostile file (a save, an export,
   a structure someone hands over); the network (forged, replayed, tampered packets).
3. *Entry points:* one line per untrusted input, each naming its decoder or handler and its
   fuzz target (Q1's and Q2's tables, and later rows' targets).
4. *The threats:* one table, one row per threat:

   | Id | Threat | Entry | Defence | Covered by | Milestone | Status |
   |---|---|---|---|---|---|---|
   | T-PACK-1 | a malformed pack JSON crashes or hangs the server at load | pack JSON | `json_parse`'s caps; `Pack_Error` | `fuzz:pack.json`, `test:test_json_depth_cap` | Q1 | built |
   | T-SCRIPT-3 | a script's infinite loop stalls the tick | server scripts | slices and metering | `test:...` | M51a | planned |

   `Covered by` names one or more covers, each `test:<procedure name>`, `fuzz:<target>`,
   `ci:<step name>`, `lint:<lint name>` or `bench:<scenario>`. `Status` is `built` (every
   cover exists) or `planned` (its milestone is an open row that will build the covers named;
   a planned row names the covers its milestone's spec lists, e.g. M52's hostile row
   `script_api_bomb` as `test:test_hostile_rows` with the row's name in the threat's text).
   Ids are `T-<AREA>-<n>`, areas `PACK`, `SAVE`, `NET`, `CMD`, `SCRIPT`, `CLIENT` (client
   scripts), `MSG` (messaging), `TEXT` (generated and player text), `ECON`, `TRANSPORT`.
   Every hostile row of M52, M52b, M52c, M52d is one threat row (planned until built); every
   fuzz target is the cover of at least one row; the plan's layered defences (*A world is the
   unit of isolation*, *Capabilities, not permissions*, *Hard metering*, *Economy
   containment*, *Validation before anything runs*, *Signed packs*, *Journal and replay*)
   each appear as the defence of the rows they answer.
5. *Accepted risks:* what is not defended and why (for example: a hostile server can show a
   player any text its packs carry; moderation is M54h's hook and the service's job; a
   client can see what its replica holds).

**`docs/quality.md`** (new): the bar, one table, each line the claim and the CI step or lint
that enforces it:

| Claim | Enforced by |
|---|---|
| Zero Vulkan validation messages in every frame CI draws | `ci:Game · Linux x64` (validation layer on; any message fails) |
| Sanitizer-clean: the game under AddressSanitizer | `ci:AddressSanitizer` |
| Sanitizer-clean: the unit suite under AddressSanitizer | `ci:Test under AddressSanitizer · nightly` (new, below) |
| Sanitizer-clean: every fuzz target under AddressSanitizer | `ci:Fuzz · nightly` |
| Fuzz-clean on every push and every night | `ci:Fuzz (smoke)`, `ci:Fuzz · nightly` |
| No leak and no bad free in any test | `ODIN_TEST_FAIL_ON_BAD_MEMORY` in `build test` (`lint:test_flags`, new: the driver passes it) |
| Every budget met | `ci:Benchmark check`, `ci:Benchmark check, telemetry`, `ci:Benchmark check, budgets`, the M51b/M51c script benchmark step once built |
| Deterministic across OSes and optimization levels | `ci:Determinism`, `ci:Compare` |
| No flaky test: every test runs once; a failure that passes on a re-run is a bug, written down | `lint:no_retries` (new: no workflow step has `continue-on-error: true`, a retry action, or a loop re-running a command on failure; `if: always()` on artifact uploads is not a retry) |
| Every claim in this file and in threat_model.md has its cover | `lint:quality_docs` (new, below) |

Sanitizers: ThreadSanitizer is not in the bar: Odin's `-sanitize:thread` instruments only
function entry and exit and reports no races (written in `docs/quality.md` with how
data races are prevented instead: no mutable globals, deterministic tests, the stepped
server). MemorySanitizer is not either (it needs every linked library instrumented, the
system's Vulkan loader and C library included).

**The new CI step:** "Test under AddressSanitizer · nightly" in `nightly.yml` (ubuntu-latest,
timeout 120 minutes): `./build.sh test --sanitize` (a new option of `build test`: every
package built with `-sanitize:address`, `ASAN_OPTIONS=detect_leaks=0` since the suite's own
tracking finds leaks; the per-package time limit times 5). Whatever it finds on the first run
is fixed at the cause in this row (each a test that fails without the fix).

**The lint `quality_docs`** (`tools/build/lints.odin`, run by `check`):

- parses `docs/threat_model.md`'s threat table and `docs/quality.md`'s table (Markdown tables
  by their headers; a malformed table is an error naming the line);
- `test:<name>`: a procedure `<name>` marked `@(test)` exists in a first-party package
  (`SOURCE_DIRS`);
- `fuzz:<target>`: the target is in `tools/fuzz/targets.odin`'s table;
- `ci:<step>`: a step or job with that exact `name:` exists in a workflow under
  `.github/workflows/`;
- `lint:<name>`: a lint of that name runs in `check`;
- `bench:<scenario>`: the scenario is one `build bench` accepts;
- a `built` row: every cover exists; a `planned` row: its milestone is an open row of the
  plan's rows table; **a planned row whose milestone is done fails** (the milestone landed
  without updating the threat model);
- every fuzz target in `targets.odin` is the cover of at least one threat row, and every
  target is in `docs/fuzzing.md`'s table (Q1's table kept current);
- errors name the doc, the line and the missing cover.

**Kept current: the rule.** Ground rule 6 (*Untrusted input is validated at the edge*) gains:
"A milestone that adds an untrusted input adds its fuzz target, and a milestone that builds a
defence marks its threat rows `built` with their covers, in the same commit;
`lint:quality_docs` fails otherwise." This row writes that sentence into the plan and adds
one line to each open spec that builds covers (M51c, M52, M52b, M52c, M52d, M52e, M53, M54,
M54b, M54c, M54f, M55): "Mark this row's threats in `docs/threat_model.md` built, with their
covers (Q5)." (Already added at planning, 2026-10-30, #84: check they are there.)

**Tests:** `tools/build/lints_test.odin`: `quality_docs` on fixture docs: a missing test, a
missing fuzz target, a missing CI step, a planned row of a done milestone, a target in no
row, a malformed table: each one error with the exact text and line; the real docs pass.
`no_retries` on fixture workflows: `continue-on-error: true`, a `retry` action, a shell
`|| ./build.sh test` re-run: each an error; the real workflows pass.

**Steps, in order:** `docs/threat_model.md` from the plan's section, the specs' hostile rows
and Q1-Q2's targets; `docs/quality.md`; the lints and their tests; `build test --sanitize` and
the nightly job, fixing what the first run finds; the plan's ground rule and summary.

**Left out:** a security audit by a person (the owner may want one before online servers);
threat rows for online services (M55c's hooks, the auth client: added by those rows);
ThreadSanitizer and MemorySanitizer (above).

**Open questions** (none blocks this row): none.

**Exit check:** `build check` passes with the two lints on the real docs and workflows, and
the lint tests pass; `./build.sh test --sanitize` passes on Linux locally; the suite and CI
green.

**Check by hand:** none.
