# R11b: the look, part one (tonemap and exposure, the colour grade, dithering, the look file)

The first of two rows of the owner's look (R11b, [R11c](R11c.md); split by #87: the
output chain and the tunables are one session, the world shaders' water and foliage another).
Arc rules: [R.md](R.md#rules-for-every-r-milestone).

**Why.** R11 gave the scene an HDR target and a tonemap that is a clamp. The owner decided
(2026-10-30) the look that goes on it; this row builds its output chain. **The owner's
decisions are kept as written** (the effects, toggles on by default, Reduce motion, the UI
clean, what is not in it, the budget rule); what changed is below.

**Checked against the code (2026-10-30, #87; corrections to the old R11b text):**

- **The Options tab is Video** (`Options_Tab.Video`, `client/screen_options.odin`); there is
  no Graphics tab. The toggles go there.
- **No renderer data hot-reloads today except shaders** (`client/shader_reload.odin`,
  `debug.hot_reload_shaders`, development builds). "The format the other hot-reloaded
  renderer data uses" has no referent; decided (engineering): the tunables are one JSON file
  read with the packs' JSON reader (`common/game/pack_json.odin`, its limits and line-exact
  errors), `assets/look.json`, embedded in the executable (`#load`) and reloaded from the source
  tree by the shader watcher in development builds. Whether a pack may carry its own look is a
  product question (below); until answered, only this file is read.
- **The palette** a grade would be built from exists: `planet_palette(reg, params)` and
  `worldgen.PALETTES` (`client/planet.odin`), from the world's parameters, which come from
  its address. **How a palette becomes a grade is not stated** (which colours move, toward
  what): that is the look itself, an open question below. This row builds the grade's machinery
  with the table at the identity until the owner answers.
- Reduce motion exists (`Settings.reduce_motion`): adaptation follows it as decided.
- "CI screenshots each effect on and off" needs a CI step: one is added (`Look`, beside `Sky`
  and `Held items`).
- "Each toggle off gives `images` output identical to R11's": R11's baselines are kept as the
  **plain set** (`assets/baselines/images/plain/`) and `build images` also renders every scene
  with every effect off and compares with it; a single effect's toggle-off is the identity by
  its own test (below).

## Design (R11b)

### The look file (`assets/look.json`, `client/render/look.odin`)

`Look :: struct` with one field per tunable and its range (`LOOK_FIELDS`, the console's table
form: name, range, default, help), read by `look_parse(json) -> (Look, []Pack_Error)`: unknown
fields, types and ranges refused with line and column, as pack files are. Tunables of this row:
`exposure.speed_up`, `exposure.speed_down` (EV per second), `exposure.min`, `exposure.max`
(EV), `exposure.bias` (EV), `grade.strength` (0..1), `dither.strength` (in output steps,
0..1). A reload that fails keeps the old values and logs the errors. The console's `look`
command prints the current values; `look reload` reloads by hand.

### Toggles

`Settings.look: bit_set[Look_Effect]` (`Tonemap`, `Exposure`, `Grade`, `Dither`, and R11c's
`Water`, `Foliage`), every one on by default, saved in the settings file, each a toggle in
Options → Video with its help line; the console's `set look.<effect> 0|1` for scripts and CI.
Off means the identity, by construction:

- **Tonemap off**: R11's clamp. **Exposure off**: exposure 0 EV (and adaptation stopped).
- **Grade off** (or strength 0): the table is skipped. **Dither off** (or strength 0): no
  noise added.

### Tonemap and exposure

- **Luminance** (compute, label `luminance`, metric `gpu_luminance`): the HDR target's log2
  luminance (Rec. 709 weights, clamped to [-16, 16] EV) averaged over a 64 x 36 grid of
  samples (one per 20 x 20 px at 1280 x 720, scaled with the output), as a fixed-point
  integer sum (`atomicAdd` on `uint`, 1/1024 EV units), so the result does not depend on the
  order the invocations run in.
- **Adaptation** (a second dispatch of one invocation, after a compute-to-compute barrier): `ev += clamp(target - ev, -down * dt, up * dt)` with `dt`
  the frame's time (push constant), the target `clamp(bias - mean_log_luminance + 3, min,
  max)`; the exposure lives in a device-local buffer that persists across frames and is never
  read by the CPU (the statistics read a copy, frames late). Reduce motion: `ev = target`.
- **AgX** (`assets/shaders/agx.glsl`, in `tonemap.frag`): the published AgX base (its inset
  matrix, log2 encoding between -12.47 and 4.03 EV, the sigmoid's polynomial fit, the outset
  matrix), no look transform; applied to `colour * exp2(ev)`, before the grade and the dither.
- `tonemap_reference` and `exposure_step` (`client/render/look.odin`): the CPU twins, from the
  same constants (rule 9).

### The colour grade (machinery; the table is the identity until the owner answers)

A 32³ `R8G8B8A8_UNORM` 3D image per world, built on the CPU at join (`grade_table(palette,
strength) -> [32*32*32][4]u8`), uploaded once (R10's ring is buffers only: the setup path on
the graphics queue, as the texture array is), sampled in `tonemap.frag` after AgX with linear
filtering at texel centres (`(c * 31 + 0.5) / 32`). `grade_table` returns the identity table
until the owner's construction is decided; strength 0 skips it.

### Dithering

A 64 x 64 blue-noise texture generated at start-up by void-and-cluster
(`client/render/blue_noise.odin`, deterministic, a fixed seed; `R8_UNORM`, nearest, repeating),
read at the output pixel, `(n - 0.5) * strength / 255` added to each channel after the grade
and before the sRGB encode. Applied in `tonemap.frag` only: the UI is drawn after it, so it
stays clean.

### CI

- `build images`: every scene twice (the look on, against the re-accepted default baselines;
  every effect off, against `plain/`, R11's pictures moved there unchanged, with their counts).
- The `Look` CI step: the `north`, `down`, `cave` and `night_lamp` scenes' scripts with each
  effect off in turn, screenshots `look_<effect>_off_<scene>` uploaded with the others.

## The order of the steps (R11b)

1. `plain/` (R11's baselines moved; `build images` runs both sets); `assets/look.json`,
   `Look`, the parser, hot reload, the toggles in Settings, Options and the console.
2. Luminance and adaptation, `exposure_step`; `--check look`'s exposure part.
3. AgX and `tonemap_reference`; the check's tonemap part.
4. The grade's table, image and sampling (identity table).
5. Blue noise and the dither.
6. The default baselines re-accepted (each effect's commit re-accepts what it changes, its
   before and after uploaded by the CI step); the `Look` step; docs; history.md.

## Tests (R11b)

- `client/render/look_test.odin`:
  - `test_look_parse`: the shipped file parses; an unknown field, a wrong type and a value out
    of range are refused at their line; a failed reload keeps the old values.
  - `test_exposure_step`: steps toward the target at the set speeds up and down, never past
    it; instant under Reduce motion; clamped to min and max.
  - `test_tonemap_reference`: AgX of 0 is 0, monotonic per channel on a ramp, hue kept for a
    saturated input brightened 8 EV within the published curve's tolerance, 1 maps below 1.
  - `test_grade_identity`: the identity table sampled at 4 096 random colours with the
    shader's addressing reproduces them within 1/510; strength 0 is skipped.
  - `test_grade_table_deterministic`: the table for three fixed world addresses hashed
    (XXH64), the same on every run and platform (the cross-OS test job).
  - `test_blue_noise`: deterministic (hash), every value 0..255 used about equally (a flat
    histogram within 10%), and its spectrum low at low frequencies (the energy in the lowest
    eighth of frequencies under 5% of the total: what makes it blue).
  - `test_dither_keeps_ui_clean`: (by construction) the UI pipeline's fragment shader does not
    include the dither: a check over `assets/shaders/ui.frag`'s includes.
- `--check look` (`client/look_check.odin`, a CI step on lavapipe under validation): a compute
  shader including `agx.glsl` over a 33³ grid of HDR colours from 0 to 64 against
  `tonemap_reference`, each channel within 1/4096; the luminance pass over three synthetic
  HDR images (uniform, a gradient, a bright spot) against the CPU's fixed-point mean exactly
  (integer sums); 120 adaptation steps against `exposure_step` within 1e-5 EV.
- `images`: the look-on set re-accepted in this row and still catching a change (rule 2 and
  R1: a mutation of `exposure.bias` by 0.25 EV, of `grade.strength` once the grade exists, and
  of `dither.strength` fails the default set, tried by hand and said in the report); the
  look-off set equal to `plain/` with no re-accept.
- Hot reload: `test_look_hot_reload` (the watcher's callback on a changed file updates the
  values without a restart; a stepped test on the watcher's own clock).

## Benchmarks (R11b)

Each effect is its own commit, so `bench compare <its parent> views` and `views
-size:2560x1440` gives its cost alone; all four reported, with `gpu_luminance` and
`gpu_tonemap`. **The budget (the owner's rule):** until measured, the look's effects together
at most 15% more `gpu_frame` than R11's last commit; after this row and R11c, the budget
becomes the measured figure plus 25% headroom, written into this spec's history entry and into
`docs/debugging.md`'s cost table. Over 15%, the costliest effect is made cheaper before the row
is done (a smaller luminance grid; the grade folded into the tonemap's table), never the
budget raised.

## Left out (R11b)

Water and foliage (R11c); bloom, light shafts, vignette, film grain, sun shadows,
anti-aliasing (the owner's choice: they wait in R.md's "Visual changes that wait for the
owner"); a histogram-based exposure (the average decided); the grade's construction (open).

## Exit check (R11b)

**Gated in CI:** `--check look` passes on lavapipe under validation; the look tests; `images`
passes both sets (the look on, re-accepted and catching a mutation; every effect off, equal to
R11's pictures); the `Look` step uploads each effect on and off; `build check` and the suite.
**Measured** (development machine, reported): each effect's cost by `bench compare` against
its parent; the four together within 15% of R11's `gpu_frame`.

## Open questions for the owner

1. **The grade's construction.** The owner decided a grade "built from the world's palette".
   What should it do with the palette: tint every colour toward the palette's average hue
   (keeping brightness), pull colours toward the nearest palette colour, or something else?
   Until answered, the grade's table is the identity (no change to the picture), its toggle and
   strength already in place.
2. **A pack's own look.** May a pack (or an experience, M54c) ship its own `look.json`
   values, so a creator sets their world's exposure, grade and dither? Until answered, only the
   game's file is read.

## Check by hand (R11b)

1. Open the CI run's `screenshots` artifact: compare `look_<effect>_off_<scene>` with the look-on
   picture of the same scene for each effect; tune `assets/look.json`'s starting values (listed
   in the row's report) by editing the file with `./build.sh run` open (it reloads).
2. Walk from a cave into daylight and back: the exposure follows in about the set speeds; with
   Reduce motion on, it jumps.
3. Look at a sunset sky at full screen: no banding in the gradient; the hotbar's text and
   icons have no noise.

## The owner's decision as written (2026-10-30; moved here from R.md by #87)

The text below is the decision R11b and R11c build; where the code made a point of it
stale, the correction is at the top of R11b and R11c, and the decision itself is unchanged.

**Why.** R11 gives the scene an HDR target and a tonemap pass that is the identity. The owner
decided (2026-10-30) the look that goes on it. This section is the spec; nothing is built yet.

**Design (decided).** Each effect is its own toggle in Options (Graphics), on by default, with
every tunable (below) a data value that hot-reloads. CI screenshots each effect on and off.

1. **Tonemap and exposure.** A neutral AgX-style tonemap (hues stay true as they brighten)
   replaces R11's identity. Exposure follows eye adaptation (a caves-to-daylight and back
   transition) from the average log luminance of the HDR target, computed in a compute pass
   in the frame graph; the tonemap reads the exposure from a GPU buffer, with no CPU
   readback. Reduce motion makes adaptation instant. Tunables: adaptation speed up and down,
   exposure minimum and maximum, exposure bias.
2. **A colour grade per world.** A small 3D lookup table (32 cubed) built on load from the
   world's palette (the palettes already come from the world's address; same address, same
   table), applied after the tonemap. Tunable: grade strength (0 is the identity table).
3. **Dithering at the output.** Ordered (blue-noise texture, generated, no asset file) noise of
   under one output step added before the swapchain's quantization, removing banding in sky
   and fog gradients. It is applied to the scene only: the UI is drawn after the tonemap pass
   and stays clean. Block textures keep nearest filtering and their palette quantization; the
   dither is at the output's resolution and one output step, so it does not soften them.
   Tunable: strength.
4. **Water.** A reflection of the sky at grazing angles (Schlick fresnel; the sky colour from
   the sky model's horizon and zenith, no screen-space trace) and a fade of the water's
   opacity and colour with depth (the depth behind the surface from the depth target).
   Tunables: fresnel strength and power, depth fade distance.
5. **Foliage.** Grass and leaves sway in a wind computed in the vertex shader from the
   server's time (the world tick, not the client clock), the block's position and a fixed
   noise, so every player sees the same motion. Reduce motion sets the sway to zero.
   Tunables: sway amount, wind speed.

**Not in R11b (the owner's choice):** bloom, light shafts, vignette, film grain, sun
shadows, anti-aliasing; they stay in "Visual changes that wait for the owner".

**Data.** The tunables live in one data file (in the format the other hot-reloaded renderer
data uses), with the starting values listed in the report for the owner to tune.

**Tests.** The grade table is deterministic per address and the identity at strength 0;
the tonemap's reference function agrees with the shader on a grid (as `--check cull` does);
adaptation steps toward the target at the set speed and is instant under Reduce motion;
the wind at a given tick and position is the same on two clients and zero under Reduce motion;
the dither leaves UI pixels unchanged and a flat gradient banding-free; each toggle off gives
`images` output identical to R11's; hot reload changes a tunable without a restart.

**Exit check.** The `images` baselines are re-accepted with the new look and still catch a
change (as R1 requires: a mutation of a tunable fails them). The effects' GPU cost is measured
with `bench compare` against R11's last commit on `views` and `views -size:2560x1440`, each
effect's cost reported on its own; the budget is stated from that measurement (decided now:
until measured, at most 15% more `gpu_frame`, to be replaced by the measured figure plus 25%
headroom). CI screenshots with each effect on and off. Check by hand: look at those
screenshots and tune the starting values.
