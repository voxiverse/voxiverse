# R12: the sky at a fraction of the cost (clouds traced once, at half resolution)

Arc rules: [R.md](R.md#rules-for-every-r-milestone). One session; not split (#87).

**Why.** At 2560 x 1440 the sky pass was 2.35 ms of a 5.65 ms GPU frame (at 13932f5): every
sky pixel walks the cloud slab's cells (`cloud_hit` in `assets/shaders/scene.glsl`, up to 160
steps, each `cloud_at` a dependent buffer-address load of the `Cloud_Map`), and every world
fragment whose way to the camera crosses the slab walks it again (`world_shade` →
`with_clouds`).

**Checked against the code (2026-10-30, #87; corrections to the old R12 text):**

- The sky is drawn after the world, entities and held items, writing no depth (only where the
  world left the screen empty). World fragments run `with_clouds` themselves (`world.glsl`):
  under the slab looking down they skip it (`max(y0, y1) > CLOUD_BOTTOM` fails), so the cost is
  in the sky and in views from at or above the slab.
- The clouds are switched by `Settings.clouds` (`Scene.cloud.w`); clouds fade from twice the
  fog distance to `CLOUD_FAR` (2 400 blocks). The trace depends only on the camera and the
  direction, not on what is in front, so it can run **before** the world, once per half-res
  pixel, to `CLOUD_FAR`.
- After R11 the frame has a graph, so the clouds' target is a transient image and its pass a
  compute pass the graph orders; after R11b the sky and world write HDR colour.
- **Scene constants in a uniform buffer** need a descriptor the code does not have (one
  bindless set: sampled images and samplers; everything else by address), and the held pass's
  view model has a second `Scene` per frame. The old text's step is kept as a **measured
  candidate** (R5b's method): built only if `bench compare` shows it, never on faith.
- What `images` scenes show clouds is found, not assumed: the session lists them (the horizon
  views `north`, `east`, `south`, `west` at least) from the scene counts' new
  `cloud_pixels` count.

## Design (R12)

### The cloud map as an image

The 256 x 256 `Cloud_Map` bits become an `R8_UNORM` image (`cloud_map_image`, 64 KiB, made
once from `cloud_map_generate`, uploaded by the setup path), read with `texelFetch` on its
bindless id (`Scene` gains `cloud_map_id`; `cloud_map` the address is removed). The map is
generated once per session as now.

### Clouds traced at half resolution (`assets/shaders/clouds.comp`, graph pass `clouds`)

- A transient `R16G16B16A16_SFLOAT` image at half the output's size each way (rounded up):
  rgb the shaded cloud colour (`with_clouds`' shading: face, `Scene.cloud`, the horizon's
  share), a the fade-weighted coverage, and a second transient `R32_SFLOAT` with the hit
  distance (`CLOUD_NONE` = 1e30 when the ray hits no cloud within `CLOUD_FAR`).
- One invocation per half-res pixel, the ray through the pixel's centre in full-res terms
  (the centre of its 2 x 2 block) from `inv_view_proj`; `cloud_hit` as now (the same DDA, the
  same 160-step cap, the map by `texelFetch`). Skipped wholesale (the pass not declared) when
  clouds are off.
- Runs before the world pass (it needs only the scene), so the graph can alias its targets with
  nothing else alive then; label `clouds`, metric `gpu_clouds`.

### Reading them back: the depth-aware upsample (`clouds_at(pixel, distance)` in `scene.glsl`)

For a full-res pixel and the distance `d` of what it shows (the world fragment's, or
`CLOUD_FAR` for the sky): the four half-res texels around it (bilinear positions and weights),
each **counted only when its hit distance is below `d`** (a cloud in front of what this pixel
shows); the cloud colour and coverage are the weighted mean of those counted, renormalized by
the counted weights times their share (so a hill's silhouette against a cloud gets no cloud
colour from texels whose cloud is behind the hill). `world_shade` calls it instead of
`with_clouds`; `sky.frag` calls it with `CLOUD_FAR`. `clouds_reference` (CPU) from the same
rules (rule 9).

### The measured candidate: scene constants as a uniform buffer

A binding 2 in the bindless set, an array of `MAX_SCENES` (8) uniform-buffer descriptors over
the `Scene_Buffers`' per-slot buffers (written once at start-up; the buffers never move), indexed
by a push-constant scene id (dynamically uniform: `shaderUniformBufferArrayDynamicIndexing`, a
Vulkan 1.0 feature every target exposes; required and refused with a log line otherwise, rule
5). Built in one commit, measured with `bench compare <its parent> views` and
`-size:2560x1440`, and reverted unless `gpu_sky` or `gpu_world` falls (p < 0.05); the report
says which.

## The picture

The clouds' edges change slightly (half resolution; the trace's position is the 2 x 2 block's
centre): the scenes that show clouds are re-accepted (`build images` writes the rendered
picture and its difference to `build/images/` when it fails, before `--accept`; the report
lists those scenes under Check by hand and keeps the old pictures in `build/images/before/`;
the row does not wait). Scenes without clouds must pass unchanged, and
the scene counts tell which is which (`cloud_pixels`: output pixels with cloud coverage above
zero; exact on lavapipe, `~1%` tolerance like `chunks_occluded`).

## The order of the steps (R12)

1. `cloud_pixels` in the scene counts, accepted on the code as it is (one commit).
2. The cloud map image; `images` unchanged (a texel fetch reads the same bits).
3. `clouds.comp`, its targets and graph pass; `clouds_at` in the sky and world shaders;
   `--check clouds`; the cloud scenes re-accepted, the others unchanged.
4. The uniform-buffer candidate, measured, kept or reverted.
5. Measurement; docs (debugging.md: Graphics, the clouds pass); history.md.

## Tests (R12)

- `client/render/render_test.odin`: `test_cloud_map_image` (the image's bytes are the bits:
  255 where set, 0 where clear, for the generated map); `test_clouds_reference` (a pixel
  whose four texels' clouds are all behind `d` gets none; all in front gets their mean; a
  silhouette case by hand).
- `--check clouds` (`client/render/clouds_check.odin`, a CI step on lavapipe under
  validation): (1) the compute pass's hit distance and colour for 4 096 rays (horizon-grazing,
  straight up and down, from inside, above and below the slab) against `cloud_hit` on the CPU
  (`cloud_hit_reference`, the DDA in Odin from the same steps): the same cell and face, the
  distance within 1e-3 block, colour within 1/4096; rays within 1e-4 of a cell edge rejected by
  the generator, at least a quarter hitting and a quarter missing; (2) `clouds_at` against
  `clouds_reference` for synthetic half-res targets and depths, within 1/4096.
- `images`: cloud scenes re-accepted with `cloud_pixels`; the rest unchanged.

## Benchmarks (R12)

`bench compare <the commit before R12> views -size:2560x1440` (the full run, not the smoke)
and `views`:

| Metric | Target |
|---|---|
| `gpu_sky` at 2560 x 1440 | at most 30% of the commit before R12's (p < 0.05) |
| `gpu_sky + gpu_clouds` at 2560 x 1440 | reported (the trace moved, not vanished) |
| `gpu_world` | not worse at either size |
| `gpu_frame` at 2560 x 1440 | lower (p < 0.05) |

## Left out (R12)

Temporal reprojection of the clouds (a quarter of the pixels a frame); volumetric clouds;
clouds in R11c's water reflection; a cloud shadow on the ground. Any change to the clouds'
shape or colour.

## Exit check (R12)

**Gated in CI:** `--check clouds` passes on lavapipe under validation; the tests above;
`images` passes after the cloud scenes' re-accept, every other scene unchanged and the scene
counts' `cloud_pixels` matching; `build check` and the suite. **Measured** (development
machine, reported): `gpu_sky` at 2560 x 1440 at most 30% of the commit before R12's, and
`gpu_world` not worse.
