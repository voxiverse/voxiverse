# R9: a GPU memory allocator (every buffer and image sub-allocated)

The first of two memory rows (R9, [R9b](R9b.md); split by #87: the allocator and moving
every resource onto it is one session, the world's growing arena another). Arc rules:
[R.md](R.md#rules-for-every-r-milestone).

**Why.** Every buffer and image has its own `vkAllocateMemory` (`gpu.allocate`,
`client/gpu/resources.odin`); drivers cap the count (`maxMemoryAllocationCount`, 4 096 on
many) and an allocation costs far more than a sub-allocation. Buffers that grow
(`buffer_reserve` in `world_pass.odin`: the water commands, the cull commands and their
staging) free and allocate again in the middle of a session.

**Checked against the code (2026-10-30, #87; corrections to the old R9 text):**

- 27 call sites of `create_buffer`, `create_image` and `buffer_reserve` across `client/gpu`
  and `client/render`; `create_buffer` takes `host_visible: bool` (host-visible buffers are
  mapped and coherent), and buffers with `SHADER_DEVICE_ADDRESS` usage need memory allocated
  with `MEMORY_ALLOCATE_DEVICE_ADDRESS` (`allocate`'s `device_address`).
- `Gpu.memory_bytes` counts bytes allocated; `memory_report` reads `VK_EXT_memory_budget`
  when present. There is no count of allocations, and no metric for either.
- Dedicated allocations: Vulkan 1.1 core's `VkMemoryDedicatedRequirements`
  (`vkGetBufferMemoryRequirements2`, `vkGetImageMemoryRequirements2`) tell when a driver
  prefers or requires one; the old text's "at or above 32 MiB" rule is kept beside it.
- Buffers and optimal-tiling images in one block must respect `bufferImageGranularity`; the
  old text did not say how. Decided: they never share a block.

## Design (R9)

### `client/gpu/allocator.odin`

- **Blocks.** Per (memory type, kind) with kind `Linear` (buffers) or `Optimal` (images), a
  list of blocks of `BLOCK_SIZE` (64 MiB) or, for a heap smaller than 1 GiB, an eighth of the
  heap rounded down to a power of two. A host-visible block is mapped once when made; its
  sub-allocations' `mapped` point into it. A block for buffers is allocated with
  `DEVICE_ADDRESS` (every buffer may need an address; the flag costs nothing).
- **Inside a block: a two-level segregated-fit free list** (TLSF): first level by the size's
  highest set bit, second level 16 linear subdivisions of it; a bit map per level, so
  finding a fitting free range and freeing are O(1). Ranges carry boundary tags in a CPU-side
  node pool (never in GPU memory); a freed range merges with free neighbours at once. Every
  offset is aligned to the resource's `alignment` (the padding is part of the range).
- **Dedicated allocations** for a resource of at least `DEDICATED_MIN` (32 MiB), or whose
  `VkMemoryDedicatedRequirements` say `prefersDedicatedAllocation` or
  `requiresDedicatedAllocation`; allocated with `VkMemoryDedicatedAllocateInfo`.
- **Empty blocks**: one empty block per (type, kind) is kept; a second empty one is freed.
- `Allocation :: struct {memory: vk.DeviceMemory, offset: vk.DeviceSize, size: int, block:
  i32, node: u32, mapped: [^]u8}` replaces `Buffer.memory`/`Image.memory`; `memory_size`
  stays. `create_buffer` and `create_image` bind with `vkBindBufferMemory`/`vkBindImageMemory`
  at the allocation's offset; `destroy_*` free it. The CPU side is a pure data structure
  (`base.Tlsf`, `tlsf_alloc`, `tlsf_free`, `tlsf_check`) with no Vulkan in it, so it is tested and
  benchmarked without a GPU.
- **Counting:** `Gpu.allocations` (live `vkAllocateMemory` count), `Gpu.allocate_calls`
  (since start), `Gpu.memory_bytes` (block bytes, plus dedicated), `Gpu.used_bytes` (bytes
  in live sub-allocations). Metrics `gpu_allocate_calls` (calls this frame, so a scenario's
  sum is its count) and `gpu_memory` (MiB in blocks); the scene counts gain
  `gpu_allocations` (live, exact). F3's memory line and `memory_report` show blocks, used
  and the driver's budget.
- **Out of memory**: `vkAllocateMemory` failing with `ERROR_OUT_OF_DEVICE_MEMORY` for a new
  block logs the request, the type and `memory_report`, and returns false to the caller, as
  today; nothing is retried silently.

### Buffers that grow

`buffer_reserve` (`world_pass.odin`) keeps its doubling but its old buffer is freed only when
the frame slot that used it comes round (a per-slot list of buffers to free, like `freed`
ranges), so a grown buffer never waits for the GPU; with sub-allocation a regrowth is a
`tlsf_alloc`, not a `vkAllocateMemory`.

## The order of the steps (R9)

1. `base/tlsf.odin`, its tests and its budget scene (no Vulkan).
2. Blocks, dedicated allocations, `Allocation`; `create_buffer`/`create_image`/`destroy_*`
   on them; every caller unchanged in its arguments.
3. The counters, metrics, scene counts, F3; deferred frees in `buffer_reserve`.
4. Measurement; docs (debugging.md: Graphics, memory; the cost table; history.md).

## Tests (R9)

- `base/tlsf_test.odin` (no device):
  - `test_tlsf_fits_and_coalesces`: allocations of sizes 1 B to 32 MiB with alignments 1 to
    64 KiB never overlap and are aligned; freeing every other one then the rest leaves one
    free range of the whole block.
  - `test_tlsf_fragmentation`: a fixed table of sizes in the test (the quad meshes of `build
    bench chunks`' region, recorded once), allocated and freed in a flight's order, fits in
    two blocks.
  - `test_tlsf_against_model` (property, fixed seed 87, 100 000 operations): random allocs and
    frees, checked after each against a model (a sorted list of ranges): no overlap, every
    offset aligned, the same free bytes; a request TLSF refuses has no free range of its
    rounded-up size class in the model (TLSF's good-fit rule, so it is never refused for
    lack of searching); `tlsf_check` (bit maps agree with the lists, no two free neighbours)
    after each.
  - `test_dedicated_rule`: at and above `DEDICATED_MIN`, and on `prefers`, a dedicated one.
- The game's checks under validation (every `--check`, `images`) are the device test: every
  resource now lives in a block; validation's memory-binding checks (offset alignment,
  overlapping images) run on all of them.
- `images`: pictures unchanged; counts gain `gpu_allocations` (exact).

## Benchmarks (R9)

- **Where `Tlsf` lives:** `base/tlsf.odin` (a pure data structure beside
  `base/range_alloc.odin`, depending on nothing), used by `client/gpu/allocator.odin` and by
  R9b's arena.
- `build bench budgets -check` gains `budget_tlsf` (`tools/bench/budgets.odin`, which already
  imports `base`): 1 000 000 mixed operations from a fixed seed; metric `Tlsf_Op`, mean at
  most 0.2 us (CI's release-like build, the margin the other budgets use; set from the first
  measured run and never raised to pass).
- `bench compare <the commit before R9> flight`: `gpu_allocate_calls` summed over the
  measured span (the target: at most 10, from the old text), frame p99 within noise.
- `views`: `gpu_frame` within noise (memory placement can change cache behaviour: reported).

## Validation and synchronization

Every resource in CI's `--check` runs and `images` is bound through the allocator, under
validation (binding offsets, `bufferImageGranularity`, mapped ranges). No new barriers.

## Left out (R9)

Defragmentation of blocks; aliasing of transient images (R11's frame graph does it on this
allocator); a budget-driven eviction policy (R9b, for the world's arena only); memory
priorities (`VK_EXT_memory_priority`).

## Exit check (R9)

**Gated in CI:** the allocator tests and property test; `build bench budgets -check` within
`Tlsf_Op`; every `--check` and `images` under validation with `gpu_allocations` in the scene
counts; `build check` and the suite. **Measured** (development machine, reported): `flight`
makes at most 10 `vkAllocateMemory` calls while measuring; frame p99 within noise.
