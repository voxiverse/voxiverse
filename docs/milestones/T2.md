# T2: the deterministic harness

The second row of the test and CI overhaul (issue #66, the owner's priority; the overview
and the order are in [T.md](T.md)). T1 moved the source-scanning tests into `check`. T2
builds the harness every later row stands on: T3's scenarios run on it, T4 moves the 32
threaded-server files onto it, T6's lints forbid what it makes unnecessary.

## Why

Measured for #66, every flake since 2026-10-27 came from one of three patterns: wall-clock
timing, real threads with sockets and sleeps, and world state nobody controlled (natural
spawning). M38's stepped server already removed the thread: `Config.stepped` starts no
thread and no worker, and the caller runs each tick with `step`. Three gaps keep the tests
on it from being fully deterministic, and keep the threaded tests from moving onto it:

- **One player, and no network.** The stepped server takes one in-process player, on the
  local `game.Pipe`, which is reliable and ordered by contract. Every test that wants a
  second player, or a lossy link, opens a real UDP socket on loopback (`listen = true`) and
  sleeps so the packets arrive: `client/still_test.odin` (`time.sleep(time.Millisecond)` a
  tick), `client/input_modes_test.odin`, `client/weapons_test.odin` and
  `server/party_test.odin` (`time.sleep(300 * time.Microsecond)` a tick, and 2 ms waits for
  the handshake). How many ticks a packet takes depends on the machine.
- **netcode reads the wall clock.** `netcode.Socket` holds simulated loss, duplication and
  jitter, already drawn from a seeded `base.Rng` (`Conditions.seed`), but its delays are
  measured against `time.tick_now()`, as are the reliability layer's keepalives, resends
  and timeouts: the server passes `time.tick_now()` to `host_update` and `host_flush`, the
  client session to `link_update` and `link_flush`. So the same seed does not give the
  same losses at the same ticks. `common/netcode/conn_test.odin` simulates its own wire
  with the unseeded `rand.float32()`.
- **No fixed world.** Each file makes its own: seed 38 Earth (determinism), `GRIEF_SEED`
  Earth with `rules_still()` (journal and its dozen users), seed 33 with `still_rules()`
  (client), seed 23 Classic (party). Sheep, random ticks and the daylight cycle are on
  unless a file remembered to turn them off, and terrain features decide where a test's
  player lands.

T2 closes the three gaps with one in-memory network on a tick clock, one fixed test world
and one stepping API, and moves every test file that starts a stepped server onto them.

## Design

### The simulated network (`common/netcode/simnet.odin`)

`Simnet` is an in-memory datagram network: ports with an inbox each, a clock, and the
conditions every packet on it meets. No socket, no thread, no wall clock. The reliability
layer (`Conn`), the host and the link run over it unchanged, so a test exercises the same
code as UDP play, down to the handshake, resends and fragments. Only delivery differs.

```odin
Simnet :: struct {
	now:        time.Tick, // the network's clock: advanced by its owner, never read from the OS
	conditions: Conditions, // what every packet sent on it meets (seed: never 0, see below)
	ports:      [dynamic]Sim_Port, // bound, in the order bound
	next_port:  int, // the next port given to a socket that asks for any (from SIM_FIRST_PORT)
	sent:       int, // datagrams handed to the network
	delivered:  int, // ... put in an inbox
	unbound:    int, // ... sent to a port nobody holds (dropped, as UDP does)
	overflowed: int, // ... dropped because the inbox held SIM_INBOX_MAX (logged once)
	allocator:  mem.Allocator,
}

Sim_Port :: struct {
	port:  int,
	inbox: [dynamic]Sim_Packet, // arrived, oldest first
}

Sim_Packet :: struct {
	from: net.Endpoint,
	data: []u8, // owned by the network until received
}

SIM_FIRST_PORT :: 50000
SIM_INBOX_MAX :: 4096
SIM_EPOCH_NS :: 1_000 * i64(time.Second) // tick 0's time (a constant cannot be a struct)
```

- `simnet_init(n, conditions := Conditions{}, allocator := context.allocator, loc :=
  #caller_location)`, `simnet_destroy(n)` (frees what nobody received),
  `simnet_set_conditions(n, c)` (from the next send on), `simnet_tick_time(tick: u64, rate:
  int) -> time.Tick` (`SIM_EPOCH_NS + tick * time.Second / rate`, in integers, so 30 ticks
  at rate 30 are exactly one second; netcode does not import `game`, so the rate is passed;
  below, `simnet_tick_time(t)` is short for `simnet_tick_time(t, game.TICK_RATE)`).
- **Addresses** are `127.0.0.1:<port>`. A socket asking for port 0 gets `next_port`, then
  `next_port` moves on; binding a port that is held fails as `socket_open` does
  (`.Address_In_Use`).
- **The Socket gets a second backend**: `Socket.sim: ^Simnet` (nil: UDP).
  `socket_open(s, port, broadcast := false, sim: ^Simnet = nil)`: with `sim`, no OS socket
  is made and `broadcast` must be false (LAN discovery stays UDP: see Left out).
  `send_now` puts a copy in the destination port's inbox (an unknown port: `unbound += 1`).
  `socket_receive` takes the oldest packet from its inbox, copies it into `recv_buf` (the
  same "valid until the next call" contract as UDP) and frees it. `socket_close` unbinds
  the port and frees its inbox. The capture hook (`Capture`) records simulated packets
  exactly as UDP ones, so a harness run can be opened in Wireshark.
- **Conditions on the simulated network** are `n.conditions`, read by `socket_send` at
  each send (the socket's own `conditions` field is for UDP only). Each socket draws from
  its own stream, seeded `n.conditions.seed ~ (u64(s.port) << 32)`: the server's draws do
  not depend on how many packets a client sent. A simulated network is **never seeded from
  the clock**: `simnet_init` and `simnet_set_conditions` replace seed 0 with
  `SIMNET_DEFAULT_SEED :: 0x5eed_0002`. The existing code path does the rest: loss and
  duplication per packet, delay `latency_ms + jitter_ms * u` (jitter reorders), packets held
  at the sender until `now` reaches their time, measured against `n.now`.
- **The clock.** `socket_now(s) -> time.Tick` is `s.sim.now` on a simulated socket, else
  `time.tick_now()`. `host_now(h)` and `link_now(l)` return their socket's. Every
  `time.tick_now()` inside `host.odin` and `link.odin` (closing, pumping before close)
  becomes `host_now`/`link_now`. Time on a simulated network moves only when its owner sets
  `n.now`, so keepalives (`KEEPALIVE`, 100 ms), resends, the rate allowance and the 10 s
  timeout are counted in ticks.
- **Single-threaded.** A `Simnet` has no mutex: the harness owns it and runs every party on
  its thread.

### The server and the client on it

- `server.Config.net: ^netcode.Simnet`: with `listen` (or a later `open_lan`), the server's
  host opens on that network instead of UDP. `start` refuses (logs and returns false) `net`
  without `stepped` (a simulated network has no lock) and `net` with `conditions` set (on a
  simulated network the network's conditions are the only ones).
- `server_now(s) -> time.Tick` (`server/server.odin`): `s.config.net.now` when set, else
  `time.tick_now()`. It replaces `time.tick_now()` in the calls into netcode:
  `host_update`, `host_flush` and the two `host_kick`s (`server.odin`, `players.odin`). The
  live tick's pacing, `tick_ms` and the save timings keep the wall clock: they are not
  state (determinism.md rule 5).
- `client.Session_Config.net: ^netcode.Simnet`: with `join`, the link connects on that
  network (`link_connect(..., sim = config.net)`). Every netcode time the session passes
  comes from `netcode.link_now(&s.link)`: `link_update` in `receive`, `last_flush` and
  `link_flush` in `flush`, `ping_sent` in `net_update`.
- **The double tap** (`Session.last_jump`, the fly toggle) stops reading the wall clock: the
  session keeps `frame_seconds: f64`, the sum of the `dt` it is given, and `last_jump`
  becomes that sum at the last jump (an `f64`). `DOUBLE_TAP_SECONDS` is unchanged. A player
  sees no difference (the frames' `dt` is the wall clock's in play); a test driving frames
  of `game.TICK_SECONDS` gets the same answer on every machine.
- `server/net_test.odin`'s test client follows: `net_connect(c, port, name, password := "",
  capture := "", sim: ^netcode.Simnet = nil)`, and `net_pump` passes `link_now`. Its
  threaded callers stay on UDP until T4.

### The fixed test world: the flat generator

`worldgen.Kind.Flat` (`"flat"`, `common/worldgen/flat.odin`): the same at every (x, z) and
for every seed.

| y | block |
|---|---|
| 0 and above | air |
| -1 | grass |
| -4 to -2 | dirt |
| -255 to -5 | stone |
| -256 (`WORLD_MIN_Y`) | bedrock |

`flat_generate` returns `is_uniform` for every chunk but the two that hold a boundary
(chunk y -1, with grass, dirt and stone; chunk y -16, with the bedrock floor): air above,
stone between. `column_top` is -1, `column_tops` all -1, `spawn_point` `{0.5, 0, 0.5}`. No
trees, caves, ores, structures or gates: `locate` and `arrival_gate` answer "none" as for
Classic. `kind_by_name("flat")` works, so a `world.cfg` may name it. It is not offered in
universe creation (the creation screen offers no generator).

### The harness (`server/harness.odin`)

Non-test code in package `server`, beside `stepped.odin`, because both the server's tests
and the client's use it and a test file is visible only to its own package.

```odin
Harness :: struct {
	srv:     Server,
	net:     netcode.Simnet, // every remote player's network (the server listens on it)
	pipe:    game.Pipe, // the local player's (harness_local), when there is one
	parties: [dynamic]Harness_Party, // run each tick before the server, in the order added
	started: bool,
	last:    State_Hash, // the last step's
}

Harness_Party :: struct {
	tick: proc(data: rawptr), // receive what has arrived, decide, send
	data: rawptr,
}

HARNESS_SEED :: 66 // issue #66; the flat world does not depend on it, its RNG streams do
```

- `harness_world() -> Config`, the fixed small test world: `seed = HARNESS_SEED`,
  `generator = .Flat`, `view_radius = 2`, `view_height = 1` (75 chunks a player),
  `spawn = [3]f64{0.5, 0, 0.5}`, `max_players = 8`, `allow_cheats = true`,
  `everyone_cheats = true`, `no_sheep = true`, `backups = 0`, `save_dir = ""`, and
  `rules = harness_rules()`.
- `harness_rules() -> game.Rules`: `game.RULES_DEFAULTS` with `random_tick_speed = 0` and
  `daylight_cycle = false`. **Natural spawning, random ticks and the daylight cycle are off;
  a test turns one on** by changing the `Config` before `harness_start` or the rule through
  the server's command path (`/gamerule`) as a player would. The game has no weather yet;
  when it has, its switch is added here, off.
- `harness_start(h, config := harness_world(), local := false, conditions :=
  netcode.Conditions{}) -> bool`: `simnet_init(&h.net, conditions)`, `h.net.now =
  simnet_tick_time(0)`; the config is taken with `stepped = true`, `workers = 0`, `net =
  &h.net` forced (a test's own config keeps everything else: the M38 sessions keep seed 38
  Earth, the journal's `GRIEF_SEED`). With `local`, the pipe is made and the server takes
  it as seat 0, as singleplayer does. `h` must stay at its address until `harness_stop`.
- `harness_local(h) -> game.Endpoint`: the client's end of the pipe (asserts `local`).
  `harness_address(h) -> net.Endpoint`: where the server listens on the simulated network
  (asserts `listen`).
- `harness_add(h, tick: proc(data: rawptr), data: rawptr)`: a party (the mirror, a test
  client, a `client.Session` driven by a test, a bot). The harness never decodes a message;
  a party is whatever the test gives it.
- `harness_step(h, n := 1) -> State_Hash` runs n ticks. One tick is, in order:
  `h.net.now = simnet_tick_time(h.srv.tick + 1)` (the time of the tick about to run); every
  party's `tick`, in the order added; `step(&h.srv)`. So what a party sends in a tick is
  handled in that tick (the pipe as M38 has it; the simulated network when conditions are
  zero), and what the server sends at the end of a tick is there for the parties at the
  next. It returns the last tick's hash.
- `harness_step_until(h, until: proc(data: rawptr) -> bool, data: rawptr, max_ticks: int) ->
  (ticks: int, ok: bool)`: steps until `until(data)` is true, checked after each tick, at
  most `max_ticks` ticks; `ok` is false when it never was (then exactly `max_ticks` ran).
  It never sleeps and never reads a clock: a condition that does not come in `max_ticks`
  ticks is a failure, the same on every machine.
- `harness_now(h) -> time.Tick` (the network's clock) and `harness_ticks(h) -> u64`.
- `harness_stop(h) -> bool`: `stop(&h.srv)`, then the pipe and the network (whatever is
  still in flight is freed). The parties are the test's to end, before or after.

### What moves onto it

Every test file that starts a stepped server, directly or through a helper: 23 files today.
(T.md's "16" counted the files that name `stepped` or call `step` themselves; the helpers
`session_start` and `grief_open` carry 7 more.)

- **The M38 session** (`server/determinism_test.odin`): `Session` holds a `Harness` instead
  of `srv` and `pipe`; `session_start` calls `harness_start(&sess.h, config, local = true)`
  with its own Earth config (`with` still replaces it) and adds the mirror as a party, which
  does what `session_step` did before `step` (pump, predict, send, act).
  `session_step` becomes `harness_step` plus its bookkeeping (hashes, seen, log).
  `sess.srv` reads become `sess.h.srv`. The mirror stays on the pipe: **M38's roots, the
  cross-OS logs and M39's bandwidth baselines (`bandwidth_test.odin`'s committed numbers and
  roots) do not move.**
- **Its users** (through `session_start`, `grief_open` or `crash_setup`):
  `bandwidth_test`, `journal_test`, `journal_compact_test`, `compact_test`, `crash_test`,
  `lock_test`, `protect_test`, `pack_reload_test`, `packs_test`, `containers_test`,
  `backup_test`, `export_test`, `save_slice_test`, `save_tx_test`, `save_budget_test`,
  `shapes_test`. `grief_open`'s "up to 900 ticks until ready" becomes
  `harness_step_until(&g.sess.h, ready, g.sess, 900)`; every hand loop of the form
  `for i in 0 ..< n {session_step(...); if cond {break}}` becomes `harness_step_until`.
- **Servers with nobody on them** (`server/migrate_test.odin`, `client/universes_test.odin`):
  `harness_start` with their config and no party, `harness_stop`.
- **The four on real UDP** (`client/still_test.odin`, `client/input_modes_test.odin`,
  `client/weapons_test.odin`, `server/party_test.odin`): the server listens on the harness's
  network, each `client.Session` joins with `net = &h.net` and `Join{address =
  harness_address(h)}`, the party bots with `net_connect(..., sim = &h.net)`; each frame or
  bot step is a party. **Their `time.sleep`s are deleted** (nothing is waited for: a packet
  sent in a tick is in the inbox at once), and their "until met / until playing" loops
  become `harness_step_until`. `party_test`'s per-client downstream budget is compared as
  before; if the simulated clock moves the measured bytes (keepalives now fall on ticks), the
  baseline is measured again with `build bench party`, never loosened by hand.
- **The pieces T3 and T7 decide on stay**: `rules_still()`, `still_rules()` and each file's
  seed are not replaced by the harness world in T2 (that changes what the tests see; the
  scenarios of T3 are where tests start on `harness_world()`).

`conn_test.odin`'s private `Wire` (unseeded `rand`, its own 5 ms clock) is replaced by two
`Conn`s over one `Simnet` with a seed: one simulated network in the code, not two.

## Left out

- **The scenario runner and invariants** (T3), **the 32 threaded-server files** (T4: they
  keep `start` without `stepped`, `net_wait`'s wall-clock deadlines and their sleeps until
  then), **timing budgets** (T5), **the lints** that forbid sleeps, clocks and `start(&srv…)`
  in unit tests (T6: switched on when nothing violates them).
- **Changing what a moved test checks.** A file moves onto the harness with its assertions,
  seed and rules as they are; deleting or merging tests is T3 and T7.
- **LAN discovery on the simulated network** (`Discovery`, broadcasts): stays UDP; the smoke
  suite (T6) keeps a real-socket test of it.
- **The pipe's own conditions** (`pipe_set_conditions`: latency, jitter, bandwidth on the
  wall clock): they stay for the debug variables in a live game; the harness never sets
  them, and loss on the pipe stays impossible by its contract. Lossy tests use the network.
- **Several local players**: the pipe is one seat, as M38 has it. More players are remote
  parties on the network.
- **Seeding the handshake's crypto** (the host's cookie secret and tokens, the link's salt,
  the server's challenge nonce): `crypto` randomness is never state (determinism.md rule 3),
  their lengths are fixed, so they draw nothing from the condition streams and change no
  state hash.

## Decisions (made here; T.md left them open)

- **Loss lives on netcode, not on the pipe.** T.md asks for "seeded loss, latency,
  reordering and duplication" in an in-memory transport. The pipe is reliable and ordered
  by contract (the in-process protocol relies on it), and the code that copes with loss is
  netcode's reliability layer. So the lossy transport is netcode over an in-memory network,
  and the pipe stays as singleplayer has it. This tests the code a remote player runs, not
  a second copy of it (ground rule 8, one source of truth), and keeps M38's mirror and its
  baselines where they are.
- **The Socket gets a backend rather than netcode getting an interface.** Loss, duplication
  and jitter already live in `socket_send`, seeded; only delivery and the clock were
  missing. A second backend in one file touches two procedures; an interface over Host and
  Link would touch all of netcode.
- **Names**: `harness_step` and `harness_step_until` (T.md's `step(n)` and
  `step_until`), because `step` is M38's single tick and Odin procedures in one package need
  distinct names; the `harness_` prefix follows `pipe_`, `link_`, `host_`. The network is
  `Simnet`.
- **The harness is non-test code in `server/`**, like `stepped.odin`: the client's tests
  need it, and a `_test.odin` file is private to its package. It imports no client code.
- **A party is a procedure and a pointer**, not a client type: the server package cannot
  know `client.Session`, and the mirror, the test client, a session and a bot are all
  parties. Parties run before the server's tick, in the order added, which is what M38's
  `session_step` already did.
- **The fixed world is a generator** (`Flat`), not an Earth seed with a known spawn: flat
  ground is the same for every seed, so nothing a toolchain or worldgen change does to Earth
  can move a test's player, and most of its chunks are uniform (cheap). Its layer depths
  are Minecraft's superflat order (grass, three dirt, stone, a bedrock floor) on this game's
  world bottom; the surface at y -1 puts a standing player's feet at y 0.
- **Size**: `view_radius = 2`, `view_height = 1`, the smallest interest the client's own
  27-chunk desync rule and landing are comfortable in, so a step stays cheap; a test needing
  more says so in its config.
- **Cheats on** in the fixed world (`allow_cheats`, `everyone_cheats`): tests drive state
  through commands as the M38 script does; a permissions test turns them off.
- **The tick's time is exact**: `SIM_EPOCH_NS + tick * 1 s / 30` in integers, so 30 ticks are
  one second with no drift. `SIM_EPOCH_NS` is far from zero so a zero-valued `time.Tick` in any
  struct reads as "long ago", as it does against the OS clock.
- **The count is 23 files**, not T.md's 16 (see "What moves onto it"); T.md's T2 line is
  corrected to "every file that starts a stepped server".
- **No split planned**: the harness without the files moved onto it proves nothing. If the
  session must split, steps 1-5 are T2 (exit: the harness tests, the transport test, the
  M38 session and its users on it, baselines untouched) and step 6 is T2b (exit: the four
  UDP files and the two serverless ones on the harness, no sleep in any of them).
